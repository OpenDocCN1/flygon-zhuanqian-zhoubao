# 零基础・Cursor实战｜不懂代码，我竟也为机械部门做出了自动化评估程序

大家好，我是龙哥。加入赚钱圈子已经一年半，也完成了从应届生到职场人的身份切换。上次发长篇推文已经过去挺久，入职以后副业探索的速度放缓了些，不过我对AI发展的关注没停，尤其是AI在传统行业里能带来哪些变化，我格外在意。

这篇文章想分享的，是一个完全不懂编程的新人，如何把部门里的新产品评估工作做成自动化程序的全过程。写到一半，我发现更想聊的其实是AI编程里的那些“最少必要知识”——站在小白的角度，用通俗的语言把它们捋清楚。

近段时间，身边圈子用AI编出了不少互联网与自媒体方向的小工具，但我所处的传统机械制造领域，AI的存在感一直不强。去年我曾试着用AI做新产品评估，可这门工作牵扯到大量精确的产品参数，现成AI工具很难直接落地，精度和细节始终过不了关，所以一直没能突破。

直到Cursor出现，我再度燃起了对评估自动化的期待。借助它，之前的技术瓶颈总算被绕过去，评估做到了精准且高效，时间省了，效率也上去了。今天就来聊聊：零编程基础的我，如何靠Cursor把这个工具造出来，以及AI在传统制造行业里的想象空间。

## 先讲个背景

我大学时的成绩单相当难看，非水课基本挂过一遍，高数拿了7分，算得上标准的“混子工程师”。去年碰上好运，成了一家传统制造外企的员工。跟着同事做了两轮新产品的评估，之后就被要求独立负责这项任务，还要给出设备工装的建议。一开始真的无从下手。但慢慢想明白了一件事：所谓评估，说白了就是把新产品信息导入系统，对比已有产品，判断现有产线的能力，再看要不要追加设备和工装。这套流程完全可以交给AI来跑，效率会提升不少。

以前我就靠Excel表，把新品参数和量产产品手动逐行比对。有经验的同事可能一个小时收工，而记忆力和经验都欠佳的我，大半天也不一定搞得定。更麻烦的是要找设备工装的老师傅逐个确认，哪些投资才能落地。这类反复又琐碎的活计，既让我尝到低效的滋味，也让我意识到：沿用老办法，已经很难满足现代工程师的诉求。

我下定决心用AI编程，理由很实在：提高评估的速度与准确率，同时压低新产品在设备工装上的采购支出。评估越准，产线规划和新品引入时的无效成本就越少。

另外一个原因和“AI大使”有关。公司总部在物色一批“AI大使”人选，打算先重点带出50名AI培训师，再由这50人去影响5000名工程师。这个机会对我有吸引力，因为我本来就打算一两年后离职去做AI相关创业，有了这个身份等于多一份背书。但眼下的处境是：我的机械基础还很薄弱，日常工作已经有些吃力，领导不可能同意我拿出三分之一的工作时间参加AI培训。所以我想换个思路——研发一款能提高工程师生产效率的工具，用实际成果展现AI的潜力，争取名正言顺地进入AI大使计划。

## 编程，到底需要懂到什么程度

第一次正经接触编程是在9月的AI编程航海，跟着手册学了基础概念、把编程环境装好，实战就碰了贪吃蛇和合并文件夹这类办公小工具。全程多半是照着手册一步步来，编程到底是啥，心里其实没底。![](img/6c8ea3eea4f94cfa20a1ffdb087b926f.png)直到后来刷到圈友分享的Cursor实操教程，我才重新把评估程序的念头拾起来。一开始用的是GPT+PyCharm，后来才体会到Cursor的便利。GPT+PyCharm的体验是：代码要从GPT反复搬去PyCharm，排错时还要把调试信息再搬回GPT，聊天窗口被大段信息占掉，还容易搞混。而Cursor支持折叠代码，也可以同时开几个编辑栏调bug。![](img/c769fbedc0782b7df46124a301752c54.png)![](img/a7f8bef64eda0353fbc27b5d4e33b694.png)

参加AI编程航海前，我的学习策略是只了解最少必要编程知识：代码在哪里跑、开发环境长什么样子、编程语言大概什么样，剩下的交给AI。

**代码到底在哪运行？**代码并不会直接在你写下的地方执行，它需要运行环境，也就是常说的编程环境或开发环境。![](img/5ab477e7b2f230649d45a248260457ad.png)本地开发环境就是在自己电脑里装工具（编辑软件+解释器）来跑代码。以Python为例，需要装解释器（相当于让电脑理解Python语言的“翻译官”，比如Python 3.10）和一个编辑器。PyCharm就是一种集成开发环境（IDE），方便我们编写、调试和运行Python代码。Python和PyCharm的安装可以翻看9月的AI编程航海手册。![](img/7db178c15e8b147cb53bd0b4791088d0.png)不想装软件也行，在线编程平台会自动把环境准备好，在网页上就能写完运行。比如Replit和Google Colab，打开网页登录后，写好代码点运行，云端就会执行。![](img/15e9300154a385ea53c5adb92919799b.png)

**编程环境包含哪些部分？**编辑器/IDE（如PyCharm）是写代码的地方，通常会提供：代码区域（输入和编辑代码）、输出区域（显示运行结果或调试输出）、文件浏览器（管理项目文件）、调试工具（排查代码问题）。![](img/60e4494b88429eaf504cd703310f5ed1.png)命令行/终端则是文字交互界面，用来敲命令。Python开发中，它常被用来运行代码（比如python 文件名.py）、查看错误信息，以及执行安装命令。![](img/dd9d92de40db5fb9c9751761d88ab9a3.png)

**编程语言又长什么样？**简单说，编程语言是人和计算机之间的沟通工具，语法就是它的规则，代码就是按规则写出的句子。用Python演示最直观。![](img/eb24eef74579636b336d2c7ece6a2c9c.png)

再铺几个基础名词：

**标识符**是程序中的名字，给变量、函数、类命名，可以理解成“=”左边的符号。规则不多：只能由字母、数字和下划线组成，不能以数字开头，区分大小写，name和Name是两个不同标识符。![](img/4ec32f2bb6d9a6a00e987db0e57e4baa.png)

**关键字**是Python预留的特殊词，像if、else、for、while，相当于语言里的“如果”“所以”，不能拿来当标识符用，否则程序会报错。![](img/e1f52c50b70bbd158cf768d4bbcddb48.png)

**缩进**是Python中表达层次关系的语法元素，能看出代码的结构，推荐用4个空格。![](img/e078116406192ebce18f19db1e59040a.png)

**表达式**可以是一个数字，也可以是一段复杂的计算或逻辑判断，它的核心价值是算出一个结果。![](img/ab604b9e635a7ebe6ced0451ee9d9aa8.png)

**控制流语句**控制程序执行的顺序，好比一套决策流程，if、for、while都属于这个范畴，让程序能选择也能循环。![](img/a7d589b3b4e7a34690914f069b69fbb8.png)

**赋值语句**用等号把右边的值填充到左边的变量里。![](img/0be96ee26dd69b04d3d534f0f44206e2.png)

**变量**就是带标签的“盒子”，把数据存进盒里，以后用标签就能取出。Python里创建变量很直接，比如age=25，age就是变量名，里面装的25。命名规则跟标识符一致，开头不能用数字，也不能有特殊符号。![](img/915a7c2584ae43fddc5f3e2f1a5f49ed.png)

**数据类型**指变量内容的种类，常见有整数（int）、浮点数（float）、字符串（str）和布尔值（bool，只有True/False两种，表达对错）。![](img/785117f5e1e2c081551862b327a0711d.png)

**注释**是写给人看的说明，不会参与运算。单行注释用#，多行可以用三个引号包裹。```
pip install 库名
```

**函数**可以理解成一个算法盒子，接收传入的信息，按内部逻辑给出结果。用def来定义，可带参数，也可以用return返回结果。```
pip install requests
```

**库**是别人写好的代码集合，能直接调用。Python里的库分为标准库（自带的数学运算、文件处理等）和第三方库（比如处理数据的pandas、科学计算的numpy）。第三方库需要通过pip工具在终端安装。引入库时，import可以引入整个库，from...import可以取特定功能，as能给库起个简短的别名。![](img/84627adf5acf6072973e7fa7e3dff62e.png)

## 工具是怎么造出来的

**需求分析与功能设计。**我们公司的评估任务，其实就是弄清新品和现有系列谁更接近，然后找出能用最少投资搞定新产品的产线。动手前，我明确了自己的目标：让程序自动找到与新品最相似的那款量产产品，再结合相似度判断产线生产能力，并列出需要新采购的设备工装。评估维度是多项产品参数，最终目标就一个——在更快更准的前提下，把采购成本压到最低。需求理清后，AI给出了对应的实现模块，剩下的就是结合实际情况反复讨论，把逻辑打磨到可用。![](img/5f4670f17b11990dbaa16f485e411d11.png)![](img/648ec9442f7e9de14f001cf3b404a99f.png)

**框架构建。**AI讲得头头是道，我还是不知道该怎么办，于是直接问它：“我该如何开始？”让它一步步带我。第一步是安装Python及配套的编程环境，再把需要的库补齐。![](img/f15b97197d2d894aad4103d97f312fe5.png)![](img/774e50b785d2053164c5066b142f1f9a.png)接着创建编程文件，搭起整个程序的框架。![](img/a3f6d272999d7214ad8d2b9da64bd20f.png)![](img/00d6b8d0267f9f358bc7dd0ee345ab8d.png)

**核心算法一：评估产品差异，找到相似量产产品。**写第一个模块（找相似产品）时，我把整理好的产品数据库给到AI，代码由它完成。先是引入存储、读取、计算相关的库，然后确定相似度的算法逻辑。我说不好怎么实现，就让AI直接告诉我要替换哪段代码，或者给出完整代码。![](img/82c557e2407951866781202cfbed3503.png)![](img/dbc394e6e125357195579f06384f78d6.png)![](img/740be347b582051ce1c17ca6fc160ad5.png)AI给的是加权欧氏距离算法，比较契合我们的产品特性。直白点讲，就是对各参数与基准的差值做平方、加权、再开方，最终得到一个用来衡量产品参数差异的数值。

**确定程序开发流程。**说实话，做到这里我已经有点晕了，代码到处报错。虽然我是照着吴佳文分享的步骤先搭框架再补模块，但实际遇到的问题远比预想多。我当时冒出个想法：程序员平时到底按照什么流程开发？于是去问GPT。它建议从输入输出界面入手。最终的流程我定为：搭整体框架——设计输入输出界面——确定各模块核心算法——完善各模块代码。![](img/f7c859af050001556a9aac9241e08881.png)![](img/353f1dae55f82d4b96635771d734447d.png)

## 一步步实操记录

**输入输出界面设计。**最初版本的界面很简单，只有产品参数输入栏，每个输入框都得手动点选，数据库按AI的建议用CSV格式。做到这一步，我发现它已经能实现预设需求：输入新品参数，输出最相似的产品型号。我把它称作“新产品评估1.0”。![](img/99b3fcec421aa2c8ed7bc54da9edf168.png)![](img/e78ee380da2e8b45009417ddbcc7903f.png)但推进下一个模块时，1.0的问题开始冒出来：要么数据库读取容易乱码，要么参数不符合逻辑。只能一个个地处理。

**数据库格式问题：**CSV格式的数据在读取时，编码会在utf-8和gbk之间反复横跳，折腾了好几天，我突然意识到：很多软件都能直接打开Excel，我这个程序是不是也可以？一问AI，果然可以。那我前几天到底在折腾什么……![](img/78401f7c8be9af399c6a7045742e872d.png)![](img/d6ab494ffbd8a3fc042dd9213516f611.png)

**参数不符合逻辑：**我们的产品是轴承，天然有“外径大于内径”的约束，为防误输入，加了参数验证环节。

**强行推荐相似产品：**测试时发现，有些全新产品的参数跟所有量产品都不同，程序却仍会输出一个“相似型号”。后来设置了一道门槛：权重最高的几个参数里，至少要有两个完全对得上，才认定为相似产品；不然就归入全新产品。

这类大小问题来回调了几轮，输入界面的需求也逐渐清晰：要有参数输入区，自动选择数据库，参数逻辑要能被验证，全新产品不强行匹配，输完参数按回车自动进入下一项。![](img/d1a136f09829cf8dbaa23793eb029caa.png)![](img/e4d30e9e4bd26578057e3e02602d90e8.png)![](img/d9d5d35beecaf7650542175f04dde9a3.png)

**核心算法二：通道能力评估。**做第二个模块时，我另开了一个聊天窗口，从需求谈起，确保AI完全理解业务，然后让它列出实现所需的数据和信息，再提出算法思路，确认可行后才进入编码。按这个流程走下来，你大概率还是会收获一个到处报错、不符合预期的程序，不过没关系，继续学就是了。![](img/395e5428a12de8abf1614d6a7848a92b.png)![](img/52832660ae10154757f6bba2b5b4f8fd.png)

这就是我借助Cursor完成新产品评估程序开发的真实过程。希望我的经历，能让更多制造业的朋友看到AI编程的可能性。

![](img/d786f6a2c2c2a0630acb67dfb5ce0cee.png)

从一个“翻车”现场说起：程序改到自己都看不懂，屏幕里满是神奇乱码。我把每个模块拆开发给AI，拜托它逐段讲语法，折腾一圈才恍然——两套数据库根本没关联起来，动手时只盯住了核心片段，前后逻辑却断了线。

后来和AI聊了几轮，把第二模块的算法彻底重排：
先拿第一模块跑出的相似型号和量产数据，筛出能承接量产产品的那批产线；
再调出产线设备库，判断哪几条能造新品、具体还缺哪些设备；
最后输出相似产品可走的通道、推荐的路线，以及不推荐的理由。

两个核心模块加上输入输出界面全部装回框架，新产品评估2.0就这么诞生了。

![](img/245ba565b0dc576d99a007a5f60f5f75.png)

当然，这一路没少踩坑：
比如cursor总爱把两个不同位置的代码塞进同一个代码块，刚入门的我又看不懂就整段复制，报错自然成了常客。后来我学乖了，逐行对照代码开头，只粘真正有差异的片段，再把确认无误的代码块折叠起来，世界一下子清爽了。

第三方库也让我头疼。引入的库要在终端里另外下载，我一度连命令该粘到哪都搞不清楚，程序自然一路报错。后来老老实实弄懂了编程环境和“库到底是什么”，才算入了门。

还有一次，提交参数后弹出两个输出窗口，我逐个代码块排查，才发现是替换输出代码时，旧代码没删干净。

如果你也是刚开始学AI编程的圈友，这篇只想给你打打气：新技能前期最有门槛的不是天赋，而是几个绕不开的核心概念。只要补上“最少必要知识”，很多看起来无解的问题，都会在某个瞬间突然通透。愿你早日写出自己的第一个程序，一起龙哥盟！
