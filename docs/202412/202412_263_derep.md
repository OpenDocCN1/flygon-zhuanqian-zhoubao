你有没有遇到过这种情况：AI 编程助手正帮你改得飞起，结果一不留神，代码核心逻辑就被“优化”得面目全非，想找回原来能跑的那版，却只能干瞪眼？别急，这事儿有解。

先交代下背景。我是云飞，盈腾科技创始人。最初接触 Cursor，是因为在杭州招算法工程师，一个半月只等到两个人入职。后来让同事试着用 Cursor，效果出奇地好，于是全研发团队都切到了“Cursor + 本地 IDE”双工具模式，招聘信息也就撤了。这段经历让我攒下一些心得。刚好看到有人问 Cursor 编程里怎么做代码版本管理，就顺手写篇经验帖，算是给亦仁的“第三个超级标”交个作业。

为什么一定要做版本管理？打个比方，写日记的时候，谁不希望每天的内容都能留在本子上，想翻随时翻？代码也一样——每次改动都被记录下来，万一出了岔子，还能顺着痕迹找到问题出在哪一步。

实现这件事，靠一个叫 Git 的工具。它就像一本超级耐用的“代码日记本”，专门负责记录每一次修改。

先说安装。去 Git 官网（git-scm.com）下载匹配你系统的安装包，Windows、macOS 还是 Linux，选对应的就行。下载完双击，一路点“下一步”，跟装普通软件没区别。装好之后，打开命令行（Windows 用命令提示符或 PowerShell，Mac/Linux 用终端），敲一句 `git --version`，能看到版本号就说明成了。

接下来是四个核心操作，全部记住就能应付日常需求，甚至可以把它们抄在备忘录里随时用。

第一步，在你的项目文件夹里打开命令行，输入 `git init`。这相当于拿出一本崭新的日记本，告诉它“我要开始写了”。Git 会默默在项目里建一个 `.git` 隐藏文件夹，所有的版本信息都存在里面。

第二步，输入 `git add .`（注意别漏了最后那个点）。意思是：把当前目录下所有新增、修改、删除的文件都挑出来，放进“待写”的暂存区。这个暂存区就是日记本前的草稿纸，你可以决定哪些内容要写进这一次的记录。

第三步，输入 `git commit -m "你的提交信息"`。`-m` 后面写上你对这个版本的命名或简短描述，比如“修好了登录bug”。提交之后，Git 就为当前项目拍了一张快照，并把它按时间顺序存好。每次提交都会生成一个独一无二的 ID，就像日记本的页码。

第四步，万一改坏了想回到之前的某个版本，先输入 `git log` 查看所有提交记录，找到你想回去的那个版本对应的提交 ID（一长串数字和字母，比如 `a38502e...`），然后输入 `git checkout 提交ID`。瞬间你的代码就会恢复到那个时刻的状态。就这四个命令——init、add、commit、checkout——足够让你在 Cursor 发疯的时候稳住局面。

如果你还有余力，可以试试更进阶的玩法。比如想试验新功能又怕搞坏主代码，就用 `git branch 新分支名` 开个新分支，再用 `git checkout 新分支名` 切过去。这就好比在日记本里另起一章写新故事，不影响原来的内容。如果新故事写得不错，想并回主线，用 `git merge 新分支名`，Git 会帮你把两边的改动整合起来。万一有新代码和旧代码打架（冲突），Git 也会提示你并协助解决。

掌握了这些，Cursor 再怎么“天马行空”，你都有后悔药可吃。希望这套方法能让你的编程之路更稳，一起加油，一起生财有术！
