# RPA实战指南：用PC上的Python，指挥安卓手机替你“人工操作”

你有没有设想过，自己刷抖音、逛📕的时候，背后其实是一群不知疲倦的机器人在帮你点？这不是科幻片，而是RPA（机器人流程自动化，Robotic Process Automation）正在做的事。简单来说，RPA就是让软件机器人模仿你在电脑或手机上的手动操作，自动跑完那些重复、繁琐的流程，把人力从机械劳动里解放出来。

## 为什么你需要这样一套脚本？

举个例子，你正在做某类日用品的抖音或📕带货，想研究同类目里有哪些“低粉爆款”——也就是粉丝不多，但点赞、评论、转发数据很好的内容。这类内容往往预示着选品思路或运营套路值得参考。如果纯靠人肉去搜、去记，费时费力。而用RPA，你只要输入搜索词和筛选条件，机器人就能自动刷视频/笔记，把“粉丝数小于3000且点赞数大于2万”的内容记录下来，最后汇总成Excel报表交给你。

再比如，你想运营20个垂直领域的抖音或📕账号，用来做矩阵引流和互动。人工养号成本太高，但RPA可以一次挂起20个机器人，按你设定的关键词去搜索、浏览、点赞、收藏，甚至去评论区捞人、按话术回复，最后把作者信息和粉丝ID整理成表格。如果你恰好需要这类能力，这篇文章就是为你准备的。

不过要说明的是，这套玩法需要一定的Python基础和相关技术底子。如果零基础，也可以先借助影刀（https://www.yingdao.com/）这类工具；另外还有Scrcpy（开源免费，投屏+群控，https://github.com/Tomotoes/scrcpy-gui/releases）和Total Control（安卓多控系统，https://www.sigma-rt.com/tc/）可以参考，但那些更偏向群控，算不上真正的RPA定制。

## 开始之前，先知道这些

整个方案基于 Python 的 uniautomator2 框架，只支持安卓手机。手机需要与电脑用数据线连接，并开启开发者选项和USB调试权限。项目代码已经在gitee上开源，不过坦白讲，因为这些脚本最早是我自己用的，涉及的App包括抖音、📕、知识星球、闲鱼等，代码比较零散，风格也不算规范，大家参考思路就好。

## 写代码时，这些坑一定要绕开

基础方法同样可以参照前面那篇CSDN博文。但根据实战经验，有几个特别提醒：

1. **Python版本最好用3.7**，否则一些功能可能会不兼容。
2. **toast操作基本不能用**，而且会卡住后面的流程。
3. **相对定位方式特别慢**，慎用。
4. 有子元素和兄弟定位，但**没有父级元素定位**，开发时偶尔会有点别扭。

实际开发中还有这些细节：

- 抖音和📕很多控件的 `resourceId` 不是固定的，会随手机、账号等因素变化。所以不能只靠 `resourceId` 定位，要灵活用 `text` 等方式。
- 除了 `d(resourceId="xxx")`、`d(text="xxx")`，还可以用 `d.dump_hierarchy()` 拿到整个页面的XML控件树，再配合 `from xml.etree import ElementTree as ET` 去解析查找。但注意，有些弹窗或特殊页面的信息是拿不到的。
- 安卓10/11之后，系统**不允许直接读取剪贴板**，只能写入。想读的话，可以先把内容粘贴到一个文本输入框，再读取该输入框的文本。
- `click(0.2, 0.8)` 这种写法是按屏幕宽度和高度的比例来定位点击位置的，可以兼容更多机型，省掉不少适配代码。
- 脚本自动跑的时候，经常冒出各种奇怪的弹窗，建议多用 `d.watcher` 系列方法把它们自动过滤掉，例如这样：
![](img/40b393116593ca5ea78f10e130fef3a5.png)

- 启动抖音时，记得写成 `d.app_start(pkgName, wait=True, use_monkey=True)`，否则可能启动失败。
- 📕笔记点进去可能是图文、视频甚至直播，界面差异比较大，记得分类处理。

## 项目里的重要文件

- `U2Syner.py`：封装了设备获取和基本操作、部分脚本的类。
- `U2DevTool.py`：把抖音、📕、知识星球、闲鱼等脚本逻辑封装成一个个方法。
- `BatchRunDevices.py`：保证每台手机对应一个**独立进程**（而不是线程），并一键生成子文件。运行后会根据设备id生成对应的子文件，再在 Run/Debug Configurations 里添加 Compound，就能一键批量运行所有脚本：
![](img/526a24ec57fd79605cf1125c5af11bbd.png)
![](img/2c2c64b1754a9fc28803da6201ee9b19.png)

- `xml.etree`：配合 `dump_hierarchy()` 处理XML用的。
- `xlwings`：采集信息时先用txt保存，高效方便；后期再通过 `RecordUtil.py` 一键生成美观的xlsx。
- `adb-multi\Config\Params.py`：把 `ROOT_DIR` 设置成你本地的项目根目录，比如 `ROOT_DIR = r"D:\PythonProjects\adb-multi"`。

## 除了uniautomator2，还有别的路子吗？

有，但各有各的短板。

**AccessibilityService**：安卓原生无障碍服务，不需要电脑，每台手机装一个APK就能独立跑。缺点也很明显——

- 每次启动后都要手动打开无障碍权限；
- 遇到弹窗或某些信息列表时，控件定位会失效；
- 不能按坐标点点击；
- 每台手机各跑各的，没法电脑统一群控。

**安卓端按键精灵**：通过坐标点击、找颜色坐标、找图来实现模拟操作。但2018年以后，基本就没什么动静了。

## 现在用RPA，到底划不划算？

RPA的价值在于：它像一支不知疲倦的机器人部队，按你的规则在手机里埋头干活。在一些冷门App或特殊场景里，它的作用会非常大。但像抖音、📕这种主流平台，就算只是模拟人工点击，也会在接口请求频率上做限制。举个例子，📕私信，你本来打算每个号每天发10条，3个号×5台手机=一天150条，听着很爽。但实际上平台对私信总数也有控制，可能连续发到第5天就直接禁言了。所以RPA在私信这类强互动场景里没那么美好。

不过，**只采集信息、不发私信**，一般没什么限制；普通的点赞、关注、评论，只要别太猛，每天能操作的数量依然远超私信。所以，用RPA做数据采集或批量养号，是个不错的选择。
