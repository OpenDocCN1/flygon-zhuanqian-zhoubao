# 开发者必看：把 Git Worktree 当成“实习生”，我彻底告别了心流被切断的日子
作者：龙哥

你有没有过这样的体验？

一天从早到晚，需求会、临时 Bug、代码切来切去、消息弹个不停……忙到飞起，但到了晚上回头一看，真正能拿出手的“整块产出”少得可怜。

不是不努力，而是我们最宝贵的专注力——心流，被切得七零八落。

更扎心的是，AI 编程工具的流行，又新增了一种更隐蔽的“微中断”：你跟 AI 说一句，它干活，你等它，通常在 30 秒到 90 秒之间。你说短吧，短到让你没法专注做别的；你说长吧，长到又够不上干一件完整的小事。你只能干巴巴地卡在那儿，等它回话，心流又一次碎掉。

这种感受，做开发的你，一定懂。

于是我开始琢磨：有没有一种方式，能让我在等待 AI 的空隙里，也能安心推进别的任务，而不会被搞乱？

后来我发现了一个特别好用的玩法——把 Git Worktree 当成“实习生”来用。

什么意思？就好比你给每个任务都分配了一个独立的工作区，互不打扰、互不冲突，你可以在一个工作区等 AI 反馈的同时，去另一个工作区继续写代码、查逻辑。同一个仓库，多份工作目录并行，却完全不打架。

这就是我在实践的“无冲突并行开发工作流”。


如果你也受够了被 AI 等待打断节奏的日子，可以点开看看，也许这就是你提升开发体验的下一个突破口。
