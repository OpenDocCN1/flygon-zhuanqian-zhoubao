## (精华帖)(127 赞)实操笔记：借助 MCP 把公号排期流程变成自然语言触发

作者：陈序员大康
日期：2025-04-28

**扣子空间最近迎来了一次关键更新。两天前我还在说 MCP 插件太少且不能自行增添，现在这道限制被正式放开了。**

从此刻起，能把在扣子工作流平台搭建好的自动化链路，以及扣子开发者平台上发布的各类能力包，按需挂载到个人空间里直接使用。

看到推送的第一反应就是：终于可以实现用口头指令完成一篇推文的全流程了。

举例来说，直接对空间说：“查一下今日热门话题，给我写一篇推文并存进草稿箱”。

其实类似的自动化发文方案，过去我用纯工作流甚至 RPA 也已经验证过。

**那为什么还要转向对话触发的 MCP 形态？**

工作流更像是一条固化生产线，环节一旦排好就很难临时调整，更适合已跑通的批量化场景。

它的局限在于弹性不足。比如之前做的国学类内容生成，想换风格就得重新梳理提示词、改动节点；写稿过程中临时需要路线规划，还得回到工作流里去挂载地图能力，操作成本偏高。

MCP 的思路是即插即换。以往配图用的古风生图能力，后续要做穿搭选题，只需把配图 MCP 换成时尚配图 MCP，就能立刻生效，无需重建整条流水线。按需拼装、随时重组，能力组合更自由。

**有人会问，这是否意味着工作流可以被淘汰？**

短期看并非如此。Manus 或扣子空间这类智能平台，在处理复杂多步任务时偶尔会出现理解偏差，导致结果不可用。相比之下，传统工作流在确定性与可控性上仍更占优。

概括起来：MCP 更适合探索与创新，工作流更适合稳定量产，两者定位不同。
