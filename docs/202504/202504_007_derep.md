# ('(38 赞)如何做一个最简单的套壳网站', (2, 21))

今天聊一个特别有意思的话题：AI套壳。

可能有人一听到“套壳”就觉得是山寨、是low货。但刘小排老师说过一句话：套壳产品，藏着巨大的机会。为什么？咱们先弄明白套壳到底是什么。

说白了，就是你自己不研发AI技术，而是把别人已经训练好的成熟模型，拿来包装一层界面、换一套品牌，就变成你自己的产品了。你说它没技术含量？但用户根本不在乎你搞没搞底层技术，他们在乎的是：你的产品能不能解决我的问题。

那问题来了，既然套壳没有自研AI，凭什么能活？

因为自研大模型这事的成本，高到离谱。普通小团队连门槛都摸不到。放眼国内，能做自研大模型的基本都是巨头，阿里的通义千问、字节的豆包、腾讯的混元，个个家大业大。

但巨头们有个习惯：大模型研发出来以后，会把API能力开放出来，在各自的开放平台就能找到调用入口。这时候谁要调用，按量付费就行。

这就给普通人撕开了一道口子。

你不需要自己造模型，只需要发现用户痛点、调用现成的模型能力、做一个用户愿意用的产品就好。套不套壳，真没人关心。

今天这篇文章，就手把手拆一个最简单的套壳网站——AI生成图片站。它能做什么？用户在网页里输入一句提示词，AI就给他生成一张图。

一共五步：“

第一步，注册并使用Replicate平台。它是干什么的？你可以把它理解成一个“模型超市”，聚合了一大堆AI模型，想用哪个挑哪个。

第二步，一行命令，调用AI绘图模型。这行命令跑起来以后，纯服务端就能完成模型调用，完全不需要你手写那些繁琐的底层逻辑。

第三步，用Next.js搭一个最简单的网页。用户在前端输入提示词，后端调API，AI把图片生成后展示在网页上，整个过程干净利落。

第四步，把代码传到GitHub。这一步不多说，代码托管必备。

第五步，部署上线到Vercel。免费、快速，域名一挂，网站就跑起来了。

你要是只想动手试试，可以直接看作者的飞书文档，地址在评论区。

最后多说一句：很多风口，不是等你看懂了才动手的。套壳这件事，框架已经这么简单了，真正值钱的是——你想清楚了你的用户到底有多痛吗？
