# 抖音视频筛选与飞书保存Chrome扩展PRD

## 项目概述
开发一个Chrome浏览器扩展，用于在抖音网页版博主主页上筛选点赞数超过特定阈值的视频，并将这些视频的信息（标题、链接、点赞数）保存到飞书多维表格中。

## 技术要求
1\. 使用Chrome扩展Manifest V3规范
2\. 使用Service Worker而非Background Pages
3\. 使用侧边栏(Side Panel)作为主要界面
4\. 遵循最小权限原则设计Content Scripts
5\. 实现响应式设计，确保在不同分辨率下的良好体验

## 核心功能需求

### 1\. 视频筛选功能
- 在抖音博主主页上自动识别所有视频元素
- 提取每个视频的标题、链接和点赞数
- 根据用户设定的点赞数阈值（默认1000）筛选视频
- 支持多种点赞数格式解析：纯数字、带逗号的数字、带单位的数字（如"1.2万"）
- 实现多级选择器策略，确保在页面结构变化时仍能正确识别视频
- 添加严格的验证机制，防止非视频内容被误识别

### 2\. 飞书保存功能
- 将筛选出的视频信息保存到指定的飞书多维表格
- 使用飞书开放API进行数据传输
- 支持批量保存多个视频记录
- 处理各种错误情况，并提供友好的错误提示
- 链接字段必须使用对象格式，包含text和link属性，而不是直接的URL字符串

### 3\. 用户界面
- 使用Chrome侧边栏展示操作界面
- 提供点赞阈值设置输入框
- 显示筛选结果列表，包括视频标题、链接和点赞数
- 提供"筛选视频"和"保存到飞书"按钮
- 添加调试信息区域，可展开/折叠
- 实现友好的加载状态和错误提示

### 4\. 调试与日志
- 实现详细的日志记录系统
- 记录所有关键操作和错误信息
- 在侧边栏提供日志查看功能
- 支持日志清除功能
- 添加视频详情查看功能

## 技术实现细节

### 视频识别策略
1\. 使用多级CSS选择器定位视频元素
2\. 当主选择器失效时，使用备用选择器
3\. 实现通用选择器作为最后的备选方案
4\. 对识别到的元素进行严格验证

1\. 使用多种CSS选择器定位视频链接元素
2\. 从视频卡片中的a标签直接提取href属性
3\. 从元素的各种属性中提取视频ID
4\. 分析元素的HTML内容，提取可能包含的视频ID
5\. 从链接中提取视频ID，构建标准视频链接
6\. 将相对路径转换为绝对路径
7\. 验证提取的链接是否为有效的视频链接
8\. 添加完善的错误处理机制

不过，在搭建这套流程时，有几个容易踩坑的地方需要提前注意：

**1. 不建议直接在 Chrome 插件中调用扣子 API**

从理论上看，可以把扣子智能体发布成 API，然后由插件直接请求。但实际运行中可能遇到响应速度、稳定性或性能方面的问题，因此更适合把相关处理环节放到飞书多维表格内部完成。

**2. 注意扣子智能体的调用额度**

扣子平台本身可能存在使用次数或额度限制。如果把视频内容提取任务直接放在扣子智能体侧执行，批量处理时容易触发限制。发布到飞书多维表格后，目前使用上相对更宽松，因此可以优先考虑这种方案。

**3. Chrome 插件可能遇到跨域权限问题**

如果插件无法正常请求飞书接口，通常是权限没有配置完整。可以直接让 Trae 为插件补充访问飞书 API 所需的权限，一般即可解决。

**4. 飞书应用必须安装到目标多维表格**

如果创建好的飞书应用没有被安装到实际使用的多维表格中，插件即使配置正确，也可能始终无法成功保存数据。

**5. 约束扣子智能体的输出格式**

生成视频文案时，如果提示词写得不够明确，智能体可能在正文前后添加解释性内容，例如“这个视频主要讲述了……”或者“具体文案如下……”。

为了保证后续改写结果干净、稳定，需要在提示词中明确要求：只输出最终文案，不要添加任何额外说明。

**6. 控件必须使用“字段选择器”**

发布扣子智能体时，控件配置部分需要选择“字段选择器”。如果没有使用这个控件，智能体在飞书多维表格中运行时，就无法正确引用链接字段，也就不能根据视频链接自动提取文案。

**7. 配置飞书参数时不要只填写 AppToken**

Chrome 插件中如果只填写了 AppToken，却没有填写 Table ID，也会造成数据保存失败。

这里的 Table ID 不能只凭表面信息猜测，需要复制完整的飞书多维表格链接，并在浏览器中打开，才能从完整地址中获取对应的表格 ID。
