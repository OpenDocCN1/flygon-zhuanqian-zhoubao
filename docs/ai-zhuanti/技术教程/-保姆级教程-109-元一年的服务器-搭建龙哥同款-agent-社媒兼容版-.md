# 【保姆级教程】109 元一年的服务器，搭建龙哥同款 agent（社媒兼容版）

## 109 元/年，我把“收藏癖”改造成了自动知识流水线

你有没有这种体验：

看到一篇好文章，顺手保存；刷到一个好视频，赶紧复制链接；遇到值得研究的账号，也先收藏起来。

当时觉得以后一定会看，结果过几天再回头，链接已经淹没在聊天记录、文件传输助手和各个平台的收藏夹里。

我以前也一样。

后来，我在 iPhone 上设置了“轻点背面两次”的快捷操作。复制内容链接后，敲两下手机，它就会自动发送到我的飞书群。我把这个动作叫作“万物归虾”——先把看到的东西集中起来。

但这只解决了“收集”，没有解决“处理”。

真正让我改变工作流的，是龙哥分享的“小D”。我看到相关直播后，马上照着说明部署了一套：

赚钱站内《小D 复制部署说明：音视频转录整理 Agent》


它可以接收音视频地址，自动完成下载、转录、清理口语和时间标记，再整理成一篇适合阅读和分享的长文。它不会只给你几句概括，而是尽量保留原始表达、案例细节和核心判断。

不过，我的收藏内容并不只有音视频。

公众号文章、小红书笔记、抖音内容、视频号作品，同样占了很大比例。它们需要的不是语音识别，而是查找、抓取、分析。做选题、研究产品、观察竞品时，我还经常要看评论、找账号、整理内容脉络。

于是，我又往这套系统里接入了一组社交平台采集能力。

### 一套入口，处理四类平台内容

这部分通过 TikHub 的 API 连接四个平台，并封装了 20 个可调用功能。每个平台都覆盖四个方向：

- **小红书**：查笔记、查创作者；输入分享口令可读取笔记详情；支持查看一级评论和回复，也能读取主页与作品列表。

- **抖音**：按照关键词查内容；通过分享地址获取视频信息；可读取评论、账号主页和作品集合。

- **微信公众号**：搜索文章和账号；提交文章地址即可获取正文；支持留言读取及账号文章列表。

- **微信视频号**：查找视频内容；通过分享短链取得作品详情；支持评论、主页和发布记录。

最实用的一点是：不需要先告诉系统“这是什么平台”。

只要把地址发过去，它会自行识别来源，再抓回对应内容。这样，“万物归虾”就不只是一个收藏入口，而成了整个流程的起点。

采集后的内容会统一整理到多维表格中。我根据接口实际返回的共通信息设计了字段，便于把不同平台的结果放进同一个资料库。

整个过程可以概括成：

```
手机背板双击 → 链接进飞书群 → agent 拉内容 → 转录/整理成稿 → 归档
```

以前是“先存起来，之后大概率忘记”；现在则是“发过去，系统自动完成阅读、整理和归档”。

### 成本到底是多少？

这套方案的门槛并不高，主要开销如下：

| 项目 | 费用与情况 |

| 云主机 | 腾讯云轻量服务器，4 核、4G、3M，活动期间约 109 元/年，近期价格上调过 |

| 模型调用 | 按实际使用量结算，DeepSeek 少量充值即可使用较长时间；如果已有 ChatGPT 会员，也能接入可用额度 |

| 内容接口 | TikHub 按请求次数收费，各平台价格不同；返回结果含 `cache_url`，同一数据在 24 小时内再次读取无需重复付费 |

| 软件 | 项目本身免费开放 |

转录部分还有一个很重要的节省原则：

**能直接拿字幕，就不要先做语音识别。**

不少 B 站视频可以通过 yt-dlp 获取现成字幕，这样完全不产生转写费用。只有在找不到字幕时，才进入语音转录流程。短内容可以使用服务器本地处理，长内容则按需调用云端识别服务。

目前 YouTube 的兼容表现还不够稳定，主要和机房 IP 限制有关，后续还需要继续调整。

### 飞书和微信怎么使用？

飞书侧依靠企业应用自带的机器人完成交互。你可以把机器人加入不同群聊，让每个群承担不同任务，例如：

- 一个群负责素材收集；

- 一个群负责选题分析；

- 一个群负责竞品监测。

微信侧则可以直接接入。安装时说明需要启用微信功能，配置完成后，就能像普通聊天一样发送任务。不过微信目前只支持一个聊天窗口。

### 部署时最容易遇到的三个问题

我用真实密钥跑过完整流程，下面这些问题已经提前处理：

**问题一：请求被拒绝**

第一次连接 TikHub 时，接口返回 403。原因不是密钥，而是 Cloudflare 拦截了 Python 默认请求标识。项目代码已经替换为可用的 User-Agent，否则很多人会在刚开始调用时直接失败。

**问题二：微信相关接口报 404**

旧版 SDK 中的微信接口地址已经过时，直接照搬会找不到路径。现在应以线上 OpenAPI 文档为依据，并使用 v2 路径。仓库里已完成统一调整，四个平台的 20 项功能也跑过真实调用，公众号正文曾用我自己的文章验证过。

**问题三：长内容转写又慢又贵**

不要把所有音频一股脑送去语音识别。系统会先判断是否能拿到字幕：

1. 能拿字幕，直接使用；

2. 没有字幕，再启动转录；

3. 短内容本地运行；

4. 长内容按需调用云端服务。

这套判断已经放进任务规则里，不需要每次手动提醒。

### 部署完成后，可以怎么玩？

下面是几个实际使用场景。

#### 1. 自动整理历史收藏

配合定时执行，让系统定期读取群里的旧链接，识别内容价值，完成分类、摘要和归档。

```
每天早上八点，把昨天飞书群里的链接逐条拉内容，音视频出提纯稿，文章出要点归档，整理成一份日报发我。
```

#### 2. 一次做完多平台选题调查

输入一个主题，让它同时查询四个平台，再汇总热门内容、常见表达、账号分布和用户关注点。

```
「手冲咖啡」这个方向，小红书和抖音各搜一页，归纳两边的爆款角度差异，给我 3 个能直接用的选题。
```

#### 3. 从评论里发现真实需求

指定品牌、产品或关键词，持续观察相关评论，把反复出现的问题、抱怨和购买意向整理出来。

```
帮我监控，这几篇笔记是否有新评论。把评论和高赞的二级回复拉下来，提炼高频问题、抱怨点和购买信号，用户原话保留。
```

#### 4. 研究竞品账号

给出目标账号，让系统读取其主页、作品结构和评论反馈，辅助分析选题规律、内容风格与受众反应。

```
这个博主的主页和最近的笔记列表拉一下，归纳他的内容支柱、发布节奏，说说哪些可以学、哪些不该学。
```

采集接口是按调用量收费的，所以我还给它加了一套费用控制规则：

- 先用少量样本确认方向；

- 相同数据优先复用缓存；

- 每轮任务结束后汇报调用次数；

- 不确定时先询问，不要大规模抓取。
