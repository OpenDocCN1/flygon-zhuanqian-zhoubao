# 高中学历，不会写代码：我靠 AI 做出有收入的产品，全流程拆给你看
先交代一下背景。我只有高中学历，服过役，退役后做过新媒体，也加盟过奶茶店，亏损 30 万，后来学 AI 美术，当助教带过两万名学员，如今经营一家打印工厂。2024 年，我才正式开始用 AI 做开发。到现在，几个项目的成绩：一个叫 pngtrid 的网站上架首月没投流赚了 5K；图片资源站“PNG 部落”三个月做到 5 万营收、利润率 86%；还有一次把自动化写作流程打包成 Skill，7 天变现 3285 元。说这些不是炫耀，而是想证明：哪怕是我这种连完整 React 组件都写不出来的人，也能靠工具做出能卖钱的东西。我的全部武器只有一样：VS Code 里的 Claude Code 插件。下面这篇是操作级复盘，打开哪里、按哪个键、输入什么，全部写到。没有理论，只有我自己跑过的路线。

## 一、别再用老眼光看 AI 开发
如果你以为 AI 写代码等于在聊天框里要一段文字再手动粘贴，那真的过时了。2026 年的工具已经变成驻扎在电脑里的搭档：你说“帮我做一个待办清单网页”，它会自动建文件、写逻辑、装依赖、跑测试，发现 bug 自己修，最后给你一个地址预览。全程你不需要碰代码。你要做的只有三件事：第一，用中文描述想要什么；第二，打开浏览器看效果；第三，把不满意的地方说给它听。这套循环听起来简单，但多数人过不了第一关——不是不会打字，而是不知道需求要拆到什么粒度。下面这节先解决环境，再教你怎么和它对话。
## 二、30 分钟备齐开发环境
硬件要求极低：一台能上网的电脑，Windows 或 Mac 都行，不需要任何编程基础。编辑器选用 VS Code。Windows 用户去官网下载安装包，一路“下一步”完成；Mac 用户下载后拖进“应用程序”文件夹，然后打开。在左侧活动栏找到扩展商店图标（四格方块），或按 Cmd/Ctrl+Shift+X 打开扩展面板，搜索 Claude Code，认准 Anthropic 官方出品，点 Install。装好后侧边栏会出现它的入口。
模型方面，默认是 Anthropic 的 Claude，但也可以换到国内模型，成本更低、网络更稳。我推荐两个选择：GLM-5.1（智谱 AI，编码能力比前代提升 28%，兼容 OpenAI 接口，按量付费）和 Kimi K2.6（月之暗面 2026 年 4 月发布，1 万亿参数 MoE，支持 300 个子 Agent 并行，原生多模态，输入 $0.60/百万 token，输出 $2.50/百万 token）。我现在主力用 GLM-5.1。更换方法：按 Cmd/Ctrl+Shift+P 调出命令面板，输入 settings json，在用户配置里给 Claude Code 加上模型字段，指定 glm-5.1；也可以在编辑器底部状态栏的模型菜单里直接选。更细的操作去智谱官方文档里查。
再装三个增强工具，开发体验会明显不一样：gstack 相当于外部顾问团，管方向讨论、代码审查和质量测试；GSD（Get Shit Done）像项目经理，管拆任务和盯进度；Superpowers 像监理，强制做测试、调试和完成验证。装法：在 VS Code 终端里依次执行下面的命令。
```bash
#### 安装 gstack
git clone --single-branch --depth 1 https://github.com/garrytan/gstack.git ~/.claude/skills/gstack && cd ~/.claude/skills/gstack && ./setup
#### 安装 GSD
npx get-shit-done-cc@latest
```
其中 Superpowers 需要在对话面板里单独执行：
```
/plugin marketplace add obra/superpowers-marketplace
```
全部装完后，输入 `/help`，如果能看到一长串技能列表，就成了。万一报错，先查两件事：是否缺 Node.js（去官网装最新版），以及网络能否访问 npm（不行就设国内镜像）。
## 三、最容易被忽略、却能决定上限的一步：项目手册
Claude Code 每次启动都会自动读取一个叫 CLAUDE.md 的文件，相当于给 AI 立的规矩：技术栈、代码风格、禁忌事项都写在这里。没有它，AI 像一个能力很强但没有方向的新员工；有了它，AI 才像熟悉项目的工程师。
注意：不要自己找模板硬改。普通人不认识技术名词，根本无从下手。正确做法是把这个文件的生成也交给 AI——在对话框发出指令，让它先问你几个问题，再自动产出：
```
我想做一个 [你的产品想法，比如：在线抠图工具]。
请帮我生成一份适合这个项目的CLAUDE.md 文件。
我目前的情况：
• 我不会写代码，需要你帮我做所有技术决策
• 我希望用最主流、最成熟的技术栈
• 我需要这个项目能部署上线、能收费
请根据我的产品需求，帮我决定：
1. 用什么技术栈（前端、后端、数据库）
2. 适合的编码规范
3. 项目目录结构
4. 常用命令
5. 需要遵守的红线规则
生成完后直接写入项目根目录的CLAUDE.md 文件。
```
它会问你项目类型、技术偏好等问题，然后把写好的手册放进项目目录。你不需要逐条读懂，后续发现它犯过的错，直接说“上次那个 XX 方案出了问题，以后改用 YY”，它自己会更新进去。这是一套持续进化的循环：初版、试错、纠正、沉淀。久而久之，AI 会越来越懂你的项目。
## 四、第一课：用大白话写出第一个程序
我的工作方式永远只有三步：描述、验收、反馈。对应到操作就是：对 AI 说需求，检查生成结果，再告诉它怎么改。基础模板见下：
```
第一步：描述你要什么 ← 你的工作
第二步：看它生成了什么 ← 你的工作（审核）
第三步：运行验证结果 ← 你的工作（测试）
```
第一个练手项目，我建议做一个随机数猜谜工具：程序随机生成数字，用户输入后给出“大了/小了”的提示。在对话框粘贴这段需求：
```
帮我写一个猜数字游戏，用Python。
要求：
1. 程序随机生成1 到100 的数字
2. 让用户输入猜测的数字
3. 告诉用户猜大了还是猜小了
4. 猜对了告诉用户用了几次
5. 游戏结束后问用户要不要再玩一次
```
它会创建 Python 文件、补全逻辑、告诉你运行方法。验收时看三件事：文件是不是只有一个、名字是不是 guess_number.py、它有没有解释代码含义。然后在终端运行：
```bash
python guess_number.py
```
如果系统提示找不到 Python，就换这一条：
```
帮我检查一下Python 是否安装了。如果没有，帮我安装。
```
跑通之后，开始迭代。核心原则：一次只加一个功能。先加计分：
```
给游戏加一个计分功能。每次猜对后记录用了几次，最后显示历史最佳成绩（最少猜对次数）。数据存在同一个目录下的score.txt 文件里。
```
再加难度档位：
```
加一个难度选择功能。游戏开始时问用户选难度：
• 简单：猜1-50 的数字
• 普通：猜1-100 的数字
• 困难：猜1-500 的数字
```
每加一个点就跑一次测试，出问题能快速定位、快速回退。需求一次给得越多，完成质量越不稳定。
顺便提一下权限机制：AI 读文件、搜索、查看目录不会问你；但写文件、执行命令或新建目录时，会弹确认框。你会看到类似这样的选择：
```
Allow Claude to write to /Users/you/hello.py?
[y/n/a]
```
y 放行这一次，n 拒绝，a 以后同类操作都放行。对执行命令这类操作，前期别轻易给 a——里面可能有删除文件之类的高危动作。等熟悉了再放开。
程序报错也别慌。直接把报错信息发过去，并说清楚三件事：你刚才做了什么、期望的结果是什么、实际发生了什么。描述模板在下面：
```
1. 期望行为：应该发生什么
2. 实际行为：实际发生了什么
3. 错误信息：完整的报错文本
```
错误示范是只说“有 bug，帮我修”：
```
我的程序坏了，帮我修一下。
```
正确示范是给出完整的操作背景和报错信息：
```
我的猜数字游戏（guess_number.py）有个问题：
1. 期望行为：输入字母q 应该退出游戏
2. 实际行为：输入q 后程序崩溃了
3. 错误信息：
ValueError: invalid literal for int() with base 10: 'q'
帮我修复。
```
AI 拿到这些信息，常见错误的修复成功率能到 90% 以上。记住：报错是信息，不是惩罚。
还有一个关键概念：上下文。Claude Code 的短期记忆像一张办公桌，桌面上堆太多东西，就会找不到早先的文件。我的经验是：上下文占用超过 60%，它的表现就开始下滑。所以从功能 A 切到功能 B、感觉它开始忘事、或一次对话超过 30 轮，就该开新会话。同一个任务想继续做，用 `/compact` 压缩；换新任务，用 `/clear` 清空。另外，引用文件时记得加 @ 前缀：
```
@guess_number.py 这个文件里有什么Bug？
```
这样 AI 看到的是真实文件，而不是凭印象猜。
这一阶段的毕业项目：写一个能增删查改、重启后数据还在的命令行待办清单。功能分优先级，P0 是添加、查看、标记完成，P1 是删除，P2 是搜索。分四步推进：
第一步搭基础结构：
```
帮我创建一个叫todo-cli 的项目。
要求：
• 创建目录todo-cli
• 使用Python
• 先只做最基本的添加任务和查看任务功能
• 数据存在JSON 文件里
```
验证能添加和查看后，第二步补完成与删除：
```
现在帮我加上以下功能：
1. 标记任务为已完成（用编号）
2. 删除任务
3. 数据自动保存到tasks.json
```
第三步优化交互体验：
```
帮我优化用户体验：
1. 任务列表显示编号
2. 显示任务总数和已完成数
3. 输入无效命令时给出提示
```
第四步写 README 说明文档：
```
帮我写一个README.md，包括：
• 项目名称和简介
• 功能列表
• 使用方法
```
完成标准：能添加、能查看、能标记、能删除、重启数据还在、有说明文档。做到这里，你就已经入门了。你练的是 AI 开发最核心的几种能力：需求描述、结果验收、小步迭代、Bug 定位，还有上下文管理。
## 五、一个人，如何打出一个小团队的效率
如果你希望 AI 不仅能写，还能把项目管起来，前面说的三个工具要配合使用。简化版分工是：GSD 管流程，gstack 管质量，Superpowers 管纪律。
GSD 把大项目切成小阶段，每一段都有明确目标和验收标准，状态自动保存在 `.planning/` 目录里。你做到一半关机，第二天接着开工，进度还在。它的流水线是：spec（需求）→ discuss（讨论）→ plan（计划）→ execute（执行）→ verify（验证）。
gstack 里提供多个角色：`/office-hours` 是 CEO 顾问，帮你想清方向、追问盲区；`/review` 是代码审查员，查质量和安全隐患；`/qa` 是测试员，在浏览器里实测并截图；`/cso` 是安全官，按 OWASP + STRIDE 做审计；`/ship` 是发布经理，上线前做最后检查。你不需要懂技术细节，只需要用它来提问、审查和验收。
Superpowers 则像纪律委员，自动触发测试、统一调试方法、完成功能后做验证。它管的不是“做什么”，而是“怎么做才对、哪些动作不能碰”。
总结起来：GSD 告诉 AI 今天干什么，gstack 告诉 AI 干得好不好，Superpowers 告诉 AI 哪些线不能越。这三层叠加，一个人也能做出一个小组的量。
AI 编程真正的坑，从来不是代码写不出来，而是写出来就失控。
我把这套打法总结成一套组合拳：三件套负责把想法落地，四级治理负责不翻车，四件套质量门确保不出事。核心是让 AI 自己管自己，而不是你全程盯着。
先说最被低估的那件：Superpowers。
它不是一个你需要手动去点开的功能，而是默认就挂在你身上的自动驾驶。写任何功能前它会先写测试，严格走 TDD 的红-绿-重构流程。遇到 Bug 时它不会猜，它会强制启动系统化调试，口头禅就三条：不调查不修、不要猜测、不要瞎试。代码收尾时它会自动跑完成验证，确保东西是真的能跑而不是看起来能跑。
三件套怎么配合，我用 pngtrid.com 的真实流水线给你拆开看。
第一步，用 gstack 把方向想明白。进 Claude Code 打 /office-hours，跟它聊你的想法。比如我想做一个面向国内的 AI 生图站，价格要合理，不用🪜。gstack 不会拍胸脯说开干，它会一连串追问把你逼清醒：目标用户到底是设计师还是电商卖家？用 Stable Diffusion 还是 Midjourney API？定价是免费加付费还是纯付费？获客靠 SEO 还是社群？把模糊的冲动变成可执行的方案。
第二步，用 GSD 把项目切碎。想清楚后输 /gsd-new-project，把产品方案喂进去，AI 会自动生成项目骨架并切成若干 Phase。接着用 /gsd-plan-phase 做细化。它会给出类似这样的拆分：Phase 0 基础搭建一天，Next.js+Tailwind+数据库+登录+基础布局；Phase 1 核心功能三天，生图集成+生成队列+展示下载；Phase 2 付费系统两天，微信/ Stripe 接入+会员额度+回调；Phase 3 上线准备一天，SEO+性能+部署 Vercel。每個 Phase 都带验收标准，比如 Phase1 的标准就是能输入提示词、点生成、看到图、能下载。
第三步执行，GSD 负责排兵布阵，Superpowers 负责质量落地。输 /gsd-execute-phase，AI 就按计划开工。你要做的只有三件事：看它报计划，确认就开干；Phase 完验收，用浏览器点一遍看是不是你要的效果；中文直接给反馈，按钮位置、页面速度、颜色都行。电脑关了也没关系，状态存在文件里，第二天说继续上次的 Phase1 它立刻接上。
第四步质量检查，回到 gstack 做三轮体检：/review 做代码审查找 Bug 和安全漏洞；/qa 让 AI 真实打开站点操作并给你截图；/cso 全面安全审计。为啥 AI 写的代码还要审？因为它有确认偏误，自己审自己容易自我感动。我实测过，用另一个 AI 交叉审 Claude 代码，查出 Blocker 的准确率约 47%，数字不高，但它唯一标出的 Blocker 正是 Claude 自己完全没看到的盲区。审查的价值是视角互补，不是追求满分。
第五步发布，用 /ship 一键构建部署，你确认就行。
为什么很多人 AI 编程做出一坨？缺治理。AI 是个能力强但没方向感的新员工，不给规则它就自嗨。治理的本质是把人脑里的隐性知识变成 AI 能执行的显性规则。我用四级渐进模型：
L1 基础级，5 分钟搞定，就是 CLAUDE.md。让 AI 帮你生成，90% 个人项目到这一步就够了。
L2 规范级，30 分钟，团队超过 2 人、有生产部署、重复指令、重复犯错时升级。加规则、钩子、自定义 Agent。比如 API 目录强制错误处理，前端组件强制类型定义；修改文件后自动跑测试，不通过就回滚。
L3 协作级，2 小时，5-15 人团队。加 Plugin 打包、Agent Team 多 AI 并行、Forked Subagent 继承完整上下文。
L4 度量级，15 人以上公司。Managed Settings 通过 MDM 强制下发配置，统一规范。核心原则是宁可低一级，不要高一级，有痛点再升级。
再说质量保障四件套，防止看着能用实际有坑。
第一是 ralph-loop，口号 Memory is Poison, Tests are Cure。Claude 会忘事会幻觉，测试不会。循环是约束确认→代码生成→执行监控→闭环验证，测试失败就回滚。
第二是 code-review 三层隔离，避免互相带偏。Layer1 Claude 自审 30 秒；Layer2 Codex 交叉审，变更大于 200 行推荐；Layer3 /ultrareview 云端审，重大变更用多个 AI 并行。
第三是对抗性审计，上线前必做，三阶段信息不对称。Phase1 只给需求不给代码，让 Agent 猜风险；Phase2 给代码加假设验证；Phase3 融合前两轮找盲区。Phase1 必须新对话，防止上下文污染。
第四是 verification，铁律是代码已写不算数，测试通过才算。不要用我觉得，没问题，要用 curl 返回 200。验证矩阵要写清声称、验证方式、通过标准、结果。
完整的从想法到上线 SOP 可以直接抄：
阶段0 调研3小时不能跳。先花3小时 BRD 再决定要不要花3周。我第一次上线 pngtrid.com 没调研定位模糊，后来花2天重做调研，上线1个月变现5K。那2天价值是之前乱做的10倍。
阶段1 配置项目30分钟。建文件夹，开 Claude Code，让它生成 CLAUDE.md 并讨论确认。
阶段2 讨论规划1小时。/office-hours 想方向，/gsd-new-project 切 Phase，/gsd-plan-phase 出执行计划。
阶段3 执行开发7-14天。/gsd-execute-phase 执行，每个 Phase 你验收，不满意就中文改，半路断了也能续。
阶段4 质量检查1天。/review + /qa + /cso，不通过就修，做到全过。
阶段5 上线。/ship 一键发布，获客走垂直渠道 Reddit、社群、平台插件市场，别走大搜。
我的踩坑也给你省时间：跳过调研直接写代码定位崩；不给 AI 定规则用上不熟悉的技术栈；跳过审查上线支付就炸；对话太长 AI 忘事重复造轮子；定价先免费导致付费用户为零，后来 Freemium 才转化；一次性给太多需求，改成先注册测通再做下一步，质量立刻提升。
