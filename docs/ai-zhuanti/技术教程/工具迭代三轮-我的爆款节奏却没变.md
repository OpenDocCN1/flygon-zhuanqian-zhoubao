# 工具迭代三轮，我的爆款节奏却没变
260420 副业 SC 精华
作者：龙哥 | 时间：2026 年 04 月
应七天之邀，跟大家聊聊这段时间做内容和做产品的一些实操体会。
上一次在群里开口还是去年初。那会儿分享的是小猫补光灯，一个用 Cursor 跑出来的 iOS 小应用，直接登上 AppStore 付费榜首。当时的主角模型是 Claude 3.5 Sonnet，Cursor 也被奉为 AI 编程头牌。
![](img/zhuanqian_c6f438172db4b3949295e1a0869587c8_0_0.png)
转眼一年多，模型序列从 3.5 到 3.7 再到 4，如今已到 Opus 4.7。开发端也从 Cursor 切到了 Claude Code。整个 AI 圈换了好几拨主角。
![img/c6f438172db4b3949295e1a0869587c8_1_0.png](img/c6f438172db4b3949295e1a0869587c8_1_0.png)
回看最近几个月的产出，有个感受挺清晰：外界工具轮换很快，我的工作范式却始终在线，而且成效依旧。
于是我开始琢磨，到底是哪一块在真正起效。
## 近期发生了什么
前两个月 OpenClaw 忽然火了，坦白说我很长时间没怎么跟进。但兼着 AI 自媒体的人设，完全无视也不太合适。
我便让 Claude Code 帮我整理出了一份 98 页的《OpenClaw 橙皮书 🍊》。一来想借点热度，二来也方便后续做长视频拆解，有份 PDF 在手上解读会轻松很多。结果意外走红，X 平台阅读突破 200 万，飞书文档访问破 20 万，并在各大 AI 群组和某海鲜平台上刷屏。
![img/c6f438172db4b3949295e1a0869587c8_2_0.png](img/c6f438172db4b3949295e1a0869587c8_2_0.png)
紧接着上个月的 Claude Code 源码外泄事件，我正好把做 AI 主题小册子的流程已封装成 skill。结合自身使用心得，迅速做了期解读视频，并顺手产出《Claude Code 橙皮书》。
随手试发到微信读书，第二天就冲上热搜榜首。
![img/c6f438172db4b3949295e1a0869587c8_3_0.png](img/c6f438172db4b3949295e1a0869587c8_3_0.png)
此前我对这类榜单一直持敬畏心，觉得与我无关。没想到只要真正动手，就已超越了 99% 的旁观者。而当动机不是来自压力，也不是为赚钱，只是单纯觉得好玩把它做完，又会再一次甩开 99% 的人。
这是第二个案例。
第三个是女娲.skill。这个更像是副产物。
起因是写一篇《把同事作为 Skill》的评论。某个开源项目把公司同事的工作方法提炼成 AI skill，在网上引发讨论。我觉得角度有趣，就写了篇随笔。写着写着我突然意识到，我本人不也一直做着类似的事吗？我把写作、视频制作、橙皮书撰写等能力都已流程化，效果稳定。如果能蒸馏同事，那蒸馏我真正仰慕的人的思维模型岂不是更有价值。
于是女娲.skill 问世。开源后一周 GitHub star 破万，陆续被媒体报道。
## 三个项目有何共通
复盘下来，它们有一个共同点：生产时我都没想过要爆。
橙皮书是为了解决内容生产而顺手做的，女娲.skill 是写稿过程中蹦出来的点子。没有事先做过《什么能火》的市场调研。
但事后才发现，它们还有一个更隐蔽的共通操作：做完之后，我都把过程做成了可复用单元。
### 什么是 Skill 化
Claude Code 内置 skill 机制，允许把一套方法写成配置文件，后续同类任务会自动按此套路执行。
第一本橙皮书写完后，我把「如何写橙皮书」这个行为本身沉淀成了 skill。信息采集、章节设计、排版美化、封面生成、微信读书上架，整条链路都在里面。
有了它，第二本的耗时从数天压缩到数小时。到目前写了七本，初稿基本半小时可出。
人物提炼同理。先把芒格的框架蒸馏出来，并把「蒸馏一人」的流程固化成 skill。之后费曼、Naval、塔勒布、乔布斯、张一鸣，每一份都在加速。最终该方法本身进化为女娲.skill，成为通用的人物蒸馏工具。
对我而言，这是转折点。完成一件事是经验，把它封装成可调用单元才算资产。
### 资产会自行组合
这些单元并非孤立，会互相触发。
女娲.skill 并非灵光一闪。它是 perspective skill 的产出，加上橙皮书 skill 的方法，加上长期使用 Claude Code 的经验，三者碰撞后，「把蒸馏方法本身产品化」的想法自然浮现。
就像手里有二十块形状各异的乐高，看到的不是二十块，而是上万种组合可能。每新增一块，可能性是乘法而非加法。
我目前手上约有数十个 skill，覆盖写作、调研、审校、配图、排版、分发、脚本撰写、人物蒸馏等场景。它们叠加后，做事时经常自发产生新玩法。女娲.skill 就是在这种缝隙中涌现的，不是顶层设计的结果。
### 方法过时慢，工具迭代快
一年前我用 Cursor + Claude 3.5 Sonnet 打造小猫补光灯，现在用 Claude Code + Opus 4.7 产出橙皮书与女娲.skill。工具、模型、品类全变了。
我真正积累的是「把一次成功经验提炼为可复用流程」的能力。该能力与工具解耦。工具从 Cursor 换到 Claude Code，模型从 3.5 换到 Opus 4.7，封装的逻辑始终一致：做成 → 提取流程 → 下次更快 → 释放时间做新事 → 再封装。
每次工具升级，多数人从零上手。我也在学，但学会后会直接把新工具接入既有 skill 矩阵。别人是重开，我是在系统里添积木。启动速度因此完全不同。
所以工具换了三轮我仍能持续产出爆款，并非更聪明或更拼，而是 skill 在复利。
### 一个可借鉴的视角
我不确定这套打法是否普适。我每天投入 AI 超十小时，做的是内容与产品创作，对封装很敏感。
但有一个底层问题更通用：你现在做的事情里，有多少是做完即忘，下次还得从头再来？
那些就是封装点。不一定要用 Claude Code 的 skill，用清单、模板、SOP 也算。关键是让经验变成沉淀，而不是一次性消耗。
当你的单元库达到阈值，新的创作机会会自己冒头。你不需要硬想下一步，手里的积木会给出答案。
谈到「有趣」。我知道在龙哥盟说「做有趣的事」容易显得凡尔赛。但我的体感是，只有发自内心觉得好玩，你才会把它做到足够好的程度。做到了才值得封装，封装了才有后续复利。
若一开始就盯着「能不能火」「能不能赚钱」，注意力会被算计占据，反而做不到位。
这个世界很多时候像个大排档。多数人疲于工作不知方向，你因为好玩去做了，反而鹤立鸡群。
这不是鸡汤，只是我的一个意外观察。
工具会持续更迭，模型会不断升级。若能在每一次迭代里把经验沉淀为 skill，你就不是在追工具，而是在搭建系统。
系统不会被淘汰。
# 看完这篇 SOP, 你觉得你懂了。但 90% 的人一到实操就会卡在第一步。
工具和教程只是最低级的壁垒，真正的壁垒是“立刻动手”和“圈层信息差”。
我们不聊虚的，只做商业闭环的拆解与 AI 效率的压榨。系统内已沉淀 1000+ 跑通的套利实战局。
