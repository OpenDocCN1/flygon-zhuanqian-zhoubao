# Cursor 最新能力一览：

主要更新点：

1. Yolo 模式：可无感自动执行终端指令，不必每步都点确认，AI 权限被放开 （Windsurf 目前仍需逐条确认）

2. @docs、@git、@web 和 @folder 在 Agent 模式下都能用了

也就是 @docs 能拉取远程仓库文档，@git 能分析分支差异并自动 commit&push

@web 能联网检索信息，@folder 能一次性吃进整个文件夹内容

Agent 可并行改动多个文件，Windsurf 现阶段只能同时操作单个文件

Composer 的改动支持了 checkpoints，也就是时间切片，不满意的部分可直接回滚

Agent 的改动会实时落盘，不怕数据丢失

# 我的 Cursor 工作流：编程

![](img/zhuanqian_7f2d2c2943aaffdb4aa31acc662102e3.png)

### 给 AI 划规矩

我最常用的四件套：

全局规则 + 项目规则 .cursorrules + .cursorignore 补充 + notepad

说人话：

用全局规则把对话语言锁成中文，不用再看英文

用 .cursorrules 让 AI 吃透项目选型，多少补上了记忆上限的短板

用 .cursorignore 屏蔽 AI 不该碰的代码区

用 notepad 存常用提示词，灵活调用

四者配合，Composer Agent 开启 Yolo 后的自动编码会准得多

Windsurf 缺少了后两项，虽然 notepad 能用普通文件引用代替，但体验差一截。

#### 全局规则

就是写代码时的通配约定，比如对话用中文

在单文件里按 ctrl/cmd + k 时也会生效

![](img/zhuanqian_453e7943909dab93e756eff21b5716a1.png)

#### 项目规则 .cursorrules

针对当前项目的技术栈做设定，帮助 AI 快速理解上下文

主要描述项目结构、前后端交互、命名规范等

#### .cursorignore 补充

AI 默认会索引当前打开项目的所有文件

.gitignore 里的是不会索引的

.cursorignore 就是额外黑名单，可以自定义屏蔽哪些文件不被 cursor 看到

![](img/zhuanqian_5065c8669d10d4c746c1da425d0e5e96.png)

#### notepad

本质是一个提示词仓库，方便复用

把经常用的提示词放进去，随时引用

![](img/zhuanqian_23a7cf3ccfdb675ec942b962da723d02.png)

### 中文章撰写

没错，完全可以写文章，而且是 claude-3-5-sonnet-20241022 驱动下，AI 味很淡的文章

#### 中文章范围：

公众号稿、知乎回答、技术分析、番茄小说、年度报告；甚至个人润色等等

#### 中篇限制：

受限于 Claude 单次输出的 token 上限，一次性生成 20 万字长篇小说不现实

总结：所有文字创作类需求都能通过它完成

#### 本质：

核心是用了 Claude 的文本能力

此时 Cursor 或 Windsurf 都能用，因为都有 Agent 模式支持连续生成，也能自动建文件做大纲

#### 怎么操作？

两个工具都能引用文件或文件夹，有思路了吗？

再想想你平时写文章的流程

没灵感怎么办？

终极痛点：字数不够，达不到目标

## 举例拆解：

### 先想后写：

1. 我有素材没思路，想基于它展开

2. 我想一键产出 4000 字文章

3. 写完后整体不满意

4. 我只想改局部

5. 我想发到某个平台，需要排版美化

6. 所有关于文字生成和修改的需求

### 分步拆解：

#### 找灵感

把写作的基础材料放到一个文件夹，统一引用，最好是 .txt 或 .md 格式

告诉 Claude 你的意图，哪怕不引用它也能找到，但引用更精准

这样就能快速获得写作灵感

![](img/zhuanqian_7ce08c11ae7cd5b95c9d302303aff4a1.png)

#### 主体创作：

有了灵感或大纲后，把这些生成的文件再作为上下文，让 Claude 按需求续写

#### 润色：

局部润色：选中某段，ctrl/cmd + k 或 ctrl/cmd + L 直接润色

![](img/zhuanqian_8203075f527adaeeee6d5c9162adb2b2.png)

全局润色：引用整篇文件，输入修改方向，让它整体改写

想法 + 指令 = 成品

别限制想象力

不同类型写法不同，但通用逻辑是：我有一堆材料不想读，就让 Cursor 帮我读，通过文件引用交给它，限定写作手法、行文思路、文章结构、成品微调，即可得到想要的效果

# Cursor 对比 Windsurf 的核心优势

## 命令行操作的多样性

```
实现了稳定的命令行操作
实测整体的响应速度要快于 windsurf
cursor支持多文件并发修改
cursor的Yolo模式可以不用确认，自动执行命令
支持 pop out terminal，也就是在命令行窗口预览
```

## git 索引能力

![](img/zhuanqian_cd02a5733921e34155e02e50ab149732.png)

```
cursor可以自动commit / push代码
@Git 允许 Cursor 的扫描差异并查找可能由差异引起的错误或问题
@工作状态差异@Diff of Working State 从你当前的差异中生成提交消息
windsurf暂不支持以上的git操作
```

在 AI 与系统深度融合这条路上，命令行操作的稳定性是关键

看 Cursor 在这块的突破，我越来越确信：AI 不只要懂代码，还要懂开发者习惯

当它能稳定执行命令行时，真正的 AI 辅助编程才更近一步

在辅助编程上，AI 需要深度理解业务逻辑，能猜到你真正想要什么

帮新人更快上手项目，节省 debug 时间

自动修改跨文件重复引用，理解业务逻辑

这些都是刚需

## 上下文智能检索

早期 Cursor 支持 200k 上下文的 claude3.5-sonnet 长文本阅读

我曾让它读几万行混淆代码，很快定位修改点并基于上下文生成功能

当时受限于 10000 tokens 不能直接 apply，但已经很强

现在的 Agent 模式下，代码分析更全面，索引更快

上下文能力提升，就像人类学编程必须先理解整体

Cursor 在这条路上追平了 Windsurf 的优势，让人看到 AI Agent 下真正读懂代码的希望

## 记忆能力

多轮对话的指令遵循上，Cursor 很稳：

* 能持续记住首次对话的指引

* 支持 .cursorrules .cursorignore notepads 持久化记忆

* 在项目根目录建一个 .cursorignore，就能避免索引大量第三方代码

* 用 notepad 快速引用组件编写预设，能显著提升生成代码的准确性，更贴合项目需求
