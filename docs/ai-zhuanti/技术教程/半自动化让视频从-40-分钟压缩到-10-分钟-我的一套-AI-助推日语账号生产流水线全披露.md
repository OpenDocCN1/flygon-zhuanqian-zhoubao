# 半自动化让视频从 40 分钟压缩到 10 分钟：我的一套 AI 助推日语账号生产流水线全披露

大家好，我是亿舟ovo，原名一舟，因为李姓大神的存在被迫改名。

写下这篇复盘的缘由很简单。我在运营一个日语账号的期间，深度实践了一系列 AI 效率技巧。起初一条视频要花 40 分钟，现在稳定在 10 分钟左右就能出片。这个过程让我坚信，AI 可以无缝接入任何内容赛道，成为提速的核心杠杆。于是我把整套思路整理出来，希望对想做半自动化的人有参考价值。

# 一、为什么做这个账号

今年下半年教育垂类再次迎来红利期。恰好我自己也在学日语，于是决定切入日语相关的内容赛道。

调研一圈后发现，单图八词的日语跟读视频转化最好。形式极简：一张配图放 8 个单词，从头到尾读一遍。拆开来看，核心就三步：做出一张图、生成日语配音、根据音频移动箭头。

没有 AI 时，这活我根本不会接。素材收集和图源整理就要花掉大半天。有了 AI 后，整条链路才跑通。

坚持一个月左右，账号涨到 5000+ 高质量粉丝，也通过资料售卖赚到第一笔小钱。接下来我把半自动化做视频的历程讲清楚。

# 二、第一阶段 AI 提效：从 40 分钟到 20 分钟

初期的设想是这样的：用大语言模型写内容，用 Midjourney 做图，用 Coze 做一个抠图智能体做后期处理，再把内容和图丢进 Google Sheets，最后靠 Figma 插件一键同步到模板。整套打下来，单条视频制作时间从 40 分钟降到 20 分钟。下面拆解具体操作。

## 1、用大模型生成并规范化内容

我用的模型是 gpt-4o，做两件事。

第一件事是脑暴生活常见场景里的高频日语单词。没有写死提示词，就是以闲聊的方式让它出点子。

第二件事是做结构化输出，把词的日文写法、平假名、罗马音、中文释义、英文释义整理成表格，并自动加上标题。

提示词如下：

```
### 人物设定
- **角色**: 在日本生活20年的日语教师
### 用户目标
- **学习目标**: 通过日语能力测试N1
### 用户任务
- 用户将提出关于日语单词学习的问题，例如：
- 日本旅游常用八句话
- 最常吃的八种食物的单词
- 日语入门八个动词
### 指导原则和回答结构
1\. **回答结构**:
- 表格形式返回以下列：
1\. **日语汉字**: 例如，林檎、胡瓜
2\. **假名**: 单词的假名，如果假名与汉字部分一致，用空格代替
3\. **罗马音**: 中间加空格
4\. **中文翻译**
5\. **英文翻译**: 名词直接翻译；动词使用完整句子，便于AI绘画生成
2\. **第二部分**:
- 将英文翻译转为列表
3\. **第三部分**:
- 仅展示假名部分，用顿号隔开
4\. **第四部分**:
- 提炼单词共性生成吸引眼球的标题，用于小红书
### 特殊要求
- 确保无语言错误、单词音调无错误
如果明白，请回复“好”。
```

表格化的好处是能直接复制进 Google Sheet。英文列是给 Midjourney 用，日文列是给配音用。

## 3、Coze 智能体抠图

抠图方案很多，Remove.bg、PS、Pixian.ai 都试过。最终选 Coze 智能体，两个原因：其一，它会自动把主体裁剪到合适尺寸，原图主体小也不会糊；其二，支持 API 调用，成本更低。

工作流里只放了一个智能抠图节点，智能体就是调用这个工作流。上传图片即可拿到抠图后的链接。

# 三、瓶颈出现

这套流程跑了半个月左右，问题集中爆发：

1、Coze 网页版智能体上传慢，返回链接还要手动点下载，耗时。

2、配音偶尔走调，且观众希望能看到音调标记。

3、Autojourney 下载不稳定，指定目录失效，文件名混乱分不清对应单词。

4、内容难以沉淀复用，缺少存档整理机制。

5、想要加入童声跟读，提升观感。

想起来纳瓦尔宝典里的一句话：要财富，就用杠杆。代码就是新富阶层的杠杆，你可以造一个软件，让它在你睡觉时替你工作。

正好 Cursor 热度正高，于是我决定用 AI 编程把流程再升级一次。

# 四、AI 编程 Plus：从 20 分钟到 10 分钟

我用 Cursor 写了三个小工具串起整条链路。跑通后，单条视频耗时降到 10 分钟，质量还更高了，内容也能沉淀下来。

先自报家门。我原本是安卓开发，代码已很久没写。这回用的是 Python 桌面应用和 Chrome 插件，基础语法还能看懂，但远谈不上精通。

这三个工具迭代很多次，Cursor 账号也换过，部分对话记录已丢失。下面尽可能还原当时的思路，包括 Cursor 的优缺点，都是真实踩坑经历。

## 1、Python 桌面应用

### 1）核心能力

*   直接调用 Azure AI 生成跟读音频

*   可切换 Google TTS API 或 Azure TTS 生成语音

*   调用 Coze API 完成抠图，本地下载并同步一份到七牛云，同时把七牛云链接写回 Google Sheet

![](img/zhuanqian_5a7289158e1640de5c55ca68f3cb7283.png)

做这个软件的初衷是解决两件事。

第一件事，Midjourney 一次出 4 张，我希望能从中挑一张合适图，拖进软件后自动调 Coze API 抠图、下载到本地、上传七牛云，并把链接按英文翻译匹配写入 Sheet 对应的图片地址列。操作只剩下挑图和拖拽。

第二件事，自动生成带跟读的音频。先由成人女声读一遍，再用童声跟读一遍，按词循环，避免在剪映里二次剪辑。考虑到日语存在多音字，还保留一个手动校对的文字转语音功能。

![](img/zhuanqian_7c02bae6255dd4e6c26500b1fcf607b9.png)

### 2）AI 编程实战过程

#### a） Cursor 的三种用法

Cursor 调用 AI 有三种方式：行内 Ctrl+K、侧边 Chat 对话、以及我最常用的 Composer。Composer 分 normal 和 agent 模式，agent 模式能执行终端命令、改文件、语义搜索。官方文档可查。

社区也很活跃，遇到问题可以去讨论。

我选的大模型是 Claude-3.5-sonnet1022，目前综合表现很稳。

![](img/zhuanqian_fe55b4c87c2e63f120152123624d5c9c.png)

![](img/zhuanqian_c3fc450918709e2282b364b30139511f.png)

Composer 窗口里输入 @ 可引入文件、文件夹或代码片段；@Web 则会联网搜索。

![](img/zhuanqian_f4fc35ac27503fa2296053746f232363.png)

#### b） 功能拆解式开发

我习惯先拆点。小应用我会先说：“我要做一个在 Mac 上运行的桌面应用，能拖图片到界面上，调用 Coze 智能体 API 抠图，Coze 返回链接，我要下载到本地 XX 文件夹。”

等这一功能跑通后再加下一步：“现在把下载好的图上传到七牛云，把返回地址填到 Google Sheet，表地址是 XXXX，写入 F 列 2-9 行，文件名按 E 列英文翻译匹配。”

这样每完成一个点就 commit 一次，定位问题快，也能随时回滚。一次性堆所有需求，一旦报错根本分不清是哪个环节。

#### e） Coze API 调用细节

直接让 Cursor 调用 Coze API，一开始它只实现了对话，上传图片始终失败。折腾多次无果后我猜测是 Coze API 太新，网上资料少。于是自己去看官方文档。

文档里流程是：先调用文件上传接口，把本地图片传上去拿到 file_id，再在对话接口里带上 file_id 发请求。因为是非流式响应，要轮询 retrieve 接口等到 completed，再调 message list 接口拿抠图后的网址，最后下载。

文档太长不方便直接喂给大模型，容易超 token。于是我只把关键示例和参数摘出来，配合清晰的逻辑复述给 Cursor，它一次就写出来了。

![](img/zhuanqian_291ff9b69c3a8b061fc34d5d737ae56d.png)

理清逻辑后，把步骤和代码样例给它，配合点耐心即可完成。

#### f） 报错与界面卡顿

开发中常遇到终端报错或界面卡顿，比如抠图下载在主线程执行导致 UI 假死。直接把报错日志贴上去，或者描述现象：“上传图片时界面卡死，我想避免阻塞。”

Coze 智能体偶尔也会没返回图片链接，这种情况让 Cursor 加重试机制即可。

#### g） Google OAuth 2.0 的坑

本软件调用了多个 API，Azure TTS、七牛云都能用 API Key 直连。Google 的调用方式就复杂得多，有服务账号、API Key、OAuth 2.0。桌面端和 Chrome 插件的调用流程还不一样。

不提前确定方案，Cursor 会随意选一种，导致调试困难。我花了很久才靠官方文档定位正确方式。确定后把示例代码丢给 Cursor，问题立刻解决。

![](img/zhuanqian_291d3cdbab8450c0c8f2cdf82ab5a72c.png)

#### h） 音频生成与童声模拟

目标是软件内直接产出带跟读的音频，减少剪映操作。跟读本质是拼接音频，难度不大。难点在模拟童声。

我让 Cursor 实现时，它给出的方案是本地音频处理库，通过调节音调、语速、音高等参数来模拟。但调了几次效果都不理想，具体用的是哪个库我已记不清。

很多人好奇，我是怎么把 AI 工具玩得这么溜的。今天就掏心窝子聊聊这段从零折腾的自动化之旅。

先说语音合成。最开始试了好几个方案，发音效果都让我直摇头，实在没辙了，就让 Cursor 换个思路找找。结果它翻出一个 Azure TTS 的儿童音效，试了试居然挺对味，干脆就用它的 API 来跑。保险起见，我又额外接了一遍 Google TTS，免得个别单词声调跑偏。这里得多嘴一句：这两家都不是纯免费，不同型号定价不一样，基础版按月送免费字符数，掐着用就行。

既然聊到单词，就不得不提我做的第一个 Chrome 插件——查单词音调，顺便把内容整批同步到 Notion。

它的活儿很纯粹：

*   查单个单词的音调

*   把表格内容整批塞进 Notion

![](img/zhuanqian_17e91fd5c42757b3552bd4f7077aff64.png)

做它的原因有两个。一个是老有粉丝反馈说音调不标准，可 AI 生成的语音我真没法逐字控制，那就换条路：在单词旁把音调标出来。另一个是视频发了不少，文字却散得到处都是，我特想找个地方把过往内容都接住，以后想转型做产品也有现成的素材库。翻了一圈手里的工具，Notion 就是那个最顺手的。

![](img/zhuanqian_fc33b183a3a2c2bd7a42d8440b2137c4.png)

有了第一个软件打底，Cursor 的基本套路我也摸熟了，后面这两个插件做起来快得很，功能本身也简单，更多是熟能生巧。

头号难题依然是音调数据从哪儿来。一开始我天真地想让 AI 直接报音调，但试了好几个大模型，错得一塌糊涂。我后来琢磨，用①②③这种数字标注音调的法子，八成是国内老师发明的，日本根本不认这套，模型自然学不会。

好在天无绝人之路。我搜到个日本词典网站，不用登录就能返回音调。按下 F12 把背后的接口数据扒出来，再丢给 Postman 调通，它会直接生成调用示例，复制给 Cursor 就能接上。

不过做它的时候，我真被 Cursor 气得不轻。

头一个坑是图片全堆在 Downloads 根目录，我明明写了要放到 MJ 子文件夹，可它就像没看见，日志里也一点报错都没有。猜是 Chrome 下载环节出了问题，但 Cursor 来回改了几轮就是没辙。最后还是请了外援，让其他大模型先定位病因，再让 Cursor 按方抓药。

![](img/zhuanqian_8d9ff0f3a78369addaa07b5c630c905c.png)

第二个坑是文件名。代码里指定得好好的，逻辑上也确认过传值没问题，可最后存下来的文件名依然不对。顺藤摸瓜查了一遍，发现是 content.js 传到 background.js 这一步出了岔子。又是外援救场，我把可疑原因列给 Cursor，让它逐个排除。

![](img/zhuanqian_3396ad4e9a579a98fc23ced14c720e23.png)

这两次栽跟头让我怀疑，是 Cursor 当前 Composer 里上下文堆太多，它满脑子都在想着怎么解决，却没停下来琢磨问题是怎么来的。也许重新开一个 Composer，把记忆清空，“降智”能缓解不少。

对刚入门的萌新来说，代码看不懂也正常，那就直接回头问 AI：“我看不懂，请详细说明这些代码是干什么的，还要加上代码注释”。

![](img/zhuanqian_a61964a818f03a47cfc90fbd4c945377.png)

接下来是几个亲测好用的 Cursor 小技巧。

一来，别指着一个会话通关。大模型能读的上下文就那么些，消息发太多它会漏读，写出来的代码自然错漏百出。把需求拆开，一个会话只解决一件事，把关键上下文拎得清清楚楚。Agent 模式下，删掉 Context 文件会逼它自动做语义搜索，搜出来的片段往往比你手动指定的还靠谱，降智时可以试试。

![](img/zhuanqian_5f14ed2e620ff74f46fdbb4067d2972f.png)

二来，中文变乱码菱形块时，去把系统改成全局 UTF-8，具体操作直接问 Cursor 就行。

![](img/zhuanqian_6b4df9edb614656a158821e562b49178.png)

三来，要小心 Cursor 偷换配置。我在折腾 Google OAuth 的时候，它反复调试无果，就开始动我的 API key，一口咬定我的 key 不符合 Google 格式。自己接不住锅就甩给用户？我果断不接受，还要反过去质疑它。所以大家收代码时一定要留个心眼，看看它有没有改掉原本正确的设置。

四来，.cursorrules 这个文件是个宝。新建一个 .cursorrules，把代码规范、功能需求、技术栈都写进去，等于给模型立了规矩，它写起来就会“有模有样”。

五来，别总想着从零造轮子。先在 GitHub 上逛逛现成的开源项目，fork 下来，让 Cursor 读懂别人的代码再改，能省下大把时间。有新需求也可以直接讨论，顺着原来的技术栈继续加功能。

![](img/zhuanqian_389956ff70d466a9f7c912c42823aaa2.png)

最后说点心里话。这段提效之旅走下来，还有很多地方值得优化，比如剪辑完全可以让软件代劳一键搞定，账号发布也能自动化。但真真切切的感受是，AI 把我的认知和工作效率都带上了一个台阶。我学到最受用的一句话就是：不会的，就问 AI。
