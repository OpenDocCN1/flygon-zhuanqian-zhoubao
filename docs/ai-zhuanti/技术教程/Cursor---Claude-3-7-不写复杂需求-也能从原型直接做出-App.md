# Cursor + Claude 3.7：不写复杂需求，也能从原型直接做出 App
过去，做一个 App 往往要经历需求梳理、产品设计、原型绘制、界面开发、功能调试等多个环节。对于没有开发经验的人来说，光是把想法变成清晰的产品原型，就已经是一道门槛。
但最近尝试了一种新的工作流：先让 Claude 3.7 Sonnet 生成完整的 HTML 原型，再交给 Cursor Agent 根据原型完成 iOS App 开发。整个过程可以概括为两步，而且每一步都能直观看到结果，特别适合非专业产品经理或独立开发者。
## 第一步：先让 Claude 生成完整的 HTML 原型
首先，新建一个项目文件，让 Cursor 生成 App 的原型页面。
以“AI 自动记账 App”为例，可以这样描述需求：
> 我想开发一款 AI 自动记账 App，目前需要先完成产品原型设计。请按照以下流程协助我：
>
> 1. 分析用户使用 AI 记账 App 时需要哪些功能；
> 2. 以产品经理的角度规划所需页面；
> 3. 以 UI 设计师的角度确定各个页面的布局和视觉风格；
> 4. 使用 HTML 在同一个页面中展示所有主要原型界面，可以调用 FontAwesome 等开源图标库，让页面更精致、更接近真实产品。
>
> 这些原型页面需要具备较高的完成度，后续能够直接作为开发参考。
这一阶段，本质上是让 Claude 同时承担“需求分析、产品规划和界面设计”三种角色。
### 生成原型时需要注意三件事
**第一，模型要选 Claude 3.7 Sonnet。**
建议优先使用普通模式，不必一开始就开启 thinking。
**第二，模式选择 Composer normal。**
如果使用的是 Cursor 0.46 版本，也可以选择 editor 模式。这里不要使用 Agent 模式，第一步尤其不要选 Agent。
**第三，遇到代码过长导致生成中断，不需要重新开始。**
因为所有页面集中在一个 HTML 文件中，代码量可能比较大，生成过程中有可能出现文件创建失败或内容被截断的情况。
这时可以点击生成失败的文件，按照 Cursor 的提示创建文件，并把已经生成的代码复制进去。随后重新 @ 这个文件，让 Cursor 继续补齐剩余内容即可。
![](img/91c27c4ecea043194e355799ad3d10f6.png "None")
等 HTML 文件补全后，直接在浏览器中打开，就能看到一个页面里集中展示的 App 全部主要界面。
![](img/077f43bc1e0cd946643edc0bc3c76827.png "None")
相比只看文字需求，这种方式最大的优势在于：你可以一边查看原型，一边发现问题、调整布局，并逐步明确自己真正想做的产品。
## 第二步：把原型交给 Cursor 开发 iOS App
完成原型后，使用 Xcode 创建一个新的 iOS 项目，再将这个项目的根目录用 Cursor 打开。
如果没有接触过 iOS 开发，不清楚如何创建项目或打开目录，可以先参考之前的 Cursor 教程和 iOS App 开发相关内容。
![](img/0e59cbdab03218e9d7e0d60580eae670.png "None")
接下来，把第一步生成的 App 原型图发送给 Cursor，并提出开发要求：
> 请根据我提供的原型图，完成这个 App 的界面设计与功能开发。
![](img/2246eaea5de283ea4e3b061b103656ba.png "None")
这一步的操作方式和前面不同，需要特别注意下面三点：
**1. 仍然选择 Claude 3.7 Sonnet。**
thinking 和非 thinking 模式都可以分别尝试，具体看任务复杂度。
**2. 必须启用 Agent 模式。**
第一步不建议用 Agent，但第二步正是依靠 Agent 来连续创建文件、修改代码和推进开发流程，所以这里一定要选择 Agent。
**3. 持续确认 Cursor 生成的代码文件。**
在开发过程中，按提示不断 accept 代码变更即可。如果之后在 Xcode 中运行出现错误，可以直接把报错信息复制回 Cursor，让它定位并修复问题。遇到调试和排错任务时，建议使用 thinking 模式，通常会更稳妥。
![](img/9a063588e1137a501d5396258ffcc024.png "None")
![](img/e8a3980c88ba56540ead096c50b7303f.png "None")

这次实际测试中，第一步出现过一次 Cursor 生成异常，第二步也遇到过一次 Xcode 报错，除此之外整体流程都非常顺利。
最终生成的 App 不仅完成了界面搭建，很多功能也已经可以直接操作，基础交互和业务逻辑基本符合预期。对于一个没有完整开发团队的个人来说，这个结果确实相当惊艳。
## 这套方法为什么有效？
整个流程的关键，并不只是 Cursor 或 Claude 3.7 单独发挥作用，而是两者配合形成了一个清晰的开发链路：
1. Claude 3.7 Sonnet 能够快速产出较完整、较真实的产品原型；
2. Cursor Agent 可以围绕原型图拆解任务，连续完成多文件、多步骤的 App 开发工作。
也就是说，先用原型把想法“看得见”，再让 Agent 把页面和逻辑“做出来”。这比一开始就让 AI 直接从一句模糊需求生成完整 App，更容易控制，也更适合没有专业产品设计经验的人。
