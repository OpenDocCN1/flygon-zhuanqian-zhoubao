这次案例最有参考价值的地方，不是“用了哪个模型”，而是先把成熟账号的历史内容整理成一套可调用的写作资料，再让 AI 在动笔前寻找相近主题的优质范例。这样做之后，5 个号每月大约只需投入 2 小时维护，单号最高达到 1.1 万阅读，目前相对稳定在 1000+。

当然，流程也有明显的失败点：如果只把标题丢给 AI，却不调整指令，连续产出十篇后很容易变成千篇一律的模板文，缺乏真实感。选题方面，与其凭空琢磨，不如优先研究同赛道已经验证过的数据表现。

目前得到的阶段性结果：

- 每月用 WorkBuddy 处理 5 个账号的内容，耗时约 2 小时；

- 每周集中用 20 分钟完成一周内容的发布安排；

- 其中一个账号已经完成流量主验证，其他账号虽然更新时间较短，但近几天的基础阅读大多在 150 左右；

- 已跑通账号曾出现 1.1 万阅读的单篇内容，近期平均表现保持在 1000+。

# 需要准备什么

整个过程并不复杂，关键在于提前准备好三样东西：

- 一个你能读懂、且已经连续经营一年以上的公众号。它的日常数据相对平稳，偶尔还能出现高表现内容；

- 一套在马老师相关方案基础上继续改良的 V5.0 指令副本；

- WorkBuddy，以及用于保存公众号文章的采集工具。

# 从找到案例到跑通流程

最初是在龙哥盟看到马老师分享的相关方法，随后接触到“文风复刻”方向的提示词。

后来，我注意到某个账号长期围绕职场话题展开，文章框架清楚，内容也具备较强的可拆解性，于是决定把它当作研究样本。

具体步骤如下：

1. 使用 `wechatDownload` 将该账号的历史文章集中保存；

2. 把素材交给 WorkBuddy，配合指令进行批量拆解，最终得到一份体量很大的 JSON 分析结果；

3. 先挑出历史上阅读量超过 1 万的标题进行测试；

4. 连续生成约 10 篇后发现，文章虽然形式完整，却明显带着机器味，段落和表达过于套路化；

5. 于是与 DeepSeek、GPT5.6sol 一起排查问题，边测试边修改指令，最终形成第 5 版；

6. 目前先让系统理解账号资料，再输入新的标题，成稿质量比早期版本明显提升；

7. 排版时，取一篇参考文章的 HTML 作为样本，让 WorkBuddy提炼其中的版式规律，再应用到自己的内容里，最后把这套排版流程固化成 skill，之后可以批量处理；

8. 完成审核、发布和分发，继续观察数据反馈。

# 为什么要不断改指令

最早的设想，是让模型模仿某个作者的整体表达方式。参考的基础方案是“多篇文章风格分析与模仿系统 V3.0”。

但实际使用后发现，一个账号往往同时覆盖多个内容方向。若只提取统一文风，再让模型机械套用，结果很容易僵化：看起来像同一个作者，却不像针对具体话题写出来的文章。

后来又看到“为什么精心写指令，有时还不如直接提供案例”的讨论，这带来了一个新的思路：

**每次开始写之前，先根据标题寻找同类高质量样本，再结合账号自身的表达规律完成创作。**

因此，V5.0 不再只做简单的风格模仿，而是承担了几个更具体的任务：

- 把项目中已有的内容全部整理出来，按类别、主题和表达目的建立检索体系；

- 找出作者长期稳定的语言习惯，同时区分不同题材对应的写法；

- 将这些规律整理成可重复调用的风格模型；

- 之后输入新的内容方向时，系统可以先匹配相应主题，再生成更贴合的文章。

换句话说，V5.0 的核心变化，是从“记住一个人的语气”，升级为“理解这个账号在不同主题下应该怎么写”。

# 实操中容易忽略的细节

这里有几条经验，能够减少后续返工：

- 采集完成后，建议清理掉 HTML，只留下 Markdown 文档，并统一放进同一个目录；

- 用 WorkBuddy读取这批 Markdown 素材，再发送 V5.0，让它先完成账号画像和文章体系分析；

- 等资料分析结束，再输入新的内容方向，要求系统生成对应稿件；

- 不建议从零开始凭感觉找题目。更稳妥的方式，是参考同赛道已经验证过的高表现标题，再做改写和延展。

# 过程中看到的几个现象

## 1. 公众号似乎仍会给新账号基础曝光

从近期测试来看，只要内容没有触碰平台规则，即使是新账号或小号，也可能获得一定的初始阅读。朋友的账号和自己的测试账号都有类似情况，很多文章的基础数据能够达到 100+。

## 2. 工具不是决定性因素

很多人首先关心“哪个模型最好用”，却容易忽略真正影响结果的能力，包括：

- 如何设计提示词；

- 如何拆分复杂指令；

- 如何设定角色；

- 如何安排资料和上下文；

- 如何限定输出格式；

- 如何提前写清边界；

- 如何根据结果持续调整；

- 如何把大任务拆成多个小任务。

同一个工具，使用方法不同，最终产出的差距可能非常大。

## 3. 现在仍有低成本试用窗口

目前这套内容生产流程主要消耗免费额度。各家厂商仍在激烈竞争，普通用户可以趁这个阶段多做测试。

我自己的工具路线也换过几次：从 Cursor，到 augment、kiro、Codex，再到 WorkBuddy，整体花费并不高，但依然有机会接触到能力很强的模型。
