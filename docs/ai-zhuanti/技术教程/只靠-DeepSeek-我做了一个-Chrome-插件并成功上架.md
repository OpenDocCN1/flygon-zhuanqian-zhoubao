直到 51 假期，我看到一位圈友分享如何借助 AI 开发 Prompt 管理类 Chrome 插件。更巧的是，我自己的 TODO List 里也一直放着类似想法，只是迟迟没有开始。如果没有看到那篇分享，这个项目大概率也会和其他收藏文章一样，被我放在角落里慢慢积灰。

# 先确定 MVP：只做最核心的功能

一开始，我没有试图把插件做成一个“大而全”的工具，而是先明确最低可行版本需要解决什么问题。

## 一、创建 Prompt

1. 支持新增 Prompt

2. Prompt 信息保存在本地

3. 支持带占位符的 Prompt 模板

## 二、管理已有 Prompt

1. 可以给 Prompt 添加标签

2. 支持通过关键词搜索 Prompt

功能范围非常克制，先解决“保存和查找提示词”这个核心需求，其他内容以后再考虑。

# 开始开发

因为本身是程序员，我的习惯是遇到陌生技术时，先去看官方文档，了解基本概念和项目结构。

这次我简单浏览了 Chrome 扩展官方文档，也看了官方提供的示例代码，对插件的目录结构和常见功能有了初步认识：

[`github.com/GoogleChrome/chrome-extensions-`](https://github.com/GoogleChrome/chrome-extensions-) samples/tree/main/functional-samples/tutorial.hello-world>

不过，如果你没有技术基础，其实不必在这些内容上花太多时间。现在完全可以直接把需求告诉大模型，让它帮你解释工程结构、生成代码，并一步步带着你完成。

我的开发环境是：

- 编辑器：Visual Studio Code

- AI 工具：DeepSeek

- 前端框架：React + TypeScript

- UI 组件库：Ant Design

- 本地数据存储：Dexie

其中页面组件、工程框架以及数据存储方案，基本都是通过询问 DeepSeek 后确定的。

Ant Design 官网：

[`ant-design.antgroup.com/components/overview-cn`](https://ant-design.antgroup.com/components/overview-cn)

实际开发时，我先让 DeepSeek 帮我设计整体实现思路，再逐个拆解页面和功能。

比如：

- 工程应该如何搭建？

- Chrome 插件的页面如何实现？

- 数据应该如何保存？

- Prompt 标签和搜索如何设计？

- 项目如何运行和打包？

基本流程就是：先提需求，让 DeepSeek 生成代码；运行后发现问题，再把报错和现象继续发给它；修改后再次测试，循环往复。

遇到问题不要卡在那里，继续追问就行。大多数常见问题，经过几轮沟通都能解决。

至于插件 Logo，我没有额外投入时间设计，直接使用了 Chrome 官方示例项目里的 Logo，先把产品完整做出来再说。

# 插件上架流程

功能开发完成后，需要先把整个工程打包成 ZIP 文件，然后提交到 Chrome Web Store。

官方发布文档如下：

[`developer.chrome.com/docs/webstore?hl=zh-cn`](https://developer.chrome.com/docs/webstore?hl=zh-cn)

真正提交时，我遇到的第一个门槛是：必须先注册 Chrome 开发者账号，而且需要支付 5 美元注册费。

很多人可能会在这一步停下来，选择把 ZIP 文件直接发给别人，让对方下载后解压使用。这样确实能运行，但后续如果要修复 Bug、增加功能或者发布新版本，更新和分发都会比较麻烦。

所以我最后选择直接解决开发者账号的问题：

**在某宝搜索 Chrome 注册开发支付，花了 70 多元，很快完成了支付。**

![](img/f90308cd4b06fa6ba588da7f9498417c.png "None")

注册完成后，按照后台要求填写插件名称、介绍、分类、截图等信息，然后提交审核即可。

商店页面里的产品描述，我也是直接让 DeepSeek 帮忙生成，再根据实际情况微调。

有一个细节需要注意：商店展示图片要求尺寸为 **1280×800**。我先对插件页面进行截图，再通过设计工具调整到规定尺寸。

成功上架后，还可以在后台查看一些数据，包括：

- 插件安装数量

- 卸载情况

- 用户数量

- 版本和审核状态

这次插件没有申请任何额外权限，也没有调用网络接口，因此审核过程比较顺利，提交后的第二天就通过了。
