# 做公众号爆文的，还不赶紧试试？用扣子 AI 工作流，将文章自动生成+自动配图+批量发布多个公众号，完全自动化？

公众号爆文这个赛道，聪明人已经开始“全托管”了：写文章、配图、发布，一条龙交给工具处理。最近有个实操性很强的升级方案出来了，和以前那些半自动套路完全不一样，今天我把它核心逻辑给你捋一捋。

先交代下背景。之前有人分享过一套AI+RPA做公众号爆文的自动化工具，收到不少好评，但也暴露出两个扎心的槽点：第一，纯粹不懂技术的小白，光是搭建和调试RPA就劝退一半；第二，RPA不是万能的，它的稳定性受环境牵制，比如豆包网站或其它软件一旦改版，操作元素可能就得同步调整，维护成本高。

那有没有又简单又稳的办法？分享者给出的答案是：把能交给插件和工作流的全交出去，RPA只用来兜底那些没人替代得了的环节。他把这套思路落地到了扣子（Coze）上，专门给公众号场景开发了一条新流水线，实测已经做到：内容自动产出、图片自动搭配、多公众号批量分发，一步到位。

具体原理其实不算复杂：

他用飞书表格当总控台和数据库；扣子里的AI生成完文章，自动归档到飞书文档——特意先存下来，就是为了后面批量派发；然后工作流再读取文档中的文章，顺手调用微信官方API把内容推送到各个公众号后台。复杂的地方他也没硬堆代码，而是打包进了插件里，这样整体更好维护。

更妙的是，这条工作流的三段设计都留了“替换口”：

想换选题和写法？文章生成模块可以单独抽走，换成你自己领域的工作流；

嫌图片不对味？把图像生成流拆掉重搭一个也毫无压力；

最值得点赞的是发布模块，它完全独立、不绑RPA，既能挂在主流程末尾自动跑，也能单独手动触发。只要平台有API，全程都能纯工作流搞定；万一碰到没API的，再让RPA顶上去就行。

这样的设计，对新手友好，对老手灵活。完整的流程拆解、配置方式都在飞书文档里，想抄作业的直接过去看吧。毕竟这年头，能自动化的时间，还是拿来追热点更香。
