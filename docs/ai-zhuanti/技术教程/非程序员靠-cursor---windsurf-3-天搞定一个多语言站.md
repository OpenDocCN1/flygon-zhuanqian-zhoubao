# 非程序员靠 cursor + windsurf，3 天搞定一个多语言站

上周飞哥群里抛出了一个赛道词 fiech codes，让大家去抢做站点。结果关键词一放出来，10 分钟不到能用的域名基本就被秒没了。

抢不到首选，只能继续往下挖。顺着思路延伸，我锁定了 dti codes 这个词。

先用 SimilarWeb 粗略判断了一下赛道情况，关键词竞争度不算高，但搜索量还挺健康。接着在 Google 上扫了一圈现有结果，发现大部分都是大平台的内页在占位，独立站的空档很明显。判断可以做，立刻就拿下了 dticodes.vip 这个域名。

方向定下来后，我就想着做一个类似 godday coupon codes 那种优惠码站的体验：码列表清晰、能一键复制、视觉贴合主题，还要有点动效加持。总结下来就三件事：多语言切换、优惠码一键复制、主题化的精美页面。

落地就靠 AI 编程了。第一步先找一个我觉得还不错的现成模版，把截图丢给 cursor，让它先搭出一个骨架。然后我又找了 fiechcodes.org 作为样式参考，![](img/zhuanqian_7416341b74ff2885669ecbabf7582bf4.png)

直接把它的页面截图给 cursor，让它复刻一个接近的排版风格。接下来根据自己的需求提需求，让它反复调优，很快就出炉了一个能用的初始版本。

![](img/zhuanqian_6a0fce035e93d15a2038e7ad985254b6.png)

有任何想加的功能，或者页面哪里不顺眼，直接跟 cursor 说，或者直接甩截图过去，它就能改。像后面我加的 blog 板块和 feedback 留言功能，全是让 cursor 从零写。连多语言切换也是它一并实现的。

![](img/zhuanqian_29f8f9acdc3e09db193cb2a26def5045.png)

刚上手时 cursor 习惯把所有代码堆在一个文件里，这点不用纠结，先把功能跑通再说。等核心功能都齐了，再让它帮你把代码拆成组件化结构，只要说一声拆分就行。

拆分的过程中难免会冒出点 bug，把报错信息丢给它，它通常能自动修复。如果实在卡住了，把鼠标停在报错代码上，下面会出现 fix in composer 的提示点一下就能修。

![](img/zhuanqian_4ec8eac52792815cb185ed430119160b.png)

等代码量上来后，cursor 的改动会变得有点粗暴，有时一改整段逻辑就乱了。这时候该换工具了，windsurf 上场。

![](img/zhuanqian_959a953b381673ecebae9bf9c62ebc46.png)

windsurf 的工作方式更稳一点，它会先读懂文件上下文再逐步修改，不像 cursor 有时先改了再说。后续的功能迭代和 bug 清理，我基本都交给 windsurf 来收尾。整理完后直接推到 github，再一键部署到 vercel。

域名绑定 vercel 也就几分钟搞定。部署途中肯定会踩坑，报错日志复制给 windsurf，它会一点点带你排雷，最后顺利上线。

![](img/zhuanqian_d50985faf7fb306c6645aea60238c6cb.png)

听起来很顺，但实操里肯定还是会遇到各种小插曲。我就不展开讲那些基础操作了，像 github 怎么用、vercel 怎么部署、cursor 和 windsurf 怎么开，这些网上教程一搜一大把。想真正做出东西，还是得自己多动手练。

最核心的感悟就一条：AI 编程的瓶颈不在 AI，而在你提问。能不能把问题描述清楚、把需求讲明白，这才是决定成败的关键。
