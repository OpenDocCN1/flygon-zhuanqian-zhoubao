# 小团队如何把公司做成 AI 原生？我的 9 条实操心得
260518 副业 SC 精华
![](img/zhuanqian_b8c2604e5f4c220c6e77c133dd143df3_0_0.png)
前两年我们基本把市面上能摸到的智能工具都跑了一遍，用来拼凑流程、打磨效率。
今年的感知变了。模型的任务承接能力明显上移，代码类工作也开始下放给非专业人员。这个拐点让我更看重组织本身的改造价值，而不是工具的堆叠。
下面是关于做 AI 原生型团队的一些现场感和实践记录。
## 一、工具清单越短越好上手
现阶段我们内部的 AI 栈就是四件：飞书、Codex、Workbuddy、OpenRouter。
**知识沉淀靠飞书。** 关键是全员启用飞书 CLI，让模型能直接读取文档和表格里的上下文。
**编程与代理执行选 Codex。** 人均先买 100 美元档，用完再升到 200 美元，算下来很够用。
**中文写作用 Workbuddy。** DeepSeek 和 Kimi 在中文场景很稳，Workbuddy 的模型可切换性比较强。
**批量任务才上 OpenRouter。** 能按需调度不同模型做批量生产与复核，例如用 GPTImage-2 产图，再用 Gemini 做质检。
工具越少，手感越熟。一直在自问还能不能砍掉下一步骤。
以前开会依赖飞书，会后还要另开豆包做记录。后来飞书自带自动纪要，冗余动作就消失了。
![](img/zhuanqian_b8c2604e5f4c220c6e77c133dd143df3_1_0.png)
## 二、流程要推倒重来，不能只做补丁
内部我们把可复用的工作方式叫 Skill，底座其实是一份会生长的 SOP。
AI 之前 SOP 就存在了，但普遍问题是写了没人用、用了没人更。于是我们定了一个双要件：持续有人维护，且持续有人照着走，缺一个就不算数。
流程改造最大的坑是局部塞 AI。不是在原链路里加一个节点就算转型，而是要整体拆解再重构。
只把某一步换成智能再打包成 Skill，用不久就会废。使用者觉得麻烦，不如手动点两下；或者模型出错要返工，反而更慢。
解法是让这条链路离开智能体就无法完成。
举个例子。负责人提出周排班想交给助理。我给出的设计是：
- 先把每个人的偏好、限制、过往排班经验整理成一份资料。
- 助理把资料丢进 Workbuddy 生成排班表。
- 最后导出 HTML 截图发群。
核心是强制走这条 Skill，禁止直接复制旧表改一改。只有当智能体成为刚需，大家才愿意推行和迭代。
### 三、为什么我仍在用 Codex
Codex 人均每月大概 100-200 美元。
![](img/zhuanqian_b8c2604e5f4c220c6e77c133dd143df3_3_0.png)
**Codex 的核心是把工作流交给自主代理去跑**
换个算账方式：做一个 Skill，Codex 可能几分钟就交付，代理能自己跑 1-2 小时，你只负责指令与验收。用低配模型，你得陪它反复沟通半小时。
几分钟与半小时的差值本身就是成本，时间成本往往最隐蔽。
还有个更深的隐性损耗：新人用弱模型体验很差，会觉得 AI 不靠谱，进而产生抵触，影响整队转型的氛围。氛围的拖慢比付费更难修复。
因此飞书的团队账号我们也统一付费了，当初纠结很久才定下来。
## 四、先搞明白“方法的元方法”
要先有方法论的自省。比如让 AI 做一张电商主图，先得回答：好主图的标准是什么？从哪来？
AI 能列很多条，但来源可靠吗？我们用 AI 分析 Shopee 的投放案例，AI 会给出建议，可平台规则在变。引用的是官方资料还是博主经验？博主内容有新旧、有立场差异，有的是真干货有的是模型拼凑。
所以在优化广告前必须先厘清：
- 标准本身是什么？
- 借用他人标准时，是否可信且适配当前阶段？
- 产品是新品期还是存量期？
- 目标是冲销售额还是提 ROI？目标不同策略完全不同。
这就是方法的元方法。思路不清，越快越偏。
## 五、做 Skill 的自检顺序
一个 Skill 的常规打磨路径是：
- 是否已有现成 Skill 可直接用？
- 若没有，能否把开源组件封装成 Skill？
- 如果现有工具只覆盖一半，能否在此基础上改造？
- 以上都不可行，先沉淀方法论再动手开发。
这与上一条相连：找方法论时要先判断时效与适配性，很多看似经典的方法可能已过时，需要主观甄别。
## 六、AI 原生组织的五层结构
![](img/zhuanqian_b8c2604e5f4c220c6e77c133dd143df3_6_0.png)
做 AI 原生不是给每个人发个会员，而是把数据、工具、流程、SOP、管理方式一起改造成 AI 可介入的体系。
- **数据层。** 把核心资产沉到云端，让模型能读懂上下文。
- **工具层。** 前台入口做减法，后台 API / MCP 连接做加法。
- **流程层。** 高频重复的活改成以 AI 为主导的工作流。
- **Skill / SOP 层。** 每个流程沉淀为 Skill，明确负责人、输入输出、验收标准、更新机制，并必须加入质检环节。
- **管理层。** 默认先让系统扩容，再考虑扩人。
真正的 AI 原生是流程脱离 AI 后会明显变慢、变贵、不可复制，而非某个人会用工具。
## 七、习惯的养成比选型更关键
语音输入就是一个小切口，但很有效。我们鼓励全员使用，手机可用豆包输入法，电脑可用豆包、Typeless、闪电说等。 ![](img/zhuanqian_b8c2604e5f4c220c6e77c133dd143df3_7_0.png)
再举个例子。以前每天手工汇总社媒与订单数据，现在会先问：能不能走 API 拉？没 API 能不能用 AI 的浏览器能力直接采集？或者上 RPA？即便是发布这类小动作，也要思考能否每周自动汇总自动推送，而不是人工操作。
另一个原则是鼓励用新工具替代旧工具。比如我现在要求团队不再用 Canva、稿定设计这类传统编辑器，必须走 API 绘图或 Lovart 这类可沉淀提示词的工具。
用传统工具容易陷入细节微调，走 API 绘图就必须先把提示词沉淀好。初期效率可能下降，但磨合期正是培养“先问 AI 再动手”的肌肉记忆。AI 会越来越强，去试、去问、去调的过程，产出的是长期复利的使用习惯。
## 八、流程做到 80-90 分即可
我曾尝试把内容生产全链路自动化：选题、选题拆解、撰写、个性化改写、排版优化、发布、反馈收集。做到排版优化时发现，句式问题的边界根本穷举不了。
于是有两点认知：
第一，穷举无意义。AI 在持续进化，今天写的限制明天可能成为负担。给全局写大量规则不利于灵活，在单一工作流里限定是可以的。
第二，内容与代码不同，无法做到绝对精密。追求 100% 自动化会碰壁。AI做到 80-90 分已是性价比拐点，再往上投入产出会急剧下降。
## 九、AI 是乘数，判断与精力是基数
最后两点。
其一，有了 AI 同时开十个窗口、跑十个项目很容易，像拥有十倍人力。但方向错了，只是更快消耗资源。市场检验很残酷，不好的东西执行越快被淘汰越快。
其二，要保护精力。项目越多，注意力越分散，判断力下降。市场不缺 50 分 60 分的批量品，缺的是 80 分 90 分的稀缺品。只有把精力押在最值得投入的方向，用 AI 放大执行力，才能用更少成本产出真正有分量的结果。
