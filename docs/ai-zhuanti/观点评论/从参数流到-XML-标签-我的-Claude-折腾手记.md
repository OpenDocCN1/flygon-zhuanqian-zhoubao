# 从参数流到 XML 标签：我的 Claude 折腾手记
我是龙哥。产品经理，高龄待业，正以零基础身位闯进提示词工程这片新大陆。
上次聊完参数流之后，我又扎进去折腾了两天，自己的知识库里多了一块新内容：结构化提示词。
不过讲新东西之前，先把上一期留的坑填掉。那篇写了好几种参数写法，也说了底层逻辑，但有一件事当初忘了提——这些参数在 Claude 里到底以什么顺序执行？难怪有朋友看到同一个参数出现好几次，还以为我写错了。
实测结论不复杂：Claude 解析参数时，严格按从上到下、从左到右的顺序一路执行。
今天要分享的，是我沉淀下来的第一个底层心法——结构化提示词，更准确地讲，是 Claude 官方提示词工程师安利过的 XML 标签。
补一下背景。我最近给一个公众号爆文项目当志愿者，陆陆续续拉了 34 位圈友进群。想想手里能用什么帮到他们？正好在玩提示词，那就做一套直接能用的 Prompt 送出去。
送什么方向好呢？做“生成文章”那种提示词，赚钱圈里已经堆成山了，我不去丢人。大家这次航海的最小目标都是“上岸”，于是我决定：做一个辅助每日打卡思考的小工具。
这套提示词里，XML 标签会完整露脸，我的推演过程也会全部摊开。请务必跟住我。
## 一、XML 到底是什么
XML 是一种和 HTML 长得挺像的标记语言，设计目的是传输数据。看起来不好理解？那就只看加亮的几个字。
<xml>标签用于标记 XML 文件的开头始和结尾。这些标签中的内容也称为 XML 文档。这是任何软件处理 XML 代码所需的第一个标签。</xml>
XML 负责给技术文档定义结构，拿到这份结构的程序，就能灵活地把它渲染出来。
平时写 Prompt，我们总习惯用“---”“===”“###”“((()))”“<<<>>>”之类的符号来切分层次。但这套符号经常是换一个工具就失灵了。
我亲手测过：XML 标签在 Claude 上非常稳，放到别的 AI 上也有不错表现，值得长期用。
### 最低门槛的用法
比如你想说一位作家：
张爱玲：本名张煐，笔名梁京，籍贯河北唐山丰润，生在上海，中国现代女作家。
### 往上走一步
比如你要告诉我：你有两个朋友，一位叫李雷，一位叫韩梅梅。
<name>Lilei</name>
<name>Hanmeimei</name>
### 再往上走一步
假设想表现书店里的数据，可以构造 <book>、<title>、<author> 这类标签。
其中一本书的 XML 文档如下：
<title>Learning Amazon Web Services</title>
<author>Mark Wilkins</author>
一句话概括：用标签把内容包起来，一层套一层，活像俄罗斯套娃。但别套得太深，一般两层就顶天了。层数多了，不但自己容易写乱，解析效果也可能变差，反而亏时间。
## 二、实战：给航海打卡配一个复盘助手
前面立了目标，要给船员做个打卡小工具。接下来是完整思考过程，希望能给你启发。
### 第一步：拆解问题
航海打卡页面一般都摆着哪些栏目？我看到的是：航线图、今日行动、心得感悟、好事分享、下一步计划。
因为这是临时起意的小玩意，痛点调研就先拿我前几期航海踩过的坑来顶一顶。
每天打卡时最常遇到的困惑：
- 只干了一件很平常的事，比如注册账号、买粉；
- 只做了每天都重复的事，比如更新文章；
- 偶尔发现一个其实没多大用的问题。
我想带船员把“思考”这件事做起来，用每日复盘的节奏来沉淀。复盘本身绕不开几个问题：
- 我给自己定的目标是什么？
- 今天实际完成了哪些事？
- 今天哪些做得好，哪些做得不好？距离目标还差多远？
- 如果要达成目标，下一步该怎么走？
走到这里，需求已经很明确了：我需要一套指令，帮船员完成每日打卡复盘，并且由一个“有温度”的角色，把结论讲给用户听。
再往下抽象一步，本质上我是在写：一份带角色设定的对话式复盘指令。
### 第二步：第一版提示词
既然是复盘工具，里面该有什么？我斟酌了片刻，列了五块：目标、行动、思考模型、输出结构、工作流。
“工作流”这个念头，来自我前两天刷到星球里几位大佬的帖子。我本来就是 B 端产品出身，天天和流程引擎打交道，看到这个词就觉得亲切，顺手就加了进去。结果后来发现是我自作多情了，过会儿再解释。

### 第三步：逻辑拆解
先听一个《小明的快乐童年》。
小明 6 岁。他妈妈是第一次当妈的 90 后，每天放学回来，妈妈都要给他做饭。可这位妈妈比较懒，经常不想动手。这天放学，她直接把小明支出去买菜了。
“明明，今天妈妈给你做蒜香香菇。你去买 30 个香菇、一根大葱、一瓶蚝油、一袋淀粉、一瓶老抽。还有，咱们家的蒜也不多了，你在门口小卖部先买 2 头送回来给我做蒜末，然后再去小区对面买 2 斤回来。”
小明揣着购物单，去小卖部买了一兜东西，回来一路上还反复检查：这些够不够做蒜香香菇？有没有漏买的？还差多少？——这就是 Claude 拿到输入后的解析过程。
结果到家，妈妈发现他什么都买回来了，唯独没有香菇。——这就是解析结果。
妈妈的火“噌”地一下就起来了。转念一想，孩子是亲生的，不能揍。她整理了一下情绪，决定按抖音上学的教育方式，教小明怎样像大人一样做事：
先夸——小明真棒，买了这么多东西，能帮妈妈干活了；
再批——板起脸来，认真说他漏了香菇；
后给计划——再去旁边菜店买 30 个香菇，我们只差这一个就能开饭，你回来妈妈就下锅。
好，故事先到这儿。记住它，下面看每一段参数的设计意图。
#### <goal></goal>
复盘必须有个靶子。我在这里放了两层目标：周目标照着航海计划写，日目标则从昨天的动作推导。这两块需要船员自己填。
#### /action_today 今日行动
这就是打卡页里“今天做了什么”那一栏的浓缩版，同样由船员自己写。
#### <thinking></thinking>
目标和行动之间，我插入了一个思考过程：先给 Claude 一个“资深新媒体运营”的身份，再扔给它三种分析工具，让它把用户的行动盘一盘、挑挑毛病。
说句实话，这套配法不是最优解。我理想中的形态，是让 Claude 通过多轮问答逐步逼近结论。可惜我忘了是在哪儿看过类似的方法，翻遍记录也没找到，如果有人知道，欢迎来告诉我。
#### 输出人格
这一段我在给输出“化妆”：
- 表扬时是知心姐姐，语气鼓励、积极、开心，只指出做得好的地方，输出 5 个正向关键词；
- 批评时切换成一个“极端冒犯、生硬、粗鲁”的成长规划师，用轻蔑又不耐烦的口吻点出问题，并且明确要回避“评估粉丝数量”，再输出 5 个负向关键词；
- 规划时恢复成“专业的个人成长规划师”，给出明日计划，附上 5 个关键词。
#### workflow
把它理解成一张步骤表，目的很简单：锁住 Claude 的执行顺序。
#### /execute
最后用 /execute 把整张步骤表跑起来。为了避免歧义，几个词我故意用了中英混写。

### 第四步：开始做减法
第一版最大的问题，是臃肿。我数了数，光提示词就写了 681 个字。这和参数流强调的“精准、简洁”背道而驰。拿这个体量去写公众号爆文，都够塞两条广告了。
更要命的是，参数堆得越多，Claude 的解析力就越容易被稀释。再回想《小明的快乐童年》——小明毕竟只是一个 6 岁的孩子，你让他记住那么多要求，他当然记不住。
提示词里每一个多余的字，都是损耗。
这已经偏离我研究这套方法的初衷了。我必须删。
于是我把提示词翻来覆去看了好几遍，越看越觉得哪儿都重要，哪行都舍不得动。后来回到最初的诉求重新想，才理出四条减法方案：
- 周目标和日目标，如果没必要拆开，就合并成一个北极星指标，只负责指方向；
- 行动和思考模型是核心，先保留；
- 输出结构要求得太细了，简单到能生成我要的东西就够了；
- 工作流可以整体划掉。原因回到开头：Claude 本来就自上而下按顺序执行参数，我这个场景又是纯线性流程，再写 workflow 等于重复劳动，删了完全不影响。
最终优化后的版本如下。参数后面的中文只是注释，实操时可以直接删掉。整体思路只有两条：把目标、行动、模型统一归入输入区；把我想要的结果归入输出区。
