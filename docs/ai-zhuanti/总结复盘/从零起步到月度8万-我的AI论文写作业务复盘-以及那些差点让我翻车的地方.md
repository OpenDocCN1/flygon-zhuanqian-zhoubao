# 一、从寻找方向，到决定重仓AI写作
2023年，我跟着赚钱航海尝试用ChatGPT批量制作视频内容。那次经历让我意识到：AI带来的生产方式变化，才刚刚开始。
但当时的我并不清楚，AI究竟应该通过什么产品赚钱。既然看不清具体形态，我就先确定一个原则：后续选择项目时，优先围绕AI寻找机会。
2024年7月，我用“AI”作为检索入口，把赚钱里相关主题的文章、案例和结果帖逐一看过。让我注意到的是，AI写作并非只有少数人自说自话，已经有几位操盘者拿到了实际成绩，跟随学习的人也在持续推进，而不是体验几天便放弃。
之后，我重点观察了4位业内实践者的公开动态。他们有几个共同特点：
- 持续更新方法，而非停留在早期打法；
- 长期投入同一条业务线；
- 已经出现了可参考的学员成果。
经过约30天的资料整理，我从三个角度完成判断：
**第一，方向吻合。**
它与人工智能应用有关，符合我对未来趋势的判断。
**第二，具备复制条件。**
案例数量足够，且经过训练后，普通参与者也有机会完成交付，说明流程并非只能依靠天赋。
**第三，投入结构相对清晰。**
前期主要消耗时间和人工，现金成本相对可控；只要把流程跑通，后续放大的空间较大。
于是，我把这项业务定为公司重点项目，开始集中资源推进。
# 二、先把交付能力做起来
## 2.1 用低门槛订单验证基本功
通过平台内的经验分享，我很早就意识到：获客只是表面，真正决定能不能长期做下去的，是交付。
所以我没有先急着招人，而是亲自去淘宝承接订单，从最基础的需求开始训练。那时我对AI辅助写论文的具体方法还不熟，过去更多是在折腾智能体，于是继续寻找靠谱的学习材料，后来接触到苏苏老师。
她的交付资料非常实用，我消化之后，前后在淘宝完成了约10份订单，并且刻意让难度逐步上升。随着项目复杂度增加，我也逐渐掌握了长篇论文、模型分析等任务的处理方式。
淘宝订单的特点很明显：报价低、回款慢、沟通成本高。但对新人来说，它仍然是一个不错的实战场。我的做法是边做边记：
- 哪些需求最容易理解偏差；
- 哪些环节最容易返工；
- 如何拆分任务和安排进度；
- 什么样的成果才算真正达到客户要求。
期间碰到过一份特别棘手的任务，我迟迟找不到解决方案。后来我先向客户收集完整材料，再主动终止订单。订单结束后，我没有把问题放下，而是继续通过视频平台学习，最终把这类任务的处理方法补上。
前后大约花了两个月，我才敢说自己具备独立完成长篇高要求论文的能力。我的原则一直很简单：先把质量守住，再考虑提升数量。

这里有一个很重要的提醒：
团队负责人不能只懂获客，不懂交付。
如果连产品本身都无法判断，那么前端承诺、客户沟通、售后处理和人员培训都会失去依据。
换句话说，哪怕你卖的是一个很小的服务，负责人也必须具备产品视角。
## 2.2 初期招人：渠道便宜，风险却很贵

表面看，这是效率很高的方式；但回头看，问题也正是从这里埋下的。

## 2.3 更稳妥的人员渠道
后来我把筛选要求重新整理成三条：
1. 能独立完成任务，且实际水平经得起测试；

3. 候选池足够宽，不能把业务压在少数几个人身上。
综合比较后，我把招聘重心转向BOSS直聘。这个渠道更便于做身份确认、能力测试和长期沟通，也更容易持续补充候选人。

# 三、获客端的两轮试验：为什么培训没有想象中容易
## 3.1 首次招募：声势不小，结果有限
交付体系基本稳定后，我开始尝试把获客方法交给更多人执行。
一次浏览平台案例时，我想到宝妈群体可能具备时间和社交传播优势，于是联系了长期合作的圈友榴莲哥，请他协助组织首批参与者。第一期项目训练营来了70多位学员。
我通过线上会议，把账号运营、内容发布和转化步骤完整讲了一遍，按照设计，每天投入约4小时即可。
不过，当时正处于需求相对平淡的阶段，账号没有出现预期中的集中爆发，订单以小额需求为主。整体成交额不算差，但参与者实际获得的收益偏低：
- 执行较好的，每月大约一两千元；
- 普通参与者，可能只有几十元；
- 也有人长时间没有收入。
一段时间后，多数人逐渐停止更新。少数坚持的人，又受到本职工作和时间安排影响，最终也没能保持原来的节奏。

## 3.2 再测一轮：问题不在教学，而在模式
自营账号的表现后来有所改善，但距离旺季仍有差距。于是我重新思考：这种依赖自营账号、再复制给学员的模式，是否天然不适合培训？
第二期项目中，我与圈友Alex合作，由他协助招募约20位参与者。我仍然采用逐人指导的方式，把获客动作拆开演示。
结果并没有明显改变：大家能赚到一些小钱，但因为前期维护动作繁杂、持续投入要求高，执行速度很快降了下来，整体流量仍然没有形成明显突破。
这两次测试让我看清了一个矛盾：
- 如果给执行者的收益比例偏低，他们缺少持续投入的动力；
- 如果提高分成，项目又会变成高交付业务；
- 一旦发生退款，已经发出去的收益通常无法追回。
因此，问题并非单纯出在培训内容，而是合作结构本身不够适合规模化。

## 3.3 从培训转向实体团队
和搭档沟通后，我们决定不再依赖松散合作，而是建立固定团队。当时摆在面前的有两条路：
**方案一：** 延续校园和内容创业路线，在高校中筛选成员，组建学生团队。
**方案二：** 重新租赁办公地点，招聘固定人员，按照全职模式运转。
结合前两轮测试，我判断，若要稳定放大，还是需要专门投入时间的工作人员。
学生群体里当然有非常优秀的人，但筛选往往需要较大样本，而且大学课程、考试和其他安排会明显影响稳定性。此前几位能做出高播放内容的学弟学妹，甚至需要牺牲上课时间来协助项目。
我自己读大学时也经常逃课学剪辑，如今想想，确实把这份“习惯”传给了他们。
这是我第一次真正筹建实体团队。为了少走弯路，我重新整理了几位行业实践者的公开内容，最后选择付费加入饭饭的写作分工作室。
最初只是想提前避开常见问题，没想到真正遇到复杂局面时，饭饭哥多次给出了关键判断。
### 3.3.1 场地选择：别把时间浪费在无关信息上
筹备团队之初，我把目标锁定在众创空间，几乎筛查了广州各处相关场地。由于缺乏租赁经验，我还逐一查询场地背后的企业、注册情况以及负责人名下主体。
如今看来，这些工作大多没有直接帮助，更多是第一次创业时的过度谨慎。
真正决定场地是否合适的，通常只有以下几项：
1. **通勤成本**：早期负责人很可能每天工作到深夜，交通距离会直接影响精力；
2. **综合租金**：除了租金和押付方式，还要提前确认管理、停车、能源及公共区域分摊费用；
3. **周边交通**：交通越方便，招聘时可覆盖的人群范围越大。
还有一个实用建议：租约条款看不明白时，可以在闲鱼上找专业律师协助审阅。
我在大学做项目期间，就长期联系一位线上律师。每次遇到合同或合作问题，按次付费咨询，通常比自己凭感觉签字稳妥得多。
### 3.3.2 交付事故：把业务押在单个作者身上
前面提到的人员筛选漏洞，最终造成了严重后果。
早期招聘时，我们没有完整核验学历、身份及履历，只凭几次成果判断能力，随后就把大量订单交给了某位来自豆瓣的新闻学硕士。她先后拿到两笔阶段款，后来直接失联，手上还有40多份任务。
更严重的是，事后检查发现，她此前提交的内容存在大量改写痕迹，而我当时却把她当成了非常专业的作者。由于那段时间订单集中、团队又在同步筹备办公地点，人手紧张，风险没有被及时识别。
这是我至今最深的一次教训：
**任何关键环节，都不能只依靠一名核心成员。**
一旦这个人离开，所有未完成任务、客户关系和现金流压力，都会同时暴露。

### 3.3.3 事故处理：先承担责任，再重建流程
这类问题在早期很难被察觉，等到客户集中反馈时，影响已经扩大。
我们的处理方式是逐个联系客户，解释情况、表达歉意，并根据实际进度进行退款或重新安排。多数客户在看到我们愿意正面解决后，仍然选择继续合作。

### 3.3.4 最后的连锁结果：平台账号被处理
即便已经完成退款，仍有几位客户情绪非常激烈，转而向闲鱼投诉账号。
由于我们在投诉发生前已完成退款，平台最初判定我们没有责任。但第二天，账号仍因涉及站外导流，被直接永久限制。
那一刻才真正意识到：
平台规则、获客方式和售后风险，必须从项目设计之初就一起考虑，不能等出事后再补救。

# 实证研究
## 4.1 实证研究是什么
实证研究（Empirical Analysis）可以理解为：用真实数据做依据，借助科学方法进行分析，从而验证假设、得出结论的研究范式。它强调经验数据，常用统计、计量经济学、社会学等手段，对现实问题做观察和解释。
通常分五步走：
1. 锁定研究问题：明确研究对象、目标与假设；
2. 收集数据：问卷、实验、公开数据库都可以；
3. 建立理论框架：基于文献提出可供检验的假设；
4. 分析数据：用回归、ANOVA等统计工具处理；
5. 下结论：根据数据结果验证假设，解释研究价值。
实证研究在经济、社会、医学、心理等领域都很常见。它和纯理论推导不同，更依赖真实世界的数据，目的是检验理论或找规律。
在闲鱼上，单独把实证研究做成一个AI代写类目，也能够变现。一单报价通常在1000-2000元之间。

### 4.3.1 基础统计描述
基础统计描述是用来概括数据全貌的，方便快速了解样本情况。主要包括：集中趋势（均值、中位数、众数）、离散程度（标准差、方差、极差）、分布形态（偏度、峰度），以及直方图、箱线图等可视化图表。它能帮我们迅速看清数据结构，给后续深入分析打基础，常用于市场研究、社会科学、医学和教育类课题。
![](img/zhuanqian_fbaa3c1b5190c181d905837265b5ce02.png)
操作上，找到“频数”功能，把人群标签类选项拖过去。系数保持默认，导师有特殊要求再调整。
![](img/zhuanqian_540291f7e76189d9aa74590e651758ff.png)
输出结果复制到文档里存好。
### 4.3.2 可靠性检验：信度
可靠性检验，也就是常说的信度分析，用来判断测量工具是否稳定。常见指标包括：内部一致性（如克隆巴赫系数），衡量题项之间能否相互印证；重测信度，看不同时间测量结果是否一致；分半信度，把量表切成两半来比较；评分者信度，评估不同打分者之间的吻合度。信度高，代表工具可靠，误差更小，结论更稳。
![](img/zhuanqian_2ed84d09ded773db2c50d593b26211ba.png)
操作上，找到“信度”功能，把对应变量拖进去。系数保持默认，导师有要求再切换。
![](img/zhuanqian_43b63582117f32961d3ccd987300fe5b.png)
把输出结果复制下来。
### 4.3.3 有效性检验：效度
有效性检验，也就是效度分析，用来确认我们测的东西是不是真的想测的东西。内容效度看题项覆盖面够不够；标准效度是和外部标准对比，判断预测能力；构念效度则检验工具能否准确反映理论概念。效度越高，结论越有说服力。
![](img/zhuanqian_5793aada8d3e433b34d5a7328409ada7.png)
切到“效度”模块，把对应变量加进去。参数保持默认，导师有要求再调整。
![](img/zhuanqian_c375398f76d3e9af5804d20552f2f95a.png)
同样把结果复制到报告里。
### 4.3.4 组间差异检验
组间差异检验用于比较不同组别的数据是否存在明显区别。常用方法有两种：t检验适用于两组比较，ANOVA适用于三组及以上比较。它能帮我们看出性别、身份、类别等背景变量是否带来显著差异，常见于群体对比和实验场景。
一句话理解：看不同人群在不同条件上的表现有没有明显变化。
![](img/zhuanqian_060115d6e404dabe057cb3dc9a7ac7e6.png)
![](img/zhuanqian_63d6d3e9d45c383e16f0b8f5e08e8166.png)
![](img/zhuanqian_4f115d5fd40c54baff27f35203100042.png)
在系统里选择方差分析，按实际需求设置分组和分析方式。
### 4.3.5 关联性检验
关联性检验，也叫相关性分析，用来判断两个或多个变量之间是否存在关系，以及关系的方向和强度。
常见算法有三个：Pearson系数适合两个连续变量的线性关系，取值范围为-1到+1；Spearman秩相关适合非线性或非正态的单调关系；Kendall系数适合小样本或并列较多的排名数据。需要强调的是，相关不能直接推出因果。
![](img/zhuanqian_9e0d9580a1456f9844582b96d02765af.png)
打开相关分析模块，放入变量，参数默认即可。
### 4.3.6 中间机制检验
中间机制检验，通常叫中介效应分析，主要用来解释预测变量通过什么路径影响结果变量。分析路径包括：路径a是预测变量对中间变量的作用；路径b是中间变量对结果变量的作用；路径ab代表间接效应；路径c'代表直接效应。
常用处理方式有 Baron-Kenny 流程和 Bootstrap 抽样法。中介效应可能是完全的，也可能是部分的，具体要看数据表现。
![](img/zhuanqian_82e6b1a3251cf79bd24612ee964137a0.png)
将变量放入指定区域，系数默认即可。
### 4.3.7 回归建模
回归建模用来解释预测变量和结果变量之间的数学关系。关键看这几项：回归系数β，反映影响方向和力度；p值，判断系数是否显著，通常小于0.05才成立；R²，衡量模型解释力；调整后R²，排除自变量数量干扰后的更准确指标；F值与F检验，评价整体模型是否显著；标准误，反映系数估计的精度。
![](img/zhuanqian_a34a2c795f025d3441988589f3ebe480.png)
按论文实际需要的核心变量放入回归模型，参数默认，导师有要求再改动。

## 4.5 个人对AI写稿的感想
### 4.5.1 AI带来的优势
AI本质上只是提高效率，不能替代你懂内容。拿写稿来说，无论论文、演讲稿还是小说，你脑子里得先有个雏形。让AI先搭框架，再一章一章生成；生成环节跑偏，就用提示词快速润色；成稿后用自动排版软件统一格式，一篇稿子很快就出来了。
【以前我打演讲比赛，一篇稿子要磨一天，这还是在长期带校队打比赛的前提下；现在用AI做获奖演讲稿+PPT，30分钟就够】
AI也能当老师。
1. 我曾接过一篇完全不懂的计算机方向稿子，当时人都是懵的。但作为老板必须兜底，于是不退单，直接拿AI自学代码。
2. 一开始连Python都没碰过，靠着AI一步步装好环境，再慢慢熟悉操作界面，接着让AI生成爬虫代码；报错就让AI帮忙定位并修改。
3. 最后竟然搞出一份完全满足客户要求的代码，加起来只花5小时。
![](img/zhuanqian_b86f38b9256156f109dcf81d97b465ea.png)
AI还能整合信息。普通人挖到项目时，往往判断不了到底靠不靠谱，因为缺少证据。我经常针对项目的人群做数据分析，让AI汇总全球公开资料，然后自己算投产比，效果很猛。只要注意辨别信息真假就好。
### 4.5.2 AI目前的不足
AI的短板也很明确，具体有哪些坑，后面找机会再展开聊。
说实话，AI也不是完美无缺的。
它会自己脑补、自己加戏，把一些根本不存在的细节写得头头是道，那种“精致的胡编乱造”几乎成了它的招牌特长，很多人根本意识不到自己被带偏了。再加上时不时会冒出一些莫名其妙的小BUG，像是小插曲一样偶尔出现。
不过我觉得，这些缺点都只是暂时的、会逐步被修复的。AI真正的厉害之处，并不只是大家常说的省钱提效那么简单。
对我而言，最大的意义在于，普通人第一次真正拿到了可以调用的数据库级能力。我们可以拿它来查证自己的判断，用数据来支撑观点，也可以借它去挖出那些自己原本触及不到的信息差。换句话说，这才是AI给普通人带来的真正分红。
