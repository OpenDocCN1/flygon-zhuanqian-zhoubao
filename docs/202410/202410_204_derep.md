## 拆了 50 个 prompt，我找到了普通人也可以掌握的伪代码 prompt 技巧。这篇文章可能让你原地起飞

作者： 李拜日

日期：2024-09-25

这篇内容会给你一套普通人都能上手的操作思路，用来写提示词。

先划清人群：

*   有代码底子的人：你可能会觉得这套方法太基础、幼稚得像入门作业，这很正常。对你来说理解成本极低，看一眼就能通透。

*   零编程基础的人：门槛确实有，但非常低。花五分钟去查一下 Markdown 的基本用法，回来再看一遍，整个逻辑就会豁然开朗，特别顺。

最近折腾 AI 的朋友应该都刷到过两个现象级提示词，一个是国外的 superprompt，一个是李继刚老师的汉语新解。

这篇我们就拿汉语新解来拆。它的效果是：

![](img/5ee8ec6c07da1d0d597abf7a681e0715.png)![](img/abab59662bd26604f250a8852047bf29.png)![](img/fefc3f5ac5e26ce3e29e6674b42b6c4a.png)![](img/3d213f20eac62d765883aa74c4c27c58.png)  

这两个词条确实很离谱。我这段时间主攻短视频，本来不想分心，但男人就是这样，看到好玩的东西就忍不住想研究。

![](img/3c1eff996c661df3d15f41a6d321615a.png)  

绕了一圈下来发现，全是现成的大佬范本，我的流程永远是：

`复制`-->`粘贴`-->`感叹牛逼！`--->`照着别人的模板去出结果`。

想改都改不动，改一点点就跑偏。因为我看不懂里面的代码逻辑，不知道每个部分在干嘛，动一下味道全变了。

No！这样不行。

快乐凭什么只属于别人，我也要玩得转。

非要去系统学编程是不现实的，没那个时间和精力。那就换个打法，用现有的知识拼一套我能用的方法。

于是连续肝了几天，我摸出来一套不写代码的普通人也能写的提示词方案。

![](img/7ef1aa27c2f5a4b665c9eec65157d26f.png)  

核心做法是把 XML 的结构化能力和 Markdown 的易读性叠加使用，让模型好解析，人也好读。我也不确定算不算伪代码，先这么叫了：

*   **XML** ：负责结构化，方便机器去识别和自动化处理，可以很清晰地定义逻辑块、判断条件、循环等。

*   **Markdown** ：负责描述，让逻辑通顺、阅读友好。

目前这版提示词因为赶时间，还比较臃肿，后续会再精简。先看思路就行。

马上进入实操！
