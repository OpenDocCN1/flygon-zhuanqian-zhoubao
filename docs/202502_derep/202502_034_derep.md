# 把Cline用到快吐，我反而悟出了一些AI编程之外的东西

最近又开始手痒，总想着做几个AI小项目。于是我翻出AI编程工具，认认真真泡了两周。

当初会选Cline，倒不是因为它有多厉害，纯粹是我给GitHub Copilot按年付了费，却实在用不下去；四处找了一圈，好像只有Cline能接上Copilot的授权。没想到这个“凑合”的选择，反而让我撞见了一些有趣的体验。

如果只是写一个函数、搞一个单功能页面，市面上主流AI基本都能轻松搞定。但这次我想做的，是一个有一点架构、还想着以后能扩展的小项目。正是这种“略复杂”的需求，让我对AI编程有了完全不一样的看法。

用得多了以后，我首先注意到：让AI去审阅大代码、做规划时，它动不动就画Mermaid。Mermaid就像流程图界的Markdown，用极简语法把业务逻辑串得明明白白，AI理解起来也更快。更妙的是，这些图常常不用我动手——AI在Cline的Plan和Act模式里会自己画、自己检查、自己挑毛病，最后才写下代码，活像在搞一场自我评审。

第二个体会，是文档管理。代码一旦堆到某个量级，文档就躲不掉了。Cline社区有一套叫Memory Bank的打法：用一组Markdown文件当项目“记忆库”，让AI在长上下文里不迷失，也让文档始终跟着项目走，不会前后打架。这套文件包括projectbrief.md、productContext.md、activeContext.md、systemPatterns.md、techContext.md、process.md。

第三个体会，是“维护保养”。很多被叫作“屎山”的代码，本质上是长期缺保养的产物。最有名的例子之一就是GTA5的线上模式：加载慢到玩家集体吐槽，后来一位叫tostercx的玩家扒出原因，游戏要解析一个10MB的JSON文件，而解析器本身就写得很有问题；他优化之后，加载时间一下子缩短了69.4%。

到了AI编程里，“保养”需求来得更快、更猛。究其原因，大概有三条：第一，提需求的人很少把细节说全；第二，AI对代码之间的耦合性基本没概念；第三，AI更偏爱新需求，对老业务模块的稳定性不太上心。代码量和业务量一膨胀，维护压力立刻找上门。

这一轮折腾，也让我重新想起两个老观点：一个是十多年前耐克科比广告里的“Everything is a system”——万物皆系统；另一个是《编程之美》里邹欣写下的：算法+数据结构=程序，程序+软件工程=软件。

把这两个观点带回最近合伙的电商、投资类项目，再结合我在生财有术这些年的观察，我越来越觉得：系统有大有小，有像黑盒的，精华藏在细节里看不真切；也有像白盒的，比如航海项目，几乎全程透明。有复杂到令人头大的，也有简单直接的；有踩在新潮趋势上的新玩法，也有古老行业翻出来的老玩法，甚至有些老玩法被重新验证了一遍。但不管哪一种，都值得用系统化的方法去学习、重组、优化。

人本身也是一种系统。能力、态度、三观，甚至身体状态和精神状态，都会成为决定个人发展状态的开关。所以，认识自己、冷静地分析自己，才是解放自己的第一步。

最后想说“merge”这个词。在代码世界里，每一次合并，可能意味着增加功能、优化效率，也可能意味着放弃冗余。不过merge往往躲不开conflicts。新手处理conflicts，常常顾此失彼，创造出更多问题；成熟程序员则冷静高效，再大的现场也能收拾得仿佛什么都没发生。

放到“生财有术”里，这套逻辑同样成立：先认清自己，找到适合自己的那套“生财系统”——不限于精华、航海，也包括人生里的其他机会；然后大胆地merge它。遇到冲突，就冷静高效地去处理，实在不行，还能让AI来帮忙。不断吐故纳新、迭代自己，最终建立一套更强的个人生财系统。

如此，如此，亦如此。
