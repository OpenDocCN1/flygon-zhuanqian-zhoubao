当时诉求很直接：学会出海本领，在公司练成业务操盘能力，实现双向赋能。2023年6月起，我开始用OpenAI接口在非核心主链路上试水，拿到初步正向反馈。迭代多次后接入企业级OpenAI服务通道，经国内Azure代理商签约，也完成了多次工业化尝试，认知逐步沉淀。公司随后给了我首席AI架构师的头衔，后续推进也更有名分。

# 业务的AI重塑

我们是信息流产品，DAU约4000万，可类比为非洲及中亚的今日头条。内容来源分散，涵盖英语、阿拉伯语、法语、葡萄牙语、阿姆哈拉语、斯瓦希里语等，覆盖多国。

风险在于内容可能触及宗教、信仰、涉政红线，导致应用商店下架。

因此公司保留了约30人的小语种审核团队，对高消耗内容做判定。同时早期只运营中非、东非部分国家，每个国家还需本地化运营。初创公司很难自研审核模型，第三方模型又难以适配各国细节。

问题集中在两点：

1. 风险不可控
即便30人满负荷，也只能覆盖头部内容。日入库文章4万篇、小视频5万条，人均日审文章约300篇或视频1000条，30人只能覆盖一小部分。审核是主观判断，标准越细，人差也会显现。

相当于始终有风险内容在线，被持续消费。达摩克利斯之剑悬在业务头上，很难受。

2. 拓展受阻
想多做一个国家，审核量随之上升，还要配本地运营。跨国团队搭建的痛点大家都懂，尤其在非洲人才供给不足的区域，合适人选更稀缺。

# 内容审核的自动化改造：用模型替代30人多语审核

2023年下半年，我以首席AI架构师身份持续和审核运营聊分担工作量的可能性。12月正式启动。

### 阶段一：最小可验证原型

当时最强通用模型是GPT4，仅支持文本与图像。所以先从文本入口切入，把4万篇文章的部分工作分流出来。验证可行再扩展到图像。

文章本质是文字+图片。拆分策略如下：

1. 按国家标准，把标题、导语、正文与审核提示词一并输入模型，判定是否违规。
2. 若文字违规，直接下线。
3. 若文字合规，人工工作流改造为只看图，判色情、暴力等。
4. 图违规则人工下线。

改动后需要持续调优提示词，调优依赖数据闭环。因此保留原人工审核并行，双轨运行，仅用于效果评估，不执行真实下线。核心指标看准确率与召回率。

准确率：模型判为违规的内容中，真正违规的占比，即误伤。
召回率：所有真正违规内容中，被模型抓到的占比，即漏放。

以人工标注为基准评估模型表现。迭代后，纯文本场景下表现最好的是GPT3.5 1106。首版可用提示词如下：

### 阶段二：小范围试探，先通路后省钱

原型可用后，人工在文字侧的负担大幅下降，可腾挪到短视频侧。

2024年春节期间，外包团队需排班补岗，标准波动问题暴露。文字已模型化后，人员只需看图，问题明显缓解。收益开始显现。

年后启动图像审核调研。当时可选Claude3、Gemini1.5、GPT4V。实测GPT4V表现最好，但出现过模型返回“未发现可识别内容”的情况。

回溯发现是图片压缩过狠导致模糊。信息流下发多清晰度图，早期为省成本选了最狠压缩，导致偶发失效。

教训是：验证通路时可先不计成本优化，确保链路打通后再拆解优化、保证利润率。

换到中等与高质量图后问题消失，且准召率差异不大。

图像可用的前提下，流程升级为：

1. 文字模型审核，违规直接下线。
2. 文字合规后图像模型审核，违规下线。
3. 两项均合规则正常分发。

成本可控，继续双轨线上验证，流程同文字改造。

### 第三步：用发展的眼光沉淀业务标准，让业务自己会长

2024年5月GPT4o出来，算是真·质变。速度快、理解强，我们立刻把原来的审核工作流重做了。

之前文字和图片是分开喂给模型，分步判断，结果信息总有丢失。比如一张比基尼图单独看肯定要下架，但文字描述的是女性健康科普，在人工标准里属于合规的健康知识类。这种错杀就出在割裂上。

用上GPT4o后，直接把图文一起丢进去让模型整体理解。逻辑就变成了：
1. 图文打包送AI，一次判断，违规就下架。图片上限9张还在，靠文本图片分批绕过去
2. 图文都正常，就上架派发

同样双跑，算下来反而更便宜。因为之前提示词要重复喂给图片和文本，现在一次搞定。

#### 成本要卡在合适的节点

图片计费这块，OpenAI是按tile算的：
1. 低分辨率模式：85
2. 高分辨率模式按512px*512px一个tile算
3. 厂商会先缩放：长边超2048px就等比缩到2048，短边超768px就等比缩到768，长短边都在范围内就原图
最终token=170*tile+85

所以我们会根据文章配图尺寸，在保证效果前提下，主动缩到计费最经济的区间。

#### 用自己的数据盘活飞轮

模型迭代太快，今天做不到半年后可能就成了，今天扛不住的成本半年后也可能扛住了。拥抱AI是方向，但每个模型升级都要回答两个问题：效果怎么评，成本怎么算。

于是我们开始沉淀自己的业务评测集和评判标准。核心就在于，高消费文章才通过审核，还有80%的量卡在未质检，风险一直挂着。AI流程通了，只差扩量，算了一下五倍成本后依旧比人工便宜，最后直接全量铺开，合规做到极致，最大风险被堵住。

复盘时发现，公司本来就在做信息流分发，需要内容分类和标签。之前北京有6-7个人在做推荐系统，用开源框架魔改，分发效率低。为什么不把这套工作流直接复用，一套框架同时做审核、信息流分类、标签定义。

2025年6月我们再升级一次，用同一套工作流给文章打标签，再基于标签做分类和审核。迭代三个月做完新标签体系，AB实验效果比老体系更好。原本专门维护这块的团队，自然也就没有存在必要了。

### 第四步：模型升级打开的想象空间

那段时间一天成本大概800美元，审核团队的工作基本只剩视频。文章问题还没完全解决，我们就把审核员的工作拆了：

1. 看封面
2. 均匀截9张图，抽样看
3. 有举报的视频才快速拖拽看

1和2完全可以自动化。当时GPT4o能看图判断违规，流程照抄之前：先审封面，跑通再考虑审9张图。

2024年11月按老路子先搭评估标准数据集，线下调prompt、批量脚本测，准确率召回率达标后上线双跑。

12月高消费小视频的封面审核，AI完全顶替人工。准备要上9张图抽检时，数据告诉我们，封面被判违规的那部分，已经覆盖了98%的违规内容。剩下的2%收益和风险，换算成ROI和兜底保障，不值得再烧成本。

最后保留人工只处理举报视频，且量已经很小。AI审核封面是全量的，导致举报量直线下降。

## 信息流业务的AI化，让内容运营无边界

此前拓展新国家时最大的痛点是文化不懂。不知道当地用户爱什么，不知道什么社会事件会成为爆款。头部内容才能带来信息流消费，消费才有收入。

前两年公司只能局限在尼日利亚、肯尼亚这几个有本地运营的中非国家，因为只有本地人能盯着当天的事做运营动作。

经历了去年一年的AI探索和工程化沉淀后，今年3月我们开始改造信息流运营全流程。

### 第一步：把工作拆到骨头里，分清自动和思考

经历过审核改造后我们得出结论：所有工作都能抽象成SOP，关键是识别出哪些环节需要人决策思考，下一步动作是什么。拆得足够细，工作就变成执行动作+思考判断的组合，这就是Agent的雏形。

但对特定业务，模型不懂细节，最好的用法是：
1. 先制定计划，也就是把业务SOP拆出来
2. 固定的执行动作用代码完成
3. 执行结果交给AI判断
4. 按AI判断选择下一步固定动作，而非让它自由规划

基于这个思路我们设计新方案：

内容从高消费榜单和各国本地网站抓取入库后，运营要判断当天热点是否构成爆款，是否要建专题热榜。

如果认定是爆款，运营要写清大话题是什么，子话题是什么，创建话题名和节点名，再做push推送、热榜置顶等动作。

于是核心环节变成：识别爆款、归属已有子爆款、编辑创建名称。后面就是机器按数据执行。

### 第二步：把单点工作流规则化融合

Gemini2.0成本大幅下降，可以放开试。

1. 先做爆款识别并命名。把文章内容、prompt、属性一起喂给AI，返回结构化JSON。入库时就判定是否爆款，每个国家定义不同，prompt里要塞满背景文化和评判标准。

这里踩过坑：全球通用爆款一开始被归到某个国家，最后发现他国根本不关心，会错失机会。所以背景信息要给足。

我们发现给AI标准越细，同时要求它给出理由，准确率越高。

最终分了S、A、B、normal四级。S是爆款中的爆款，A是爆款，B和normal是普通。单拎出B，是因为调试时发现模糊地带很多，分成中间级能保证S/A的纯度。

把需求、背景、期望的东西不断细化，AI就给出你想要的结果。

2. 对S、A文章，结合线上有效期内的爆款标题，用AI判断是否已归属。已归属就返回对应爆款，不再新建。
3. 若已命中爆款话题，就把文章和该爆款下已有的子话题一起喂给AI，判断是否新子话题。是已存在就记录，不是就让AI命名新的子话题。

举例：马来西亚电商文章进来，AI判定为爆款，大类出海。下一步看出海下有没有，已有就把海外自媒体、海外电商、海外中介等子话题一起给AI判断归属。再往下命中海外电商后，把该标签下所有文章简介和本文一起对比，判断是否讲的是tiktok、独立站等同一子话题。

这样一层层筛完，运营动作就能精准定向推送给对应人群，提升消费。

一套流程跑通后，运营动作完全被AI驱动，结合数据反馈持续调prompt和流程。之前纳瓦尔说重要的不是一万小时而是一万次迭代。我们审核迭代了四五次就平替且做得更好，方法论沉淀下来，今年做运营改造就很快。

# 如何把AI工作流真正绑到业务上

1. 拆解，把业务拆到岗位级的细节。输入+输出构成动作。初始信息+业务场景提示词=AI输入；AI参数+参数决定的固定工作流=业务动作；业务动作结果+其他输入=AI参数。
2. MVP测试阶段先不计成本跑通链路，再谈压缩成本。
3. 判定和识别类任务温度设0最优，创作类0.3-0.5。
4. 判定识别类一定要让AI给出理由，保证准确性，这跟大模型原理有关。
5. 别想着一口吃成胖子改造整块业务。迭代思维，一次只改一个工作细节，稳步推进，成本可控。
6. 用发展的眼光看AI。GPT3.5->GPT4V->GPT4o->Gemini2.0，一路走来正是因为早期相信。
7. 多读官方文档，认清能力边界和推荐方向。
