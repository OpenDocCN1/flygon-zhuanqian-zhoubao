# 从零搭建自己的 AI 问答系统：一份跑通过的实操笔记

这里是峰兄。这个系列会分三次聊透提示词。上次讲了怎么正确使用 ChatGPT，这次讲怎么自建模型并搭建内部问答库；下次会聊提示词在更多行业的落地方法。觉得有用的话，点赞、投币、收藏，我会继续出后续内容。

很多个人或团队都想要一个专属智能助理，把重复劳动交给它，自己专注更重要的事。个人可以做“AI 替身”：之前有歌手的声音被 AI 复刻，在网上刷屏；海外博主 Caryn Marjorie 卖掉了一套 AI 替身，同时陪上千粉丝聊天，按分钟计费，一周入账 7.16 万美元（约 50 万人民币），年化收入相当惊人；还有位博主把过去所有文章喂给 GPT，此后由“另一个自己”自动回复读者。公司则可以用自动问答机器人，减少人工支持成本。对外方便合作伙伴查资料，对内方便员工学习业务。

更灵活的是，同一个系统只要接入不同资料库，就能切换角色：

- 放财报，变成财务分析顾问；
- 放聊天记录，变成售后支持；
- 放案例卷宗，变成法律助理；
- 放医学百科，变成在线问诊助手。

可玩的方向非常多。个人和小团队完全可以用自有数据训练系统，既贴合业务，又避免敏感信息流出。自己训练的成果，在专业度、差异化和可控性上有天然优势。

这套流程我不只写过，还完整跑过一遍，也对比过市面上大多数同类方案。按成本和落地难度来说，它是当前比较省心的一条路。照着步骤操作，零基础也能完成。目前已经有一家报社用它搭内部问答库，一家电商公司拿它做售后机器人，反馈都不错。

## 一、为什么不用现成方案？

现成的在线工具确实强，但有两个痛点。

一是数据隐患。每次提问都会传去第三方平台，敏感内容可能被留存。二是定制不足。各家的业务情况千差万别，通用工具很难结合内部资料给出有针对性的答案。

自己搭一套，刚好能解决这两点。

## 二、哪些场景适合自建？

- 更可靠：底层是对话模型，回答有逻辑；
- 更安全：文件留在本地，可内网部署；
- 更全面：适合售后问答、员工自助查询、新人培训、对外协作、个人资料管理。

操作上，只需要把文档或问答对放进资料库，让系统持续学习；不需要的内容随时替换。

## 三、微调和向量检索怎么选？

### 1. 两种手段

微调（Fine-tuning），是在已经具备通用语言能力的基座模型上，再拿专项数据做二次训练，让它更懂某一类任务。

向量嵌入（Embedding），是把文字、图片、音频等信息压缩成数值向量。文本变成向量后，系统可以计算语义距离，判断内容是否相关。

实际使用时，两者可以搭配：先让基座模型懂通用语言，再做微调适配；同时用向量表示增强理解。

微调的一个实际场景是：

- 让模型按统一模板识别输入；
- 让模型用特定口吻回答；
- 让输出结果带上某种倾向。

不加入示例，直接提问：

```
prompt: 
小红喜欢洋娃娃。小红的性别是？ 

completion: 
女孩，所以她很喜欢洋娃娃。洋娃娃通常有着丰富多彩的服装和装饰，可以让小红玩得很开心。此外，红还可以给洋娃娃起名字，造出一个属于自己的小世界，从而获得更多的乐趣。
```

模型会给出完整答案，但你很可能只想要一个“男/女”的判断。在指令里加入示例：

```
prompt:
示例：小红喜欢洋娃娃。小红的性别是？
答案：女 

下面是问题：小明喜欢坦克，小明的性别是？ 

completion:
答案：男
```

它就会照示例格式回答。再拿大量同类数据做微调：

```
prompt:
小红喜欢洋娃娃。小红的性别是？ 

completion: 
答案: 女
```

之后只要按模板写指令，返回内容就会自动符合预期。这种做法很像完形填空：把答案位置标成 [mask]，让模型去预测空缺内容。

### 2. 二者有何不同

微调像备考，知识被写进参数里，形成长期记忆；但时间久了可能忘，甚至记错不存在的事实。

向量检索像开卷考，现场翻资料；资料里有的，回答就准，资料里没有的，很难编出来。

开卷也有成本：除了原始问题，还要附带检索段落。GPT-3.5 的上下文窗口约 4K（5页上下），GPT-4 最大约 32K（40页上下）。好比有一柜子书，每次只能翻其中几页。

OpenAI 官方推荐的做法是“先检索、后生成”：先在本地文件里找出相关段落，再把段落和问题一起交给模型，由它综合作答。

### 3. 选型思路

微调擅长让模型学会新任务，不适合让它记住大规模资料。想要特定风格写作，选微调；想要问答和检索，微调帮助不大。

向量检索正好适合问答：先用相似度找出候选内容，再让模型基于候选内容作答。它比微调更快、更省、更容易上手。

总结一下：

- 有现成语料，想让系统照着回答 → 向量检索；
- 想让系统表现温柔语气 → 微调；
- 想统一提问格式 → 微调；
- 想让系统按说明书作答 → 向量检索。

所以，做问答系统和内部资料库，优先走向量检索。下面重点讲这条路线。

### 4. 向量是什么？

向量可以理解为一串数字，它能表示文本、音乐、视频等各类内容。做法是调用嵌入模型（例如 OpenAI 的 Ada），把内容转换成向量，然后存起来备用。

![](img/f3d70aaeb6adc93585af65f7266d6e1b.png)

举个生活中的例子：你面前有一箱积木，想找“小轿车”和“公交车”。它们都能载人移动，算是相近概念，这就是含义接近。再比如“小轿车”和“公路”，概念并不相同，但因为车在路上跑，人们也会觉得它们相关联。

### 5. 大文件如何进入上下文？

巨型 PDF 没法整篇塞给模型。做法是切块，逐块转成向量，放进向量数据库。

流程是：

1. 文档切块，逐块向量化并存储；
2. 用户问题同样转成向量，用相似度算法取出最相关的几块；
3. 把这几个片段连同问题一起交给系统，要求它只依据片段内容回答；找不到相关内容，就直接说“不知道”。

开源社区里热门的“LangChain + ChatGLM”问答项目，正是这个思路。

## 四、完整链路

一句话版本：加载文件 → 读取文字 → 分块 → 文本转向量 → 问题转向量 → 找出最相近的若干片段 → 拼成指令 → 交给模型生成回答。

![](img/c642f40576f2ab60672a1f72342a74d8.png)

![](img/c14b355eca81dc1d14347942bf210504.png)

核心在于向量检索。资料进库时要做向量，提问时也要做向量，再从库里取最匹配的片段，和问题一起交给模型。常见指令格式如下：

```
"""
已知信息：
{context} 

根据上述已知信息，简洁和专业的来回答用户的问题。如果无法从中得到答案，请说 “根据已知信息无法回答该问题” 或 “没有提供足够的相关信息”，不允许在答案中添加编造成分，答案请使用中文。 
问题是：{question}
"""
```

现在主流实现基本可以概括为“编排框架 + 生成模型”：LangChain 负责调度、拼接、检索，ChatGLM 负责生成。为什么要这样组合？因为生成模型本身有随机性和幻觉，直接裸问容易跑偏；用框架把检索结果接住，回答才会更稳。

## 五、两个关键组件

### LangChain

LangChain 属于语言模型应用开发框架，相当于程序与模型之间的中间层。它能串联多个组件，也能接入 API、数据库。组件包括模型、指令模板、索引、代理、记忆等。

它 2023 年 3 月拿到 Benchmark Capital 的 1000 万美元种子轮，后来又获得红杉 2000 万至 2500 万美元投资，估值接近 2 亿美元。之前刷过屏的 Auto-GPT 和 BabyAGI，都用到了受它启发的链式思考。

### ChatGLM

ChatGLM 由智谱公司推出。这家公司源自清华大学计算机系，曾合作研发 GLM-130B 双语模型，后来又做了 BigModel 开放平台，提供 API 服务，并附带代码生成、图像生成等能力。

这家公司的目标是让更多人用上大规模模型。

本文选用的是 ChatGLM 一个约 62 亿规模的版本。选择原因有两点：中英文表现均衡，且对硬件要求不高。加上量化压缩，显存占用约 6G，普通家用电脑也能尝试本地运行。它在中文问答上做过专门优化，又经过指令微调与人工反馈迭代，生成效果比较自然。

更详细的内容可参考知乎文章：https://zhuanlan.zhihu.com/p/627509623

## 五、离线私有部署实战项目

前面演示Embedding训练流程时，用的是目前很火的LangChain+ChatGLM方案，开源项目文档写得挺全，还配有交流群。但自己体验下来，发现操作有点繁琐，对零基础的人来说不太友好；而且训练效果平平，回答有时也不太到位。所以这次就不讲LangChain+ChatGLM了，换另一套方案：Wenda+ChatGLM。

底层大模型没变，还是ChatGLM，但应用框架从LangChain换成了Wenda。换完之后，步骤明显简化，训练效果也更突出，大家待会儿看看展示就明白了。

补充一点：上面说得不太严谨，本质其实是——先把知识库内容做 embedding，存进向量库；你每次提问也会做 embedding，再通过向量相关性算法（比如余弦相似度）找出最匹配的几个片段，把这些片段作为上下文，连同你的问题一起作为 prompt 抛给 LLM，最后由 LLM 把嵌入了本地知识的答案返回给你。
