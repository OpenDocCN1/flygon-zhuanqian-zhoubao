# 别再先啃教程了，真正的高效学习是边做边卡边查

很多人对学习的误解，其实是从小被训练出来的固定套路：先找一堆教程狂看，整理笔记做总结，自认已经掌握，然后一上手就全懵，最后只能灰溜溜回去再看一遍教程。这一轮又一轮的内耗，看起来很努力，实则是在原地打转。

创作者 Dan Koe 提出的学习思路很反常识，却一针见血：先把项目干起来，卡住的那一刻再去找答案。

为什么顺序这么重要？因为记忆带来的不是能力，挣扎才会。

你提前看完教程，大脑其实是处于一种松弛的接收模式。内容流进来了，但没有锚点，很快就被遗忘。反过来，先动手做项目，你会瞬间把自己所有不懂的地方全部暴露出来。这时你带着明确的求知欲去检索，脑子处于高度饥渴的状态，学到的每一句话都会被转化为解决问题的工具，直接长进肌肉记忆里。

评论区里不少人也踩到了同样的点。

有人提醒，看教程本身不是错，关键是看什么、跟谁学，最好能跳出内容本身，升级自己的学习方法论。

也有人感慨，那些收藏的教程、做笔记的清单，在动手之前，不过是另一种形式的精神安慰，是让人产生“我在进步”的假象。

还有人补充现实的限制：你想去搜，总要有精准有用的信息能搜到。先做起来，问题才具体，搜索才有效。

带着问题学的人，最有体会。启动项目后，会不断冒出意想不到的坑，但坑的同时也是灵感的源头。每解决一个卡点，就是一次向前的小进步。结果可能不完美，但状态会进入每天都在变好的正向循环。

与其追求先学会再开始，不如先开始再学会。让需求引领学习，让挣扎成为记忆。
