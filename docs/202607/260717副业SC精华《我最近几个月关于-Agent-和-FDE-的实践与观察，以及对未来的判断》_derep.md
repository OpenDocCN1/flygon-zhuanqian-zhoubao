## 1 从 AI 工具到 Agent：接下来十年的主线

![图片](img/ea621ebd44a19e56f01cd31055af5e19_0_0.png)

这段时间我自己动手做的事很多：

在赚钱内部，我已经让几十个 AI 员工正式上岗，并且进入真实的生产链路。现在很多产出不再靠人一步步推动，而是交给 AI 去持续运行。在我的推动下，团队里大家也开始自发搭建各类 AI Agent。有的只是把原有工作的某个环节升级，有的则是对过去使用 AI 的方式彻底重构。截止到现在，团队里每天都有新 Agent 上线，我粗略估算内部总数至少在三五百个左右。

这已经不能用“做个 Demo 玩玩”来概括了。现在必须去想的问题是：这些 Agent 怎么来、怎么迭代、怎么养；更关键的是，Demo 如何变成能扛生产的 Agent，真正接入公司业务系统。

过去半年是我接触 AI 以来进步最快的一段。除了内部建 AI 员工，我还同时推进了几十个项目，有停留在验证阶段的，也有已经进入开发的。其中最有体感的是 TokenRank，以及龙哥盟·会员榜单这个产品。会员榜单从零到一的所有环节都是我亲自操刀，这种真实面向用户的打磨，和只做内部使用完全不一样：用户反馈的压力、迭代的节奏、问题暴露的密度，都会把你对 AI 产品化的理解拉到一个新层级。

基于这些体感，我现在的判断非常坚定：未来十年最值得押注的方向只有一个，就是 Agent。不是某个 AI 工具火、不是某个赛道火，而是 Agent 会重塑几乎所有行业、服务和产品形态。去年我们聊 OAI，今年在公司和赚钱社区内部的说法已经进化为 OEAgent。重点不再是“会不会用 AI”，而是把 AI 训练成 Agent，让它能承接任务、串联流程、直接进入生产。

所有人都需要统一认知：

**AI 工具只是提升局部效率，Agent 才是重构生产关系。**

## 2 FDE：普通人也能拿到的高位机会

当 Agent 成为十年主线，一个新角色就自然走到台前：所有领域都需要 Agent，所有公司都需要 Agent，所有人都在问谁来做。但 AI 能力、技术理解、业务拆解、落地部署，这四块很难一个人全占。

这个角色就是 FDE。全称 Forward Deployed Engineer，前端部署工程师。最早是一些头部 AI 公司提出的思路：自建强技术平台，然后把人派到客户现场，用 AI 把能力真正落到业务里。

这个概念现在已经在扩散。OpenAI、Claude、国内大模型厂商、飞书等，都在招募和孵化 FDE。这不是某家公司的岗位，而是一种新的能力模型。

通过我这几个月的实践，我反而更看好：

**FDE 不只是大厂的专属，更是独立个体和普通人的弯道机会。** 不同层级的机会当然不一样。对个人而言，如果能卡位到 FDE，很可能迎来十倍级别的增长。如果你正处在职业转型、方向迷茫、找项目的阶段，不妨认真研究一下 FDE。也许几年后你会庆幸今天的投入。

我这几个月做的事，本质上就是把自己打造成公司的 FDE。我先把关键项目、核心产品、服务 Agent 化跑通，再带着团队一起复制放大。

在传统外包里，一个人通常只服务一家客户。随着大模型能力提升，以及你对 AI、业务和部署的理解加深，一个人同时服务多家客户的上限会被不断拉高。未来，一个足够强的 FDE，可能同时托起几十家企业的 Agent 化进程。这种人的价值会非常惊人。

## 3 把飞书改造成 AI 员工的前台

现在打开我的飞书左侧导航，已经不是会议纪要、营业执照、时间表这些过去的内容了，而是几十个 AI 员工的入口，随时待命。

这套东西基本在 5-6 月搭建的。飞书 CLI 上线不久，配合爱马仕等工具，我就把它们组合起来，做成了内部 Agent 体系。

目前飞书里的 Agent 被分成好几个部门，最核心的一个叫“Agent 组织部”。它相当于 Agent 的 HR，负责 Agent 的创建、维护、审核、入职、运维等全生命周期。

### 3.1 Agent 架构师：替我发现可被智能化的工作

组织部里我设了一个 Agent 架构师角色。它接入 Claude Code，有比较高的权限。

这个角色每天能看到我和他人的聊天记录、群内发言、当天会议、文档转发，以及同事间的协作流程。它的日常任务是每天告诉我：哪些流程可以被智能化，哪些环节有被 Agent 替代或重构的价值。

我收到的一大批建议里，有的是工作流可以直接自动化，有的流程可以被重塑。只要我觉得有价值，就让它直接生成对应的 Agent，把那项工作接走。

等于 Agent 架构师接管了我“观察流程、判断智能化价值”这部分工作。

### 3.2 Agent 运维官：让所有 Agent 自动自愈

用上 Agent 之后才发现，运维很耗精力：权限错了、授权过期了、飞书升级导致流程跑不通了……于是我专门建了一个 Agent 运维官。

它按时巡检我所有的 Agent，大部分问题它能自动修复。非紧急问题我也不必立刻介入，等它处理完即可。这样就把我从琐碎的权限、授权、版本兼容问题里解放出来。

### 3.3 Agent 审核官：解决团队 Agent 洪水

现在团队每天上线十几个 Agent，大家各自创建。只靠我一个人审，根本审不过来。每個 Agent 的权限、工具调用范围、风险点都不一样，人工审查成本太高。

所以我又建了一个 Agent 审核官，专门审新 Agent。他会检查权限配置、风险点、是否合理，让 Agent 的扩张不再受限于我个人。

这套组织部里还有技术专家等角色。核心逻辑很简单：Agent 数量上来之后，你不能只造“干活的 Agent”，必须同时造“管理 Agent 的 Agent”。

## 4 已在内部跑通的三大类业务 Agent

目前跑通的 Agent 大致分三类。

第一类是运营类，比如周报自动生成、申请流转、会议纪要、财务对账、微信日报。大量运营琐事已经可以交给 Agent。

微信数据特别有意思，拿到权限后可以做很多自动化服务：读取聊天记录、👸号文章、收藏、通讯录，然后基于这些数据做日报、洞察、提醒。实现细节不展开。

第二类是内容生产类，覆盖选题、改写、发布、转录等。内容链路里有很多有规律但需要判断的重复动作，很适合拆成多个子 Agent 协同完成。

第三类是社群管理类，比如评分卡、帖子筛选、打标签、用户洞察。群里用户在说什么、什么困惑在集中出现、哪些帖子值得沉淀、哪些用户行为需要关注，都能通过 Agent 流程自动化。

这只是开始。我们还在做内部 Agent 工作台，完成后整个体系会再扩大一层。

## 5 案例：我最常用的多平台音视频转录 Agent

我个人使用频率最高的 Agent，是多平台音视频转录 Agent。

原因很简单：我现在几乎不看长视频了。几十分钟、一两小时的课程，或三四小时的播客，即便内容顶级，我也很难一次性投入。YouTube、播客平台都有大量好内容，时间成本太高。

市面上的转录工具普遍有两类问题：一是过度压缩成摘要，细节全丢；二是保留太多口水话，阅读很累。

我想要的是中间态：去废话，但不丢细节。因为真正拉开差距的，往往是细节、案例、推理过程和上下文，而不是一句结论。

于是我做了“小 D”，视频转录助手。它能把主流视频、音频、图文内容转成干净的文档：口水话被过滤，细节最大化保留。对我来说价值巨大，如果市面上有，我愿花上万块买。

使用方式很简单：刷到 Twitter、YouTube、小宇宙上的好内容，直接丢给它。它能把一个 4 小时的 Claude 教学视频完整转出来，我不用亲眼看完。

它不止转录，还会在文档里标注重点，根据我的阅读偏好，标出我已知的、未知的、值得关注的内容。相当于一个非常懂我的超级助理。

背后是一套完整工作流：下载、转录、提纯、写入飞书文档、基于我的上下文标注重点。可以看成若干子 Agent 的组合。

这套方法的 Prompt、流程、Skill 文档我已经分享到星球里。类似这样的 Agent，团队内部还有很多。

## 6 Agent 时代，人要负责什么

当 Agent 能主导流程，人还干什么？我现在越来越清晰，人的精力要集中在几个关键点。

第一，是提出好问题。你要清楚自己要什么，能不能把问题定义好。有想法的人在 Agent 时代会迎来最好的窗口。没有问题、没有好奇心、没有行动欲望，Agent 也帮不出高价值结果。

第二，是判断力。你要判断什么有价值、往哪走。过去我用 AI 时，我在等它：我下指令，它开发，我等结果。现在反过来了，是 AI 在等我。因为我能同时开十几个线程，最多时我同时推进 15 个项目，每个项目里还有多个 Agent 在跑。

这时重要的不是你能不能亲手执行，而是能不能快速判断：这个方向该砍、这个方向该放大、这个结果可否用、这个结果要重做。

很多人用 AI 用得更累，正是因为仍在旧工作流上叠加 AI。旧流程不变，只是把 AI 插进某个环节。线程一多，人就会被判断和衔接拖垮。

更好的做法是让 AI 主导整个生产流程，人做配套。你要把意图、目标、判断标准、样本都讲清楚，让 Agent 重新组织流程，而不是在旧流程里补一块 AI。

这也是 Agent 和传统工作流的核心区别。过去的工作流改造是把 AI 嵌入旧流程，Agent 出现后，效率能提升 10 倍甚至百倍，关键在于：不是让 AI 兼容老流程，而是让 AI 定义新流程。

## 7 幻觉问题的本质：定义、标准、上下文

很多人担心 AI 幻觉、结果不可靠。我的判断是：**AI 是人的能力放大器。** 你本人容易跑偏，AI 也会更跑偏。你讲不清边界、标准、目标，AI 只能靠猜。反过来，你能清晰定义问题、给出好与坏的标准、划清产出边界，它给出的结果往往远超预期，能直接上生产。

对大多数业务场景而言，我们离 AI 的真实边界还远。OpenAI 研究员可能在研究极限，但对我们来说，绝大多数情况 AI 只会带来惊喜。很多“AI 不行”的抱怨，本质是问题、上下文、标准和授权没有讲清楚。

幻觉还和上下文工程有关。现在很火的概念叫 Harness。简单说：Agent 减去大模型能力，剩下的就是 Harness。它包含你有没有搭好上下文、是否给了 AI 足够授权和信任、是否让它理解目标-流程-结果，以及人与 Agent 的角色分工。

这些都清楚了，效果会远超“幻觉期”的想象。

最后一条底线：高风险决策必须人兜底。涉及法律、财务、品牌、重大业务风险的事，不能完全交给 AI。Agent 可以主导流程，但责任必须由人承担。

## 8 团队工作方式：从工具统一到组织重构

### 8.1 为什么我们统一到飞书、Codex、爱马仕 Agent 框架

过去团队的 AI 基建比较分散：有人用 Claude Code，有人用 Codex，有人在飞书做自动化。随着实践深入，我们意识到要让 AI 真正进入组织协作，就必须统一技术栈。

飞书是底座。团队几年的文档、项目、汇报、沟通都在飞书。飞书开放 AI 能力后，Agent 就能无缝接入：发消息、读文档、整理汇报、盯项目、沉淀内容。这不是加一个工具，而是让原有协作系统长出 AI 能力。

服务层统一到 Codex，并不是抛弃 Claude Code，而是现实约束。Claude Code 的 Token 配额消耗很快，个人每周 200 多美金，通常周一到周二就用完；团队账号还常被封。因此现在 Claude Code 只供给核心 5 位工程师。

新成立的工程师团队统一配置：每人 200 美金 Codex 配额 + 250 美金 Pro Code 配额。判断很明确：给工程师足够的 Token 和工具保障，才能产出高质量成果。现在鼓励所有人把 Codex 当主力工作台，在这里建项目、开发 Agent、做产品。过去分散的工作台会逐步收拢到 Codex。

但光有 Codex 不够，要让 Agent 在飞书、企微、微信等协作环境里自动维护、持续运行，就需要一套框架。爱马仕 Agent 框架就是干这个的。它让 Codex 去修、去维护、去处理异常。对大多数成员来说，只要会用 Codex 即可，框架理解即可，维护交给 AI。

目前团队的技术栈是三件套：

- Codex，作为核心工作台；
- 爱马仕 Agent 框架，用于 Agent 自动维护和多平台接入；
- 飞书 AI / 协作体系，用于文档、项目、消息、办公落地。

我们还在做一个内部 Agent 工作台，把所有 Skill、Agent、MCP 聚合，让团队共享能力。把这套栈用好，价值会非常大。

### 8.2 Obsidian、知识库与 Skill：个人和团队是两回事

Obsidian 依然好用，但更适合个人。它是个人知识库，沉淀大量资料，再通过插件接入 Claude Code 或 Codex 处理内容。

团队的核心需求是协作，Obsidian 在协作上很难顺畅，飞书天然更适合。团队在 Codex 做出的 Demo，可以直接一键放到飞书里让所有人讨论、迭代。如果放在 Obsidian，链路会很复杂。

因此团队层面，飞书比个人知识库更关键。即便对个体，我也建议提前用飞书，因为协作、共创、与外部伙伴协同会是常态。飞书文档在分享和协作上的体验依然很强。

“知识库”和“Skill”的边界也在变化。AI 进化很快，很多知识库和 Skill 的能力会被模型和工作流内化。更理想的方式是：让 AI 用它擅长的格式维护知识库，沟通过程自动沉淀成本地库，项目结束自动整理成 Skill，下次同类任务自动调用。

用飞书 Bot 作为入口还有个优势：上下文和记忆能力更强，任务可以在同一协作环境里延续，Skill 复用也更自然。人不需要频繁打开知识库，也不需要手动管理 Skill。

知识库不是没用，而是它不该成为人的负担。最好状态是：**AI** 自己维护知识库，人只负责提问题、定标准、推结果。

### 8.3 普通人最该跨的门槛：先把 Codex 用起来

这套配置听起来很唬人，真正落地时，你要死死盯住的关键却只有一个：Codex。什么框架工程、智能体维护、技能包治理，统统可以甩给它。遇到故障也别亲自上手修，把现象描述清楚丢给 Codex，让它自己排查、自己补。

暂时没有 Codex 的入口，国内也有一些平替能先顶上。不过，想在这个领域拿到更高上限，还是尽力靠近 Codex；如果不嫌折腾，Claude Code 也可以作为备选。不同工具带来的能力边界与使用手感，差异比你想象中更大。

很多人卡在智能工具门外，不是因为没资料，而是缺一个领路人。参加一次线下活动，请一位已经玩转的人当面演示，发个红包或者请顿饭，那道门槛通常就迈过去了。迈过去之后，你对人工智能的理解会完全不同。

龙哥盟最近把线下场当重点来推，一个月大约三百到四百场。目的就是让会员当面认识、互相学、互相拉一把。过去一个月，光是没设主题的开放交流就开了七八十场。许多分享者自己先上过大课，对工具有实在的手感；他们分享的也不是“哪个按钮怎么用”，而是“业务高手怎么在真实业务里使唤人工智能”。这种贴着场景的分享，回去就能直接套用。

**轻应用：一个新的结构性机会**

这次航海只留下七条船。过去项目太多，十几条线铺开反而让大家选择困难；这一轮团队反复筛选，只留下那些砍到底也会舍不得的赛道。留下来的每一条，都值得投入、能学到东西、也能拿到新能力。

头号重点，是让 AI 造轻应用。这件事不难，过去一年里已经冒出不少靠它做到百万级的样本。放在以前，开发小应用有真金白银的成本，很多小众需求根本没人愿意碰；现在人工智能把软件成本急剧压低，新的红利正在浮现。

一位圈友做的是轻应用加虚拟资源，几乎不花什么成本，行情好的一个月能进账上百万。还有一位 2005 年出生的少年，高中没读完就退学，在📕上向老师卖课堂管理类的小工具，最好的月份能摸到近 50 万。

真正值得琢磨的变化，不是“AI 能写应用”这么简单，而是软件造价崩塌之后，供需两端的格局彻底变了。过去做一个 App，几十万起跳，开发周期三个月起步，结果就是大量细分人群的需求没人看得上、没产品愿意接。

好在中国的体量足够大。只要一个需求覆盖 1% 的人，放在全国就是上千万用户。在这个市场里，再小的需求也可能很值钱。所以，自己有什么痛点，或者发现身边人有需求却找不到产品，就可以自己去造。先把最小可用版本做出来，再找到那群人，把流量做起来。集齐一百个、一千个愿意掏钱的人，这门生意就成立了。

对新手来说，用 AI 造一个轻应用、顺带把一个商业模式试一遍，是极友好的起步方式。往后国内软件市场会成倍放大，各个细分赛道都会长出好玩的 App 与轻应用。

轻应用比出海更适合大多数人当作起点。出海看着能赚美元，实际很难：不了解海外用户、要搞 SEO、投广告、做社媒，折腾几个月不一定有反应。轻应用则不同，做好之后丢到微信聊天和群聊里，也许很快就能等来第一单 9 块 9，甚至 2 块 9。这种正向刺激，会让人愿意一轮轮改下去。

所以这场航海会围绕完整闭环来讲：需求怎么定位、产品怎么制作、流量怎么获取、0 到 1 怎么跑通。过去半年到一年沉淀下来的打法，会拆开摊平讲给大家。我的判断是：将来每个人都能造出一堆轻应用，里面一定会冒出让人惊艳的爆款。

**从“讨论想法”到“亮出原型”**

组织内部的协作方式也在变。现在最怕听见的，就是“我有个想法，大家聊聊”。有想法，别聊，把能跑的原型端上来，把真实在线的产品亮出来。能不能行，一眼便知。

去年团队要求所有人学智能编程；今年 6 月之前，要求所有人都能做出智能体；到眼下，要求全员沉到后端。所谓沉到后端，就是每个人都要学会调 API、操作数据库、把产品部署上线，并且用 Git 这类方式持续迭代。

这不是工程师才有的要求，而是全公司每个人的要求。因为人工智能已经把“想法”和“产品”之间的距离压到了极短。有想法，原型就该同步出来。组织形态也因此松动。过去一个项目从念头到上线，要运营、产品、设计、开发、测试一轮轮交接；现在这套按职能切段的标准流程正在失效。人工智能把个体能力撑大了，个人就可以直接当入口：运营有想法，就该自己把产品做出来、发上线。

这也正好解释了最近很热的 Loop 概念。它指的是个人能力被智能工具放大之后，公司不再需要沿传统的职能条线去推项目。项目不再在部门之间流转，而是由几个人围着同一个目标，迅速把闭环跑完。

全球关注度最高的人工智能企业之一 Anthropic，也在呈现同样的状态。这家公司大概 3000 人，整体却采用项目制：有人冒出个点子，再组两个队友，三个人就开干。

龙哥盟内部也正在长成这个样子。未来所有人都要成为 FDE，人人都得能全栈。现在公司里已经有一些运营做出了生产级的产品。以后很可能两个人配合做一个产品：一个主攻推广智能体，一个主攻产品智能体，两个人叠起来，就能完成从前整个团队的活。

**智能化必须是老板亲自下场的工程**

在不少大厂和传统机构里，智能化主要发生在中台：研发部、数据部、后台部门用起来了，一线业务却很难切入。部门壁垒、权限限制、人员规模、流程惯性，随便一样都能把业务人员挡在外面。

龙哥盟的差别在于：成员权限完整，数据可读，工具全开，token 不设上限，账号也是最高规格。一位从阿里出来加入团队的同事，再回头和原来的同事聊天，会有一种“鸡同鸭讲”的错觉。不是老同事不拼，而是两边手里的上下文、权限、工具和成长速度，已经完全不在同一维度。

这件事对老板格外要紧。无论是 5 人、10 人还是上百人的公司，都要认真想一想：如何把公司改造成原生智能组织。因为这不是局部提效，而是整个组织结构要重来。

有个判断很直接：老板不下场，就没有好下场。智能化是真正的老板工程。创业路上，你早就见识过哪些事离不了老板：人力、流量、团队建设，全是。现在智能化也是，而且是一次革命级的变化。老板不知道一套智能系统的边界，就不知道公司该怎么用它。

只让员工去学，组织的效率上限大概也就提升两到三成。因为员工站在自己的部门、模块、岗位里做优化，能得到的最好结果也只是局部的。老板如果学会用智能工具，看到的是全局流程，他可能会直接拍板：这条流程不该改，该扔掉，公司要重新搭一整套结构。

所以，智能时代的组织升级，不是各部门各自打磨一点，而是从公司整体的维度，把工作方式重新设计一遍。

**新团队的两种入场方式**

随着每个人的能力上升、边界被抹平，团队目前并不急着按传统方式大规模招人。因为单兵能承接的事情越来越多，组织也就没必要继续膨胀。

不过接下来会组建新团队，重点放开两类合作机会。

一类是 FDE 团队，适合那些在某个行业里有资源、有经验，一年能赚几十万到上百万、但智能底子还偏弱的人。加入以后，有机会在某个细分行业成为合伙人，和团队一起做行业级的智能落地。

另一类是 SD 团队，适合那些智能工具已经用得很熟、却缺商业方向的人。这类人可以加入团队，一起去给企业提供智能服务。

两条通道都会持续开放。后续可能还会有专门的招聘直播，系统讲讲龙哥盟正在找什么样的人。相关团队会由主理人亲自带。

**出去看标杆，眼界本身就是战斗力**

针对老板、组织，以及走到 0 到 1 之后还想系统学习的人，那里还有一个社群叫 AI 航海家。可以理解成智能方向的老板私董会，主要交付都放在线下：既教你用工具，也会组织大课和游学。

下周末就会有一场大课，主题是内容智能体。平时，社群也会带大家去看看各个行业里把智能体用得最好的企业，到底是什么状态。

一个很有代表性的参访对象是方片传媒。它的智能体改造做得相当彻底，内部已经搭出了类似“技能包+智能体”的工作台。公司 500 人，有 100 人已经会做智能体，工作台里沉积了 100 多个技能包和智能体。连出去谈业务的商务人员，也在搭自己的智能体系统，用来让跑单更顺利。

这套经验也分享给过无忧传媒等 MCN 老板。它说明了一个道理：亲眼见过标杆的样子，极其重要。智能时代，很多时候你不必当场学会，看一眼就够了。看到一个不错的工作台或智能体系统，拍照、录视频带回去，往 Codex 里一丢，附一句“照我们公司的标准来”，5 到 10 分钟后，一个适配自家公司的智能体模型可能就出来了。

所以，智能时代最值得修炼的是眼界、标准和品位。品位，就是你真的见过好的。老板尤其需要往外跑：看看哪些企业已经完成了智能化、智能体化，它们的组织和内部工作台是怎么搭的。

眼界本身就是战斗力。这也是主理人每天雷打不动花两小时刷信息流、逛 X 平台、看视频网站的原因。老板最怕的就是没有眼界；没有眼界，再努力都很难知道究竟什么才算好东西。

**念头一出现，产品就开始长**

创业的方式正在被重写。以前是有个点子，开会、评审、写需求文档、出设计稿，再排队找程序员开发。这条链路已经明显过时。

现在更像是“想到即开始生成”：脑子里蹦出想法的那一刻，产品已经开始成形。接下来一两个小时里，你就能和智能工具来回沟通，把雏形磨出来；快的话，20 分钟就能看到像样的东西。

这意味着，智能时代最关键的并不是找项目，而是智能工程力。很多人还在问“现在该做什么项目”，但更该问自己：你有没有把想法迅速变成产品的能力？

会写代码、能玩数据库、会做内容、能搭智能体，这些技能会把一个人的可能边界撑得非常宽。没有它们，你能走的路又窄又短，只能去抓短期的信息不对称，可这种差价很快就归零；一旦有了智能工程力，你会发现能做的事突然暴增。

项目不是最要紧的，智能体工程力才是长期竞争里的硬通货。更长远地看，各行各业都需要被智能化改造一轮。未来甚至可能是一个智能体与智能体互动的世界：人类雇一堆智能体替自己打工，自己退到消费者的位置上。智能还会把过去只有富人才能买到的服务变得便宜，让普通人以极低的价格享受医疗、健康、咨询、助理这类高品质服务。

今天的商业世界，主体还是人和人在交互，你常用的应用也大多服务于人与人。但未来，这个底盘很可能被智能体与智能体的交互替换掉。真正值得投入的，是早点把智能的功夫练上身，养出想象力和动手能力，让自己成为新世界的生产者，而不只是站在外围看。

**结构级红利：把筹码押向智能编程与智能体**

交互形式将会剧烈变化。今天我们离不开的手机、微信，以及大量现成软件，未来都有机会被新的智能体形态取代。对创业者来说，那是一整批新的位置。所以，别只看眼前的小机会，要把目光放在结构性的位移上。

这个阶段最重要的事，就是把精力集中到智能编程、Codex 和智能体上面。哪怕只从就业角度看，智能工具的使用能力也已经成为一个直接的筛子：用不好，可能连深入交流的资格都没有；用得好，对方才愿意坐下来继续聊。

对普通人更踏实的路线，是先把智能学会，先去看最好的样本：那些真正用智能做业务的人，流程是怎么走的，工具是怎么安排的。当下最值得的投资之一，就是把最多的钱、最多的精力花在学智能上。

这里有一条硬判断：再省不能省 token。社群里曾经聊过“如何用掉 10 亿 token”。这个问题真正的价值，不在于你眼下能不能烧完，而在于它会倒逼你重构做事的方式。按照现在的用法，绝大多数人一天根本用不完 10 亿 token，这本身就说明流程是有问题的。你于是开始想：哪些事该砍掉？哪些事该放大？哪些事根本不该碰？如果目标是一年赚 100 万、1000 万，我现在还缺什么条件、资源和关键人物？

埋头把手头所有事情按原样做完，是不可能做到 1000 万的。真正的变化，从开始倒推的那一刻发生：为了够到那个目标，现在缺什么？要请教谁？要补哪些资源？要换掉哪些做事方式？只有当一个人开始这样反推，大脑和工作流程才会被重构，他也才会一点点接近目标。

**第一版不怕糙，怕的是上线太晚**

做智能产品的方法很简单，第一条就是快。第一版不要惦记做得多完整，先把最核心的功能做出来，哪怕粗糙得像毛坯，也要推到用户面前。如果你的第一版上线时自己都没觉得不好意思，那说明它已经上线得太迟了。

TokenRank 就是这么长出来的。最早只是花了 20 分钟做一个原型，连新域名都没注册，挂在老域名的子域名下就发布了。发到社群里，很快就有一百多个圈友把自己的 token 数据贴上来。看到这个反馈，创始人才正式把它当作一个产品往下做。

所以，别抱着完美主义开工。先把原型拿出来，让用户用，然后高频迭代。一天提交几十次代码、做几十次调整、发好几个版本，在这里都是常态。

当然，不会写代码的人，产品很可能在某个节点崩掉，或者彻底改不动，也就是大家说的“代码烂成了泥”。但这并不是开头就要回避的问题。一个零基础的人，非逼着自己先学完完整架构，再设计一套完美架构，本来就不现实。

更合理的路线是：先给一个很粗的原型；放出去给真实用户；在密集迭代中不断想清楚功能和需求；等到了某个临界点，再交给智能工具重构。前期乱的只是代码，但被验证出来的是功能和需求。当产品功能和用户需求都清晰以后，再带着这些确定性去重构，智能工具做得又快又稳，代码也能匹配当前阶段的性能和产品要求。

工具选择上，能用 Codex 就用 Codex；暂时够不到，就找个能用的帮手。关键不是纠结工具叫什么名字，而是让产品真正落地。

**别再开会了，先把原型摆出来**

智能体时代的协作方式同样在变。以前，一个想法要先写需求文档、开评审会、反复讨论方向；现在更有效的做法，是直接做原型。不要只说“我有个想法，想和大家碰一碰”――你准备开会的时间，已经足够把想法做成一个能看的雏形。

原型一出现，团队立刻就能明白：原来要的是这个，而不是那个。一个模糊的想法，每个人脑子里可能各自藏着十个方向；原型会把这十种想象压成一个共同的确定答案。

这也是智能化必须由老板牵头的原因。老板、合伙人、操盘手、负责人，在智能体时代的新职责是：看清未来，判断方向；借助智能工具把未来的产品形态变成原型；通过原型把问题、品位、标准和方向敲定；再把后续的交棒给工程能力更强的人，让他们持续迭代和维护。

没有谁能比一号位更懂自己的用户、需求、场景，也更懂这家公司长期的想象、使命和愿景。团队成员未必能消化那些抽象信息，可一旦原型放在眼前，所有人都会迅速达成共识：这就是我们要的东西。

这样分工，效率会高出不少。擅长定方向和搭原型的人，专心去定义原型；擅长工程的人，负责把它做成稳定产品，持续优化。TokenRank 就是这样，先由负责人把形态定清楚，再交给团队维护。每个人都被安排在效率最高的位置上。

这套方法不是内容团队的专利，电商、制造、传统行业全都适用。因为在智能时代，造原型的成本已经低得惊人，主要花费就是 token。比如传统行业以前做一个 3D 或 AR 模型，可能要几十万；现在用智能工具先做一个模型给老板看，方向成不成当场就能判断。无论哪个行业，用原型降低沟通成本、提高决策速度，都是成立的。

**龙哥盟的下一步：把结果端到用户面前**

过去两三个月，我们有一个很强烈的察觉：龙哥盟以后不该只是发内容、办活动，更应该直接把结果送到用户手里。

比如一个人想做自媒体，过去的路线是自己学课程、参加训练、照着方法做。未来的路线是：用户选好一个方向，平台派出大量智能体直接把结果做出来——做视频、做内容、做电商，都能拿到可执行的作品、方案和反馈闭环。

半年前这还只是一个愿景；现在，内部已经在动真格了。团队全员向 FDE、后端和智能体工程转向，目标是让几十个人都能开发智能体产品，帮用户实实在在拿到结果。

这意味着用户不一定要先把什么都学会。只要选一个感兴趣的方向，平台先交一个作品，用户拿去发布；执行之后，智能工具帮他复盘、调优，再生成新的作品，用户继续发。循环起来，获得正向反馈会变得轻松很多。

这套系统不一定能立刻让人暴富，但完全可以把一大批人带到初级水平，甚至推到行业腰部。到了腰部以后，天花板还能抬高多少，更多取决于个人天赋和手艺。顶尖水平永远是手艺活，平台未必替代得了；但把大量用户送到腰部，完全有机会做到。

未来会有一种新的商业业态：用户不再买“课程”，而是买一个技能包或智能体，让它们直接替自己干活。

也许会有人嘀咕：人人都这么干，会不会变成同质化的海洋？这里有两个判断。

其一，内容与流量本身就带有概率属性。两个人发同样的东西，哪怕各发 20 条，结果也可能天差地别。没有人能保证谁一定被好运砸中，但有一条原则不会变：数量可以压低概率带来的随机性。发得足够多，坚持得足够久，多半能拿到一些小的、中等的结果。

其二，智能体恰恰能治好同质化。过去只有一篇内容、一个模板，大家照着复制，当然越做越像。未来智能体会去研究爆款、拆解数据，再结合每个人自己的行业、性格、对标对象和表达方式，生成更有个人味道的东西。它不会让所有人一样，而是让每个人更像自己。

**技能包：智能时代的核心资产**

智能体时代，最精华的形态是技能包。过去，社区里沉淀的是经验帖；未来，这些经验和打法会被进一步封装成能直接调用的技能包、智能体和 MCP。

所以，龙哥盟会从一个以发帖为主的社区，慢慢变成一个技能包集市和智能体中台。用户进到平台里，能看到大量优秀的技能包、智能体，以及团队汇总好的数据与实战积累。

这里的关键词是“管不管用”。公域里也有做技能包的团队，但不少都做得太宽，对创业者和具体业务根本落不了地。真正能让人赚到钱的，几乎都是从一线高手身上一层层提炼出来的技能包和智能体。

内部先行试用的智能工作台正在小范围跑通。团队先让内部数十人把手上已有的技能包和智能体放进去实操，验证稳定后再向赚钱用户开放。时间表上预计八月推送内测版，九月再推向正式。

后续会开放自助上传通道，允许用户把自己的技能与智能体放到平台上。若某个技能被频繁调用、为他人带来实际价值，上传者即可获得分成与激励。个人方法变成可复用的工具，既能被他人调用，也能给创作者带来持续的管道收入。

### 下一轮航海集中在七个 AI 主题

下一期航海完全围绕人工智能，不再安排无关方向。整体思路是把经验沉淀为可分享、可复用、可落地的 SOP 与技能。

第一，AI 小程序。国内做小程序门槛低、无需供应链、反馈快，还能在📕、抖音等渠道获得推广加成。细分需求仍很多，关键不是做一个孤立产品，而是持续服务某一类人群，可以做成长期事业。

第二，AI 海外站。包括海外游戏站、内容站等。AI 正在拉低技术门槛，2022-2023 年已有教练与学员通过海外工具站获得正向反馈。如今 AI 海外网站仍是低成本切入海外市场的入口。

航海与深海圈的差异在于节奏。航海是两三个月一期、单期约 21 天，适合试探方向；深海圈是一年周期，有老师和助教陪伴，适合已确定赛道后长期深耕。方向未定选航海，已定则选深海。

第三，AI 高质量影像。过去 AI 视频多用来换量，近期短片、短剧生成能力明显提升。抖音 6-7 月 AIGC 大赛里已出现电影级作品，推特上也能见到 5-10 分钟的 AI 长片。

本方向聚焦有剧情、有质感、可落地的作品，而非一眼假的粗糙内容。可用于短剧、带货、影视或流量变现，也可真人出镜或结合数字人。图像模型、数字人、视频生成如何融合会成为实操。团队从 2024 年 9 月起做海外 AI 视频，至今积累近两年经验。

第四，AI 视频带货。该赛道已出现多个高收益案例。

视频号大健康数字人视频，点赞转发不足 500，却带六七十元产品，据称连续售出 70 万件，接近上万单。真实性无法 100% 核实，但视频号同类机会确实存在。

宁波专升本获客案例：销售用极简数字人线索视频，仅素人讲“你是专科可报本科”，对家长转化有效。机构单成交提成一万元，两个月收入 27 万。

抖音中视频计划案例，有人做不露脸 PPT 讲解类视频，曾获高额激励，点赞 700 左右可得三四千元。当前激励是否延续不确定，但说明 AI 视频与平台激励结合时的放大效应。

三月也有圈友用 AI 视频在视频号实现数百万 GMV。整体判断是会用 AI 的人正在用效率和产能碾压不会用的人。

第五，Agent 从零到一。核心栈为 Codex、Hermes Agent 与飞书 Cli，目标是跑通闭环并做出第一个 App。并非工具罗列，而是团队踩坑后沉淀的统一方案。曾有老板愿付十万元学习，因背后的方法论与路径才值钱。学习会被简化，部分环节只需把提示词复制给 ChatGPT 即可完成。

第六，AI 第二大脑。结合 Obsidian 与自媒体流程，覆盖选题、素材收集、内容生产、分发，目标是搭建个人知识库与计算中枢。很多用户用 AI 越用越累，根源是未重构工作流。第二大脑要解决的就是工作流改造。

第七，如何做 Skill。社区过去教写精华帖，现在升级为做 Skill：把业务经验、方法论提炼成可调用技能，把经验 SOP 化后共享。

七个方向为 AI 小程序、AI 海外网站、AI 高质量影像、AI 视频带货、Agent 从零到一、AI 第二大脑、AI Skill，均与 AI 强相关且具长期性。

线下大课不讲工具堆砌，而是用 AI 原生方式重构工作流。很多人越用越累，因流程未变，只是旧流程上叠加新工具。

航海、工作台、线下课指向同一目标：不是学会 AI，而是让 AI 成为产品、工作流、Agent、Skill 与可交付成果。

### 从 Agent 黑客松到生产级产品

重要规划是 Agent 黑客松平台。企业与社群常想办黑客松却缺流程与方法。团队沉淀经验后希望产品化，方便他人组织自己的 AI 黑客松。

平台服务内外皆可。未来周末聚会可是一场黑客松，航海也可是一场黑客松。例如一万人参赛比拼谁能做出 Agent，优胜作品由赚钱分发展示甚至售卖。

创业者最缺的是首批真实用户，有初始用户才能快速迭代。作品广场的价值在于让圈友作品先在圈内获得反馈与冷启动。

#### 官网改版与白话 AI 小百科

现场展示的几项 Demo 多已接近生产级工具，可实际使用。未来一两个月官网将大改版，首页换成 AI 主页，“赚钱有数”名称也在评估是否调整，因承载内容已变化。

另有面向基础学习者的“白话 AI 小百科”在规划，用于补齐基础概念。

很多人已经把 AI 当成日常工具在用了，却对它背后的基础术语仍感到陌生。循环、Token、模型、神经网络这类词汇在公开课、直播间、产品说明里反复出现，听起来熟悉，真正讲清却很难。白话 AI 小百科的定位，就是把这些高频概念用通俗语言拆解，并搭配具体场景案例，让普通读者意识到这些名词并非高不可攀。

先把底层概念弄明白，后续理解工具逻辑、Agent 协作模式以及整体工作流的难度会明显下降。科普的目标不是学术化，而是降低心理门槛。

### 让 AI 修代码反而更乱，根因是技术判断不足

现场有提问：代码报错后交给 AI 修复，结果 bug 越来越大怎么办？

这并非单纯的模型问题，更核心的是使用者自身的工程功底与判断能力不足。连问题根源都不清楚，也无法评估模型给出的改动是否合理时，代码很容易被改得更复杂。这个阶段试错频繁，却也是成长必经之路。

做产品不必一开始就追求完美架构，也不存在放之四海皆准的方法论。早期更重要的是把能跑的版本先推出去，能用即可。等到产品跑起来后发现瓶颈，功能趋于稳定，需求也更清晰，再做一次重构往往更划算。那时你更清楚痛点，也积累了足够经验，之前 AI 没改好的片段都能变成素材。

主讲人举例，自己早期也不懂 worktree 与 Git，照样把产品跑通，后来才在实战中补齐短板。关键在于做中学，不被完美主义绑住。团队通过统一技术栈与智能体脚手架降低风险。曾有成员因线上客服产品的代码问题花了两个月重构，痛苦却也是从演示走向生产级的必修课。

### 内部围绕智能体构建的三阶培训体系

围绕智能体的生产能力，内部已形成三条递进的培养路径。

第一条是零到一的基础训练。围绕 Codex、Hermès Agent、飞书 CLI 等技术栈，带人从零做出可用的智能体。后续也会在航海里向圈友开放，团队内部同样按此方式培养。

第二条是把演示体升级为生产级产品的训练。不能仅停留在前端展示，要打通数据库、MCP、API、网络、发布、Git、Worktree 等完整链路，具备持续维护与迭代能力。

第三条是前沿探索层，涉及产品判断、AI 基础设施、循环工程等议题。核心问题包括：哪些需求真正有价值？知识库如何搭建？如何为 AI 建设基础设施？如何让 AI 管理 AI，提升整体生产效率与资源利用率？

三条路径逐级递进。第一条适合入门，第二条适合想把演示做成真实产品的实践者，第三条团队自己也在摸索，跑通后会逐步同步。整体逻辑是先改造个人工作流做工具，再尝试 C 端产品让真实用户使用，复杂度提升后再补齐技术与产品能力。学习应跟随生产节奏，而非闭门造车。

### 先跑通可演示原型，再用真实反馈决策

关于演示体的使用建议很直接：先在本地跑通，再借助飞书妙搭或 CLI 分享给同事或用户体验，原理类似 Vercel 的分享与站点功能。

分享后观察真实反馈，有效就继续开发迭代，无效就换方向。不要一上来就做完整产品，先做出可运行原型，让用户先用起来，用反馈指导下一步。这是从想法到生产级项目的关键过渡。

### Token 排行榜：用量不是全部，但用量过低难以高产

另一个项目是 AI 编程资源消耗排行榜，会抓取本地各编程工具的 Token 使用数据并聚合展示。早期一天 1 亿可进前百，现在 5 亿也不一定上榜，门槛在提升。用户可在 Cursor、Windsurf、ProCode 等工具中统计日使用量，日消耗数亿已属高强度。

需要强调的是：用量高不等于能力强，但用量过低大概率说明工作流尚未重构。真正把大量工作交给 AI 参与开发与生产，用量自然会上升。排行榜的意义不是炫耀数字，而是通过数据倒推工作流是否发生变化。

### 用用量倒逼工作流重构

顶级玩家的日常用量已非常夸张：榜单第一 45 亿，第二 38 亿，第三 34.7 亿。包子老师复工后上午测试 Remotion 视频流程就用掉十几亿，李香君、小排老师也在 18 亿左右，李香君同时在跑十个项目。

这组数据的价值在于提供参照：用量不等于厉害，但不使用大概率不厉害。高强度使用者会在持续交互中完成大量任务、调整架构、拆解需求、重构流程。哪怕每天稳定消耗十亿，也值得重视，背后一定有任务管理、工作流设计与多线程执行能力。

可为自己设定阶段目标：先把日使用量拉起，如每天投入一到两小时，主动询问 AI 今天该做何事、如何安排任务达到目标用量、工作流哪些可外包、哪些任务可并发。先把使用强度做上来，再找边界。用量上去后，你才会明白哪些任务有价值、哪些流程需重构。

资源排行产品六月上线，已有 1600 多名圈友上榜。早期因架构与采集问题出现过重复计算，后经重构才稳定。这个过程本身说明做产品必然踩坑，只有持续重构才可靠。

### AI 时代的核心是并发生产能力

AI 时代衡量标准不再只是会不会用某个工具，而是同时在运行多少项目、多少线程。

过去很多人习惯单线程，AI 时代拉开差距的是多项目并发生产。OpenClaw 创始人 Peter 一台电脑同时开近 40 个线程，更多任务分发到多台设备，总线程数可能达百级。这不是靠人脑硬扛，而是 AI 在管控。

背后对应的是 Lookup Engineering 能力——以工程化方式让 AI 管理任务、拆解流程、推进项目、持续反馈。当这项能力形成，就能并发运行多项目，生产能力与判断力被放大。

因此要先学 AI 编程与工程，不是为了人人都变程序员，而是没有工程能力，判断力无法放大。仅有直觉与审美，无法变成系统与产品，最终仍难突破。用量在早期像虚荣指标，但先达到一定量级是必要的：它逼你重构工作流，从单线程走向多线程，逼你让 AI 接管更多任务。过了这关，才能判断哪些消耗有价值。

### 不要在模型与用量上过度省钱

很多人担心日消耗十亿成本高，实际情况不必靠 API 烧钱。榜单高消耗用户多用订阅额度，200 多元的订阅账号基本可支撑日消耗数亿，不足时可通过多账号或重置方式扩展。

核心提醒是：再省也不能省 Token，再穷也不能穷模型。想提升能力，就不要在模型与额度上过度节省。能用更强模型就用更强模型，能用适合编程与任务执行的工具就用。

不少人觉得 AI 无用，是因为模型不够强或使用方式停留在浅层对话。国产模型各有优势，但若从未用过 Claude、Codex、Claude Code 这类适合复杂任务与代码执行的工具，对 AI 的认知会完全不同。

现在关键不是只会打开聊天窗口提问，而是把 AI 嵌入工作流。Codex、Claude Code 这类工具的使用熟练度，已成为理解 AI 边界的关键。公司内部也可搭建中转服务，分享者所在公司内部日消耗约百亿 Token，专业技术同事日消耗五六十亿，预计未来可能达千亿级别。对个人而言，优先建议购买靠谱订阅，少走质量不稳的中转站。

### 判断力与工程力需同步提升

多项目并行时，稀缺的不仅是执行力，更是判断力。需要持续做取舍：是否做这个功能？何时做减法？何时重构？何时砍需求？没有产品判断力，多线程只会手忙脚乱。

推荐张小龙的产品观：极度聚焦，做减法，在核心能力上放大。下一步要提升两件事：产品判断力，可读《微信背后的产品观》，理解克制与聚焦的价值；工程能力，深入研究 HALLIS、Mook 等工程方法，把 AI 工程能力推上台阶。

两者是乘法关系。在少数聚焦领域做深做透，再用工程杠杆放大。未来一个人有可能做到千倍强，因为能服务过去几百人才能覆盖的需求，能为圈友做数千个产品，能把重复繁琐流程交给 AI 执行。前提是既有判断力，也有工程化能力。

### 万事先交给 AI，从小事重塑习惯

AI 不应只在大项目时才出现，而应进入日常每个环节。比如整理发票，过去需手动找邮件、下载、归类、制表，现在直接让 AI 帮你下载并整理成飞书表格，离开电脑两小时回来就完成。

重点不是技术多复杂，而是习惯改变。第一反应先问：能不能让 AI 做？尤其是想偷懒时更应让 AI 做。今天记住一句话：用 Codex 帮你处理任何事务。不是只写代码，而是整理资料、拆解任务、生成脚本、下载文件、做表格、跑流程、写产品、改后端、迭代功能。习惯越早建立，进入 AI 工作方式越早。

这也是赛道焦虑的解法。AI 做小程序的参与者可能很多，但能长期迭代、推到生产级的人不多。与其担心别人做，不如关注自己能否持续用起来。

### 未来三类核心人才，都需具备自研智能体能力

未来最有价值的人才大致分三类：

第一类是 Owner，即老板、操盘手、负责人，能对结果兜底，推动结果，具备创业机会。

第二类是 Agent Builder，能开发、迭代、维护智能体，把需求变成系统，把经验变成可运行智能体。

第三类是 IP 或 Influencer，能沟通用户、建立共情、影响用户。

无论哪类，若自己不会开发与使用智能体，效率会受限。竞争对手一旦自研智能体，你会慢慢掉队。包子老师既是 IP 也是 Owner，他学会 AI 编程后给自己做了大量功能，视频内容可全自动生成并发布到抖音。短短两周围绕高考志愿赛道做出近百条视频，每条数百到数千赞。这不是个人对抗，而是系统对抗。

所以无论是 Owner 还是 IP，都不能长期依赖别人。每个人都要往后端走，去开发智能体、维护智能体，把业务流程沉淀成系统。

### 进后端是能力跃迁最快的方式之一

很多人没真正进过后端，也没独立上线过产品给用户用。但一旦做过一次，能力跃迁明显。分享者在六月开发 Token Rank 产品时一天提交近四十次代码，从凌晨五点到晚上十一点，AI 协助中也有大量试错、修复与重构，正是这次经历让能力明显提升，也建立了信心。

信心不是听课听出来的，而是做出产品、用户用起来、修掉 bug 后长出来的。AI 做小程序、网站、App、生产级产品都会碰到后端问题。刚开始不懂没关系，跟着做、跟着错、跟着迭代，积累到一定程度就能承接更复杂项目。

年龄不是限制，二十岁、四十岁、六十岁本质无差别。四五十岁的人有经验、有判断力、有资源，叠加 AI 可能更适合转型。AI 能弥补体力短板，放大经验与创造力。

五十岁也可以是创业正当时，四十岁依然很年轻。

## 12.8 掌握 Codex，可能是普通人拥抱 AI 的最快入口

如果要把这一阶段最重要的建议浓缩成一句话，那就是：先把 Codex 用起来。

不必一开始就研究复杂的技术栈，也不需要先证明自己是“懂技术的人”。先从实际使用开始，等你真正用上一段时间，就会发现这个选择可能比想象中更有价值。

掌握 Codex 后，至少可以走向两个方向。

**第一条路，是自己做产品。**

你可以从一个轻量项目开始，比如小程序、网站、App，或者团队内部使用的效率工具。先做出第一个版本，再不断测试、优化、推广，逐步跑通从想法到产品、再到市场的完整链路。

**第二条路，是把能力提供给企业。**

如今很多企业并不缺少“听说过 AI”的人，真正缺的是能把 AI 接入业务、做成工具、落到流程里的人。你可以进入企业工作，也可以作为外部服务者，为老板、团队和公司提供 AI 化解决方案。

市场已有相关报告显示，FDE 类岗位的日薪大约在 2000—4000 元之间。但真正拥有工具开发和落地能力的人仍然稀缺。如果你既能熟练使用 AI，又具备较强的理解、判断与解决问题能力，就有机会为身边的企业创造实际价值，并获得相应回报。

不过，如果目标是更深入地成为 AP 或 FDE，只会制作简单 Demo 远远不够。企业需要的是能够进入真实生产环境的能力，而不是只能展示效果的样品。

这意味着你需要学习 AI 编程，理解后端，能够把一个想法真正接入生产流程。现在网上有不少免费课程可以入门；如果希望系统训练，也可以通过 AI 编程生产圈、航海实战训练营等项目，在老师带领和真实任务中学习。

这类训练的重点不是把概念听懂，而是把成果做出来。比如：

- 用 AI 开发国内小程序；
- 用 AI 搭建海外网站；
- 用 AI 制作高质量视频；
- 用 AI 做视频带货；
- 搭建企业知识库；
- 为 Agent 打造专属 Skill。

真正值得投入的方向，应该经过筛选：尽量保留那些不能再删、学完能够立刻产生实际结果的内容。

## 12.9 别只追着短期收益跑，先把创造价值的能力练出来

有人可能会问：如果十个人里，最终只有一两个人能在短期内赚到钱，那普通人为什么还要参与这些 AI 项目？

答案是：不要把注意力全部放在眼前的收益上。越是急着赚钱，越容易忽略真正决定长期收入的东西。

短期来看，有的项目会带来回报，有的项目可能暂时没有结果；但放到更长的周期里，收入最终还是会回到一个基本规律上：你能够创造多大价值，就会获得多大回报。

在 AI 时代，创造价值的能力，越来越集中在以下几个方面：

- 处理和吸收数据、信息的能力；
- 熟练使用 AI 的能力；
- 把 AI 嵌入产品与业务流程的能力；
- 开发、维护和持续迭代 Agent 的能力。

所以，学习 AI、制作 Agent、利用 AI 开发产品，并不只是为了某一个项目赚到多少钱。项目可以作为训练场，让你更接近结果，但更重要的是，在一次次实践中把能力真正沉淀下来。

从长期看，会做 **Agent**，比某一次短期盈利更重要。无论你将来选择就业、接企业服务，还是自己创业，都需要这套能力作为基础。否则，即使偶然通过某个项目赚到钱，也可能很快因为无法持续交付而失去竞争力。

## 12.10 对上班族来说，AI 能力会成为新的职场稀缺资源

AI 并非只属于老板、创业者或超级个体，普通职场人同样需要，而且越早掌握越有利。

在相关学习和生产群体中，打工人可能占到四成甚至更多。很多人暂时不打算创业，也不准备立刻离职转型，但这并不妨碍他们学习 AI。恰恰相反，如果一个员工能够把 AI 真正用进工作，竞争力会明显提升。

企业需要的不是只会和聊天机器人对话的人，而是能够把 AI 连接到业务、流程、工具和最终结果中的人。谁能提供别人难以替代的价值，谁就会在职场供需关系中变得更加重要。

因此，对大多数上班族而言，最稳妥的方式不是马上辞职，而是先在现有岗位上增加自己的不可替代性：

- 用 AI 提高产出；
- 优化日常流程；
- 自动化重复工作；
- 承担更复杂的任务；
- 把原本需要多人完成的工作压缩到更短时间。

当你能完成别人无法完成的事情，职场价值自然会上升。

## 13 从内容社区走向 Agent 平台：AI 时代的组织升级与个人跃迁

### 13.1 赚钱未来的两条主线：Agent 平台与 FDE 人才服务

接下来，赚钱希望从单纯的内容社区，逐渐升级为一个“成果工作台”。

过去，平台主要向用户提供信息和内容；未来，更重要的变化是通过 Agent 直接向用户交付结果。这个方向曾经只是设想，如今已经开始进入落地阶段。未来一两个月内，平台希望推出一批可以直接使用的 Demo。

内部已经率先搭建了一个自媒体平台，相关团队成员都开始尝试做自媒体，其中已经有人制作出了爆款内容。如果这套系统能够帮助公司内部高效开展自媒体业务，未来就有可能进一步服务整个社区。

平台希望把这种能力产品化，把结果交到用户手里，而不只是提供一堆需要自行消化的信息。

AI 主页的 0.1 版本已经上线，目前仍在快速迭代。未来的赚钱，可能会呈现出一种全新的形态：

- 航海不再只是需要用户自行阅读的项目手册；
- 用户可以直接跟随航海 Agent 执行并获得结果；
- 做短视频、网站、小程序、👸号文章、抖音项目、星图等，都可以调用对应的 Agent；
- 项目背后会整合大量 Skill 与 Agent，直接为用户提供能力支持。

本次航海已经出现了一个重要变化：会提供大量 Skill。接下来，平台会围绕不同项目继续沉淀和整合 Skill、Agent，让用户不仅能学习方法，还能直接调用工具完成任务，再将成果发布到目标平台。

因此，赚钱正在推进的第一条战略主线，就是从内容社区走向 **Agent 平台**，利用 **Agent** 直接交付结果。

第二条主线，是培养和服务 FDE 人才。

平台会帮助圈友掌握 AI 技术、相关知识与实际能力，再通过项目训练将能力转化为成果。同时，也会连接外部企业资源，让具备能力的人可以接企业项目，帮助企业完成 AI 化服务。

现在已经有不少企业在询问：

- 有没有合适的 FDE 人才？
- 有没有人能够帮助企业完成 AI 改造？
- 有没有可以直接交付结果的服务者？

但市场现实是，需求远远大于供给。内部虽然已经出现这类人才，却连自身需求都还无法完全满足，更不用说大规模服务外部企业。

许多企业都有 AI 化升级的需求，但市场上还没有足够多的人能够真正进入企业、理解业务并完成改造。

因此，赚钱的第二个战略方向，就是帮助圈友成为 FDE：掌握 AI 技术，既可以自己开发 Agent，也可以为企业提供运营、自动化和业务改造服务。

这不是一个只存在几个月的风口，而是至少持续十年的长期机会。中国拥有数量庞大的企业，它们未来都需要进行不同程度的 AI 转型。如今，真正懂 AI、懂工具、懂业务落地的人依旧很少。

即使赚钱的 3 万名会员全部成长为 FDE，市场仍然可能处于供不应求状态。

也不用过分担心大厂的竞争。中国市场足够庞大，个人和小团队在寻找机会时，不应把“大厂会不会做”当成首要顾虑。下一个时代仍然会诞生新的大公司，机会不可能全部被今天的大厂提前拿走。

许多大厂目前只是把 AI 叠加到已有产品上，主要目的是维护原有用户和业务，并不完全等同于真正的 AI Native。相反，围绕 **Agent** 原生构建的新机会，可能更适合小团队和个人切入。

### 13.2 企业 AI 转型，老板必须成为第一责任人

企业要进行 AI 化升级，不能只把任务交给员工，也不能简单外包给第三方机构。最关键的人，始终是老板。

老板必须亲自学习、亲自使用 AI，真正理解 AI 的边界。

只有深入实践过，老板才知道：

- 哪些事情 AI 能完成；
- 哪些事情现阶段仍然做不到；
- 什么要求是合理的；
- 什么标准过高或过低；
- 员工说“做不到”时，问题究竟出在哪里。

如果老板自己都不了解 AI，就很难给团队提出有效要求，也无法判断员工是真的无法完成，还是根本没有认真尝试。

当老板能够用 AI 完成后端工作、并行推进多个项目时，才有底气告诉员工：我能做到，你也可以做到。企业的深度 AI 改造，往往从这里开始。

目前团队内部提出了一个非常激进的目标：

- 过去 30 天完成的事情，尝试压缩到一周；
- 过去一周完成的事情，尝试压缩到一天；
- 到 8 月底，希望部分 Agent 工程师达到稳定的 10 倍产出；
- 也就是说，一个人可以同时运行 10 个生产进程。

团队内部已经有人展现出这样的趋势。一旦标杆出现，其他成员就会有清晰的参照，整个组织也会逐步向更高标准靠拢。

当每个人每天都能稳定调用大量 Token、调度多个进程时，企业的生产效率会发生巨大变化。一个人的产出，可能抵得上过去一个小团队；几十个人的总和，则可能相当于过去数十个生产团队，甚至上千个生产单元。

所以，AI 工程能力和 AI 编程能力不应再被视为程序员的专属技能。只要是对未来还有期待的老板和职场人，都应该尽早掌握。

它有点像早期的互联网。那时上网需要配置路由器、拨号网络，很多人因为不会设置而无法接入。今天学习 AI、使用 Agent，也存在类似的起步门槛。越早完成入场，越早获得优势；等所有人都熟练之后，这种能力就不再稀缺。

FDE 的能力基础主要有两部分：

1. 服务者自身具备扎实的业务能力；
2. 能够以 AI Native 的方式完成企业改造。

未来，优秀的 FDE 很可能来自各个行业的一线经营者。因为企业 AI 化并不是简单添加几个工具，而是需要理解行业上下游、业务流程、客户需求和真实经营场景。

比如夜息原本就是珠宝行业的老板。当他判断珠宝行业未来几年的增量有限后，开始转向 FDE，为电商企业提供 AI 化改造服务。

由于他已经在自己的企业里实践过 AI Native 改造，拥有真实经验和可复用的方法，因此更适合帮助同行或相关企业完成升级。

未来，每个行业都可能出现属于自己的 FDE：他们既熟悉行业业务，又懂 AI 工具，还能把真实案例、判断标准和审美能力反过来提升自身业务。

### 13.3 年龄不是门槛，不会代码也能进入 AI 产品时代

AI 学习并不只属于成年人，也适合更年轻的人群。

高考结束后的孩子，如果拥有一段相对充裕的时间，可以尽早接触 AI。初中生、高中生、大学生，都可以学习 AI、尝试制作 AI 产品。

甚至五岁的孩子，也可以从制作简单的 AI 小游戏开始。

例如，让孩子用语音说出自己想做什么，并尝试把需求分成第一步、第二步、第三步；等 Demo 做出来后，再继续询问她想如何修改。这个过程能够帮助孩子建立一个重要认知：

只要需求表达清楚，就有机会把想法变成产品。

随着年龄增长，还可以进一步带着孩子尝试产品包装、用户反馈和商业化。

过去的线下课程中，也有高中生参与，并获得了不错的收获。对孩子来说，提前了解 Agent、亲自做一些小项目，本身就是非常有价值的起点。

至于很多人担心的“不会代码能不能学 AI 编程”，答案同样是肯定的。

Token revenue 产品就是一个案例。在整个制作过程中，没有写过一行代码，甚至没有阅读过一行代码。真正决定能否做成的，并不是是否会读代码，而是有没有足够的判断力。

当然，过程中仍然需要逐步理解基本的技术架构。但当你拥有清晰的判断能力后，并不一定要亲自编写或检查每一段代码。代码只是逻辑的具体表达，而 AI 可以协助完成实现。

这个时代更重要的能力，是理解逻辑、识别问题、做出判断，以及知道一个产品应该解决什么问题。

### 13.4 企业 AI 化落地的三阶段

团队推动 AI 改造，可以按照三个阶段逐步展开。

#### 第一阶段：老板先掌握 AI

老板需要具备 AI 编程能力，能够利用 Codex 或 Claude Code 做出生产级项目。

如果老板自己完全不懂 AI，就无法真正推动组织变化，也不能指望员工替老板完成管理层面的 AI 升级。老板需要主动学习、连接高手，并不断提升自己的判断标准。

#### 第二阶段：让所有员工尝试使用 AI

这一阶段不要过早设置过多限制，而要尽量提供基础支持，包括：

- Token；
- AI 账号；
- 网络环境；
- 电脑设备升级；
- 必要的学习和试错资源。

过去半年，团队内部一直鼓励成员探索，AI 账号可以报销，设备需要升级也可以申请支持。

在这个阶段，员工会出现各种各样的尝试，但公司业务未必马上发生明显变化。个人效率提升后，节省下来的时间也不一定会立刻转化为新增产出。

这并不意味着尝试无效。第二阶段的任务，首先是让员工把部分个人工作压缩掉，建立使用 AI 的习惯。

#### 第三阶段：统一技术栈，打造内部标杆

当前团队统一使用的技术栈包括 Codex、Hermes 和飞书，并围绕这套技术体系设计了三类训练：

- “三道剑”：帮助所有人具备制作 Agent 的能力；
- 生产级流程课程：让每个人都能参与产品开发；
- 10 倍产出训练：让每个人都能稳定调度多个进程。

与此同时，团队还需要持续沉淀优秀的 Agent 与 Skill。

内部已经搭建了类似 Agent 导航和 Skill 导航的平台，并建立评价机制，对优秀作品和贡献者进行整理、展示与激励。

这样一来，团队成员能够看到什么是好标准，也会自然形成学习氛围和竞争压力，推动更多人研究 Skill、Agent 以及产品开发方法。

此外，内部还设立了 AI 局小组，每天交流 AI 的新用法、新工具和新玩法。许多有效的方法，都会在持续分享和实践中逐步出现。

因此，团队 AI 化不是单向命令，而是一个循环过程：

1. 老板先亲自实践，理解方向与边界；
2. 全员开始自由探索；
3. 组织逐渐形成技术规范；
4. 好的 Agent 和 Skill 不断涌现；
5. 再把优秀案例推广到更多业务中。

### 13.5 未来真正拉开差距的，是调度 Agent 的能力

未来人与人之间的差距，可能不再主要体现在谁更勤奋，而在于谁能同时调度更多 Agent。

沈龙潇创始人就是一个明显案例：他可以并行调动上百个 Agent。这个能力看起来非常夸张，却也提供了清晰的方向：

- 如何创造更多 Agent；
- 如何让 Agent 分工协作；
- 如何同时调度多个 Agent；
- 如何让它们替自己完成工作并持续创造价值。

现阶段，与其只埋头做单个项目，不如投入时间建立自己的 Agent 系统。

今年 418 时曾经提出过一个观点：如果工作阻碍了你学习 AI，就应该考虑辞职学习 AI。现在这个观点依然成立，只是 AI 已经不再是抽象概念，而是具体落在 Agent 上。

如果老板年龄较大，或者缺乏耐心学习，也不必简单归因于年龄。很多时候，没耐心是因为迟迟看不到结果。

解决方式可以有两种：

- 找一位 AI 助教，进行贴身辅导，让学习者尽快获得正反馈；
- 进入集体学习环境，在老师带领下完成实操，通过白天课程和晚间自习保持持续投入。

人在什么环境里，就容易形成什么状态。好的环境，往往能够显著降低坚持的难度。

### 13.6 进入“想到就能做”的创造阶段

仅仅两三个月前，还有大量工作无法由 Agent 协助完成；而现在，越来越多的工作已经可以交给 Agent 参与。

一旦进入正循环，你会明显感受到自己的能力在快速迭代：每隔一两个月，都会像换了一个人。两个月前的自己，和两个月后的自己，可能已经不在同一个能力层级。

这不是错觉，而是创造能力的真实增长。

过去，你可能只有一个模糊想法；现在，你能够把它做成 Demo。过去，你只能设想一个产品；现在，它可能下个月就能被真正开发出来。

我们正在进入一个新的创造阶段：只要想法足够清晰，就有机会把它变成现实。

可以把它概括为四个字：**言出法随**。

你提出目标，AI 负责协助实现。真正需要学习的，是如何让 AI 更快、更稳定、更可靠地完成任务。

有些人会担心 Token 的成本，比如每天消耗几亿甚至十几亿 Token，似乎价格很高。但如果这些 Token 最终创造出了有价值的产品、内容或业务结果，它依然可能是极其便宜的。

过去要完成同样的事情，可能需要组建一支庞大的团队。如今，真正稀缺的未必是 Token，而是高质量的想法和准确的判断。

而判断力不会凭空出现，只能从实践中长出来。

你需要亲自下场，持续尝试、不断犯错、及时复盘，再继续行动。真正有效的学习，不是只看教程，而是在一次次动手中获得反馈。

如果一定要把 AI 能力成长路径压缩成一句话，那就是：

**持续动手，把 Codex 用好，是当下最值得走的一条路。**

### 13.7 关于方向、工具与后续学习

如果参加过几次线下活动，尤其是在大航海之后仍然感到迷茫，不知道下一步该做什么，可以先不要追求同时掌握所有方向。

本次航海已经提供了 7 个方向，你可以先选一个真正感兴趣的领域作为切入口。最重要的是先把 AI 用起来，让它进入日常，也可以把探索 AI 当成一种兴趣。

工具方面，如果已经能够熟练使用 Coze，其他类似平台不必全部学习。

不过也要注意，Coze 目前的使用体验还不算特别成熟，产品方向仍在变化：有时重点推 Skill，有时又更像验证工具，整体仍处在持续调整阶段。

更值得优先投入的，是 Claude Code、Codex 这类更强的工具。可以看到，Codex 与 Claude Code 的发展方向正在逐渐接近。

既然已经有更强的选择，就先把强工具真正用深、用透，不要把时间分散在大量次级工具上。

不建议再把主要精力放在 N8 上。与其不断追逐新工具，不如围绕高质量工具和 Agent 工作流，真正建立稳定的生产能力。
