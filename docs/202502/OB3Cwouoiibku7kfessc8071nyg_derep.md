# 零代码背景也能靠AI撸出Python算法，把费比管得更准



大家好，我是来一，正在一家年营收破百亿的电商公司担任数据产品负责人，平时特别喜欢把AI大模型的落地玩法琢磨透。之前已经连载过几篇实践笔记：

这次想聊聊我最近的一个实战：借助AI大模型生成Python算法，并把这套算法直接用在真实投放决策上。

乍一听是要写代码就想跑的同学先别走，这次真的是让AI代写，我们本人不碰键盘，也不必去啃算法原理。

## 实战复盘

### 起点

我现在负责电商这边的数据产品，之前是从K12在线教育创业起家，侧重教研设计和私域转化。两年前入行电商时自学过一点Python，能看懂基础语法，但离开手写代码已经超过两年半，自认已经不具备独立编程能力。

网购的日常大家都懂，运费险、退货率这些名词不用解释。作为电商，核心经营指标里有一项很关键，就是费比，即投放费用除以销售额，本质上是ROI的倒数，也能理解为日销单元模型的简化版。

眼下大盘承压，公司更关注真正到手的利润，于是大家开始盯退后费比，即投放费用除以剔除退款后的销售额。

举个例子，昨天产生了1万元销售额，但这笔钱最终能留下多少，今天根本说不清。因为退款会持续发生，可能拖到15天、25天甚至更久。业务却需要立刻根据昨天的退后费比来决定今天要不要加码投放、要不要收手。

于是业务方向我们抛出了一个需求：能否在今天就给出昨天订单的最终退后销售额预估。

公司内部并没有专门的算法团队，但这个指标直接牵动投放节奏，重要性极高。

放在两年前，我可能会犹豫很久。恰好去年就有几次AI落地的正向体验，自己也对探索型任务挺上头，好奇大模型在这类问题上能做到什么程度，最后这个活就落到我头上了。

这回难度明显升级：

1. 数据安全难以保证。这些是公司真实的销售数据，体量不小，无法直接上传给大模型；
2. 业务复杂度高。不同品类、不同销售节奏，比如大促期与平销期、不同渠道平台，情况各不相同。

受限于这两点，再加上我自己已经不写Python了，唯一可行的路径就是让AI来写代码。

于是核心问题变成：怎样指挥AI大模型写出符合我业务的Python算法。

### 踩过的坑

目标明确后我马上开干。去年写过数据处理的提示词经验，这次依旧照搬套路。

![](img/c117e51ca1c95d5b264d72c55003e3c1.png)

AI很快给出了代码，跑通了，表面看✅成功。

随后发现一个致命点：我根本判断不出运行结果是不是业务想要的。因为每日退款率本身是预估值，我没法验证对错。

![](img/f17aafc39efb30c1d18a2ca52f5ba1ed.png)

更糟的是，因为代码功底薄弱，即便结果偏差，我也找不到问题所在。整段程序对我而言就是黑箱，看不懂在干嘛。当时真的很卡、很焦虑。

* 这个需求到底还能不能交付？
* 是模型不行，还是我不行？

我习惯先自查。复盘后发现三处卡点：

* 问题一：代码全由AI生成，我对内部逻辑一无所知；
* 问题二：代码量庞大，阅读成本高，看起来很痛苦；
* 问题三：输出质量好坏缺乏判断依据。

回想自己平时跟技术同事提需求的流程，为什么他们能落地，我却被AI卡住？总结出两点关键：

1. 给技术同事的需求文档，必须写清楚要什么数据、数据来源、计算逻辑；
![](img/532970f8b26466964aeb5053b448483a.png)
2. 无论是对AI还是对人，表达必须逻辑严密，模棱两可的地方最后一定会返工。

我意识到，数据流转全貌不搞清楚，AI就很容易按自己的理解乱处理。

针对上述三点，我开始想办法：

问题一：因任务链路过长，AI需要自主决策的部分太多，我看不到细节。
对策是把整条数据处理链路拆得更细，把每个模块的处理规则讲明白，让AI严格按步骤执行。

我也发现自己心里有侥幸心态，觉得只要说明白输入输出，AI就能自动给出正确答案。实际上复杂项目里，如果我自己都没理清逻辑，就指望AI撞大运，下属也做不好。

另外一个认知是：只要提示词够清晰，AI一般不会瞎写代码。

问题二：代码太多看不懂，也提不起兴趣看。
那就让AI给每段代码加上通俗注释，我就能知道每一步在做什么，从而判断思路是否合理。

问题三：预测结果不好判断对错。
数据逻辑本身是确定的，对就是对，错就是错。难判断的只是预测环节。历史数据已经超过25天，我可以算出真实的退款金额，所以可以先验证除预测外其余环节是否正确。

我的验证标准是：「T+25的预估退款额」和「25天后实际的退款额」是否一致。历史数据能对照，逻辑就通了。

2. 过程复杂就继续拆，按流程拆或按模块拆
3. 能精确就精确，能具体就具体

### 经验沉淀

1. AI大模型的编程能力很强，哪怕是零基础小白，也能借助它写出业务需要的程序；
2. 要想写出可用程序，需要做足准备。

| 准备项 | 说明 |
| 探索AI大模型的边界 | 方案设计和代码实现都可以交给模型 |
| 需求描述清晰 | 明确自己到底要什么 |
| 提示词表达准确 | 让模型明白实现路径 |
| 具备拆解和分步实现能力 | 做不到一次完成就拆成若干步 |

* 这个项目是去年完成的，如果现在用Cursor和Windsurf，效率估算能再提升三成以上。

## 小白如何“用”AI写程序

最近我一直在思考，对于编程几乎零基础的人来说，用AI写程序会卡在哪，以及哪些前提信息必须掌握。

如果你已经有使用意愿并能稳定上网，下面这些问题很可能遇到：

### Q1：选什么工具做AI编程？

建议直接上Windsurf或Cursor这类专业IDE，能省去大量环境配置麻烦，在引导下快速从环境到运行。

### Q2：编程环境要怎么配？

选对工具基本就解决了。Windsurf、Cursor都是现成的方案；也可以装Anaconda，配置也十分简单。

Windsurf下载链接：https://codeium.com/windsurf

Cursor下载链接：https://www.cursor.com/

Anaconda下载链接：https://www.anaconda.com/download

### Q3：AI编程提示词怎么写更好？

提示词拆解要点

1. 明确输入、输出、处理过程
2. 过程复杂就按流程或模块拆分
3. 精确到尽可能具体的程度
4. 提示词很长时分段喂养，每完成一块再继续下一块

### Q4：完全不懂编程能做吗？

零基础可以上手，但要清楚：

* 哪些问题适合用程序解决，哪些不适合
* 如何写提示词让AI处理
* 出现报错后如何借助AI修复

### Q5：程序报错怎么办？

直接把报错信息发给AI，让它自行修复。

![](img/08356b275d5a67072dfc647b185b1328.png)

![](img/b144215600164361fc0f78221076d49e.png)

小技巧：在提示里加一句“请考虑运行报错的可能性，并把错误信息完整展示出来”。

### Q6：反复尝试还是不行？

先定位模糊点，迭代提示词。若对话过长导致模型遗忘，果断新建对话，从头逐步搭建逻辑。

### Q7：看不懂代码怎么办？

让AI给每一行代码加上大白话注释，就能明白每一步在做什么。
