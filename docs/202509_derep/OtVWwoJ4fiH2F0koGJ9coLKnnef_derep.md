# 用 n8n 搭了一套焦点新闻自动采集管道：从需求到落地全复盘

我是越越。这篇文章记录的是我用 n8n 完成新闻采集小项目的过程，从零开始到跑通大约花了半天。先感谢星球里的教练和作者们，你们的教程和实战经验让我学到很多。

## 起因与目标

有圈友在做垂直小号矩阵，需要稳定获得焦点资讯。我的想法是：让系统每天自动访问若干资讯源，抓取全球范围内的重点报道，再写入飞书 Base。因为后续要给矩阵工具用，这套程序得能承受较大的并发访问量，还要有不错的容错能力和长期稳定性。

说实话，我在接触 n8n 前没有任何流程编排经验，编程也是零基础。能这么快跑通，主要靠 n8n 航海期间的材料和 Youtube 深海圈的氛围。我现在已经能通过 Youtube 月入 5000 美元，学 n8n 是想给圈友做点工具，也想继续拓宽收入来源。

## 动工之前，把四件事想明白

### 目标定义

以前我每天都要在多个新闻站点和搜索引擎之间人工检索关键词，又慢又容易遗漏。我希望做到：早晨六点系统自动启动，访问预设的资讯源，抓取与关键词相关的报道，把标题、简介、原始链接整理成简报，再推送到飞书 Base。这样我一到公司，就能直接看到当天的信息摘要。

### 人工环节有哪些

把一切交给机器并不等于不用管。我梳理出三个必须人工处理的点：
- 搜索关键词，需要结合业务方向来定。
- Base 中的字段结构，比如标题、来源、发布时间、链接。
- 自定义代码的格式，如果流程里要写代码，我会先用 Gemini 定好逻辑。

### 账号与接口准备

n8n 使用在线社区版。数据接口我准备了 GNews、NewsAPI、Mediastack 三家候选。如果不知道选哪个，可以让 AI 帮你推荐。下面是我用的检索提示词：

### 新闻接口调用说明

GNews 的搜索类接口是 GET 方式，主要传两个参数：关键词 q 和密钥 apikey。具体域名、路径和申请方式可以看官方文档，我这边就不重复贴完整地址了。

NewsAPI 同样是 GET，参数包括 q、from、sortBy、apikey。from 表示起始日期，把 sortBy 设为 popularity 就可以按热度排序。

![](img/fa50a71cad6d61feda0af808abaf0bad.png)

流程里还需要接入一个 AI 节点，所以还要准备模型接口的 Key。我选了第三方中转，到中转平台申请 Key 后，填进 n8n 的 AI 节点即可。

数据采集类流程的通用结构是：

## 先看整体链路

这套自动化可以浓缩成六个环节：设定启动方式、抓取外部内容、精简字段、汇聚多路来源、让 AI 做语义加工、最终入库飞书。下面按实际接线顺序，把每个关键组件拆开讲清楚。

### 环节三：把返回结果梳理成可用字段

HTTP 请求拿回来的通常是一整坨 JSON，直接拿去给下游用并不友好——字段层级深、无用信息多，后续取数会很别扭。

这时可以用 Set 节点（也常叫 Edit Fields 节点）做一次瘦身：只留下真正会用到的标题 title、链接 url、摘要 description，其余冗余内容一律丢到一边。

![](img/8ddd54a5eb2e3d0135ad6224a019f63c.png)

具体操作很简单：双击节点改名为“整合字段”，切换到手动手映射模式，然后把需要的字段直接拖进下方的映射区域。

![](img/7d1d8ea1923a08b01842169a83dbbe2b.png)
![](img/0716978ed35cecf22186d06cae825212.png)

拖完之后千万不要跳过验证这步，点击“执行此步骤”跑一遍，确认输出正确。

调试时还有一个便利功能：输出框右上角有枚图钉，点一下就能把上一轮的输出结果固定在界面上，后续反复调整逻辑时方便对照。

![](img/14a5bd2ba6bb40162991f6e41ca58d77.png)

另一条分支也按相同方式配置，但必须留意：各家 API 返回的结构并不相同，所以不要图省事直接复制节点，重头配一遍参数才能避免运行报错。

![](img/289ff46b95ccd8b351cb0da23f70fdf7.png)

### 环节四：把几路来源汇成一条流

既然两边都在采数据，后面步骤希望面向单一数据源操作，就需要先把两路结果归拢到一起。这一步交给数据合并组件来完成。

![](img/5cecc6b0099d99490da041cd58506137.png)

它会接收多个分支的输出，最终合成一个完整的条目集合，供下游统一消费。

![](img/972db5098661677cab04476a03c069c5.png)

Merge 节点提供了四种工作方式，各有各的脾气：

**第一种：Append（追加）**
这种模式最直接。它等所有上游分支都执行完毕后，先取第一路的所有条目，再把第二路接在后面，依次往后排，最终交付一条长列表。好处是简单可靠，适合“多个关键词分别抓完，再汇总成一批”的场景；也适用“两个接口分别返回用户名单，想拼成一份总名单”的情况。

**第二种：Combine（合并/配对）**
它和追加不同，会把不同分支的条目“对号入座”。配对依据可以按位置来：第一路的第一条对上第二路的第一条，第二条对第二条；也可以指定一个匹配键：比如两边都含有的 email 字段，或者订单号，节点会自动把相同键值的条目捏成一条。典型场景是：一份数据只有用户基本信息，另一份里有同样的用户 ID 和对应的订单记录，用 ID 做键，就能把两边信息拼成一张完整档案；再比如产品列表和库存列表，用同一个商品编码，即可在同一条记录里看到商品信息和实时库存。

**第三种：SQL Query（SQL 查询）**
这是 Merge 里的“重型武器”。n8n 内置了 AlaSQL——一个可以在浏览器/Node 环境运行的 JavaScript SQL 引擎，所以你能直接拿 SQL 语法来操作 JSON 数据，SELECT、JOIN、GROUP BY 都支持。什么时候会用到它？比如要做 LEFT JOIN（左分支数据全保留，右边的匹配不上就补空值）、合并前先按条件过滤或排序、或者需要分组聚合。当前两种模式满足不了逻辑时，SQL 模式就是兜底大杀器。

**第四种：Choose Branch（选择分支）**
它本质上不做合并，而是充当“同步闸口”：等所有上游全部完成后，只挑出指定分支的那一路数据放行，其他忽略。听上去有点奇怪，但实用场景不少——比如 A 分支在创建文件夹，B 分支在处理数据，你希望文件夹建好之后数据再继续向下走，这时候在中间插一个选择分支节点，就能确保前序任务是真正完成而非只是发出请求。

### 环节六：把 AI 的“散文”改写成“表格”

大模型的输出往往是一段连贯的自然语言，比如“王芳，邮箱 wangfang@example.com，她的评价是：很满意”。人读起来毫无障碍，但程序要做进一步处理就麻烦了——下一次 AI 换个语序，你的逻辑就崩了。

解决方案是提前约定好输出结构。你给 AI 一个 JSON 骨架，命令它必须按这个格式回填，它就会交出一份规整的 JSON 对象。

```
{
  "name": "",
  "email": "",
  "feedback": ""
}
```

这样干净的结构化内容，下游节点不需要任何解析技巧就能直接读字段。

```
{
  "name": "张三",
  "email": "zhangsan@example.com",
  "feedback": "产品很棒"
}
```

本工作流里有两种方式达成这个目标。

**推荐方式：用 Code 节点自定义处理。**  
由于大模型的输出不稳定，在写入飞书多维表格前，最好先经过一道格式清洗，提升入库成功率。Code 节点支持 JavaScript 和 Python，我们优先使用 Python。  
因为后面要做入库操作，字段必须先与飞书表的列名对齐。飞书多维表格要求的 JSON 模板如下，其中引号内部需要接入变量参数：

```
{"fields":{
  "标题": "",
  "摘要": "",
  "原文链接": "",
  "来源/机构": "",
  "关键词": "",
  "发布日期": "",
  "序号": ""
}} 
```

传入的参数就是 AI agent 生成的内容，直接拿来作为代码输入即可。

**备选方式：用 Set 节点做字段映射。**  
如果不需要复杂逻辑，只是把 AI 返回的字段重新映射为表格列，用 Set 节点更轻快。

```
import re

def process_data(input_items):
  """
  解析包含多条新闻的字符串，并将其转换为结构化JSON对象列表。

  Args:
    input_items: 平台提供的项目列表 (例如, _input.all())。
                每个项目都有一个 .json 属性。

  Returns:
    一个字典列表，每个字典代表一条新闻，并包含在 "output" 键下。
  """

  # 假设输入数据是一个列表，且我们只处理第一个项目
  if not input_items:
    return []

  # 从输入项的.json属性中获取原始文本

  articles_str_list = re.split(r'\n\n(?=\d+\.\s*\n)', cleaned_text.strip())

  output_items = []

  # 遍历每个新闻字符串
  for article_str in articles_str_list:
    if not article_str.strip():
      continue

    # 移除每条新闻开头的 "数字." 标记
    cleaned_article_str = re.sub(r'^\d+\.\s*', '', article_str).strip()

    # 定义一个正则表达式来匹配所有键值对
    # 键是预定义的中文词汇，值是双引号内的任何字符
    pattern = re.compile(
        r'"(序号|标题|摘要|原文链接|来源/机构|关键词|发布日期)"\s*:\s*"(.*?)"', 
        re.DOTALL
    )

    matches = pattern.findall(cleaned_article_str)

    article_data = {}
    for key, value in matches:
      # 将找到的键值对存入字典
      article_data[key] = value.strip()

    # 如果成功解析出数据，则将其添加到输出列表中
    if article_data:
      # 按照期望的格式 {"output": {...}} 创建新的项
      output_items.append({'output': article_data})

  return output_items

# 实际代码节点中的调用方式。
# 这会调用上面的函数，并将处理结果作为整个节点的输出。
return process_data(_input.all())

```

2.  第二种做法：借助 Structured Output Parser 结构化解析输出器来做。这个解析器并不适合当前这套工作流。

不过你完全可以单独用它来做结构化输出。

所谓结构化输出，就是提前写好一个 JSON 骨架，明确告诉模型：“输出必须死守这个格式！”。

在 Ai Agent 节点里怎么调用 Structured Output Parser：

*   进入 Ai Agent 节点，勾选“输出特定的输出格式”

![](img/dca9d367e9793168d8904715c048e4c1.png)

![](img/1b037b7c0afb654803eb7d6d2a3a5e99.png)

打开结构化输出解析器后，把下面这段模板原样贴进去：

```
{
  "output": {
    "output": [
      {
        "标题": "",
        "摘要": "",
        "原文链接": "",
        "来源/机构": "",
        "关键词": "",
        "发布日期": "",
        "序号": ""
      }
    ]
  }
}
```

这就是一个信息抽取的模板。

它的逻辑是告诉模型：不管原文是一篇长文、一个网页还是一份报告，都要按这几个字段整理，最后给我一份 JSON。

字段含义拆解如下：

*   "标题": ""：提取原文标题。

*   "摘要": ""：提炼或生成内容摘要。

*   "原文链接": ""：抓取文章的原始网址。

*   "来源/机构": ""：判断发布方或所属机构，比如新华网、某公司。

*   "关键词": ""：总结核心关键词。

*   "发布日期": ""：找到确切的发布时间。

*   "序号": ""：可自定义的编号或索引，由你定义规则让模型填充。

在 n8n 的结构化输出解析器里配置好这个模板后，给它一段非结构化文本，它就会自动阅读、拆解，并把结果规范填入这些字段，最后吐出干净可用的 JSON。
