# 如何在 1 天内完成 1 部 2000000 字的巨著创作
作者：龙哥

说出来你可能不信，我上个月接了个150万字的写作订单，真正动手写的时间加起来不到一天。没错，是一天，不是一个月。

先别急着说我吹牛。其实这不叫“一天爆肝”，而是找到了一个完全不同的生产路径。今天我把这套玩法彻底拆开，从提纲到正文、从工具链到避坑细节，全部分享出来。看完你会发现，一个人搞定千万字级别的写作工程，真不是天方夜谭。万一未来接了个“300万字”的单子，反而要偷着乐，因为钱没变少，活儿却还能按时交付。

先说这件事是怎么来的。之前我在风向标里提过一个思路，叫“借助AIGC降维打击各种代写”。当时有位甲方看了之后真找上门来，一开始说300万字，后来觉得确实太夸张，主动降到了150万字。不过有意思的是——虽然字数砍半，钱一分没少。我负责内容创作，搭档负责和甲方周旋以及补充图表。前后拉扯了一个月，文章这边已经全部交掉，款项也收到七成了。而我这边，从头到尾投入进去的个人时间，不到一整天。

你可能要问，150万字，一天，怎么可能？答案不是某个无所不能的超级Prompt，而是一套生产线式的拆解打法。ChatGPT这种东西，你直接甩给它一个“写150万字”的指令，它当场就得懵。哪怕你的提示词写得再精美、再高级，也没办法一口吃成胖子。问题的关键，是让AI“化整为零”，然后靠系统把它一片片拼回来。

先说提纲。这条链路的起点其实很朴素：先根据主题让AI生成一级大纲，也就是章；然后拿每一章再去生成二级提纲；再往下，每一级继续细化。说白了就是不断向下拆，拆到AI一次能消化的体量为止。这里有个前期实测出的结论：普通的Prompt让ChatGPT写正文，单次输出大概在一千字左右。我们这次实际跑下来，平均单次约970字。你想写150万字，那就得让提纲深到7级，拆到不能再拆为止——我们把N取到了6，最终细化到第7级的小标题。

这一步在实现上有一个绕不开的关键问题：7级标题可能有海量条目，怎么去挨个遍历？总不能人肉一个个复制粘贴标题去喂AI，那不叫自动化，那叫工伤。于是必须写程序跑循环。同时，AI返回的一大堆分散内容，怎么按顺序合并？这同样不能靠人工拼，不然手都得断。所以从一开始就必须设计好规范的文件格式，让程序来兜底。

格式这块我选了Markdown，虽然最后交付给甲方的是Word文件，但中间所有过程文件都用Markdown。自己动手写一个针对Markdown提纲的解析器，把各级标题提取出来，再让AI在生成提纲的阶段就按Markdown的格式输出。这样既解决了遍历问题，又让后面的合并逻辑能顺畅跑起来。

正文的生成其实就变得很“机械”了：拿着解析器提取出的7级小标题，拼成一套标准化的Prompt，扔给ChatGPT让它写。这个阶段真正吃功夫的地方有两个：一是怎么保证所有章节都被调用到，二是生成的内容怎么落地成单个文件。我的做法是每写一个小节就单独存成一个Markdown文件，再加一个CSV备用。这种结构的好处是万一中途出现某个接口报错，恢复起来非常痛快，不至于前功尽弃再从头跑一遍。

你可能会好奇：为什么我用ChatGPT，而不是必应？很简单，必应不仅响应慢，免费额度也限制得厉害，写不了几小节就熄火了。ChatGPT这边稍微好点，不过也好不到哪去——一天200次请求，真实开销起来也是转眼就没。所以但凡这种体量的项目，建议多准备几个账号轮着跑。我自己是在Jupyter Notebook里面直接跑的，边调边观察，速度可控。等到写某一个分节的时候，如果遇到AI超限报错，就设置等待约7分钟再继续重试，这是官方额度机制的硬约束，绕不过去，只能配合。

啰啰嗦嗦讲了这么多，其实整个逻辑浓缩下来就是两句话：第一，拆级，拆到AI单次能完成的程度；第二，用程序把所有重复劳动包圆，人只做最前端的策略设计和最后端的质量把关。提纲阶段你可以自己动动手，一级二级甚至三级提纲都可以人工修一下；但再往下还靠纯手搓C和V，那就真是浪费生命了。

最后再说个福利。评论区里也有朋友提到，这种模式拿去写小说、接代写，甚至直接包装成产品对外售卖，都有人买单。我个人觉得确实有得玩。时代变化快到什么程度？很多你现在觉得“不可能”的东西，其实只是还没用对工具而已。

所以如果你也有积累已久的长篇创作梦想——不管是小说、专著还是行业报告，别急着给自己设定“三年写完”的苦役。用对方法，也许你真正需要花在键盘上的时间，只是一杯咖啡的工夫。
