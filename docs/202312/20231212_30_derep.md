# 如何将几百篇公众号文章作为 Gpts 的知识库？

最近不是大家都在折腾GPTs嘛，我自己也试了一把，把手头公众号里的几百篇旧文全部变成知识库，让GPT学着我的文风来仿写新内容。想法挺好，动手就遇坑，好在最后折腾通了。

先说说官方卡得挺死的限制：一个定制GPT最多只能挂10个文件，单个文件允许512MB（图片是20MB），但token上限只有2M。账号级别的话，个人用户总共10GB，组织是100GB。所以想象中“把资料一股脑全丢进去”根本行不通。

在实践过程中，我还反复纠结过几个问题：到底用什么格式喂给它最好？Word、PDF还是JSON？上传到知识库和放到网络服务器走API，哪种性能更优？内容是拆成一个个小文件方便逐章检索，还是合并成一个大PDF省空间？有没有一套推荐的内容管理玩法？

一开始我试过把所有文档打包成压缩包，结果直接被告知文件太大，而且压缩包压根没法被检索。后来查了一圈资料，发现最靠谱的路径是：先把所有Word文档转成纯文本格式，再把文本拆分成相对小的文件块，检索效率会明显提升。最终我是这么操作的——把每个Word文件转成txt，然后将每10到20个txt合并成一个大文件，最后把这些合并后的文件全部上传到知识库。

整个转换和合并过程，都是让ChatGPT帮我写代码搞定的。我给的提示词大概是：请用Python写一个脚本，遍历指定文件夹下所有.docx文件，用python-docx提取文本，每个文档保存成单独的txt；然后再以10个txt为一组，合并成一个新的文本文件，自动命名，注意保留分隔符。

评论区有人问实际写作质量如何，其实关键还是看你后续怎么设计提示词。提示词写得好，GPT就能抓住你文章的精髓；写不好，知识库再大也白搭。也有人感慨“方法很硬核”“正好遇到同样的问题”，看来感兴趣的朋友不止我一个。
