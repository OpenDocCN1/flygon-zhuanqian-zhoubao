# 三年四十万背后，我更想复盘的是怎么分摊精力
作者：龙哥

先说好，这篇不是操作指南，也不是包装成励志故事。我是龙哥，02届大学生，在生财学习的第一年。过去三年里，我借助大模型先后碰了MATLAB相关交付、编程服务、还组了工作室；回校后折腾过自用工具，毕业暑假又试了Codex的单人辅导。加在一起，流水大约40万。

先把底线讲清：40万是三年累计，不是单年爆发；Codex的辅导目前只是跑通雏形，离可复制还远。真正想给还在找路的人的，是我反复在用的一个分层思路——主营板块扛现金，次级赛道探机会，早期种子做小范围验证。

## 一、过去几年我在找方向，也在检验方法

2023年我开始大量玩大模型。写东西、画图、剪视频、写代码都试过，因为本身学计算机，最后把注意力集中在模型和MATLAB的结合上。

2024年我休学冲这个方向。当时闲鱼上能把模型能力接进MATLAB交付的还不多。我不敢说自己占了多大市场，只是在我能触及的范围内，做得比较靠前。那段经历让我从会用工具的执行者，变成要管生意的人：技术研究之外，还要搞流量，最后甚至拉了团队。

[PRE3]

真正上手后才明白，一桩生意由多少琐碎环节堆起。

2025年我复学，开始尝试把想法变成可用的东西，想看看能不能让别人直接拿去用。我做了个内部工具 matlab.ai，用来承接之前的MATLAB交付。过去接单是先聊需求、写代码、再迭代，我想把这些步骤封装进一个流程：用户提交问题、系统追问确认、进入代码生成与交付。之前服务里积累的经验，反过来指导了工具设计，比如哪些信息必须提前抠清，交付后用户通常还想要什么支持。

这些折腾让我对做工具的理解更落地。现在看，出发点大概有三类：一是用工具盘活自己的主业，把重复环节固化；二是看见别人的痛点，先做个能用的原型；三是纯自嗨，自己好玩就做。它们经常重叠。matlab.ai既想让主营更顺，也想让客户提需求更省事；歌词玩具更像自我娱乐，重点在乐趣。

但工具这件事比想象中厚。模型能快速搭出原型，可从能跑到能被长期使用，中间还有大量工作。这也让我重新评估：现阶段该从哪里切入更现实。

这一年我还给人工智能学院的老师做过讲解。自己钻研和教别人，难度不一样。自己会用靠的是熟练和经验，要教人则必须把省略的细节摊开。

2026年7月毕业，暑假有了整段空档。我想从零再跑通一件事来验证自己。2024年MATLAB有结果，不代表下一次还能复制。我想检验过去找需求、判断机会的方法有多少能迁移。于是选了Codex的单人辅导，做调研也做实测。

目前只能算初步验证。想做成稳定生意，还缺不少拼图。

## 二、收入上来以后，关键是学会分配关注

读《增长炼金术》时提到把事情分成三种角色，我很有共鸣：主营提供当下主要现金流，次级赛道有投入价值，未来种子是早期验证。

[PRE10]

这三种角色要同时被看见，但投入节奏不同。放在个人上也一样。假设你有一条客户稳定、现金流还行的线，把大部精力放进去很正常，生活需要钱，已经有人买单的事值得认真经营。可新方向从想法到有人用、到付费、到稳定交付，需要时间；你着急变现，这个过程也不会被压缩。等到旧线明显吃力，再临时找新收入，选择面会变小。

### 1. 主营板块：要养着，也要更新

MATLAB相关的交付是我从零起步、被市场检验过的线。它带给我的不仅是现金，更是一套完整的做事习惯：先找有需求的渠道，接洽后把要求问透——数据是什么、结果用来干嘛、最终交付什么文件。需求明确后才进入代码编写、运行、修改。前面没问清，后面越快越容易返工。

用模型时这点更明显。一句话发过去，它也能吐一大段看起来完整的输出。但完整和真正符合预期之间，隔着人的判断。做MATLAB让我越来越重视前后衔接：从需求中判断工作量，用模型完成，再检查解释。每一步都会影响客户感受。

竞争也在变。会用模型写代码的人多了，原来“我会你不会”的优势在缩小；工具变强，客户对交付速度的期待也在提高。这不代表MATLAB没价值，而是主营也需要换打法。有些需求可能不再值得接，有些环节要做得更深。客户愿意为哪部分买单，和两年前是否一样，需要在实际沟通里观察。过去有效的报价和工作方式，不能一直照搬。

对已经跑起来的线，我现在更在意可持续性。一段时间的收入好值得高兴；接下来有没有稳定需求，交付会不会把自己耗空，也要算。做服务很容易只记单子收了多少钱，却忘了前面聊了多久、后面改了几次。把时间加回去，才知道这笔买卖到底合不合算。

[PRE11]

主营能给人底气。开销有着落，试新方向时才敢按反馈调整；否则一个没成熟的尝试，很容易被要求立刻养活自己。但主营也需要照看，不能因为熟悉就以为它会永远按老样子赚钱。

### 2. 试水工具：先贴近人，再谈规模化

我一直对工具化有兴趣。把某个问题梳理清楚，做成可重复使用的东西，这件事本身有吸引力。接触到模型编程后，动手欲望更强了，原先受限于开发能力的想法，现在可以先搭出来试试。

可真正动手后体会更具体。功能能跑，只解决了一部分问题：这个功能对应谁的真实需求？对方以前怎么解决？愿不愿意换做法？出问题后谁维护？这些都会影响是否能持续使用。写代码时目标明确，做完一个功能就能看到变化；需求和使用习惯却没那么听话。你觉得有用，对方可能觉得还行；你花大量时间打磨的点，也可能并不影响选择。

所以我更理解，工具能力需要积累。模型降低了一部分实现成本，剩下的仍要学、要做。

说清我的判断：我现在更愿意从服务切入，先贴近具体的人，把问题解决好。这个选择和我的经历相关。大模型让更多人有机会开发软件，不代表每个人都愿意自己开发。个体具备能力，和是否愿意投入时间，是两回事。省心、稳定、有保障，本来就能成为付费理由。

健身是个好比喻。Keep这类App能提供动作讲解和计划，有些人用得很好；对另一些人，私教的价值在于观察个体情况、调整训练，并在执行中持续反馈。同样是健身，付费对象不同，买到的帮助也不同。我对模型教学的理解有点像：资料很多，某人在实操中卡住，往往需要有人指出他现在进行到哪一步。这个判断和现场调整，就是服务能提供的价值。

当然，服务也有限制。工具有机会把一次开发成果供给更多人；单人辅导需要投入时间。客单价提高，可能带来更好收入，也可能伴随更多准备、沟通和跟进。高客单价本身说明不了生意是否舒服。

对我而言，先做服务的意义是更直接地接触问题、检验理解。后面若发现某些需求反复出现，再考虑哪些部分适合做成内容，哪些值得开发工具。到那时，工具的作用会更具体。

[PRE12]

工具和服务可以互相喂养，但我现在更要把启动顺序想清楚。

### 3. 辅导验证：用新项目检验旧方法

今年暑假选Codex单人辅导，和之前的积累有关。我用了三年大模型，在MATLAB项目里实践过，也研究过工具和教学。准备新方向时，Codex是我重点关注的对象，身边讨论它的人也在增多。

还有一个考量，想往企业服务走。想做这件事，就得先了解企业里的人平时怎么工作，哪些环节耗时，哪些问题一直没解决。我希望通过辅导多接触有真实需求的人：可能是大学生，也可能是企业主，或某个岗位的员工。围绕他们手头的工作交流，我才有机会了解模型到底能在哪一步帮上忙。

[PRE13]

这些了解，对我后面做工具、做企业服务都有帮助。先把具体问题看清，再判断自己能提供什么。有些问题适合做成工具，有些则需要进一步沟通，提供相应服务。

经过调研和实测，暑假把这个项目初步跑通了，让我愿意继续投入。接下来能否持续吸引合适的人、辅导能不能做好，还要继续观察。

目前的单人辅导一共五小时。我会先讲大模型能做什么，重点讲提示词、工作流、Skills。讲完后，最终还是要回到学员自己的业务里实操。所以我希望学员带着自己的事来：可能是一项重复工作，也可能是一个想实现的设想。先挑一件范围清晰、适合现场练习的事，把要求和材料准备好，再借助Codex一步步做。卡在哪一步，就看那一步缺什么，是信息不足还是做法要调整。

面对刚接触大模型的人，我有信心把基础讲清、带着他动手做一遍。这五小时，我希望他能弄明白模型能帮自己做什么、怎么提要求，也亲手走完一次完整任务。之后遇到类似情况，能接着练，逐渐独立完成。

现在一提知识付费，有些人会警惕，我理解。教程买过不少，实际用起来还是不会；宣传里说的很厉害，交付时却只有一堆资料。经历过这些，谨慎很正常。我想把教学做好，就得在交付中证明：适合谁要说清，能帮助做到哪一步要把握分寸，遇到不确定的问题就一起查证，不能为了维持老师形象硬讲答案。目前做的是线上单人辅导，以后是否发展到线下，我有想法，但还需要研究。

### 4. 三种角色，不是三个分类

不能把MATLAB、工具、Codex硬塞进三个分类就觉得规划完成。板块属于哪个阶段，要看它当下的实际情况。MATLAB曾是被验证的现金来源；工具包含不少探索；Codex辅导经过初步测试，正在继续验证。以后哪项成为主要收入，要由持续结果说明。

未来种子也不是一个已经起好名字的新项目。有时候，它只是一个值得弄清的需求，或一种可以小范围试验的交付方式。

我现在理解的并行，是在经营眼前板块时，给下一步留出适当时间。已有收入要照顾好，新尝试要明确投入范围，最早期的想法先做足以回答一个问题的微型实验。几件事的分量可以不同，也应该不同。对刚起步的人来说，最要紧的可能是先建立一份可靠收入；对在职的人来说，当前工作和专业能力同样值得认真经营。未来的准备可以从学习和小范围实践开始，没必要一口气把自己变成三个项目的负责人。

这个框架给我的提醒很实际：今天有钱赚，要珍惜；以后靠什么，也要趁自己还有余地时想一想。

## 三、如果今天重新开始，我会怎么选赛道

我能讲的，主要来自自己走过的路。休学、做MATLAB、再回学校，这些选择跟我当时的条件有关。你有自己的生活安排，没必要为了证明自己敢干，把别人的经历重新演一遍。

如果让我重新开始，我会先把注意力放回自己身上：现在有什么条件，又能做好什么。

### 1. 先盘点自己，再定起点

选项目时，很容易先看别人。看到谁做得不错，就去研究他的产品和报价，顺便算一算自己照着做能挣多少。这很自然，谁看到机会都会想试试。

可对方现在展示的东西，未必包含他此前积累的经验。你看到他做得轻松，可能只是因为最难的部分，他早就花过时间了。我做MATLAB，也跟专业背景有关：对编程有接触，愿意研究大模型，后面又花时间做需求、交付和教学。这些条件放在一起，才有了后来的结果。别人如果没有这些积累，直接照着一个项目名称开始，困难可能完全不同。适合我的起点，放到另一个人身上，也许还要先补一些东西。

所以我会先列一列自己实际做过的事：哪些任务，别人已经愿意来找我帮忙？什么问题，我能独立解决到最后？还有一些东西，虽然暂时谈不上擅长，但我确实愿意持续研究，也可以拿出来考虑。

这里要诚实。看过教程，和自己做过一次，差别很大；跟着示范做出来，离换个条件还能完成，也有距离。同时也要看生活条件：每天实际能拿出多少时间，眼前有没有必须承担的开销，都会影响项目选择。暂时需要稳定收入，就优先考虑自己接得住的工作；需要长期学习的方向，可以另外安排时间。

[PRE14]

有时候计划做不完，是因为安排的事情太多。每天只有两小时，却给自己排了一整天的活，当然很难坚持。

### 2. 去接触用户，别只问“你会不会用”

有了大致方向，我会去了解别人正在怎么做事。可以问对方：你现在怎么解决某个问题？哪里最麻烦？这比问“我做这个，你会不会用”更容易了解真实需求。因为“听起来不错”只是一种态度，愿意把真实任务交给你，才是更具体的行动。后面愿不愿意付费，还要单独验证。

[PRE15]

这也是我做MATLAB时学到的。客户有一个明确任务，交流就能围绕这个任务展开。要求问清楚以后，才好判断工作量、自己的能力，以及能不能接下来。

说到底，这篇不是教程，也不是成功学。40万是三年累计，Codex辅导才初步跑通；真正值得带走的，是那套同时看眼前和下一步的板块分配方法。今天有钱赚，要珍惜；以后靠什么，也要趁自己还有余地的时候，早点想。
