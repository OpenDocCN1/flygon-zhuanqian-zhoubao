下面分享我怎么判断哪些环节能交给 AI，以及如何把剪辑经验转成它能执行的标准。

先说人群。已经完整做过 CPS 视频、清楚一条成片的合格线，这套方法上手更快。完全零基础建议先亲手做几条，形成基本判断再交给机器。因为你看不出问题，就写不出能让 AI 改对的指令。

## 一、为什么是 Codex + Remotion 这对组合

我现在做两类片子：一类是文字、图片、贴纸为主的 AE 感动效漫播，一类是真人出镜口播。两者文案和素材会换，但制作逻辑大量重复。比如下单金额何时高亮、优惠图何时上、指令出现时怎么强调、字幕怎么跟音频走，这些判断一旦固定就可规则化。

我也试过 Codex 操控剪映，在 Windows 环境下不太顺：Codex 总抢鼠标去点剪映，我还得干别的活；基于界面识别点击再等渲染的节奏慢。AI+剪映更像截图-定位-点击的笨办法。Remotion 走代码渲染，先把文字、图片、动画和音频的关系写成脚本再批量出片，更贴合我现在的片型。

另外 Codex 操控剪映只能一条一条来，Computer Use 很慢；Remotion 理论上可同时排 10 条一起渲染，实际数量受电脑配置和片子复杂度限制。

筛选标准就很简单：这段链路能不能被清晰描述、稳定跑通、减少我重复介入。文字动效类，Codex + Remotion 更合适。

## 二、搭建方式：先跑通一条，再把规则固化

整体思路是：参考视频 → 提取并核对文案 → 按账号换指令和时间 → 生成配音 → 处理气口建字幕轴 → 配图加动效 → 做封面 → 渲染自检 → 人工复核。

口语化说就是：找参考 → 让 AI 换成你的内容 → 自动出片 → 你发布 → 看数据。

具体操作可以拆成：

1. 找一条对标参考
把同类带货攻略链接丢给 AI，说明是用“我的口令”还是“??口令”。

2. AI 整理文案
结合原片声音和画面字幕提炼内容，替换成你的口令、更新日期，先给你确认通过后再制作。

3. 准备画面和配音
整理商品图、券图和文字动效素材，生成配音并剪掉多余停顿，让字幕随声音推进。

4. 自动成片
加入图片、动态文字、背景音乐和重点提示音，从内容里提炼封面文案并置于视频首帧。

5. 交付与发布
核对口令、日期和字幕后成片自动保存到指定文件夹，每条配一条标题，直接发。

6. 看反馈
发到对应号，配置好自己的推广口令，观察播放、下单和佣金，跑得好的方向继续放大。

日常指令可以简化成：> 参考这个视频，用我的口令，比例跟原片一样。日期改成 X 月 X 号，完成后把成片和标题一起给我。你主要负责选参考、确认内容、发布和看数据。

跑起来最花时间的是把每一步的交付标准写清楚。早期我也出现过：片子出来了但不对劲，提了修改意见下一条又犯。后来把反馈沉淀进 Skill：哪些文案不允许动、口令要核对哪些位、什么停顿要剪、图片不能遮挡哪里、封面怎么处理。把反复问题变成可执行规则。

其中三个点值得展开。

第一个，文案先核对，再往下走。
我把参考链接交给 Codex，让它抓视频、提口播，同时对照画面字幕。双重核对是因为口播不清时，纯转写容易漏字、错字。CPS 里金额、时间、条件、口令错一处就可能影响转化。我的文案 Skill 原则是：默认保留原话术结构和优惠信息，仅修改指定账号的口令与本次明确要求改动的时间。初期控制变量，方便定位问题。

第二个，音频先顺，画面再对齐。
用 MiniMax API 生成配音，流程衔接更顺。文案确认后直接出音频，再处理气口和时间轴，减少来回导出。音色我会先试听，挑有精神、中气足、表达流畅的给 Codex 调用，不合适就从库里剔除。

容易踩坑的是标点。想让 AI 说得连贯，不要把标点全删。我现在保留逗号句号，按语义断句，减少碎断。生成后处理过长的空白和可去的气口，数字和口令必须完整。剪完气口，字幕、图片、动画的时间轴也要跟着调，否则音频已前移，优惠图还在旧时间点。

第三个，每条都在为下一条积累素材。
618 时我攒过一批优惠图，这次让 Codex 优先从自有库里取。库里没有再从参考中提取，检查内容、时间和入口后再归档。特别要注意图内口令：语音字幕换了，图里还留着别的账号入口，等于白做。检查范围要覆盖文案、图片、封面和标题。

我的做法是先查库、缺啥补啥、核对后归档，下次优先复用。保留素材来源和适用活动，后续更好判断能否继续用，逐步用官方或自有素材替换参考截图。素材库越厚，下一条越快。

## 三、两种片型分开沉淀

动效漫播重在按文案和音频组织文字、优惠图、贴纸、动画和音效；真人口播先用同一套文案规则整理好话术，我去拍，拍完交 Codex 处理气口、字幕和优惠信息图。参考视频的作用是让它学会哪句话配什么信息、图片解释什么。

封面也分开：动效可单独设计；真人口播尽量保留人脸，首帧叠关键文字和图。为了省发布时的操作，我把封面嵌进视频首帧，重要信息放在居中 3:4 区域。发布前再确认是否被裁切。

## 四、从复现到积累再到改编

我把它分成三个阶段。

第一阶段，借助参考把完整链路跑通。弄明白输入到输出需要哪些步骤，每步交付什么。少改变量，先解决文案错、口令错、音画不同步、信息不清等基础问题。进入下一阶段的信号是：指令发给 Codex，能一次做对八成以上。

第二阶段，把重复项沉淀。常用的优惠图进素材库，反复的修改意见进 Skill，反复的画面结构整理成模块。判断是否进步就看一条比一条少找素材、少解释、少返工。做完一批回头看哪个环节改得最多，那个环节就是下一步要固化成 Skill 的。

第三阶段，逐步增加自主改编。流程稳定、素材积累后，开始调整表达、信息顺序和画面结构。不能等到审核提示才想办法改同质化。前面沉淀的规则是给后面内容尝试腾时间。

## 五、数据的一次验证

调整后，日产出从 1-2 条到 8 条，账号从 1 个到 5 个。各号平均千播水平，每天有万播视频，隔天出现 5 万+ 播放。最近 8 天 32 万 GMV、2300 元佣金。

最明显的变化是制作对我的占用下降，才有余力多做测试、多开账号。以前一天做一两条，想测也测不动。现在产量上来，可以观察话术、画面、声音的差异，再把有效经验补回流程。后续产量还要看选题、素材、审核和运营的承接能力。

## 六、先完成再完美，要落到发布动作

我以前做剪辑容易钻牛角尖。但 CPS 需要持续发布才能拿反馈。每条等到完美，产量会垮。我现在给自己划线：口令、时间、优惠信息准确，声音清晰，关键信息可读，音画无明显错误，就先发。动画是否更漂亮、转场是否更顺，可以下一条再优化。

好不容易做出来的视频，哪怕只有十个播放，也可能带来订单。永远优化就永远不下场。发布后把问题带回来，哪些错误反复出现就继续改流程。这样先完成才会慢慢变成做得更好。

## 七、已跑通的部分与下一步

目前这套方法在 AE 风格动效漫播和真人口播剪辑上跑通了。其他类型尚未充分验证，有潜力的是结构固定、图文占比高、需持续换内容的视频。

下一步我想验证的是：当素材库更完整、规则更稳定后，能否进一步减少返工，把更多时间放到选题、内容差异化和账号运营上。
