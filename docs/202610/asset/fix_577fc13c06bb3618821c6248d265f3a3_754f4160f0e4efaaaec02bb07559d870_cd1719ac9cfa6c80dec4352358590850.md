内容做完收尾那一刻，究竟有没有让读者带走点真能派上用场的东西？

动笔之前，手头那批一手材料有没有被真正嚼碎咽下？

画面配上去，撑不撑得住标题扔出来的那个钩子？

推送出去以后，后台那串数字能不能告诉我们下一轮往哪个方向使劲？

每个环节都摆着能核对、能较真的抓手。

头一笔进账不过是众多信号里的一个，它没法替你把往后经营路上的坑全填平。

可对刚摸工具、迟迟找不到下嘴处的创作者来说，这一步哪，分量确实不轻。

打这一刻起，他至少心里有数了：自己手上那点 AI 能耐，能落在哪几道具体工序上；接下去又该往哪儿补短板。

这比囤一柜子教程，都顶事。

## 八、Codex 跟 WorkBuddy 如何接力：从找料子到交出成稿

我最早也栽过一个挺典型的坑：以为模型写得快，产出自然就多。

把一大摞资料一股脑怼过去，几分钟就拿到一篇结构齐整的稿子。标题、正文、结尾升华一应俱全。粗看挺像回事，真到发布环节，毛病全往外冒：人物张冠李戴，画面讲的是甲事，标题却拐到乙事；句子读着顺，追问出处却没人说得清。

我早前写过一篇文章，核心意思就是：光靠 AI 追爆款，谁做谁翻车。话虽冲，判断至今没变：**如果连一个题目为什么有人愿意点都没琢磨透，工具越快，只会把没感觉的内容堆得越多。** 后来我不再催模型一次交十篇。

反过来，我把单条内容从头到尾拆开看。

这两款工具我拆开讲。Codex 的活，是把材料、判断和修改标准整理成一条后续还能复用的流程；WorkBuddy 则负责调用已经装好的赛道 Skill 去执行制作。二者能力有交叉，不必每一条都来回切换。真正的关键是：上一道工序交出的东西，下一道工序能顺利接住。

### 素材采集：存个链接不等于拿到料子

第一步进入贴图对标库，只圈定一个赛道。点开其中一条记录，拿走标题、原文和原始链接，再回到原页面看首图、正文配图和评论区。旧样本帮助你辨认写法；若要判断近期风向，就继续找近期同类作品，别把旧库日期当成实时数据。

[PRE0]

刚开始先留三到五组，每组保留原始链接、标题、正文、图片来源、当时能看见的数据和统计时间，再加几条有代表性的评论。另外补一句：我为什么把它留下来。

[PRE1]

手里已有采集表、正文文件或图片合集的，直接把这一份交给 Codex；还没有的，先手工整理也无妨。使用连接器或采集工具时，先确认登录状态、访问权限和采集范围。链接打不开的，补正文和图片，别让工具凭标题猜全文。第一次把有用的样本理清楚，比先搭一个全自动采集器更重要。

> > **给 Codex 的素材整理指令：**
> >
> > 请把我这次提交的链接、导出文档和图片读一遍，仅处理【赛道】范围内的样本。逐条保留原始链接、标题、完整正文、图片文件或图源、当前可见数据及统计时间、评论摘录。看不到的数据留空，打不开的单独列出，不要补写全文或阅读量。相同链接合并，内容相近的归组。
> >
> > 然后逐项说明：首图第一眼抓住了什么；标题抛出了什么问题；正文增加了哪些信息；评论区最在意什么。每条判断标出对应位置。输出一份可打开的素材表、候选选题清单和材料缺口，暂时不要写成品，也不要发布。等我确认后再继续。

### Codex 的角色：先把题目和要求说透，而不是催它多产

在 Codex 里新建本轮任务，指定素材目录或上传文件，把已有的赛道规则一并交代清楚。先让它复述读到了什么，再进入对标比较。

这一轮我会确认三件事：这篇内容写给谁看；图片里最值得讲的是什么；手头的事实能支撑到哪一步。Codex 可以把对标的标题、图序和正文作用拆解出来，也能指出材料缺口。选题、核事实、定观点由我自己来，它负责把确认过的材料组织成可执行的制作说明。举个例子，稿子里只剩一句“这个年纪的人很难”，我不会让它“再共情一点”，而是要求：指出这组图里的具体动作，找出能够确认的工作或照料场景，删掉没有材料支撑的身世。它交回来的不是更悲伤的故事，而是一份清楚该补什么、该删什么的制作说明书。

### 为什么装了 Skill 仍需要人动手改

航海期有位同伴分享过一段很实在的经历。

动手做贴图前，他尝试让 GPT/Codex 帮忙打磨一个👸号长文 Skill，打算交给 OpenClaw 来写。前后折腾三天，他意识到自己缺少写作经验，想凭空编出一套好用的写作规则并不现实，于是先放下了。

后来转向贴图，他拿教练给的素材，让 WorkBuddy 调用现成 Skill 出文案。稿子确实生成了，可读起来总差一点意思。他又把稿子交给 GPT 和 Claude 轮番修改，几轮下来仍觉得平淡。再后来想到 Grok 的表达方式和梗，把待改之处继续递过去，才慢慢接近他想要的感觉。

表面看只是几张图、几句话，前后却磨了两三个小时。他在分享里提到，第一篇最终拿到 82 万阅读。

我真正想让大家看见的，是中间那两三个小时。

不能只记住最后的数字，却把好素材、多轮修改和人的判断全抹掉。也不是照着他的做法把四个工具轮着用一遍，就算学会了。更值得留下来的是：哪一句读着平，哪一种梗不贴切，哪一段跟图片脱了节，自己最后为什么挑了这一版。

这样下一回就有参照：问题出在素材，就回头找素材；正文没把图片吃透，就改正文；如果只是结尾套话，先别急着把整篇推倒重来。反复冒出来的差别，才会沉淀进自己的 Skill。

我以前也容易被“眨眼间稿子就出来”这种说法吸引，现在更愿意把制作、人工修改、图片检查和后续反馈放在一条线上看。工具交出第一版，只是起点；让我明白这一版为什么可用、下一版怎样少返工，才是工作流真正有价值的地方。

### 二次创作：换自己的材料和判断，而不是换几个词

拆解对标时，我先问它凭什么让人愿意看：题目抛出了什么疑问，第一张图靠什么抓住注意力，正文如何承接图片，评论在讨论什么。接着换成自己这轮的材料、观察和表达。原作者的家庭关系、人生经历、对白和收益数据，不能顺手一起搬。

动手顺序可以这样走：拆出吸引点 → 定下本篇切入点 → 换成自己的事实 → 写出短文 → 核对图和文字是否说同一件事。痛点的位置就在这一步，不要另外塞一段“你是不是很焦虑”。原稿里的“重新戴上工牌”就是一个切入点：如果材料确实支持重新上班，可以写当事人有依据的顾虑、期待或安排；如果手头只有一张工牌图，就不能补出失业多年、夫妻争吵和经济困境。

我想要的表达是：先让读者看到一个熟悉的动作，再说这个动作为什么会带来感受，最后落到自己的观察或一件可以做的小事上。宠物和食材内容未必需要卖惨，它们的看点可能就是一个动作、一个切面、一个意外发现。痛点必须贴合这组素材，不是所有赛道都硬套变现焦虑。

#### 局部动刀的要求：

先不要重写整篇。拿参考的吸引点对照我手头的事实材料，检查标题、首图、正文是不是围绕同一个问题。挑出最空泛或最跑题的那一段，说明它缺什么，然后只动这一段。保留我的事实和表达，不挪用对标的经历，不编对话、反馈和数字；缺少过程材料就问我补，不要靠堆语气词冒充真人。

看实际改稿截图时，别只说“再口语化一点”。要看工具列出的具体改动：哪一句换了说法，补了哪个场景，删掉了多少啰嗦话。再打开结果文件自己读一遍；工具写“改好了”，不等于成稿真的顺。

[PRE5]

### 配图制作：先想清楚第一眼该看到什么，再反推提示词

先挑三五个同赛道、同用途的参考样本。不要随手抽一句“高清、生活感、电影感”就去生成图片。逐张观察主体、动作、关键物件、场景、主体占比、光线，以及是否必须加字；从反复冒出来的特征中，挑出这一篇真正该保留的。

先决定纯图还是叠字。图片里的动作已经把问题讲明白，就别再压一条大标题。观点若离开文字就说不清，才另外排一句短字；后面的图负责补细节，不必每张都把标题重复一遍。需要准确中文时，底图不要生成文字，文字单独排版并核对，不能遮住脸、手和关键物件。

> > **请 Codex 调整生图提示词时，可以这样要求：**
> >
> > 请参考这三五个样本以及本篇标题、正文。逐张指出第一眼重点、主体动作、关键物件、构图和是否需要叠字，再归纳同赛道可借鉴的共同写法。只写看得见的，不推断人物身份和经历。
> >
> > 请为我的【本篇场景】写一版无字底图提示词，按“主体与动作、场景、关键物件、画幅与主体位置、光线、保留项、避免项”展开；再列出可以替换的变量。需要文字就另外给出准确文案和留白位置。不要复制参考人物、标识、文案或私人空间。

先出一张试试，再指出具体问题。主体太小，就调整位置和占比；动作太摆拍，就换成材料支持的动作；字挡住画面，先挪字或取消叠字；手、物件或事实不对，就重做那一张。一次先解决一个主要问题，不要一不满意就把整段提示词推翻重写。

**出图以后，点开大图看。** 下面是我们之前操作时留下的截图。右边直接打开图片，检查主体、物件、文字和细节。左边那栏解释只能帮助理解处理方式，图片到底好不好，还得看右边实际成品。

可以合法使用的真实证据图片，只允许做不改变原意的裁切和清晰度处理，不得改表情，也不得通过增删人物来制造冲突。生成图或图生图示意，不能冒充新闻现场、住院现场或本人亲历。

客户端的加密核心不要解密修改；可调整的主题、补充事实、叠字、保留/替换/禁止项，按包内范围处理；自己的明文规则改副本即可。

#### 我更在意四件小事：

只看首屏，别人能不能复述这条内容讲了什么？正文里的关键细节，能不能回到图片、原文或真实观察中找到源头？图片的先后顺序，有没有一个说得出口的理由？数据回来以后，能不能倒着查回这组素材、这一版文案？少一项，第二天复盘就会断线。

所谓断线，就是你知道这条数据不好，却不知道为什么不好，也不知道下一条该怎么调。

这也是我现在衡量“提效”的方式。

我会从拿到素材那一刻开始计时，一直看到成品能发、数据能回查。

如果只盯着“AI 眨眼间就交稿”这一段，高兴得太早。

前面看似省下几分钟，后面却要花半天查资料、重排图片、删掉一整段空话——这笔账算下来，未必划算。

真正的提效，是整条路都顺，而不是中间某一截特别快。

AI 对我来说，最实在的意义就在这里。

每天总有一堆非做不可、又反复发生的活。把它们交出去，人才能腾出手继续往前看。

过去就是忙着赶稿。今天这条刚交，明天那条又顶上来，根本没空停下来想——用户真正在意的到底是什么。

现在把时间省出来，我更愿意拿去翻评论、拉做号的人核对细节、回头调整产品。让下一轮少卡一个地方，就是多出一个地方。

我想要的提效，不是让 AI 替我一天产出一百条稿。

而是同样一份时间，能多做成几件真正有价值的事，并且不把人困在“每天从头赶稿、从头找图”的循环里。

有余力做判断，有余力跟用户聊两句，还有余力再试一个小项目——这对一个人，或者一个小团队，帮助最实在。

说到底，第一条作品的任务，不是证明你有多厉害。

而是给第二条，留下能用的依据。

这句话，是我做了很多无效返工之后，才真正认下来的。

## 九、把重复步骤固化进 Skill，再接入对应工作台

如今聊 AI，很容易被名词牵着走。我的理解其实很朴素：提示词负责把这一次的活交代明白，Skill 负责把同类工作里反复要用的步骤与判断留下来，工作台则把这些步骤摆成一个看得懂的入口。

### 为什么不必每次重写提示词，而要把 Skill 封装起来

单次任务，有提示词就够。比如这一轮三条对标、五张图片，交什么、不能编什么，说清楚就能动手。可同一条赛道天天都在写，每回都要解释一遍图怎么挑、文案多短、结尾别升华，时间还是耗在重复沟通上。

所以我已经把不同赛道的要求分别做成 Skill。它不是一段更长的“咒语”，而是把入口、材料、执行步骤、成品和检查放在一处。中年实拍看动作与生活物件，婚姻家庭看关系与分工，宠物看灵动瞬间，食材看切面与来源。共同流程可以共用，内容判断不能硬套。

#### 我对一份 Skill 的要求：

何时使用，先给什么，按什么顺序做，最后交什么，哪里必须由人确认，失败时回到哪一步。少一项，使用者就还得猜。需要脚本、参考规则和模板时，把它们一起放进包，不要只给一个找不到配套文件的 SKILL.md。

### Skill 怎么改：把返工点说具体，再用新材料验证

我不再只加“更真实、更高级、去 AI 味”这类话。我会保留初稿、人工修改和定稿，找出反复出现的问题。开头太空，就写“先出现本篇的具体事情”；人物身份乱了，就写“作者、读者和故事人物分开”；图文没接上，就写“标题提到的动作必须在图或正文中有材料支持”。

先改自己可编辑的规则副本，再拿另一组同赛道素材试。材料完整时能不能交出成品，缺图时会不会主动指出，换一个题会不会还写上一家的故事？比起多塞几条要求，我更在意这些地方有没有减少返工。只有这一篇的姓名、经历和数字，留在本次素材里，不要变成每篇的固定人设。

如果只看我现在做的十个号，很容易觉得矩阵就是“一个号跑通，再复制九份”。我早期也这么想，所以一口气开过十多个号。每天切账号、追热点、改方向，动作很多，哪个都没做透。
