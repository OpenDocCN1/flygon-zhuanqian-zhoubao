## 七天三上架，我的 iOS 初开发实录

作者： 黑帽子

日期：2025-01-16

大家好。十二月参加完生财的 Cursor 大航海营之后，我就一直用 Cursor 在摸索做应用。截至现在，我用一周的时间做出了三款 App，并且全部成功上线 App Store。这是我第一次碰 iOS 开发，路上踩坑无数，但在不断查资料、反复和 AI 对线后，问题都逐个被解决了。今天把这段经历整理出来给大家做个参考。

到现在这三款 App 还没有产生收入，不过做着做着开发效率肉眼可见地在提升。最近完成的一款，从想法到写完、调通、上架，整个周期只用了大概 8 个小时。我相信变现也快了，目前已经在走 Google AdMob 的申请流程，只是海外抓取 App Store 信息有点慢，正在等审核。

先交代下我的起点。

我完全算是个开发小白，英文也不好。之前对编程的认知基本停留在用 WordPress、宝塔面板这类开源系统搭博客网站的层面。用 Cursor 开发对我来说起步阶段阻力很大。

航海营里跟着教练和手册，我试着先做了贪吃蛇、图片压缩之类的小工具。说实话，手册我翻了好几遍，几句提示词就能搞定的小东西，我反复折腾了好几次才跑通。回头看，那会儿的错误很蠢，基本都是运行环境装错了、依赖放错目录，导致一直报错。把报错丢给 Cursor 它也解释不清，那段时间的挫败感挺重的。

后来为什么锁定 iOS App，而不是继续做网站、安卓、浏览器插件或微信小程序。

先说网站。留存难，流量基本靠 SEO。百度现在收录严，不备案基本没戏；Google SEO 周期长，正反馈来得慢，我怕坚持不到回本就放弃了。站外推广的话，网站的留存也撑不住，PC 和移动的流量差距摆在那，所以果断选移动端。

移动端里，我排除了安卓。上两年朋友帮我做过任务平台 App，我知道安卓上架流程繁琐成本高，软著代办就要 300 块，周期三四周。更头疼的是兼容性，不同安卓版本机型问题多，我没能力去处理，直接放弃。

微信小程序也不选。留存差，几乎搜不到，只能靠主动投放和微信社交裂变，难度很大。而且个人资质开发限制多，我前两年在微擎买的小程序源码，没过一周就封了，还只是个打卡小程序。

最后只剩 iOS。

做 iOS 第一个前提是有一台 Mac 和一台 iPhone。手机我本来就是苹果，Mac 我是从角落里扒出了一台 2018 年的 Mac Pro，8 核 8G 内存 128G，i5 处理器。配置很老了，同时开三个软件就卡。

第一个坎是 Apple 开发者账号，年费 99 美元，约 688 元人民币/年。注册时提示账号异常无法注册，我翻了大量教程也没解决。后来给 Apple 客服发邮件，才发现问题是我八年前就注册过一个 Apple ID 并已实名，后续再注册的 ID 都无法通过开发者实名认证。好在翻出旧手机，找回了当年的 ID，这才顺利缴费注册。

关于开发者账号总结三点：
（1）尽量用同一台苹果设备从头注册到底，别中途换设备。
（2）别用登录过三个以上 Apple ID 的设备注册，会被判定为公共设备。
（3）务必用最早实名的 Apple ID，忘了的话苹果客服也不会告诉你，基本就永远注册不了。

账号也可以买，但买的账号次年续费是别人的支付信息，续不上就会导致已上架应用被强制下架，能自用就自用，实在不行用家人的。

第二个坎是开发环境。

iOS 开发离不开 Cursor 和 Xcode。流程是先在 Xcode 里新建项目，再让 Cursor 打开 Xcode 新建的这个目录。

这里有个史诗级坑：目录层级。

用 Xcode 新建项目后，目录下会出现三个同名结构。以我项目“paizhao”为例，paizhao 文件夹下还有一个 paizhao 子文件夹，以及 paizhaoTest、PaizhaoUItest。

[PRE6]

如果你用 Cursor 打开的是外层的 paizhao 文件夹，而不是里面的同名子文件夹，那么后面写的所有代码都白写了。Xcode 打包编译的是子文件夹里的内容，只有代码放在那里才生效。

第二个史诗级坑：文件关联。

Cursor 写完代码回 Xcode，经常发现文件一个都没出现。问 AI 也问不出所以然。原因是 Cursor 的打开方式和 Xcode 不同，Cursor 新建的文件不会自动同步到 Xcode。每次 Cursor 生成新文件后，必须手动回 Xcode，右键对应目录，选择 Add Files to “xxxx”，手动把文件加进来。

[PRE8]

注意别勾选默认的 Create Folder References，要选 Create Groups，否则文件加进去了也会编译失败，Cursor 也不提示原因。

第三个坑是数据线。iOS 真机调试需要在 iPhone 开启开发者模式后用数据线连 Mac。我试过淘宝 9.9 包邮的廉价线，根本连不上，最好用原装线。

再说下用 Cursor 开发的心得。

（1）功能越复杂越要拆。登录、注册、支付这些对新手不友好。我发现 Cursor 一旦代码量超过两三千行，就容易“失忆”，效率暴跌，还会把之前的逻辑删掉。复杂业务要拆开做，先把最核心的基础功能跑通。
（2）别全靠 AI。一定要自己理解业务的逻辑和流程。AI 有时惊艳，大多数时候做不出想要的效果，特别是图形界面调整，改来改去也改不动。
（3）提示词是关键。做项目时一定要先建一个 cursorrules.md 的技术说明文件，再配上功能和页面设计的产品说明文件。随着 Bug 增加，Cursor 需要靠这些文件理解产品。上下文有字符限制，写不好提示词就用 Chat 模式先沟通清楚，让 AI 帮你把需求整理成提示词，效率会高很多。
（4）主要时间都花在编译报错和功能修复上。别被“一小时做一个 App”的说法带偏了，代码超过 2000 行后，光修 Bug 就要一两个小时。功能稍微复杂点，代码量很容易就破 2000。

最后说上架。

我目前的上架还算顺利，没遇到大家说的 4.2 问题。4.2 大概就是同质化严重被拒。

上架经验几点：

（1）隐私协议直接抄改。在 App Store 找个同类应用，把它的隐私协议复制出来，扔给豆包之类的 AI 改一改再粘贴。核心是把 App 使用到的权限写清楚，比如相机、相册、WiFi 等。没有自己的服务器，用腾讯文档也能先撑着。
（2）最好有个自己的服务器。上架时要填营销网站链接，虽然可以空着，但后面挂 Google 广告就需要服务器放 ads.txt 文件，里面放你的 Google ID。腾讯文档实现不了。
（3）打包时注意两个细节：iOS 系统版本别选太高，否则低版本用户下不了。这个在 Xcode 的蓝色图标里设置。另外发布平台只勾选 iPhone，把 iPad 等全部删掉，否则要多做一套预览图。
