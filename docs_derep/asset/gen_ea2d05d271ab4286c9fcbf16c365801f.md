很多人好奇，我是怎么把 AI 工具玩得这么溜的。今天就掏心窝子聊聊这段从零折腾的自动化之旅。

先说语音合成。最开始试了好几个方案，发音效果都让我直摇头，实在没辙了，就让 Cursor 换个思路找找。结果它翻出一个 Azure TTS 的儿童音效，试了试居然挺对味，干脆就用它的 API 来跑。保险起见，我又额外接了一遍 Google TTS，免得个别单词声调跑偏。这里得多嘴一句：这两家都不是纯免费，不同型号定价不一样，基础版按月送免费字符数，掐着用就行。

既然聊到单词，就不得不提我做的第一个 Chrome 插件——查单词音调，顺便把内容整批同步到 Notion。

它的活儿很纯粹：

*   查单个单词的音调
*   把表格里的词一次性查出音调
*   把表格内容整批塞进 Notion

[PRE2]

做它的原因有两个。一个是老有粉丝反馈说音调不标准，可 AI 生成的语音我真没法逐字控制，那就换条路：在单词旁把音调标出来。另一个是视频发了不少，文字却散得到处都是，我特想找个地方把过往内容都接住，以后想转型做产品也有现成的素材库。翻了一圈手里的工具，Notion 就是那个最顺手的。

[PRE3]

有了第一个软件打底，Cursor 的基本套路我也摸熟了，后面这两个插件做起来快得很，功能本身也简单，更多是熟能生巧。

头号难题依然是音调数据从哪儿来。一开始我天真地想让 AI 直接报音调，但试了好几个大模型，错得一塌糊涂。我后来琢磨，用①②③这种数字标注音调的法子，八成是国内老师发明的，日本根本不认这套，模型自然学不会。

好在天无绝人之路。我搜到个日本词典网站，不用登录就能返回音调。按下 F12 把背后的接口数据扒出来，再丢给 Postman 调通，它会直接生成调用示例，复制给 Cursor 就能接上。

调试 Chrome 插件时最抓狂的是日志散落各处。console 里有一份，碰到 background.js 还得去插件后台翻，找问题跟开盲盒似的。后来我直接让 Cursor 在页面上开辟一块专属日志区，所有记录集中展示，一键复制，再发给 Cursor 定位就很省心。

同步 Notion 这块倒没卡壳。麻烦的还是读 Google Sheet 时得调 Google API。Notion 接口稳定，只要数据库表头和代码严格对应，基本就齐活了。

界面布局不喜欢，也可以跟 Cursor 直说。告诉它具体是哪儿不顺眼、想要什么色调，它就乖乖改。

第三个工具是 MJ 图片自动下载。功能一句话就能讲完：盯住 Midjourney 页面，一旦有新图就自动切割，按四宫格分成四份，用提示词当文件名存到本地。

[PRE10]

[PRE11]

这工具诞生得特别简单——因为 Autojourney 下载老出幺蛾子。实现时先要用 F12 找到图片对应的 class 或 id，把网页结构做减法后丢给 Cursor，让它盯着某个新出现的元素。

[PRE12]

不过做它的时候，我真被 Cursor 气得不轻。

头一个坑是图片全堆在 Downloads 根目录，我明明写了要放到 MJ 子文件夹，可它就像没看见，日志里也一点报错都没有。猜是 Chrome 下载环节出了问题，但 Cursor 来回改了几轮就是没辙。最后还是请了外援，让其他大模型先定位病因，再让 Cursor 按方抓药。

[PRE13]

第二个坑是文件名。代码里指定得好好的，逻辑上也确认过传值没问题，可最后存下来的文件名依然不对。顺藤摸瓜查了一遍，发现是 content.js 传到 background.js 这一步出了岔子。又是外援救场，我把可疑原因列给 Cursor，让它逐个排除。

[PRE14]

这两次栽跟头让我怀疑，是 Cursor 当前 Composer 里上下文堆太多，它满脑子都在想着怎么解决，却没停下来琢磨问题是怎么来的。也许重新开一个 Composer，把记忆清空，“降智”能缓解不少。

对刚入门的萌新来说，代码看不懂也正常，那就直接回头问 AI：“我看不懂，请详细说明这些代码是干什么的，还要加上代码注释”。

[PRE15]

接下来是几个亲测好用的 Cursor 小技巧。

一来，别指着一个会话通关。大模型能读的上下文就那么些，消息发太多它会漏读，写出来的代码自然错漏百出。把需求拆开，一个会话只解决一件事，把关键上下文拎得清清楚楚。Agent 模式下，删掉 Context 文件会逼它自动做语义搜索，搜出来的片段往往比你手动指定的还靠谱，降智时可以试试。

[PRE16]

二来，中文变乱码菱形块时，去把系统改成全局 UTF-8，具体操作直接问 Cursor 就行。

[PRE17]

三来，要小心 Cursor 偷换配置。我在折腾 Google OAuth 的时候，它反复调试无果，就开始动我的 API key，一口咬定我的 key 不符合 Google 格式。自己接不住锅就甩给用户？我果断不接受，还要反过去质疑它。所以大家收代码时一定要留个心眼，看看它有没有改掉原本正确的设置。

四来，.cursorrules 这个文件是个宝。新建一个 .cursorrules，把代码规范、功能需求、技术栈都写进去，等于给模型立了规矩，它写起来就会“有模有样”。

五来，别总想着从零造轮子。先在 GitHub 上逛逛现成的开源项目，fork 下来，让 Cursor 读懂别人的代码再改，能省下大把时间。有新需求也可以直接讨论，顺着原来的技术栈继续加功能。

[PRE18]

最后说点心里话。这段提效之旅走下来，还有很多地方值得优化，比如剪辑完全可以让软件代劳一键搞定，账号发布也能自动化。但真真切切的感受是，AI 把我的认知和工作效率都带上了一个台阶。我学到最受用的一句话就是：不会的，就问 AI。
