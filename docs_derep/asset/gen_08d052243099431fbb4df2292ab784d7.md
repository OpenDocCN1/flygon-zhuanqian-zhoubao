# 先体验效果

先上视频感受下这个组合的爽点在哪里。

如果你想追踪对标博主、自动发帖、实时捕捉博主动态，这个方案给你打开了很大想象空间。

不止小红书，各种采集+处理+输出的场景都能套用，快而且灵活。

现在这个闭环能做到什么？

1、批量抓取对标小红书博主的全部笔记和个人画像，后续用途基本自由发挥。
2、n8n agent 工作流自动把原始数据清洗、入表，还能调用大模型给博主出分析报告。
3、像素番薯系统把数据重新呈现，想怎么看就怎么看，还能模仿博主口吻写稿、自动配图。

# 架构拆解

[PRE0]

整体就三层在跑。

1、小红书浏览器插件：前端采集器，装在浏览器里，负责抓博主昵称、所在地、粉丝/关注/收藏/点赞等画像信息，以及每篇笔记的标题、文案、互动数据。
2、n8n agent 工作流：数据中转站，接收插件推送，清洗后分表写入数据库，同时触发 AI 生成博主画像报告。
3、像素番薯系统：前端应用层，读取数据做任意可视化，我这里做成了像素风，还加了仿写文章和生图能力。

下面把这三块怎么落地说清楚。

# 系统有什么不一样

看了那么多小红书采集方案，这个组合的优势在哪？

1、采集层灵活：插件现在用 XPath 方案，效率和反爬取平衡得不错，后面可以切接口。只做采集一件事。
2、n8n 层：负责 AI 报告生成和数据落库，目前用 Supabase。
3、应用层：数据呈现方式可玩性高，能仿写、能生图。

核心思想是各司其职。

*   可替换性强：数据已经在库里，不喜欢像素番薯就 vibe 一个新前端就行。
*   生产效率高：XPath 精准采集 + n8n 直接入库 + AI 节点即插即用。
*   业务适配强：整套东西可定制，能满足比较复杂的业务需求。
