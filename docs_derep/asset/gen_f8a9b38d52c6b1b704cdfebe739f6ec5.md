## 一. 为什么要有自己的私有模型？

ChatGPT 确实很强，但用起来也有明显的短板。

第一，数据安全没保证。所有数据都是直接交给 ChatGPT 的，私有数据有泄露风险。

第二，没法个性化定制。每个企业、每个人的需求都不一样，ChatGPT 很难针对同一个问题，结合你的实际情况，给出更智能也更个性化的回答。

## 三. 怎么构建垂直领域的 LLM 专属模型？

### 1. 先搞懂两种主流训练方式：Fine-tuning 和 Embedding

#### （1）概念

*   Fine-tuning（微调）：在预训练模型基础上，用特定任务的数据重新训练，让模型适应具体应用场景。预训练模型往往已经通过大规模数据集获得了通用的语言理解和生成能力，微调相当于再做一轮定向强化，提升特定任务上的准确率。

*   Embedding（嵌入）：把高维离散数据转换成低维连续向量。自然语言处理里的 Word Embedding，就是把单词映射成实数向量，让计算机更好理解语义。嵌入到低维空间后，能捕捉到词与词之间的关联和语义相似性，让模型完成语言理解和相关任务变得更容易。

在 GPT 模型上做 NLP 任务，一般先预训练出通用语言模型，再基于任务数据做 Fine-tuning 来适配需求。同时，模型会把单词和文本嵌入到低维向量空间，用来提升语义理解能力和任务效果。两者可以共同作用，帮助模型在特定任务上表现得更好。

为了更好理解，这里举个 Fine-tuning（微调）的例子：

1.  想让 GPT-3 按某种格式识别 Prompt 或进行回答；
2.  想让 GPT-3 用某种语气或性格来回答；
3.  想让 completion 具备某种倾向。

#### （2）Fine-tuning 和 Embedding 的区别

*   微调像备考：形成的是长期记忆。但等考试真正来的时候，模型可能会忘，甚至记错它从没读过的事实。
*   嵌入像记笔记：形成的是短期记忆。考试时带笔记，随时翻看，笔记上有的内容就能给出准确答案。

嵌入的搜索-提问方式也有个短板：每次附带的文本数量有限。因为除了原始问题，它还要带上搜出来的内容。GPT-3.5 是 4K（大概 5 页），GPT-4 最大 32K（大概 40 页）。就好比你有一整本教科书可以查，但每次只能翻其中几页。

想构建一个能对大量文本问答的系统，OpenAI 建议用“搜索-问”（Search-Ask）的方式：先在本地文档库里 Search，拿到结果后，再把搜索结果和原始问题一起交给 GPT，让它结合你给的内容和自身模型里的知识，把结果一起返回。

#### （3）适用场景

Fine-tuning 和 Embedding 是两种差别很大的技术，各有各的适用场景。

Fine-tuning 更适合教模型学习新的任务或模式，而不是塞给它新信息。比如训练模型生成特定风格的文本，或者完成某个明确的 NLP 任务。但 Fine-tuning 不适合做知识存储，也不适合问答任务。

反过来，语义搜索/Embedding 非常适合问答。先用语义搜索快速找到相关文档，再用大语言模型生成答案。而且这种方式相对 Fine-tuning 更快、更容易，也更便宜。

所以，如果你的目标就是做问答系统，或者在大量数据里快速找相关信息，用语义搜索和 Embedding；如果目标是教模型做特定任务，比如输出某种风格的文本，Fine-tuning 更有用。

一句话总结使用场景：

有一堆语料，想让 GPT-3 根据我的语料输出内容 — 用 embedding；
想让 GPT-3 扮演温柔贤惠的女人和我聊天 — 用 fine-tune；
希望用户按固定格式提交问题 — 用 fine-tune；
让模型按产品使用手册回答用户问题 — 用 embedding。

显然，做问答系统或企业/个人知识库，最适合的还是 Embedding（嵌入）方式。

篇幅有限，我重点讲 Embedding 的训练流程。对 Fine-tuning 感兴趣的朋友，可以自己去网上搜索，相关资料还是很多的。

目前实现智能 AI 问答功能，主流做法就是 Embedding（嵌入），核心依赖向量数据库。

#### （4）什么是向量 Embedding？怎么工作？

简单说，向量 Embedding 就是一串 N 维数字向量，它可以表示任何东西：文本、音乐、视频等等。我们这里主要关注文本。

要创建向量 Embedding，得借助 Embedding 模型（比如 OpenAI 的 Ada），把要处理的文本输入模型，就能得到向量表示，然后存起来备用。

[PRE3]

说个更直观的例子：

你是个孩子，面前有一个大玩具盒。你想找一些类似的玩具，比如玩具汽车和玩具巴士，它们都是交通工具，这就叫“语义相似性”——事物含义越接近，向量越相似。

再假设你有两个相关的玩具，但不完全一样。比如一辆玩具汽车和一条玩具道路，它们不算完全相同，但你会觉得它们相关，因为汽车一般是开在道路上的。

#### （5）怎么让 LLM 读大文本？

假设你有一个巨大的 PDF 文件，又懒得读完整份文档，也没办法整个复制进模型，因为它可能超过一亿页，怎么办？

可以用向量 Embedding 的优势，把相关文本注入 LLM 的上下文窗口：对 PDF 做向量化，存进向量数据库。

具体流程：

1）把 PDF 切分成较小的文本片段，用 Embedding 模型把每个片段转成向量，存入本地或远程向量数据库。

2）把用户提问也转成向量，和之前生成的 PDF 向量比对，通过语义相似性搜索（比如余弦算法），找到最相关的文本片段。

3）把用户提问和相似文本片段一起交给 LLM，写 Prompt 要求它基于给定内容作答；如果没有相似文本或关联度不高，就回答“不知道”。

这是向量 Embedding 最典型的使用方式。GitHub 上超火的 langchain-ChatGLM 项目，就是 LLM 结合向量 Embedding，实现了本地知识库问答。

为什么要这样组合？

因为 LLM 生成结果具有不确定性和不准确性，光靠 LLM 还没法提供足够智能的服务。所以要用 LangChain 这类调用框架，把 LLM 和开发者已有的知识、系统接起来，提供更智能的服务。

考虑到很多朋友对专属模型还不太熟，这里花点时间介绍一下 LangChain 和 ChatGLM。熟悉的可以直接跳过。

#### LangChain

LangChain 是一个用来开发语言模型应用的框架。简单说，它站在用户程序和 LLM 之间，起中间层的作用。

它在 2023 年 3 月拿到了 Benchmark Capital 的 1000 万美元种子轮融资，最近又拿到红杉的 2000 到 2500 万美元，估值已经涨到 2 亿美元左右。

LangChain 能轻松管理跟语言模型的交互，把多个组件串起来，还能接入 API、数据库等外部资源。组件包括模型（各类 LLM）、提示模板（Prompts）、索引、代理（Agent）、记忆等。

前段时间 GitHub 上很火的 Auto-GPT 和 Babyagi，它们用的链式思考能力，就是受 LangChain 启发的。

#### ChatGLM

ChatGLM 是智谱AI推出的生成式大语言模型。智谱AI来自清华大学计算机系的技术成果转化，做的是新一代认知智能通用模型。他们合作研发了双语千亿级预训练模型 GLM-130B，还构建了高精度通用知识图谱，形成数据和知识双驱动的认知引擎，ChatGLM（chatglm.cn）就基于这个模型。另外智谱AI还推出了认知大模型平台 Bigmodel.ai，包含 CodeGeeX、CogView 等产品，提供智能 API 服务。

智谱AI的目标是：让每个人都用上千亿模型。

我们示例里用的是 ChatGLM-6B 作为预训练模型。它开源、支持中英双语，基于 General Language Model (GLM) 架构，有 62 亿参数。配合模型量化技术，用户能在消费级显卡上本地部署（INT4 量化级别下最低只需 6GB 显存）。ChatGLM-6B 用了类似 ChatGPT 的技术，专门针对中文问答和对话做了优化。它经过约 1T 标识符的中英双语训练，再加上监督微调、反馈自助、人类反馈强化学习等方法，62 亿参数也能生成相当符合人类偏好的回答。

之所以选 ChatGLM-6B，一是中文支持效果好，二是 62 亿参数对 GPU 性能要求相对低，能省成本。

具体细节可以参考知乎这篇文章：https://zhuanlan.zhihu.com/p/627509623
