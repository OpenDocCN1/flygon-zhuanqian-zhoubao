5、返回响应

*   处理结果反馈：当具体的业务服务把登录请求执行完毕以后，无论是登录通过还是校验失败，都会把最终的执行结果回传给 Uvicorn 容器，相当于向容器汇报 “该用户登录成功了” 或 “账号密码错误，登录未通过”。

*   响应传递：Uvicorn 容器拿到这份反馈后，会立刻把它转发给前端的 Nginx，告诉 Nginx “这是处理完的答案，你帮我转交给浏览器”。

*   呈现给浏览器：Nginx 随后按合适的格式把结果送回浏览器。浏览器接收到后会根据返回内容渲染对应的页面，登录成功就跳转到网站主站，登录失败则弹出提示框告知用户问题所在。

概念补充：

什么是前端、后端？各自常用技术栈和典型应用场景是什么？

前端：主要负责打造用户可以直接感知和操作的界面层。涵盖网页的版式排布、视觉呈现、交互组件如按钮、菜单、滑块等，以及移动端用户可见可用的操作界面。主流技术以 HTML、CSS 和 JavaScript 为核心。以电商网站为例，前端同学要搭建商品展示页，保证图片清晰、价格与购买按钮布局合理且易操作。角色定位类似建筑师与室内设计师，负责把空间打造得好看好用。代表性开发框架如下：

### 5.5.3 Reject or Accept all

核心思想：用心看

常用技巧：1、务必仔细阅读 Cursor 输出的改动说明，若发现它改动了已完成的功能或与预期不符，直接 Reject；符合预期再考虑 Accept all。目前 Cursor 还支持基于某次对话回滚。2、有时 Cursor 会出现异常，如 applying 失败，需认真查看返回状态再谨慎决策。

### 5.5.4 重新启动项目

核心思想：甩手掌柜

常用技巧：能交给机器的就不要自己动手。规范的前后端项目都支持热更新，代码改动后会自动生效或服务自重启。若未生效可让 Cursor 修复，无需手动反复重启。

### 5.5.5 功能验证

核心思想：仔细

常用技巧：

1、在新增功能时，要求 Cursor 不去触碰现有功能，从而保障原有功能稳定

[PRE6]

2、一个新功能调通后，务必把之前的老功能全部过一遍。曾多次出现新功能可用但把旧功能破坏的情况。准备提交版本前，确认全部功能符合预期。

### 5.5.6 版本管理

核心思想：及时提交

常用技巧：

1、功能基本可用就立刻提交，不要等到“再优化一下”。下一次改动可能把勉强满意的版本改得面目全非，再也找不回来。

2、Cursor 支持按会话回退，若想回到某次对话的状态，可直接使用该功能快速恢复代码。

3、国内用户建议使用码云或自建 GitLab。实测 GitHub 同步时常慢或失败，码云则更顺畅。

# 六、总结复盘

回顾用 Cursor 完成智能文档问答产品开发的全过程，几点体会如下。

1.  需求精准度决定效率

Cursor 本质仍是大模型，属于自然语言序列到代码序列的映射。交互与编辑器只是外层包装。若希望输出符合预期，就必须提供高质量输入。产品经理角色至关重要，可与产品经理协同，或自行模仿产品经理的方式给出需求。

1.  耐心与毅力是 AI 编程时代的核心硬实力

传统开发中，编码技能是关键；在 AI 编程时代，耐心和毅力更重要。整个开发部署过程中，我与 Cursor 高频互动，自己虽会开发与部署，却基本采取无脑操作，异常直接丢给 Cursor，基本不亲自分析错误，反而当甩手掌柜，最终仍成功上线。过程中多次感到崩溃，越改越乱，越乱越急，导致提问质量下降形成恶性循环，但最终坚持了下来。AI 编程需做好心理准备，一次成功靠运气，大多数情况需要多次迭代。

1.  编程思维会带来加成

AI 编程依然是编程，只是代码由 AI 生成。关键架构设计、数据库建模、模块划分、整体运行逻辑仍然重要。具备这些思维就能驾驭 AI 生成的代码，上线到生产环境更安心。对已知的实现方式，能给出更详细指令，就能减少弯路。

# 八、常见问题汇总

1.  Cursor 桌面图标经常自动消失

回复：重新安装 Cursor，旧环境保留。若有更好方案欢迎补充。

1.  Apply 时经常卡死或失败

回复：手动重新点击 apply 或重启 Cursor 后再 apply。

1.  如何恢复到某次提问的代码版本

一段时间内点击某次提问会有 checkout 按钮，可恢复对应版本。现版本可能已调整，建议养成及时提交代码的习惯，避免找回困难。

1.  免费额度用完怎么办？

回复：更换账号重新注册不影响开发环境；可在电商平台购买多人共享账号，经济条件允许可自行选购套餐。

1.  某个功能尝试多次 Cursor 仍达不到预期

回复：尝试更细致地拆分功能，需求描述更具体并提供参考截图辅助；或先让 MasterGo 实现，再将生成的代码一并输入 Cursor。

1.  chat 和 composer 有什么区别

回复：Chat 主要用于生成代码片段，不会创建文件；composer 可直接生成完整代码。讨论需求用 Chat，写代码用 composer。

1.  .cursorrules 的作用与写法

.cursorrules 是配置文件，用于指导 Cursor 在代码生成时遵循特定规则与标准。通过定义项目背景、编码规范、库偏好等，确保生成代码与项目需求契合。

写法建议参考示例或在此基础上个性化修改，示例地址：https://cursor.directory/
