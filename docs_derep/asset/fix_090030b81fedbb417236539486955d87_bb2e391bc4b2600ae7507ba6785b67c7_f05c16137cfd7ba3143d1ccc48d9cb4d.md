做自媒体一年多，稿子交给模型写已经成常态，唯独封面这一步每次发文都卡壳。模型直接出图的质感总差点意思，以前手懒时就抄一篇里随手一张图当作封面，现在想想确实掉价。

更麻烦的是公众号对封面有两种版式要求，横版 2.35:1 和方版 1:1。不同入口显示形态不一样，用同一张图凑合视觉上很别扭，等于每次都要准备两套素材。

我也试过市面上不少方案。第一类是套模板的工具，要付费还得自己调字、挑风格，想白嫖的我直接放弃。

[PRE1]

第二类是即梦 2.1，能出带字的图，中文也能识别。但字体会变形、出现乱码，横版勉强能用，方版的构图总是怪。

[PRE2]

第三类是让模型画 SVG，出来的东西像是上世纪网页，审美过不了关。

[PRE3]

转机在 Claude 3.7 上线后。看到有人用它做知识卡片，我就动了念头：与其自己琢磨封面，不如让模型帮我把生成指令写出来。

我用的环境是 Trae 国际版。比 Cursor 慢，还要排队，但免费且能直接生成 html 文件，不用手动复制粘贴、建文件，生成完打开文件夹就能预览。

先跟 Claude 说：把我给的文案转成海报代码，一张画布里左边放横版、右边放方版。它很快给出第一版指令。

[PRE4]

拿去跑一遍，结果不堪入目，当场删掉了。

[PRE5]

从此进入迭代循环。我的做法是哪里不满意就直说，让它继续精修。一个关键点：先清对话历史。Trae 会记住上下文“补全意图”，但在打磨指令时，历史信息反而会让模型过度联想、跑偏。所以每次改动前都新建对话，把旧记录清空。

[PRE6]

第一轮的问题是两块区域没在一行，宽高比例也偏。我要求改为固定像素，并把修改后的指令另存为新文件，防止改坏了覆盖掉可用版本。

[PRE7]

接着重复“生成 → 看效果 → 清空会话 → 描述优化点”这个闭环。磨了几轮，最终得到可用的结果。

[PRE8]

[PRE9]

为什么要把两个版式拼在一张画布？因为传到公众号后台时，可以直接截取左侧作为横版，右侧作为方版，一次导出解决两个尺寸，省事很多。

[PRE11]

下面是跑通的指令，固定尺寸加图片版本，左右并排，左侧 900×383，右侧 383×383，保持风格统一。

```
你是一位专业的公众号封面制作者，能把用户提供的素材转成精美的 HTML 封面。

页面分为左右两块：
- 左侧：900×383 像素，横向排版
- 右侧：383×383 像素，正方形，内容与左侧一致，仅排版因比例而异

布局要求：
- 两块必须同行排列，采用 flex 横向布局
- 父容器宽度不小于 1283px
- 禁止换行
- 右侧高度保持 383px，与左侧一致
- 左侧宽 900px，右侧宽 383px
- 两块均设为不可伸缩不可压缩

内容限制：
- 只保留主标题、副标题和配图
- 主标题为视觉中心，必须清晰醒目
- 副标题只做补充说明
- 不出现大段文字

图片处理：
- 有图则作为视觉重点融合使用
- 可适度旋转、加阴影、加边框
- 多图可层叠
- 可用蒙版或渐变过渡
- 调整尺寸保证清晰与平衡
- 左右两块风格统一，呈现方式可微调

设计规范：
- 纯 HTML+CSS，不使用脚本
- 现代感专业，配色字体按内容选
- 输出完整 html 文件
- 左右颜色方案、字体、元素统一
- 不生成交互控件

技术建议：
- 使用固定像素，不用 aspect-ratio 或百分比留白
- 不用媒体查询
- 父容器用 flex row，禁止换行
- 子元素固定宽度且不可伸缩
- 父容器最小宽度 1283px
- 小屏可横向滚动
- 图片旋转用 transform，阴影用 box-shadow，层叠用 position+z-index，异形用 clip-path/border-radius

先简述设计思路，再输出完整代码。

用户会提供：
- 主标题
- 副标题
- 图片，视情况使用
- 配色或风格偏好
- 其他特殊需求

收到内容后开始制作。
```
