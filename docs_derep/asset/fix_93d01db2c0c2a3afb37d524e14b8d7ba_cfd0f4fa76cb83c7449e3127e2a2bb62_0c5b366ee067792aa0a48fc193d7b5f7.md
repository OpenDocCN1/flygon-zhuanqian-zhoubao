前阵子和朋友的工作室谋划试水小红书，翻遍手头也没找到趁手的工具。后来刷到不少圈友分享的内容工厂思路，越看越觉得这种批量打法靠它省人太明显。盯作者、找热点、抓笔记、写初稿、自动发，全套跑下来，单人照看几十个号也完全忙得过来。

圈里贡献的提示词和玩法已经很多，但真正动手落地时，还是有不少人被工具门槛卡住。我一直觉得工具不该成为项目启动的拦路石，于是一边用一边改，前后折腾了一个多月，把整套方案免费开放出来。利他即利己，也希望正在做红书的各位多来交换想法。

## 免费跑通的三块拼图

**第一，笔记采集不花钱。**
小红书的第三方采集接口大多要收费，查了一圈资料后，找到一条免费用自己账号 cookie 拉数据的路径。个人日常自用完全撑得住，但别把同一个 cookie 分给多人共用，风险自己掂量。

**第二，文字生成不花钱。**
文本这块可以接硅基流动，也能换成任何自己想用的模型。硅基流动就有免费档，比如 THUDM/GLM-4.1V-9B-Thinking。工具里已经预留好调用接口，填入密钥即可用。先用免费模型测试成稿效果，如果对质量要求高，再考虑付费模型也不迟。

**第三，图片生成不花钱。**
图文两条线都需要大模型支撑；图片这边接的接口完全免费，每天 2000 张，个人做号绰绰有余。注册一个魔搭社区账号，绑定实名认证的阿里云账号就能开通。额度不够就多注册几个号。换句话说，这套流水线就算全程不付费，也能完整跑起来。

自动发布环节可以自己接飞书来做：从 Base 表中取数，或者通过飞书侧边栏直接读表（侧边栏 TS SDK），再交给影刀、Node 服务 + 浏览器 + Playwright 去发布。因为我开发这个工具时主要围绕自己的需求，发布端对接的是一个账号矩阵管理工具，那个工具要付费，胜在发图文挂群、挂商品都支持。新用户注册免费送 3 天，填邀请码 7F20ID 还能再拿 3 天。

我最初对“接飞书”的印象，一直停留在开发者后台建应用、开权限、拿 App ID / App Secret、再换取访问凭证这件事上。对非研发或新手来说，这套链路确实劝退。后来读到圈友乔川的文章，才知道飞书 Base 里还有侧边栏插件这种玩法。

侧边栏插件轻得多：它直接跑在当前打开的那张 Base 表上，多数读和写的能力会继承当前用户对表格的权限，通常不必再单独做一套应用鉴权。只要把服务地址配好，就能在表格右侧直接调用。它不是飞书应用的替代品，更像是给 Base 表配了一个随开随用的小工具箱。缺点也很明确：用的时候得先在飞书里打开这张表，插件不打开就用不了。好在实际运营里这点并不致命。

参考了不少圈友的思路后，我用了三天时间敲定方案，把各家优点合到一起做了现在这个工具。它能跑在浏览器里，也能跑在飞书侧边栏，只有侧边栏模式才支持飞书推送。其实完全可以省略“结果推飞书、从飞书取内容”这两步，直接在网页端生成再调浏览器发布。但我仍然把飞书 Base 保留下来，因为它天生适合当内容仓库。

采集、分析、生成后的素材，按统一字段沉淀进 Base 表，先把“集中管理”和“格式统一”这两件事做扎实。业务侧只需要发一条表格链接，团队就能在同一个内容池里协作：随时改标题、改文案、补标签、标记可否发布、调整优先级，这些修改会立刻影响后续的自动化加工和发布。相比把内容锁在内部数据库里，这种可共享、可编辑、可追溯的仓库形态更贴近运营协作方式，也让内容流转更透明、更可控、更容易规模化复制。

生成内容后会直接推送到飞书，以后想在别的平台做矩阵分发，同样只需要对接飞书。这也是我做这个工具的核心意图：往后要接公众号、知乎、微博、视频号，甚至接各种第三方工具，都不必让每个平台分别跟内容工厂做接口，统一对接飞书这一个出口就行。

- 系统负责「采集 + 生成」，结果落到 Base 表；

- 他们可以用 Python、Node.js、Zapier、Make、飞书工作流等任意方式写自动发布。

换句话讲，你的系统不再是一个封闭工具，而是一个内容生产平台。多维表格就是平台对外的标准接口。

#### 2. 热词推荐
小红书会在推荐搜索里展示相关热词，实用价值很直接：
- 一个词能裂变出一串方向，核心词丢进去立刻铺开一片选题；
- 推荐词更接近用户原话，写标题、写开头更容易踩中用户意图；
- 大词拥挤，细分的组合词竞争更小，更容易打出长尾机会；
- 同一种需求换个说法也可能红，热词能把这类“别名”一起挖出来；
- 还能在项目里随时继续分析，边搜边取词边验证，越用越精准。

一句话总结：热词推荐是平台给的需求地图，让你更快知道用户在搜什么、怎么搜，选题阶段的试错成本自然更低。

[PRE5]

#### 3. 自定义文本分析
不用先去采集一大筐数据，把自己写好的标题和正文贴进去，或者传一份文档，它就能快速把内容“理顺”，告诉你核心主题是什么、哪些关键词和表达更值得保留，也方便做结构化提炼。用它来做选题研判通常更省时，试错成本也更低。

[PRE6]

#### 4. 批量指定小红书链接采集分析
你可以带着明确目标，把已收藏的对标笔记、竞品爆款或有代表性的内容链接一次全部贴进来。系统会自动抓取每条笔记的标题、正文和互动数据，然后汇总输出洞察：高频词、核心主题、创作角度、适合人群等。这个方法比关键词搜索更稳，因为它不受搜索结果噪音干扰；想研究哪几篇就分析哪几篇，样本可控，结论也更贴近真实对标对象。同时还省掉手动逐条打开、复制、整理的功夫，相当于把“收集素材→整理→复盘”压缩成一步。

智能填充本质上是一个批量填表工具：读取当前视图里的所有记录，再按你选定的规则，把某一列统一批量写入。可以写一串时间序列，也可以把一组文本模板循环写进去，或者把上传的图片批量写入附件列。整个过程不用逐行复制粘贴，适合运营侧的批量发布、排期和补字段。

### 三种填充方式怎么选

#### 1）时间序列填充
最适合排期、发布时间、定时发布。
需要设置目标列，建议选“发布时间/排期时间/执行时间”这类字段；再设起始时间和间隔时间（分/秒）。
全局填充时，第 1 行写入起始时间，第 2 行是起始时间加间隔，随后逐行累加。
账号分组填充时，每组账号都从起始时间重新开始排，互不干扰；比如 A 账号第一条和 B 账号第一条拿到的都是同一个起始时间。
最终系统会写入类似 `2026-01-09 12:30:00` 的文本时间串。

#### 2）循环内容填充
最适合标题模板、文案模板、群名、标签。
先设定目标列，再在循环内容的多行文本框中填写内容，每行一条。
运行时会按行号循环取值：比如写了 A/B/C，记录就按 A、B、C、A、B、C 的顺序循环填下云。
账号分组填充模式下，每个账号组都会从内容 A 重新开始，保证各账号拿到的模板序列一致。
建议每行只放一条内容，不要在同一行里写逗号分隔；想要 10 个模板就写 10 行。

#### 3）图片填充
最适合批量封面、批量素材补齐。
目标列必须是附件/图片列，系统也会把目标列下拉框自动限制为附件字段。
上传图片时至少选择 1 张，也可以多选。
填充策略有三档：覆盖已有图片，把原图清掉后统一换成新图；在已有图片后新增，保留原图并追加到末尾；在已有图片前新增，保留原图并把新图插到最前面。
