把自己的脑子搬进一个能被 Codex 直接调用的资料柜，关键就在于让信息既自由流转，又保持个人主导。Markdown 的纯文本特性让这件事变得可实现：任何编辑器都能打开，文件不被锁死，你的知识始终归你所有。笔记之间用双链串起，就不再是散落的文档，而是一个能互相参照的知识网络。

Codex 的用法也围绕着“人主导、AI 辅助”这一原则。它可以直接读取 Obsidian 的文件夹，无需复制粘贴。先阅文件、理思路、调工具，最后把产出落回本地目录。通过 AGENTS.md 和 Skills 告诉它你的规则，它的使用会越发贴合你的习惯。整个协作的核心是保留人的思考和判断，AI 只是执行层面的助手，而不是替代者。

### 知识库里到底要装什么

不要一上来就追求完美的目录。结构是使用出来的副产物，先靠碎片化记录堆内容，随着使用自然生长再归类。先有内容，后有结构，才是最顺的落地路径。

一个起步就能用的最小库，可以分成这几个仓位：

**1. 个人基底库**
你是谁、你信什么、你的价值观是什么，你的经历和故事线。所有对外表达的底色都从这里来。

**2. 在售产品库**
你现在在卖什么，价格、权益、差异点，为什么是你来卖，能解决什么具体问题。让 AI 能准确说产品话术。

**3. 客户洞察库**
客户画像、分层痛点、原话记录、对客户的理解、他们会搜的关键词。尤其是客户吐槽过的点，要原样保留。写内容时能从读者视角出发，就靠这一库。

**4. 素材沉淀库**
案例、故事、常见问题、基础知识，你买过的电子书、课程、复盘，以及曾经跑过量的内容，都在这里标注。还可以再分一个行业动态与关键词更新区，写作时有意识地铺词。段子、金句、生活化表达也收进来。

**5. 方法库**
你的判断、学到的技能、课程总结、爆文写法、标题套路、方法论、文章框架等可复用的创作方法。

**6. 内容生产库**
已发布和待发布的内容池，选题沉淀区。再建一个缓冲库，放那些暂时用不上但不想丢的东西。

整体看，这个库覆盖了收集、创作、储备、规划、沉淀、成果、复盘、缓冲的全链路。Codex 调用时，就像去专属资料柜取物。它不是资料堆，而是可调用资产。先把真实内容填进去，再在使用中不断归类补充调整。越真实地把自己交出去，它写得越像你。甚至录音里的口头禅、停顿、没说完的句子，都可以保留，这些不规范的表达正是个人风格的来源。

两天时间搭出最小可用库，完全可行。

### 怎么把内容喂进库

思路是让“干活本身”就是“喂库”。

**方式一：录音输入**
把日常沟通、客户对话、自己的复盘录音转成文本，让 Codex 按库的结构归档。信息越全面，归档越精准。

**方式二：存量迁移**
已学课程、业务经验、课件，直接让 Codex 存入 Obsidian。

**方式三：外部好内容归集**
平时刷到的优质内容分散在各处，可以用 Obsidian 插件或 Get 笔记集中保存。浏览网页时一键入库：点插件→确认路径→添加，内容自动进入知识库。

### 和 Codex 协作的边界感

协作要让 AI 明白四件事：我是谁、你要怎么帮我、哪些事你可以自己做、做完后结果放哪里、怎么持续变好。

可用这个框架写成协作制度：

**AI 协作工作制度**
一、你在和谁协作
二、我的业务和客户
三、协作原则
四、行为边界和确认权限
五、项目文件夹索引
六、素材归档规则
七、打标签规则
八、不同任务的处理流程
九、统一输出格式
十、结果如何反哺知识库
十一、定期体检和维护规则

### 别把所有事塞进一个提示词，拆成 Skill

以前总想一个万能提示词，输入选题就全自动生成。实际很容易失控。把每天重复的动作拆开，每个动作是一个独立 Skill：

- 从选题库筛选选题
- 写一篇公众号长文
- 从长文提炼知识卡片正文
- 从长文提炼朋友圈文案
- 用知识卡片提示词生成器生成内容
- 生成每张图片的提示词
- 发布前检查

拆开的好处是哪里不对改哪里。比如知识卡片原来要求 1000 字总超字数，就单独把这个 Skill 改成 600 字；AI 写得焦虑，就加一条“不制造焦虑，改成陪伴型表达”。

你可以下载开源 Skill，让 Codex 阅读修改，也可以自己生成。告诉它：帮我把 XX 流程生成一个 Skill，知识库地址是 XXX，按什么要求做什么，输出是什么格式。

# 公众号文章写作

###### 输入

- 接收一个已确定的选题及相关知识库素材。

- 只使用已提供或已读取的素材；缺少技术事实、案例、数据或来源时标记为“待确认”，不得补造。

- 原始素材含代码示例时，除非明确要求改写，否则保留原样。

###### 写作要求

- 围绕一个能站得住脚的观点展开，优先交付可执行的方法、清单或认知收获。

- 面向 26 至 45 岁的计算机视觉与嵌入式软件从业者，以平等、同行陪伴式口吻解释技术概念。

- 从具体项目痛点、好奇点或风险切入，依次推进为有用解释和示例、可记住的洞见、后续讨论邀请。

- 长短句交替；每段不超过五行；每三到四段切换一个自然子话题。

- 仅在帮助说明观点时使用克制的生活例子、轻度幽默或工程观察。

- 不使用夸张比喻、虚假权威、空洞口号、无依据的效果承诺、泛化的 AI 套话或标题党表达。

###### 输出

- 只输出长文正文，不生成标题、贴图正文、朋友圈文案、前言或写作说明。

- 使用清晰的 Markdown 小标题组织正文。

- 不沿用来源材料的数字编号。

# 公众号标题生成

###### 输入

- 接收公众号长文正文，以及需要时使用的原始选题和素材摘要。

- 标题必须与正文可以兑现的内容一致；信息不足时标记“待确认”，不虚构事实。

###### 生成要求

- 输出一个标题，落在工程师具体的工作处境、压力或发现上。

- 语气平等、有陪伴感，让有经验的工程师感到被理解。

- 优先表达真实矛盾、工程判断或可复用的发现，而不是泛泛承诺。

- 禁止制造恐慌、许诺结果、夸张好奇、诱导点击和居高临下的说教语气。

###### 输出

只输出最终标题，不附解释、候选标题、编号、引号或 Markdown 标记。

后续还可以拆出贴图正文 Skill、朋友圈 Skill，以及把知识卡片提示词封装成 Skill，先运行生成器再基于长文产出绘画指令。

这套体系的核心是：用 Obsidian 承载可迁移的个人知识，用双链形成网络，用 Codex 做执行层，用 Skill 把重复动作标准化。人的判断始终在前面，AI 越用越像你的副手。
