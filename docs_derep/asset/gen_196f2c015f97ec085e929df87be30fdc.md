标题：别急着上手调提示词！先吃透 Claude 官方这个隐藏功能

大家好，我是李拜日，一枚大龄待业产品经理，目前还在指令工程的世界里从零摸索。

今天写这篇文章，主要想做两件事：一是把上一篇欠下的“旧账”补上；二是把最近整理出来的结构化提示词心得分享给大家。

先说补账。上一篇聊参数流提示词的时候，我忘了一个关键信息——参数到底以什么顺序执行？估计有朋友看到同一个参数反复出现，心里会犯嘀咕：这是不是写错了？其实不是。在 Claude 里，我使用的参数遵循一套很规矩的扫描逻辑：从上往下一行行走，每一行内从左往右一个个跑完。搞懂这一点，很多困惑就解开了。

坑填完，进入新模块。

我一边摸索一边往自己的知识库里塞了新东西：结构化提示词。这招的出处可不简单，是 Claude 官方提示词工程师亲传的办法——XML 标签。听起来有点技术感，实际操作起来反而很清晰，像我这样的入门选手也能驾驭。

顺便说说这背后的故事。我报名了公众号爆文项目的志愿者，两天时间，34 位圈友被我连拉带拽弄上了船。大家的目标很一致：上岸。那我作为“船上工作人员”，能帮点什么呢？写文章的提示词？这方向在生财圈早就卷出天际了，我就不去凑热闹了。于是，我做了一套专门辅助“打卡思考”的提示词。

这套提示词里，我完整展示了 XML 标签的使用方法，同时也把自己推演时的思考路径一并写了进去。整套内容已经整理成文档放到飞书，有需要的同学可以直接自取：

最后，再回应一下评论区里的声音。

有圈友问：写公众号文章，Claude 和 ChatGPT 哪个更自然、更像真人？说实话，我不敢称老师，顶多算个前排围观的小白。目前我的体感是，GPT4 的综合实力依然领先；我一直选择 Claude，更多是因为不想再被封号折腾了。

还有朋友问：不考虑 JSON？这个问题真的超纲了。以我当前的水平，硬上 JSON 恐怕翻车概率更高，用错了反而会变成一场噩梦。

也有人觉得 Claude 写出来的东西更有人味儿，追问我用的是不是 Claude2。哈哈，这个就见仁见智了。

对了，枫晓陌在评论区留了句“握爪”，我看到时忍不住笑了——同路人大概隔着屏幕也能认出彼此吧。
