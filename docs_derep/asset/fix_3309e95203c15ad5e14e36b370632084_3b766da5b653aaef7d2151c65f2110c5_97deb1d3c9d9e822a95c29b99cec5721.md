当手边有教程附带的 3 份测试材料时，可以直接把最上面那段任务说明复制下来，当作第一次完整演练。

先把这几份材料通读一遍，然后去完成下面的真实任务：【写下要解决的问题，或你希望得到的输出】。有几点要特别注意：

- 回答只能以当前材料、以及能明确核实的事实为依据；
- 必须列出参考的文件名或相对路径；
- 要把材料原文、我自己的归纳、以及 AI 的推测区分开；
- 材料不足就直接说缺什么，不要虚构内容；
- 先在对话区给出结果，不要立刻写进知识库。

如果结果符合预期，可以继续补一句：【告诉我目标目录；如果还没定，就说“给我建一个用于 XX 的目录，结构你来设计”】。

接着，系统会把确认过的结果存为一份全新的 Markdown 文件，放到目标目录中，保留参考列表，并检查是否真的写入成功。

第一次完整闭环的链路是：材料进入 → Codex 提出整理方案 → 我确认 → 整理完成 → 基于材料做真实任务 → 结果沉淀回知识库。

对外展示时，只讲三件事就够了：我原本想解决什么；我的最小知识库由什么组成；Codex 基于材料做出了哪些实际成果。

现场演示到这个位置，闭环就完成了。之后日常维护不需要重新搭流程，直接说任务即可。

日常管理知识库时，有四句指令特别好用：

- 整理新到的材料。先自查并给出方案；涉及新增分类、移动、改名、覆盖或改动原文时，等我确认后再执行。
- 创建一个新项目。先检查有没有同名或作用重叠的项目，再给出目录、目标、交付物和进度文件的草案，确认后再动手。
- 查看哪些文档需要更新。只读扫描，重点看 README.md、AGENTS.md、文件目录.md、项目进度文件，以及与实际状态不一致的文档；先列理由和建议，不改文件。
- 基于指定材料生成指定内容。阅读材料范围，产出目标内容，列出参考文件，区分原文、归纳和 AI 推断；材料不足就说明缺口，先在对话里展示，确认后再落盘。

其它常见场景可以这样说：

| 场景 | 表达 |
|------|------|
| 统一格式 | 把这几份文档的格式调整一致，正文内容不要动 |
| 整理剪藏 | 把网页剪藏入口里的文章归类，分类拿不准就先问我 |
| 续接项目 | 先读项目里的进度文件，再继续做，结束后更新进度 |
| 学习复盘 | 读相关材料，总结掌握程度，给出下一步行动建议 |
| 知识问答 | 按指定材料回答问题，列出引用文件，材料不足要说明 |
| 执行方案 | 好，按已确认的方案执行，完成后自行检查 |

进阶内容可以等真实需求出现后再扩展，不必第一次全部做。

先说说隐私边界。“本地知识库”只表示文件存在自己的电脑上，并不代表 AI 处理全程离线。Codex 读材料并回应时，相关数据仍受当前账号、套餐、组织规则影响。开始之前要检查 ChatGPT 的数据控制设置；不要把密码、API Key、验证码、恢复码放进去；身份证、财务、医疗、合同、客户资料只给最小必要范围；对外分享前再审一遍隐私。

当最小闭环已经跑通，可以继续完善个性化方案。让 AI 先只读检查库里现有文件，再向你了解：长期目标是什么、常保存哪些材料、已有文件与项目、对命名和隐私的偏好。然后结合实际文件，输出一份完整的修订规划，包括目录推荐、材料流动路径、README.md 和 AGENTS.md 的调整建议、是否要生成文件目录.md、什么情况下需要进度文件、旧材料如何迁入、日常管理方式、执行顺序和验收标准。目录从少到多，不要为了“完整”而造空分类。此时只出方案，不碰文件。

用户需要确认：目录名称是否易懂、分类是否重叠、每个目录是否有真实用途、移动和备份规则是否可接受、先后顺序是否清楚。

文件目录.md 不是第一次搭建的必做文件。当文件数量明显增多、材料分散在多层目录不易找、需要快速检索文件名与路径、或要核对是否重复归档时，再由 AI 扫描实际文件生成。索引至少包含文件名、类型、目录、相对路径、更新时间。实际文件系统是唯一事实源；索引只是可重新生成的辅助工具；不能用旧索引反过来移动文件；不要记录不适合公开的完整本地路径；重建索引时不能改动正文。如果索引与实际文件不一致，应重新扫描实际文件，而不是按旧索引调整文件。

备份和高风险操作也要提前想好。低风险测试用副本。批量移动或重命名、删除或覆盖文件、目录重构、大规模修改正文、导入大量唯一原件之前，必须在知识库外建立可恢复副本。备份后至少核对文件数量，并随机打开重要文档或附件。同步盘只负责同步，不能当作唯一备份。

格式规整方面，Codex 默认可以直接处理：多余空行、纯空格行、行尾空格、不可见字符、重复首标题、空标题、断开的序号、列表项间多余空行。默认不能直接处理：改写或润色正文、删除看似重复但可能有意义的段落、调整观点顺序、改变标题层级含义、用摘要替换原文。分不清是格式调整还是内容修改时，先问用户。

完整的基础验收可以这样过一遍：Obsidian 能否正常打开库；Codex 是否只读验证过路径和实际文件；目录是否来自真实目标；README.md 与目录、材料流向是否一致；AGENTS.md 是否包含确认、原文保护、同名检查和自检规则；索引是否与实际一致；高风险操作前有无备份；敏感信息不会被复述；首批材料是否先给方案再执行；同名文件没有被自动覆盖；格式处理没改正文；已完成过一次带来源的真实问答或内容输出；长期项目有没有进度文件。检查时只查基础功能，不把网页剪藏、第三方平台、Skills 和总控流程当成必需项。现在只检查，不改文件。

当项目有明确目标和交付物、需要跨多次对话推进、有重要决策要记录、或相关材料会持续增加时，就适合建立项目目录和进度文件。进度文件要写清项目目标、当前状态、已完成、最近决策、下一步、待确认问题。要求：先查同名或重叠项目；有重叠就汇报现状与差异；不编造已完成事项；创建后检查 README.md 是否要更新；有索引就同步更新；最后确认各相关文件描述一致。后续继续项目时，先说“先读某路径下的进度文件，再做某任务”。

Skills 从重复任务中来。先让真实任务重复出现，再把稳定步骤固化成 Skill。可以这样理解：AGENTS.md 是整个库长期遵守的精简规则；Skill 是某类重复工作的固定步骤；总控流程负责按任务组合合适的 Skills。Skill 放在 `.agents/skills/【Skill 名称】/SKILL.md`，每个 SKILL.md 至少要有 name 和 description，并且只负责一类明确任务。手册里提到的 `.agents/knowledgebase-manager-agent.md`，是作者使用的本地总控流程文件，不是平台自动注册的 Agent，需要用户发起，并由 AGENTS.md 引导 Codex 读取后才会工作。

判断是否创建 Skill，要看一项操作是否重复出现三次以上、步骤是否基本稳定。需要读取当前库的 AGENTS.md、README.md、项目进度文件和管理记录，找出有证据的重复操作，输出完整方案：哪些适合做 Skill、哪些证据不足、每个候选 Skill 的职责边界、触发条件、名称、路径、核心步骤、安全边界、总控流程是否必要、AGENTS.md 怎么改、计划创建哪些文件、后续如何低风险测试。证据不足就明确标注“证据不足”，不要自行假设。

确认后执行时，先检查目标目录和文件是否存在；如果存在同名 Skill、总控流程或路由冲突，立即停止并说明差异，不覆盖、不自动合并；只创建方案里选定的文件；SKILL.md 按确认的名称、路径、元数据和职责来写；总控流程只在方案允许时创建；AGENTS.md 只改启动和路由规则；不擅自增加、删除或合并 Skill；删除、移动、重命名等高风险操作仍需先确认。创建后只检查路径、YAML 元数据、职责、触发条件、引用和路由。第一次测试用少量材料，并对 AI 说“用 knowledgebase-manager-agent 整理新到材料，先给方案，不要执行高风险操作”。如果技能没有出现在 Codex 里，先查路径和 SKILL.md 元数据，再刷新或重启 Codex。

线下聚会复盘时，发现这套方法确实能帮人快速上手。现场以 PPT 讲解加真实演示加实操手册进行：先讲搭建动机、Obsidian 与 Codex 的协作方式、规则沉淀和输出闭环；再打开 Codex 后台回看最初的需求与修改记录；最后让参与者照手册跑一遍最小闭环。

现场也遇到一些问题：

- Codex 安装不顺利：部分 Windows 电脑无法通过 Microsoft Store 唤起安装，可以用完整安装包；8 月航海手册里提供了相关安装包。
- Codex 配了 CC Switch 后无法正常工作，发提示词会中断：订阅 ChatGPT Plus 后，在 Codex 桌面端切换模型仍报错，后来让 Workbuddy 帮忙切换模型，成功退出 CC Switch，恢复了桌面端切换。这次经历也让人体会到“让 AI 修自己”和“跨 AI 修复”的价值，遇到问题可以回看处理过程，或让 AI 总结原因。
- 基于知识库生成内容质量差：需要补充背景和个人需求，比如“我是 AI 新手，看不懂专业名词，请用大白话结合场景解释”。

这套方法的工作顺序是：按真实用途设计 → 从三份材料开始 → Codex 先给方案 → 用户确认 → 执行 → 完成任务 → 结果沉淀 → 流程稳定后再做成 Skill 和总控流程。先跑通最小闭环，再逐步升级。

这份手册本身也经历了同样的协作过程。Codex 根据搭建过程中的对话记录和 Obsidian 沉淀的笔记，输出方案和初稿；我负责审核事实、步骤和表达，再给修改意见；Codex 按意见迭代，每次调整后还要核对手册、PPT 和相关文件版本是否一致。

现在可以先准备三份非敏感材料，完成一次整理和使用，再选一个真实需要解决的问题，确认当前版本已经能帮到你，再决定后续增加哪些目录和功能。
