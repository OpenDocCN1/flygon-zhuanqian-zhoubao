# 【AI编程实战】借助 Cursor，从零搭建抖音达人作品数据快照平台

## 写在前面

如果你每天都在收集竞品账号数据，却只能把结果堆在 Excel 和邮件里，那么你可能会遇到这样的困境：

- 数据量越来越大，难以快速定位重点作品；
- 同一条视频每天的变化趋势不够直观；
- 爆款作品无法及时被识别和跟进；
- 缺少标签、分组及筛选能力，查找效率很低。

这篇文章就来分享一下，如何借助 ChatGPT、Bolt、Cursor、Supabase 和 Vercel，快速开发并上线一个实用的数据快照工具。

整个过程不需要传统意义上的大量手写代码，适合想用 AI 编程快速验证想法、制作业务提效工具的朋友参考。

---

## 一、为什么要做“作品快照”系统？

我的实际需求是：每天定时采集近百个抖音对标达人的数据，重点关注他们最近 3 天发布的作品表现。

原本的工作流程是：

1. 定时采集达人及作品数据；
2. 汇总到 Excel 表格；
3. 通过邮件发送给相关人员。

这种方式虽然能够完成数据收集，但随着达人数量接近百人，问题也逐渐暴露出来。

每天都有数据进入表格，却很难一眼看出：

- 哪些作品正在快速上涨；
- 哪些视频可能已经成为潜在爆款；
- 同一作品在不同时间节点的增长幅度；
- 不同达人、不同标签下的作品表现；
- 哪些内容值得进一步拆解和跟拍。

因此，我希望搭建一个“作品快照”平台。

它的核心逻辑并不复杂：

每当系统再次采集到同一条作品，就向数据库中追加一条新的快照记录。通过连续保存不同时间点的数据，就可以还原作品的增长曲线和传播趋势。

对于短视频带货业务来说，选品往往直接影响最终结果。一个能够及时呈现竞品作品涨幅的系统，可以帮助运营人员更快发现潜在爆款，并及时跟进相关的选品方向、拍摄脚本和内容结构。

# 二、第一步：先和 ChatGPT 梳理需求

正式开发之前，建议不要直接打开 Cursor 就开始写代码。

更高效的方式是先把想法讲清楚，让 ChatGPT 帮忙整理成一份 MVP 需求文档。

这份文档可以包括：

- 项目要解决的问题；
- 用户有哪些角色；
- 页面需要哪些功能；
- 数据表应该如何设计；
- 作品快照怎样生成；
- 需要哪些筛选条件；
- 后续可能扩展哪些能力。

技术栈方面，我选择了 Next.js。

主要原因有两个：

第一，Next.js 目前在 AI 产品和工具类网站中使用非常广泛，生态成熟，开发资料也比较多。

第二，它和 Vercel 的结合非常方便，后续部署、更新和发布都比较省事，适合快速验证产品想法。

先把需求拆解清楚，再让 AI 辅助开发，后面的沟通成本会明显降低。

---

# 三、先做页面原型，不急着接后端

在实现完整功能前，我先使用 Bolt 制作了一个前端原型。

工具地址：

https://bolt.new/

之前看到刘小排老师分享的内容后，我发现 Bolt 生成的页面风格比较符合自己的审美，于是决定用它来快速验证产品界面。

需要注意的是，原型图并不等于完整产品。

现阶段主要验证的是：

- 页面布局是否合理；
- 主要按钮放置是否符合使用习惯；
- 数据卡片如何展示；
- 筛选、搜索、排序入口是否清晰；
- 用户点击之后的交互流程是否顺畅。

原型阶段不需要接入真实数据库，也不需要马上实现全部业务逻辑。

可以先让 Bolt 根据需求生成一个可交互的页面效果，等页面结构确定后，再把原型代码交给 Cursor，完成后续的真实功能开发。

这样做的好处是：先验证产品体验，再进入技术实现，避免一开始就陷入复杂的代码细节。

# 四、使用 Cursor 完成具体功能

## 1. 先生成 Cursor Rules

为了让 Cursor 更稳定地按照项目规范开发，我先为项目准备了一套 Cursor Rules。

这部分参考了良辰美老师开源项目中的相关思路，并根据当前项目的技术栈和开发要求进行了整理。

Cursor Rules 的作用，可以理解为给 AI 编程助手提前设定开发规范，例如：

- 项目应该采用什么技术栈；
- 文件和目录如何组织；
- 组件如何拆分；
- 命名方式是什么；
- 数据请求应该怎样处理；
- 代码风格需要遵循哪些要求；
- 哪些安全问题必须注意。

有了明确的规则后，Cursor 生成的代码通常会更统一，项目架构也不容易因为多轮修改而变得混乱。

同时，很多重复性的沟通内容可以提前写入规则中，从而减少反复说明需求的时间。

---

## 2. 把需求、原型和规则交给 Cursor

接下来，把前面准备好的三部分内容统一交给 Cursor：

1. ChatGPT 整理出的 MVP 需求文档；
2. Bolt 生成的网站原型代码；
3. 项目对应的 Cursor Rules。

然后直接告诉 Cursor：基于这些内容，实现完整的业务功能。

Cursor 负责补充的内容包括：

- 数据列表展示；
- 作品详情页面；
- 快照记录保存；
- 数据筛选和搜索；
- 标签及分组功能；
- 增长趋势展示；
- 用户登录和权限处理；
- 前后端数据交互。

模型方面，我更推荐使用 Claude 3.7 或 Claude 4.0。

实际开发过程中，通常经过几轮对话就可以搭出一个比较完整的版本。遇到页面样式问题、接口报错或逻辑异常时，直接把错误信息复制给 Cursor，让它定位原因并修改即可。

对于这类中小型业务工具，Cursor 的代码生成和问题修复能力已经相当实用。

# 五、使用 Supabase 搭建后端和数据库

前端功能完成后，还需要一个后端服务来承载用户、作品和快照数据。

这里使用的是 Supabase。

官网地址：

https://supabase.com/dashboard

Supabase 集成了不少快速开发所需的能力，包括：

- PostgreSQL 数据库；
- 用户注册和登录；
- 邮箱认证；
- API 接口；
- 权限控制；
- 实时数据能力；
- Edge Functions；
- 文件存储。

对于个人项目、原型验证和早期产品来说，免费计划基本可以满足初期使用。

## Supabase 免费方案的大致额度

截至 2025 年 6 月，免费计划主要包含以下资源：

### 基础资源

- PostgreSQL 数据库空间：500MB；
- 共享 CPU 资源；
- 约 500MB RAM；
- 每月 5GB 出口流量；
- 约 1GB 文件存储；
- API 调用次数不设固定次数上限。

### 用户和实时能力

- 月活跃用户最多约 50,000；
- 支持约 200 个并发实时连接；
- Edge Functions 每月约 50 万次调用。

### 项目数量与休眠机制

- 免费账户最多同时运行 2 个项目；
- 项目连续 1 周没有活动，可能会被自动暂停；
- 如果项目恢复使用，需要手动重新启动。

## 使用时需要注意什么？

免费计划适合个人项目和前期开发，但也有一些限制：

- 需要定期查看控制台中的资源使用情况；
- 免费版不提供完整的高级备份能力；
- 如果需要每日备份、更长的数据保留时间或更高性能，需要升级到付费方案；
- 国内访问时，受节点位置影响，可能存在一定延迟；
- 免费版本的技术支持主要依赖社区。

如果项目只是为了验证想法、内部使用或小规模测试，免费资源通常已经够用。等用户数量和数据量增长后，再根据实际情况升级即可。

## 1. 创建数据库表

数据库结构可以直接让 Cursor 根据需求生成。

例如，让它生成用于保存以下信息的数据表：

- 用户信息；
- 达人信息；
- 作品信息；
- 作品标签；
- 采集批次；
- 作品快照；
- 快照时间；
- 点赞、评论、分享、销售等指标。

生成 SQL 后，复制到 Supabase 的 SQL 编辑器中执行，即可完成数据库初始化。

这种方式比手动逐个创建表更加高效，也方便后续根据业务变化继续调整。

---

## 2. 开启邮箱登录认证

如果平台涉及个人数据或团队协作，建议加入登录功能。

在 Supabase 的 Authentication 模块中开启邮箱认证后，用户就可以通过邮箱完成注册和登录。

之后再把对应的环境变量和认证逻辑交给 Cursor 实现，就能快速搭建出基础的用户体系。

# 六、使用 Vercel 部署项目

前端项目开发完成后，下一步就是发布上线。

这里使用 Vercel。

官网地址：

https://vercel.com/

Vercel 对 Next.js 支持非常友好，部署过程简单，特别适合个人开发者和小型工具项目。

常见的上线流程是：

1. 使用 GitHub 登录 Vercel；
2. 将 GitHub 仓库导入 Vercel；
3. 选择项目并完成构建配置；
4. 填写环境变量；
5. 点击部署；
6. 等待项目生成访问地址。

部署成功后，只要代码提交到 GitHub，Vercel 就可以自动触发新的构建和发布。

这意味着：

- 不需要每次手动上传代码；
- 修改完成后提交 GitHub 即可；
- Vercel 会自动完成构建；
- 新版本发布速度非常快。

---

## Vercel Hobby 免费计划

Vercel 的 Hobby 计划主要服务于个人开发者和轻量级项目。

常见资源包括：

- 每月最多约 1000 次部署；
- 每月约 100GB 带宽；
- 约 100GB-Hrs 的 Serverless 函数运行时间；
- 支持 GitHub、GitLab 和 Bitbucket 自动部署；
- 支持绑定自定义域名；
- 自动提供 SSL 证书；
- 使用全球 CDN 加速访问。

需要留意的限制包括：

- 不支持直接部署 Docker 容器；
- GitHub 组织项目可能需要升级到 Pro 计划；
- Serverless 函数存在运行时和资源方面的限制；
- 团队协作能力相对有限。

如果只是搭建个人工具、作品展示站、内部系统或测试版本，免费计划通常已经够用。

# 七、配置环境变量

部署之前，需要先在项目中配置环境变量。

通常会涉及：

- Supabase 项目地址；
- Supabase 公钥；
- 数据库连接信息；
- 登录认证相关配置；
- 其他第三方服务密钥。

开发环境可以在 `.env` 文件中配置，线上环境则需要进入 Vercel 项目后台，在 Environment Variables 中添加。

这里一定要注意：

不要把密钥直接写进前端代码，也不要把包含敏感信息的 `.env` 文件提交到公开 GitHub 仓库。

---

# 八、开启 GitHub 自动部署

完成 GitHub 与 Vercel 的关联后，可以开启自动部署功能。

之后，只要执行以下流程：

1. 修改代码；
2. 提交到 GitHub；
3. Vercel 自动检测更新；
4. 自动构建并发布新版本。

对于需要持续迭代的业务工具来说，这套流程非常省心。

即便只是修改一个页面样式或增加一个筛选条件，也不需要重新手动打包上传。

---

# 九、绑定自己的域名

Vercel 默认会提供一个项目访问地址。

如果想让平台看起来更加正式，也可以绑定自己的域名。

我使用的是阿里云域名，具体操作步骤是：

1. 在 Vercel 添加自定义域名；
2. 根据提示获取 DNS 解析记录；
3. 登录阿里云域名控制台；
4. 新建一个三级域名前缀；
5. 按照 Vercel 的要求完成解析；
6. 等待 DNS 生效；
7. 验证域名并启用 HTTPS。

这样，一个基于 Next.js 的抖音达人作品数据快照平台就基本完成了。

# 最后总结

整个项目的开发思路可以概括为：

1. 先用 ChatGPT 梳理需求；
2. 用 Bolt 快速制作页面原型；
3. 借助 Cursor 完成实际功能；
4. 使用 Supabase 提供认证和数据库；
5. 通过 Vercel 部署上线；
6. 使用 GitHub 实现持续更新；
7. 绑定自定义域名，形成完整工具站。

真正重要的，不是单纯“让 AI 写代码”，而是先明确业务问题，再把需求拆成页面、数据和功能模块，最后让不同工具分别承担自己擅长的部分。

如果你也有日常重复、数据量大、人工处理效率低的业务场景，完全可以参考这套方法，先做一个小而实用的 MVP，再逐步迭代成真正能提升工作效率的工具。
