#### 直接在飞书对话框中指挥 Codex

以上操作，你完全不必坐在电脑前手动下指令，直接在飞书对话框里指挥即可。也就是你在手机上发一句，本地进程接收飞书事件，再调用 `codex exec` 执行，最后把结果自动回写到飞书对话线程。体验完全不同。它已不是单一工具，而是一套在后台持续运转的小型工作流。

对新手可以这么理解，整体分 4 层：

1. 飞书里有一个 bot
2. 本机 lark-cli 负责接收飞书事件、回复飞书消息
3. 本机 Codex 负责真正执行任务
4. 一条常驻 Python 守护进程把 2 和 3 串联

**首次使用时，把这段提示词发给 Codex：**请帮我在这台 Mac 上搭建一个“飞书对话框直接指挥 Codex”的本地工作流，我是小白，请你不要只给思路，直接帮我检查环境、创建文件、配置后台服务，并在每一步告知我需要点击或确认的内容。目标是：我在飞书给一个 bot 发消息 -> 本机后台进程收到飞书消息事件 -> 本机自动调用 codex exec 执行任务 -> 执行结果自动回复到原飞书线程 -> 整套流程配置为后台常驻，电脑开机即可用。**请按此顺序完成：**检查本机是否已安装 Python、Codex CLI、lark-cli；若缺失，给出最简安装方式；引导我在飞书开放平台创建 bot 应用；告知该应用需开启的权限与订阅的事件；协助完成 lark-cli 配置与授权；生成本地桥接脚本，要求仅本人可触发；生成 launchd 配置，使其在 macOS 后台常驻；做最小测试如 /codex ping；若测试失败继续排查，不要停在分析；最后把我在飞书可用的指令整理成简短说明给我。

###### 一、先创建飞书机器人应用

1. 打开 [开发者后台](https://open.feishu.cn/)，使用飞书账号登录。
2. 点击 **创建企业自建应用**。
3. 填写应用名称。建议写成 Codex 助手、我的 Codex 机器人，便于群内识别。

###### 二、为应用开通机器人能力

4. 上传头像，填写应用描述。例如：在飞书里一句话触发本地 Codex 执行任务并自动回复结果。
5. 点击 **创建**。
6. 进入刚创建的应用后台，左侧找到类似 **添加应用能力**、**能力**、**机器人** 的区域。
7. 打开 **机器人** 能力。若看到机器人欢迎语、消息卡片、可见范围等设置，先保持默认，后续跑通再调优。

###### 三、开通权限

此步关键。无权限则机器人即使进群也收发不了消息。

8. 打开左侧 **权限管理** 或 **权限配置**。搜索并开通与 IM 消息相关的权限。对“飞书一句话触发 Codex”场景，优先开通：

- `im:message:send_as_bot`
- `im:message:readonly`
- `im:message.group_at_msg:readonly`
- `im:message.p2p_msg:readonly`
- `im:chat:read`

后续若需接收图片、文件、语音，再补充：

- `im:resource`
- `im:message.reactions:read`

开通后，点击页面中的 **申请权限**、**批量开通** 或同类按钮。

###### 四、订阅事件

让飞书把新消息推送给本地进程。

9. 打开左侧事件订阅。搜索并添加：`im.message.receive_v1`。若界面要求填写“请求网址”或“回调地址”，分两种情况：

- 走 lark-cli event consume 这种本地事件消费方式，通常由本地工具接管，无需手填公网回调。
- 走传统 webhook 回调，则需填一个外网可访问的回调地址。
你当前这套“本地接收事件 -> 调 Codex”方案，核心是让该消息事件被成功订阅。

###### 五、发布应用

很多新手漏掉此步。未发布，前述权限与能力往往不生效。

10. 打开左侧版本管理与发布。点击创建版本。填写版本号如 1.0.0。填写发布说明如：开通机器人消息接收与回复能力。按提示继续。若系统提示有权限待申请，先补齐。提交发布。企业内应用通常还需将可用范围设给自己或测试成员。

###### 六、把机器人加进群聊

此步在飞书聊天界面操作。

打开飞书，新建一个测试群，建议只拉自己或 1-2 名测试成员。进入群聊右上角 ... 或 **群设置**，找到 **群机器人**、**机器人**、**应用**、**添加机器人** 入口。在机器人列表中搜索刚创建的应用名，点击 **添加**。若提示确认权限或使用范围，点击确认。添加成功后群内会显示机器人加入提示。

###### 七、测试触发

在群内 @机器人，发送一条简单测试消息。例如：`@Codex 助手 /codex ping`。私聊机器人则直接发送：`/codex ping`。正常情况下，本地进程收到事件后会把结果回复到该线程。

###### 八、常见卡点

1. 只创建应用，未开启机器人能力。
2. 开了权限，未发布版本。
3. 发布了应用，未把机器人加入群。
4. 机器人在群里，未开通消息接收相关权限。
5. 私聊可收、群聊收不到，通常是群 @ 消息权限未开。
6. 群内可触发但回复失败，通常是 send_as_bot 权限未开，或可用范围未放通。

###### 九、一句话总结

先到飞书开放平台创建“企业自建应用”，开启机器人能力，开通消息读取与机器人发消息权限，订阅 im.message.receive_v1 事件，创建版本并发布。然后回到飞书聊天界面，新建测试群，在群设置里将机器人添加进去。完成后让 Codex 接上本地执行链路。
