小宋分享了一套基于n8n搭建的自动化工作流，专门用来**高质量“复刻”播放量1w+的爆款带货视频**，甚至能直接把成品发布到带货平台。一套流程下来，省掉大量重复劳动。

## 核心理念：不是复制，而是“精细化复刻”

这套方案的核心，不是粗暴地把别人的视频拿来重发，而是：

- 用**多模态AI分析**爆款视频的创意脉搏
- 靠**LiblibAI大模型训练**提升生成精准度
- 结合**纳米banana（纳米斑马？）**保障产品一致性

最终目的是实现带货视频的**精细化生产**。

> 建议：适合中高阶玩家亲手操作。目前工作流约30+节点，还没包含配音、字幕和画面特效，但扩展性很强，也可以自己训练专属模型。

## 这套工作流到底能解决什么问题？

1. 任意Liblib模板都能用
2. 人物一致性：生成的视频中，人物/产品特征保持一致
3. 超10万+模板可选（从美女到山海经等各类风格都有）

操作流程很简单：把对标视频的抖音链接粘贴进去，设定分镜数量（5秒/分镜，可调），再到Liblib找到对应模型，复制ID填入工作流，就能直接使用那个模型了。

## 整体工作流架构

```
第一层：输入层 → 下载视频、AI分析内容、生成分镜脚本
第二层：图像生成层 → 根据脚本生成静态图片
第三层：视频生成层 → 把图片变成动态视频片段
第四层：后期处理层 → 剪辑、配音、字幕 → 输出成片
```

## 工作流拆解（6个关键步骤）

1. 用户提交表单：视频主题、视频链接、分镜数量
2. 生成分镜脚本（含旁白+图片提示词）
3. 调用Liblib API生成图片
4. 调用海螺AI生视频服务，把图片转成短视频片段
5. 合并所有片段，成完整视频
6. 自动上传至抖音（或其他平台），返回无水印链接

## 输入层关键配置

**表单界面**：视频主题（文本）、视频链接（抖音URL）、分镜数量（1-6）；一套基础表单搞定。

**参数设置（Edit Fields）**：相当于全局API配置仓库：

- **LoRA编号**：在Liblib站内选好可商用模型，复制版本号（versionUuid），填到参数模板里
- **Liblib密钥**：SecretKey + AccessKey，在Liblib后台获取
- **抖音密钥**：Appid + Appsercert（用于视频上传和解析）

**加密处理**：视频链接需要加密以满足第三方API要求，角色平台（Roll）下载抖音视频前先做地址加密。
