## 二、背后的实现原理

### 1）工作流怎么搭建？

打开 Coze 官网 [`www.coze.cn/`](https://www.coze.cn/)，首页最显眼的位置就写着已经接入了 DeepSeek-R1 模型。

[PRE11]

然后按这个路径进入：工作空间 → 资源 → 工作流。

[PRE12]

点进去就能新建工作流。飞哥已经提前搭好了，直接看完整链路。

[PRE13]

下面拆解一下每个节点到底在干什么。

#### ① 开始节点

[PRE14]

这个节点默认就有，飞哥在里面配了三个参数：

1. `org_url`：想仿写的公众号原文链接，非必填。如果填，就要用 `mp.weixin.qq.com/s/xxxxx` 这种格式。
2. `Prompt`：写给他的提示词，不需要多复杂，比如“请用大白话生成一篇 DeepSeek 的科普文”就行。
3. `feifshu_folder_token`：飞书文件夹的 token。

#### ② 选择器节点

这个节点专门判断 `org_url` 填没填：有链接就走仿写分支，没链接就走自由创作分支。

添加方式：底部“添加节点” → 选择器。

[PRE15]

判断逻辑很简单：先看 `org_url` 是否为空，再看它是不是一个合法的公众号文章链接。

[PRE16]

#### ③ 提取公众号文章内容

只要传了原文链接，就先调“链接读取”插件把内容抓下来。

添加路径：添加节点 → 插件 → 链接读取 → 添加。

[PRE17]
[PRE18]

这里只需要把开始节点的 `org_url` 引进来就行，飞哥把这步重命名成了“解析公众号链接内容”。

[PRE19]

#### ④ 调用 DeepSeek 大模型节点

接下来就是重头戏——让大模型写内容。

同样点“添加节点” → 选择大模型。

[PRE20]

模型选 DeepSeek-R1，系统提示词里指定它是公众号创作专家，并且要求用 Markdown 格式输出。

[PRE21]

没传原文时的创作节点，逻辑基本一样，就不重复说了。

#### ⑤ 变量聚合节点

这个节点用来把不同分支的输出汇总起来，正好匹配这个场景：把“无原文写作输出”和“有原文写作输出”都选上。

[PRE22]

#### ⑥ 生成标题节点

DeepSeek-R1 在生成正文后，其实也自动带了一个标题。我们要做的只是把标题单独提取出来。

用豆包大模型就能轻松搞定。

[PRE23]

#### ⑦ 创建飞书文档插件

这个插件负责把内容写进飞书文档。添加方式跟第③步一样，在插件里搜“飞书文档”，然后选“飞书云文档 → create_document → 添加”。

[PRE24]

只需要把大模型生成的内容和文件夹 token 传进去。
