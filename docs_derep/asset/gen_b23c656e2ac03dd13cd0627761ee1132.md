# 一、为什么做这个账号

今年下半年教育垂类再次迎来红利期。恰好我自己也在学日语，于是决定切入日语相关的内容赛道。

调研一圈后发现，单图八词的日语跟读视频转化最好。形式极简：一张配图放 8 个单词，从头到尾读一遍。拆开来看，核心就三步：做出一张图、生成日语配音、根据音频移动箭头。

没有 AI 时，这活我根本不会接。素材收集和图源整理就要花掉大半天。有了 AI 后，整条链路才跑通。

坚持一个月左右，账号涨到 5000+ 高质量粉丝，也通过资料售卖赚到第一笔小钱。接下来我把半自动化做视频的历程讲清楚。

# 二、第一阶段 AI 提效：从 40 分钟到 20 分钟

初期的设想是这样的：用大语言模型写内容，用 Midjourney 做图，用 Coze 做一个抠图智能体做后期处理，再把内容和图丢进 Google Sheets，最后靠 Figma 插件一键同步到模板。整套打下来，单条视频制作时间从 40 分钟降到 20 分钟。下面拆解具体操作。

## 1、用大模型生成并规范化内容

我用的模型是 gpt-4o，做两件事。

第一件事是脑暴生活常见场景里的高频日语单词。没有写死提示词，就是以闲聊的方式让它出点子。

第二件事是做结构化输出，把词的日文写法、平假名、罗马音、中文释义、英文释义整理成表格，并自动加上标题。

## 3、Coze 智能体抠图

抠图方案很多，Remove.bg、PS、Pixian.ai 都试过。最终选 Coze 智能体，两个原因：其一，它会自动把主体裁剪到合适尺寸，原图主体小也不会糊；其二，支持 API 调用，成本更低。

工作流里只放了一个智能抠图节点，智能体就是调用这个工作流。上传图片即可拿到抠图后的链接。

# 三、瓶颈出现

这套流程跑了半个月左右，问题集中爆发：

1、Coze 网页版智能体上传慢，返回链接还要手动点下载，耗时。
2、配音偶尔走调，且观众希望能看到音调标记。
3、Autojourney 下载不稳定，指定目录失效，文件名混乱分不清对应单词。
4、内容难以沉淀复用，缺少存档整理机制。
5、想要加入童声跟读，提升观感。

想起来纳瓦尔宝典里的一句话：要财富，就用杠杆。代码就是新富阶层的杠杆，你可以造一个软件，让它在你睡觉时替你工作。

正好 Cursor 热度正高，于是我决定用 AI 编程把流程再升级一次。

# 四、AI 编程 Plus：从 20 分钟到 10 分钟

我用 Cursor 写了三个小工具串起整条链路。跑通后，单条视频耗时降到 10 分钟，质量还更高了，内容也能沉淀下来。

先自报家门。我原本是安卓开发，代码已很久没写。这回用的是 Python 桌面应用和 Chrome 插件，基础语法还能看懂，但远谈不上精通。

这三个工具迭代很多次，Cursor 账号也换过，部分对话记录已丢失。下面尽可能还原当时的思路，包括 Cursor 的优缺点，都是真实踩坑经历。

## 1、Python 桌面应用

### 1）核心能力

*   直接调用 Azure AI 生成跟读音频
*   可切换 Google TTS API 或 Azure TTS 生成语音
*   调用 Coze API 完成抠图，本地下载并同步一份到七牛云，同时把七牛云链接写回 Google Sheet

#### b） 功能拆解式开发

我习惯先拆点。小应用我会先说：“我要做一个在 Mac 上运行的桌面应用，能拖图片到界面上，调用 Coze 智能体 API 抠图，Coze 返回链接，我要下载到本地 XX 文件夹。”

等这一功能跑通后再加下一步：“现在把下载好的图上传到七牛云，把返回地址填到 Google Sheet，表地址是 XXXX，写入 F 列 2-9 行，文件名按 E 列英文翻译匹配。”

这样每完成一个点就 commit 一次，定位问题快，也能随时回滚。一次性堆所有需求，一旦报错根本分不清是哪个环节。

#### e） Coze API 调用细节

直接让 Cursor 调用 Coze API，一开始它只实现了对话，上传图片始终失败。折腾多次无果后我猜测是 Coze API 太新，网上资料少。于是自己去看官方文档。

文档里流程是：先调用文件上传接口，把本地图片传上去拿到 file_id，再在对话接口里带上 file_id 发请求。因为是非流式响应，要轮询 retrieve 接口等到 completed，再调 message list 接口拿抠图后的网址，最后下载。

文档太长不方便直接喂给大模型，容易超 token。于是我只把关键示例和参数摘出来，配合清晰的逻辑复述给 Cursor，它一次就写出来了。

#### f） 报错与界面卡顿

开发中常遇到终端报错或界面卡顿，比如抠图下载在主线程执行导致 UI 假死。直接把报错日志贴上去，或者描述现象：“上传图片时界面卡死，我想避免阻塞。”

Coze 智能体偶尔也会没返回图片链接，这种情况让 Cursor 加重试机制即可。

#### g） Google OAuth 2.0 的坑

本软件调用了多个 API，Azure TTS、七牛云都能用 API Key 直连。Google 的调用方式就复杂得多，有服务账号、API Key、OAuth 2.0。桌面端和 Chrome 插件的调用流程还不一样。

不提前确定方案，Cursor 会随意选一种，导致调试困难。我花了很久才靠官方文档定位正确方式。确定后把示例代码丢给 Cursor，问题立刻解决。

[PRE22]

#### h） 音频生成与童声模拟

目标是软件内直接产出带跟读的音频，减少剪映操作。跟读本质是拼接音频，难度不大。难点在模拟童声。

我让 Cursor 实现时，它给出的方案是本地音频处理库，通过调节音调、语速、音高等参数来模拟。但调了几次效果都不理想，具体用的是哪个库我已记不清。
