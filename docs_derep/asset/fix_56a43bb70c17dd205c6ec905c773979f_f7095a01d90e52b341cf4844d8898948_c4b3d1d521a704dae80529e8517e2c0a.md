先来认识一下：我是嗡嗡鱼 Fish。

不少朋友知道我的背景——写了十几年程序，操盘过几十个出海产品站，也在生财带过好几期 AI 编程主题的航海。照理说，这种老开发做出个产品不值得大惊小怪吧？但这次的情况正好拧过来了：整个产品做下来，我手上一个字符都没敲过。为什么？因为 AI 越用越顺手，我现在真的一点代码都不想碰；而且说实话，传统的纯手工编码方式，跟 AI 编程已经不在一个量级上了。就拿 Claude Code 来说，现在一个项目里绝大部分代码都是 AI 自己写完、自己调试、自己迭代的。所以“你不用会写代码，只要会指挥 AI，就能做出产品”——这条路，普通人完全可以照着走。这正是我今天最想传达的核心。

这次经历来自生财 6-7 月的 AI 实战月。我先在线下局做了一场一个半小时的分享，随后带 11 位圈友用 3 小时各自打磨自己的产品。3 小时结束，这 11 个人全部拿出了能跑的 AI 作品。

直接说答案：零行手写。代码全部由 AI 写了七百多行，我只做了一件事——发指令，然后让 AI 自己测试、自己修 bug。如果不算上打磨界面细节的时间，核心流程一个半小时就通了。

但一整场聊下来，我最大的体会并不是“AI 多强、干活多快”，而是另一件事：“做什么、怎么做”这个判断，AI 永远代替不了你，你必须亲自决策。

绝大多数人过不去的坎，表面看是“想法太大”，实际上就是“说不清自己到底要啥”。需求太模糊，AI 就无从下手。这一点放在后面细讲。

所以这篇复盘，我不想记流水账。我想把线下验证出来的东西——从“脑子里一个隐约的想法”，到“一个能卖钱的小产品”——这条完整链路，一步一步摊开给你看。看完你就能自己上手了。

### 一、先看结果：3 小时，零行手写，能收钱

把成果先亮出来，你再判断要不要继续读。

| 用途 | 做什么 | 市场参照 |
| --- | --- | --- |
| 证件照 | 生活照 → 正装免冠、纯白/蓝/红底、A4 拼版可打印 | 街边照相馆至少 30 元起 |

### 二、一句话心法：先完成，再完美

[PRE3]

这是整场分享里我重复最多、现场认可度也最高的一句：

完成比完美更珍贵，慢一点往前挪，也比站在原地犯难强。普通人做产品，真正要面对的敌人只有三个：想得太大、怕做得不完美、不知道第一步往哪迈。对症下药，也就三条：

- 先跑通，再做好看。先让“上传 → 点击 → 看到结果”这条主线结结实实地走一遍，哪怕数据是假的、页面丑得没眼看，之后再回来谈美化。千万不要在一开始就纠结配色、收款和商业逻辑。
- 能砍就砍、能假就假、能晚就晚。这句话印在了现场手册里，是砍需求的八字诀。今天的唯一目标，是做出一个能演示的最小版本。登录、支付、后端、数据库、账号体系，统统先不做。你的构想再宏大，今天也只做那最小的一个切片。
- 不知道怎么下手？先动手。不会就问 AI，把它当作你的队友。项目跑起来报错了？别怕，把报错丢给 AI，让它修，再让它解释给你听。一来二去，你慢慢就有了“驾御这台机器”的体感。行动起来，永远比原地踌躇有用。

现场做得最快的那几个人，共同特点不是技术好，而是砍功能特别果断、动手特别快。

### 三、没思路怎么办：先把想法聊成型

现场有几位圈友，工具装好了、Codex 也学了，却卡在“不知道做什么”。如果你也处在这个状态，这一节就是为你准备的。

- 最省力的路子：把下面这段万能开场白原封不动扔给 AI，横线处填上你的想法，多模糊都行：

你是一名资深产品经理 + 全栈工程师,擅长把模糊想法变成"今天就能做出来的小工具"。我想做一个小产品,主要靠你帮我写代码。我现在的想法(哪怕很模糊都行):\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_先别写任何代码,按下面来:1. 如果我的想法有不清楚的地方,先【一次性】问我 3-5 个最关键的问题, 等我回答后再继续,不要自己瞎猜。2. 帮我把想法收敛成一个"输入 → 处理 → 输出"的单页小工具; 如果想法太大,帮我砍到里面最小的那一个工具。3. 然后输出一份大白话的需求文档(PRD), 并给一份验收标准(最多 5 条,让我能自己检查做没做对)。

AI 会反过来问你几个问题，你认真回答，想法就会一点点清晰起来，比自己闷头想要高效得多。

- 想再省事一点，就给 AI 装一个 brainstorming skill，它存放在 superpowers 这个包里。装上之后，AI 不会马上写代码，而是像访谈一样向你提问：给谁用？解决什么问题？最小做成什么样？聊着聊着，你还不知道做什么就奇怪了。装法在第五章。

- 最好的点子通常来自你自己的日常痛点。你最清楚自己忍受不了什么、最想要什么结果。从你工作里那些重复、琐碎、没技术含量但特别耗时的任务入手，这是最自然的起点。

- 实在憋不出来，就直接从这张表里挑一个，减少做决定的内耗：

| 选题 | 输入 → 输出 |
| --- | --- |
| 文案/标题改写器 | 一段话 → 几个更吸睛的版本 |
| 宝宝/网名起名器 | 姓氏/喜好 → 一批名字 + 寓意 |
| 塔罗/今日运势 H5 | 点一下 → 翻牌 + 解读 |
| 简历润色器 | 粘贴简历 → 优化版 |
| 单词卡/字帖生成 | 词表 → 可打印卡片 |
| 报价/行程生成 | 填几个数 → 一张整齐的单子 |

想法太大不可怕，逐层拆小，拆到一句话能说清为止。

### 四、保姆级 SOP：从点子到可以卖的产品

下面这几段，是我在开发拾光肖像馆时，亲口对 Codex / Claude Code 说的核心指令。其他产品怎么做？把“证件照”换成你的关键词就行。每一步踩到的坑我也全部标注了。

如果你还没装工具，先花五分钟准备：Codex 去官网下载，用 ChatGPT 账号登录即可；Claude Code 则在终端执行一行 `npm install -g @anthropic-ai/claude-code`。

装好后新建一个空目录再启动，所有项目文件统一放在一处，干净省心。从现在开始，你只需要做三件事：把需求说清楚、检查结果并挑毛病、把报错原样丢回给 AI。

#### 第 0 步 · 选题：先看“有没有人付钱”，再看“AI 能不能做”

很多人的顺序是反的，上来先问 AI 能不能实现。正确顺序应该反过来：现在有没有人正在花钱买这个东西？只要有人在卖、有成交记录，就说明需求已经被市场验证过了。

证件照、AI 写真、宝宝入园照、求职形象照——这类需求在线下一直很贵，拍一次一两百起步；小红书上的 AI 写真 9.9 元一张，卖得非常火爆。我做的，不过是用一个生图工具把这几种需求打包而已。

这个需求一直都在，真正改变的是门槛。放到去年，零基础的人遇到第一个报错基本就卡死了；到了 Codex / Claude Code 这一代，才真正实现了“你说人话、它就干活”。需求没变，代码门槛却消失了。大多数人还没动手，所以此刻正是你下场的最佳时机。

一个提醒：如果想法太大，比如“做一个像小红书的平台”，那就只做平台里最小的那个模块，像我这样做一个极度垂直的小工具。如果你的需求一句话讲不清楚，说明还不够小，继续砍。

#### 第 1 步 · 需求：先把话说透，别急着要代码

> 我要做一个能在小红书上卖的「AI 证件照生成器」网页工具,目标用户是求职者和宝宝家长。先别写任何代码,先帮我把需求理清楚:1. 核心功能有哪些?2. 用户从打开到拿到证件照,操作流程怎样?3. 哪些是今天 3 小时能做完、能现场演示的最小版本(MVP)?哪些先砍掉?4. 靠什么卖钱?用一份大白话的需求文档(PRD)回答我。

让它先出文档、先向你提问。你过目之后觉得没问题，再让它继续。

容易跑偏的几种情况，以及纠偏的话术，直接抄：

- 它没提问就闷头写代码：“先别写代码，先按要求出 PRD。”
- PRD 里冒出登录、数据库这类：“这些今天不做，删掉，只留最小版。”
- MVP 一口气列了七八个功能：“只留 1 个核心功能，其余标成‘以后做’。”

#### 第 2 步 · 计划：技术方案自己拍板，别让它自由发挥

> 基于上面需求,技术栈:纯前端单页 HTML(一个 index.html,内联 CSS 和 JS),不要后端、不要框架、不要构建工具,浏览器双击就能打开。先别写代码,先给我:写技术文档、项目结构。

为什么要自己定技术栈？因为零基础最怕 AI 自作主张选个“高大全”的框架。框架需要配环境、构建、打包，一连串看不懂的步骤，哪一步断了都能把你劝退。用最简单的 HTML，双击就能打开，写代码之前不需要搞懂任何复杂的工程概念，行动阻力最小。

技术文档出来后，后面的开发就不会跑偏。项目结构、分步开发计划，这些都是你能看懂的东西：上传的图放哪里、生成的图又放在哪。所谓分步计划，本质上是一份开发清单，目的是防止上下文过长之后 AI 发生“失忆”。

#### 第 3 步 · MVP：先让最小流程转起来

> 根据技术文档、项目结构、分步开发计划，开始写第一版 index.html。要求:能上传照片、能选规格(一寸/二寸)和底色、点生成后可以裁成证件照尺寸并拼成 A4 一版多张、预览加水印。这一版先用上传的原图占位(还不接 AI),把整条流程跑通就行,样式朴素没关系。

第一个版本丑到没法看是正常的，关键是“上传、生成、出结果”这条路已经通了。这一步只追求跑通，不追求好看。

#### 第 4 步 · 核心：AI 负责生图，代码负责精度

先说明一个实用细节：这一步需要图像 AI 的接口（比如 gpt-image 这一类），你得自己去申请 key，可能涉及一点小费用。可以参考这几家：书虫的 apimart 中转站（apimart.ai）、阿里云通义万相、火山引擎的豆包、即梦，去它们各自的控制台开通即可。如果连 key 都搞不定，那就把“协助我申请一个 xxx 平台图像模型的 key”这个问题直接丢给 AI，让它一步一步带你注册、开通。

拿到 key，正式接入：

> 把上传的照片生成成"正装、正面免冠的专业证件照,人脸保持不变,背景按需要直接出纯白/纯蓝/纯红底色"。裁标准尺寸、A4 拼版、水印这些用代码做。注意:底色通过 prompt 让 AI 直接生成对应底色(干净不改脸);用 apimart.ai 的 GPT-Image-2 图生图能力, 生图模型API 的接入文档是：https://docs.apimart.ai/en/api-reference/images/gpt-image-2/generation，api key 是：xxxxxxxxx

证件照成品：AI 负责生成正装人像（shiguangzhao.com 线上样张）

[PRE7]

这一步是我踩坑最多的环节，全部交底：

- 坑 1，出图像抽卡。我第一次生成的蓝底发灰，人脸也变了。解决方法是往 prompt 里追加英文约束词，再抽一次：底色用 solid pure blue（强制纯色、不发灰），保脸用 keep the person clearly recognizable as the same individual（确保依然是本人）。这两句直接抄。不满意就再抽一张，改一句话再试，这是常态。

- 坑 2，原图必须传进去。只在 prompt 里描述“这张照片”是没用的，原图要作为输入传给接口。不同接口的传法不一样，有的走文件、有的走 base64，让 AI 自己读文档搞定即可。真不用自己啃文档，莫自虐。

- 坑 3，出图要等 10-50 秒。我一度以为程序卡死了。后来让 AI 加了一个每几秒轮换的等待文案：“AI 正在分析五官、换正装、打光、精修”，干等多出来的空白，就变成了期待。

⚠⚠ 报错了别慌（现场最高频场景）：把报错原文整段复制回去，附一句：这是报错,帮我看看怎么修:<贴报错>。AI 一看就知道是参数或尺寸写错了，一分钟就修好。

口诀只有三步：复制报错、丢回 AI、重新跑。

再说点实在的：光图好看，不值 9.9。让人愿意掏钱的逻辑是——你的工具能稳定产出图片，能裁成精准的标准尺寸，还能免费预览效果；但预览图带了水印，要下载高清版就得付费。每一步都在引导用户走向付款，就这么简单。

#### 第 5 步 · 美化：话说得越具体，AI 改得越准

> 把界面美化成能直接发小红书的专业风格:渐变标题、卡片式布局、上传/选模板/选底色分成清晰三步、生成按钮有质感、点下去有"生成中"转圈动画、出结果时淡入揭晓、证件照带相框阴影、手机上也好看。

按这段跑一版感受一下，但别停在这一版，后面还要再磨几轮才拿得出手。

“好看”不是一步到位的，要不断挑毛病。挑毛病也有方法论：

- 错误示范：“再好看点”“有点丑”——AI 根本不知道你说的丑指什么。你可能讨厌的蓝紫色，恰好是别人眼里的最爱。

- 正确示范：“标题太小，放大一倍”“主按钮太灰，换暖橙色”“结果卡片太挤，加间距”“手机上按钮被挤出屏幕了”。

记住一套话术结构：哪个位置、什么问题、想要什么效果。

再讲一层经验。上面那段 prompt 改完，界面确实“整齐”了，但蓝紫渐变加系统字体，一眼就能认出 AI 味。这是几乎所有 AI 模型自带的审美惯性。想要真正拿得出手，我第二轮重做时在 prompt 里明确写了：风格要用“数字摄影工作室，编辑杂志感，暖纸色背景 + 墨绿赭金配色 + 衬线大标题”，“避免蓝紫色渐变和系统字体那种 AI 味”，再加一句保险：“所有现有功能不能丢”。这一轮用的是 frontend-design 这个 skill（见第五章），前后只花了 5 分钟左右。
