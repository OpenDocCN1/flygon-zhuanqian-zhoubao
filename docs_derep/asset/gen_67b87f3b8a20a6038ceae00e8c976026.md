上次在社群露面还是一年多前。那会儿聊的是小猫补光灯，一个纯靠 Cursor 撸出来的 iOS 小 App，直接冲上了 AppStore 付费榜第一。那时候顶流模型是 Claude 3.5 Sonnet，Cursor 也是全网公认的 AI 编程神器。

一年多而已，模型从 3.5 升到 3.7 再到 4，现在已经是 Opus 4.7 了。工具这边也从 Cursor 换成了 Claude Code。AI 圈子里换了好几波天。

[PRE1]

回头复盘最近几个月的产出，有个挺清晰的发现：外部工具换得飞快，我做事的底层逻辑却一直没变。并且结果还一直在线。

这就让我开始琢磨，到底起作用的是什么。

## 最近到底干了什么

前两个月 OpenClaw 话题炸了的时候，我其实很久没有认真研究过这个工具。但作为一个做 AI 内容的博主，完全不做点反应说不过去。

于是让 Claude Code 帮我整了一份 98 页的《OpenClaw 橙皮书 🍊》。一方面想蹭一波热度，另一方面也想给自己做长视频解读省点事，毕竟有 PDF 在手，拆解起来轻松很多。没想到这份东西在 X 上直接破了 200 万阅读，飞书文档访问量超过 20 万，还在各个 AI 交流群和某海鲜市场疯传。

[PRE2]

紧接着上个月 Claude Code 源码泄露那波，我恰好把做 AI 内容橙皮书的流程已经做成了 skill。结合自己用的感受，很快就出了期视频顺带把《Claude Code 橙皮书》也写了。

顺手丢到微信读书试试水，结果第二天直接登顶热搜榜第一。

[PRE3]

在此之前我对这类榜单一直是敬而远之的，觉得跟我没关系。后来才发现，只要你真的去做，就已经超过了 99% 的人。而如果你不是被逼着做，不是为了赚钱，只是单纯觉得好玩把它做出来，那你又一次超过了 99% 的人。

这是第二件。

第三件是女娲.skill。这个更像是顺手之作。

起源是写一篇叫「把同事作为 Skill」的文章。有个开源项目把公司同事的经验蒸馏成 AI skill，引发了不小的讨论。我觉得有意思，就写了篇感想。写到一半突然意识到，我自己不就是在做这件事吗？我把写作、做视频、写橙皮书这些能力都已经 skill 化了，跑得挺顺。既然能蒸馏同事，那蒸馏任何我崇拜的人的思维框架不是更有价值吗？

于是女娲.skill 出生了。开源一周 GitHub star 破万，也上了不少媒体。

## 这三件事像在哪里

看似不相关，回头看其实很像：做的时候谁都没想让它爆。

橙皮书是为了解套内容生产顺手做的，女娲.skill 是写文章时灵机一动。没有哪一个是先去研究「什么能火」再做的。

但它们有个被我事后才发现的共同点：做完之后，我都做了一样的处理，我把它 skill 化了。

### Skill 化到底指什么

Claude Code 里有个 skill 功能，就是把一套工作方法写成配置文件，下次遇到同类任务它会自动按这个套路执行。

第一本橙皮书写完后，我把「怎么写橙皮书」整件事沉淀成了一个 skill。信息搜集、章节规划、排版美化、封面生成、微信读书上架，全流程都在里面。

有了它，第二本橙皮书从几天压缩到几小时。如今我一共写了七本，初稿基本半小时就能出来。

人物蒸馏也一样。先蒸馏了芒格的框架，把「如何蒸馏一个人」固化成 skill，后面费曼、Naval、塔勒布、乔布斯、张一鸣都越来越快。最终这个方法本身迭代成了女娲.skill，成了任何人都能用的通用工具。

对我来说，这就是转折点。做成一件事是经验，把它 skill 化才是资产。

### 资产会相互组合

这些 skill 并不是孤立存在的，它们会自己连起来。

女娲.skill 并不是灵光乍现。它是 perspective skill，也就是蒸馏人物的产物，加上橙皮书 skill，也就是做小册子的方法，再加上我长期用 Claude Code 的经验，三者叠加后，「把蒸馏方法本身做成工具」这个想法自然就出现了。

就像手里有 20 块形状各异的乐高，你看到的不是 20 块，而是上万种组合。每多一块，可能性不是加法，是乘法。

目前我手里有几十个 skill，覆盖写作、调研、校对、配图、排版、发布、视频脚本、人物蒸馏等场景。这些东西叠在一起，做事时经常会自动冒出新的玩法。女娲.skill 就是被内在组合推出来的，不是规划出来的。

### 工具会过时，方法不会

一年前我用 Cursor + Claude 3.5 Sonnet 做小猫补光灯，现在用 Claude Code + Opus 4.7 做橙皮书和女娲.skill。工具、模型、甚至品类都变了。

我真正攒下来的能力是：把一次做成的事，提炼成可复用的方法。这个能力跟工具脱钩。工具从 Cursor 换到 Claude Code，模型从 3.5 换到 Opus 4.7，skill 化的路径完全一样：做成 → 提炼方法 → 下次更快 → 省下的时间做新事 → 再 skill 化。

每次工具迭代，大多数人都在从零学习。我也在学，但我学完就会把新工具接入已有的 skill 体系。别人是重启，我是在给系统加一块积木。启动速度完全不一样。

所以工具换了三轮我还能继续出爆款，不是因为我聪明或更努力，而是 skill 在复利。

### 一个可以参考的思路

我不确定这套打法是否适合所有人。我每天用 AI 十几个小时，做的内容和产品类创作也特别吃 skill 化。

但有个底层问题是普适的：你今天做的事情里，有多少是做完就丢掉，下次还得重头来的？

那些就是可以被 skill 化的点。不一定非要 Claude Code 的 skill，也可以用清单、模板、SOP 固化。核心是让经验沉淀成资产，而不是用完即弃。

当你的 skill 库达到一定量级，创作灵感会自己冒出来。你不需要绞尽脑汁想下一步，手里的积木会告诉你。

说到「有趣」。我知道在生财有术说「做有趣的事」容易被当成凡尔赛。但我的体感是，只有真心觉得有趣，你才会有动力把它做到极致。做到了才值得 skill 化，skill 化了才有复利。

如果你一开始就盯着「能不能火」「能不能赚钱」，注意力全在算计上，反而做不到位。

这个世界很多时候像个草台班子。大多数人痛苦地工作不知道在干嘛，你因为好玩就去干了，结果反而鹤立鸡群。

这不是成功学，只是我自己一个意外的观察。

工具会一直迭代，模型会一直升级。如果你能在每一次迭代里把经验沉淀成 skill，你就不是在追工具，而是在建系统。

系统才不会过时。
