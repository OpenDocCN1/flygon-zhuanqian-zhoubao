作为个人开发者想做付费业务，起步的工作不是先敲代码，而是先把商业主体搭好。最省事的做法是线上注册一张个体工商户执照，费用低流程快。拿到主体后，用它去申请小程序和开通微信支付商户号。

特别注意的是，商户号 mchid 和小程序 AppID 必须在同一个主体名下，并且在小程序后台的微信支付里完成关联。

#### 10.1 微信支付商户号手工开通环节

下面这几步必须你自己操作，AI 无法代办。

| 序号 | 操作位置 | 具体动作 |
|---|---|---|
| 1 | 微信支付商户平台 pay.weixin.qq.com | 以个体工商户身份提交资料，申请拿到商户号 |
| 2 | 商户平台 → 产品中心 | 开通 JSAPI 支付，小程序场景只能用 JSAPI，不是 Native 也不用 APP 支付 |
| 3 | 小程序后台 → 微信支付 | 把刚申请的商户号关联到当前小程序 AppID |
| 4 | 商户平台 → API 安全 | 生成一串 32 位的 APIv3 密钥，自己妥善保存 |
| 5 | 商户平台 → API 安全 | 下载 API 证书 `apiclient_cert.pem` / `apiclient_key.pem`，私钥只能放在服务器，严禁上传到前端或小程序 |
| 6 | 记录 | 把商户号 mchid、AppID、APIv3 密钥、证书在服务器的存放路径记下来 |

mchid、APIv3 密钥、证书 属于支付核心凭证，相当于钱袋子的钥匙。跟 AI 沟通时只提供 mchid 和接口说明，密钥和证书由 AI 从服务器安全路径读取，切勿粘贴到对话里。

#### 10.2 给 AI 的后端实现提示词

我要在现有 Laravel 后端接入微信支付 JSAPI 用于小程序，请按中文说明完成：

1. 创建支付订单接口
   - 地址：`POST /api/pay/create`
   - 需要登录验证，基于已有 token 识别用户
   - 参数：`product_id`、`openid`
   - 业务：根据 `product_id` 查出应付金额 → 调用微信统一下单 JSAPI → 得到 `prepay_id` → 按微信规范生成小程序需要 5 个参数：`appId`、`timeStamp`、`nonceStr`、`package`、`paySign`
   - 返回：HTTP 200 与这 5 个参数
   - APIv3 密钥和证书从服务器安全文件读取，禁止硬编码

2. 支付结果异步通知接口
   - 地址：`POST /api/pay/notify`
   - 微信会异步推送支付结果到此地址
   - 业务：校验签名 → 用 APIv3 密钥解密报文 → 核对金额 → 更新订单为已支付 → 为用户开通会员权益
   - 必须按微信要求返回成功响应，否则会重复推送

[PRE2]

3. 订单查询接口
   - 地址：`GET /api/pay/order?out_trade_no=xxx`
   - 返回订单状态及是否已支付

要点：金额单位为分；回调必须验签；订单状态变更建议用数据库事务防止重复发放权益。

#### 10.3 给 AI 的前端实现提示词

在微信小程序的“我的 / 会员中心”页面增加以下能力，使用原生小程序语法：

1. 套餐列表：调用 `GET /api/membership/plans` 获取套餐名、价格、权益，用卡片形式展示
2. 立即开通流程：
   - 先请求 `POST /api/pay/create` 拿到 5 个支付参数
   - 再调用 `wx.requestPayment`，把参数原样传入
   - 支付成功提示开通成功并刷新会员状态；失败或取消给出对应提示
3. 会员状态：页面加载时调用 `GET /api/me` 获取 `is_vip` 与 `vip_expire_at`，已开通显示“会员有效期至 X”，未开通显示开通按钮
4. 前端禁止写入任何密钥、mchid、证书，均由后端保管

注意 `wx.requestPayment` 的 `paySign` 必须由后端按规则生成，前端只负责调用。

#### 10.4 iOS 端的致命坑

虚拟商品如会员、金币、课程在 iOS 上不能使用微信支付，苹果强制要求 IAP，否则审核会拒。

因此会员订阅类业务要注意：
- Android 和微信端可继续使用微信支付
- iOS 端要么接入苹果内购，要么暂时不开放购买入口，仅提示“请在安卓 / 微信内购买”

实物商品不受此限制，微信支付全平台可用。

#### 10.5 小程序后台需要做的配置

- 微信支付由后端服务器调用微信接口，前端只需调用 `wx.requestPayment`，无需在小程序后台的服务器域名里额外添加微信支付域名
- 后端服务器必须能公网访问 `api.mch.weixin.qq.com`，使用宝塔时检查是否拦截了出站请求
- 类目选择要准确，如“文娱-付费内容”、“工具-会员服务”，隐私协议里要说明会采集支付订单信息
- 权限需提前申请

### 第十一部分：用 Gitee 托管代码

项目上线后，代码若只留在电脑或服务器本地，设备损坏或误删就全丢。Gitee 是国内的 GitHub 平替，免费、速度快、界面中文，适合个人开发者做云备份，同时记录每次修改历史，方便回滚。

简单说：**Gitee 就是代码的网盘 + 时光机。**后续部署章节里提到的 Git clone 正是依赖这个能力。

#### 11.1 在 Gitee 新建仓库

1. 访问 gitee.com，用手机号注册登录
2. 点击右上角 + → 新建仓库
3. 仓库名填项目英文名，如 `miniapp-todo`，路径自动生成

5. 初始化时勾选添加 README 文件，不要勾选 `.gitignore` 和许可证，后续自行添加
6. 创建后记下地址：`https://gitee.com/你的用户名/miniapp-todo.git`

新手建议先用 HTTPS 方式推送，稍后可换 SSH 免密。

### 11.2 给 Codex 的宝塔部署指令

服务器使用宝塔面板，Nginx/PHP/MySQL 已装，网站根目录 `/www/wwwroot/api.你的域名.com/backend/public`，SSL 已申请，数据库 `miniapp_todo` 已创建，用户名 `miniapp_user` 密码已保存。

请负责：
1. `git clone` 到 `/www/wwwroot/api.你的域名.com/backend`
2. `composer install --no-dev --optimize-autoloader`
3. 创建生产 `.env`，`APP_DEBUG=false`，数据库信息按宝塔填写
4. `php artisan key:generate`
5. `php artisan migrate --force`
6. `php artisan config:cache && php artisan route:cache`
7. 权限：`storage` 与 `bootstrap/cache` 设 775，其余 755/644，禁止 777
8. `chown -R www:www storage bootstrap/cache`

不要自行安装环境、修改 Nginx、申请 SSL。需用户操作的事项请列为“用户待办”。
