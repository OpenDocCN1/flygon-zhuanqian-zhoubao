## 先聊清楚 MCP 到底在解决什么问题

MCP 全称 Model Context Protocol，模型上下文协议，是面向大语言模型的开放式连接标准。它的目标很简单：让 LLM 能顺畅地调用外部数据源和各类工具。

过去接入一个插件，要面对不同的 API 格式、鉴权方式和调用逻辑，成本很高。MCP 把这些差异统一成一套接口，像 AI 领域的 USB-C 一样即插即用，大幅降低了多协议适配和开发门槛。对企业和开发者而言，这意味着 AI 应用与 Agent 的能力边界会被快速拉开。

协议由 Anthropic 在去年 11 月提出后，很快在开发者圈子里发酵。大家纷纷把常用功能打包成 MCP Server 去试水。今年 3 月 Manus 爆火，虽然它本身没用 MCP，但多 Agent 协同的热度让业界再次意识到标准协议的重要性。可以说，MCP 的落地正在塑造大模型应用开发的新范式。

## 腾讯云大模型知识引擎为何值得关注

4 月 14 日，腾讯云官宣大模型知识引擎正式接入 MCP 支持。之后在搭建应用时，用户既能直接调用平台已收录的精选 MCP 插件，也能接入自己部署的自定义 MCP 服务。

目前平台里上架的精选 Server 覆盖面很广，有腾讯位置服务、腾讯云 EdgeOne Pages、Airbnb、Figma、Fetch、微信读书等，基本涵盖了专业信息检索、网页部署预览、网页内容解析等常见场景。除了现成插件，用户若已有基于 MCP SSE 部署的服务，也能按协议配置后在应用里灵活调用。

知识引擎本身提供标准模式、工作流模式、Agent 模式三种玩法。MCP Server 可以在工作流和 Agent 模式下快速启用。工作流模式靠拖拽原子组件来编排业务逻辑，适合需要精细控制流程的场景；Agent 模式则交由大模型自主规划任务和工具调用，无需写代码，几步就能搭出一个智能体。

举个例子，用腾讯位置服务 MCP 插件就能快速做出路线规划助手。在 Agent 开发模式里，一键添加插件后，大模型就能直接调用地图工具完成规划。
