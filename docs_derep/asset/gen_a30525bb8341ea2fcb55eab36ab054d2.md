**Codex 的使用逻辑是反过来的**

它可以直接打开 Obsidian 里的文件夹读取原文，不用你来回复制粘贴。看完文件后，它自己梳理思路、调用工具，最后把结果写回本地目录。规则可以通过 AGENTS.md 和 Skills 喂给它，用得越久越懂你的语境。

到现在为止，我见过的做法里，只有它把「人的判断」放在第一位，AI 只是执行层面的帮手，而不是替代者。

## 知识库里到底应该装什么东西

之前实操和课上三斤老师反复强调的一点是：别一上来就去设计一套完美的目录。结构是用的副产品，不是先验规划。先让碎片化的记录堆起来，用着用着结构自然长出来。先内容后结构，才是真正能落地的路径。

所以我先搭了一个能跑起来的最小库，里面有六大块：

### 1. 个人底座库
我是谁、信什么、价值观是什么、经历和故事是什么。让 AI 能摸到你的底色。

### 2. 产品与服务库
现在在卖什么、价格和权益是什么、跟竞品的差异在哪、为什么是买你、能解决什么具体问题。

### 3. 客户洞察库
客户画像、分层痛点、客户原话、你对他们的理解、他们会用什么关键词搜索。包括他们在评论区吐槽过的内容。写东西时要从读者视角出发，这是最关键的一环。

### 4. 素材沉淀库
案例、故事、常见问题、基础科普、买到的电子书课程复盘、曾经爆过的内容都要放进来并做标注。分一个子区放行业动态和关键词更新，写作时有意识地铺词就能提升搜索。段子、金句、生活化表达也归这里。

### 5. 方法论库
你自己的判断、学到的技能、课程精华、爆文写法、标题打法、文章框架等等，所有能复用的方法都沉在这里，后面创作时直接调用。

### 6. 内容生产库
已发和待发的选题池，内容生产流水线。额外再开一个缓冲仓，放那些暂时不知道用不用得上但不想丢的东西。

整体来看，这个库覆盖收集、创作、储备、规划、沉淀、成果、复盘、缓冲。Codex 调用时就相当于去专属资料柜里取，而不是在资料堆里翻。它是可调用的资产，不是资料堆。先把真实的内容放进去，再在用中不断归类、补充、调整。

越真实地把自己交给它，写出来的东西越像你。哪怕是录音里的口头禅、停顿、说一半没说完的习惯，也能保留。这些“不规范”的细节，恰恰是个人风格的来源。

### 第二步：把 Skill 拆小，别塞一个万能提示词

以前我也想一个选题扔进去就全搞定，后来发现很容易失控。

三斤老师讲的时候我当场用酒店稿纸把每天重复的动作画出来，从上海带回西安。

现在我把重复动作拆成独立技能：

从选题库筛选选题、写一篇公众号长文、从长文提炼知识卡片正文、从长文提炼朋友圈文案、知识卡片提示词生成器、生成每张图的提示词、发布前检查。

拆开的好处是哪里不对改哪里。

比如知识卡片原来要求 1000 字总超字数，就单独把这个 Skill 改成 600 字。比如 AI 写得焦虑，就明确加一条：不制造焦虑，改成陪伴型表达。

# 公众号文章写作

## 输入

接收已确定的选题及相关知识库素材。只用已提供或已读取的素材；缺技术事实、案例、数据或来源时标记为“待确认”，不得编造。原始素材含代码示例时，除非明确要求改写，否则保留原样。

## 写作要求

围绕一个能站住脚的观点展开，优先交付可执行的方法、清单或认知收获。面向 26 至 45 岁的计算机视觉与嵌入式软件从业者，用平等、同行陪伴式口吻解释技术概念。从具体项目痛点、好奇点或风险切入，推进到有用解释和示例、可记住的洞见、后续讨论邀请。长短句交替，每段不超过五行，每三到四段切换一个自然子话题。仅在必要时使用克制的生活例子、轻度幽默或工程观察。不使用夸张比喻、虚假权威、空洞口号、无依据的效果承诺、泛化的 AI 套话或标题党表达。

## 输出

只输出长文正文，不生成标题、配图文案、朋友圈文案、前言或写作说明。用清晰的 Markdown 小标题组织正文，不沿用来源材料的数字编号。

## 输入

接收公众号长文正文，以及需要时使用的原始选题和素材摘要。标题必须能被正文兑现，信息不足时标记“待确认”，不虚构事实。

## 生成要求

输出一个标题，落在工程师的具体工作处境、压力或发现上。语气平等、有陪伴感，让有经验的工程师感到被理解。优先表达真实矛盾、工程判断或可复用的发现，而不是泛泛承诺。禁止制造恐慌、许诺结果、夸张好奇、诱导点击和居高临下的说教语气。

## 输出

只输出最终标题，不附解释、候选标题、编号、引号或 Markdown 标记。

## 知识卡片固定角色提示词生成器

3:4 竖版专用——独立多图模式

角色：知识卡片提示词生成器

背景：手绘涂鸦风格的信息图。3:4 竖版适合小红书传播。内容多时要生成多张独立完整图片，而不是把多张图挤在一张画布。

任务：根据内容分析逻辑和信息量，自动判断是否需要拆分，生成清晰明确的绘画指令，按顺序生成多张独立完整图片。

核心原则
1. 文字必须用反引号锁定
2. 位置必须具体到容器
3. 插画必须和文字绑定描述
4. 多图独立输出
5. 首图标题必须醒目

内容量判断与拆分规则、3:4 竖版构图库、视觉风格库、固定卡通人物形象杜稀饭的设定，均按既有规范执行。
