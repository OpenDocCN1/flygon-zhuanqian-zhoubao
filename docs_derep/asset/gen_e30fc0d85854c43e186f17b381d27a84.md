# 从英文小白到月入11288元：我用Codex接小程序定制单的完整复盘

很多人私信问我：不会编程、不懂英文，真的能靠AI做小程序接单赚钱吗？

我的答案是：能，但前提是你得先动手。

这不是一篇教你一夜暴富的文章，而是一个04年普通圈友的真实记录。我在2026年6月，用Codex完成了6个小程序定制项目，工作台显示成交额和实际到账均为11288元。没有一笔是大单，全是1000～2500元的小项目，但正是这些小额订单，让我第一次真正跑通了“获客→报价→交付→收款”的完整闭环。

## 6月到账11288元，都做了什么项目？

按我后台的记录，6个项目分别是：

1. 医院类小程序：1388元
2. 台球/门店类小程序：2000元
3. 酒吧/桌游类小程序：2500元
4. 保卫萝卜资料共享小程序：1100元
5. 书店类小程序：2000元
6. 汉堡/餐饮类小程序：2300元

大部分都是店铺展示类的项目。如果只要前端页面和展示效果，一般报价在1000元左右；如果涉及具体功能、后台管理和服务器配置，价格通常在2000～2500元区间。

## 我的起点：真的什么都不会

我是04年出生的，加入生财已经三年了，但前两年基本都在潜水、看帖、收藏，没有真正跟过任何一期航海。我不是程序员，连英文都看不懂。一开始听到Codex和GPT，还以为它们是两家不同公司的产品，连Git、VS Code、Claude Code分别是干嘛的都要专门建一个飞书文档才能记下来。

我甚至跟航海志愿者说：“我英文一窍不通，只能这样硬记。”志愿者安慰我说，用到了自然就懂了。

加入生财之前，我还交过998元进过一个付费社群，群里300多人，开过今日头条发文章的训练营，但最后真正赚到钱的没几个。不过那个群里我第一次听说了知识星球和生财有术，也因为好奇花了几百块加入了进来。当时我暑假工存款只有3000多，不舍得花钱，甚至用三个微信号轮流申请免费体验，就为了多看几天精华帖。

但这些都不是重点。重点是：直到今年3月参加小程序航海，我才第一次从“看别人做”变成了“自己做完还有人付钱”。

## 前两个小程序，全都没赚到钱

第一个做的是木鱼小程序，页面粗糙到连截图都没留，代码也删了。第二个是去水印小程序，因为我自己做过网盘拉新，手里有追星群大概3000人，觉得她们应该需要去水印。结果上线后发到群里，只有几十个人点击，真正使用的人更少。

当时的我连Bug都不会描述，只会说“这里有问题，帮我改一下”，AI改完一个地方又弄坏另一个地方。我不会用Git，也不知道代码能回滚，只能让AI一路往下改。

后来我才想明白：群里有3000人，不代表有3000个真实需求。很多人更习惯在原平台点赞、收藏，不会多一步打开小程序。如果现在再让我做自己的产品，我不会一上来就写完整代码，而是先做一张功能图或简单演示，发到目标人群里，有人愿意付费，再继续往下做。

## 一条随手评论，带来了十几条客户咨询

4月底，我在小红书刷到别人发小程序相关的内容，顺手留了句评论，大意是“00后自学做了小程序，可以试用也可以接定制”。发完我就没管，账号一直放在备用机上，只顾着研究别的需求去了。

到了5月底，我无意中打开那个账号，发现后台躺着十几条私信。有人问能不能做微信小程序，有人问还接不接活，也有人直接问价格。那一刻我才意识到：我到处找需求，真正的客户其实已经在私信里等了我快一个月。

可惜那个账号很快触发了验证，因为用的是新号，又是房东共用的网络，之前还封过号，我根本回复不了这些客户。后来还是让朋友帮忙发了一条，第二天就来了新的客户。

一开始加到的两个客户都没成交。原因很现实：我不会聊天，不会报价，朋友圈里也没有案例，客户一眼就能看出我是新手，不敢把项目交给我。为此我专门跑去闲鱼研究同行怎么定价，发现带后台和支付功能的定制小程序有人报价5000元左右，简单模板类的也能收到2000元。

第一次接单我没案例，所以报价比同行低一些，但我开始明白，不能只丢给客户一个数字，还要讲清楚：包含哪些功能、都做什么页面、最后怎么交付。

目前我的客户几乎全部来自小红书截流。不是靠发内容起号，而是去“小程序制作”“小程序定制”“AI做小程序”这类内容下面留言，有需求的人自然会私信过来。对新手来说，这种截流方式最直接，因为用户已经在相关内容下面停留了，说明至少对这个方向有兴趣。跑通一个渠道后，再考虑复制到其他平台，但前期千万别贪多。

## 第一单1100元：我只收了500元定金

第一位正式成交的客户，想做一个《保卫萝卜4》资源共享小程序。他在微信群里管理资料，图片、视频、文字和攻略堆在一起特别乱，想用小程序让群友方便查看。

当时我不敢主动报价，就问老板预算。老板说1000左右，最后谈到1100元，先付500元定金，交付后再付600元尾款。

收到定金那天，我特别兴奋。那时我朋友圈没有专业包装，手里唯一能展示的作品就是那个不怎么样的去水印小程序。在这种情况下，竟然有陌生人愿意先转我500元，真的很难描述那种感觉。

回头来看，我当时确实有点初生牛犊不怕虎，只做过一个不成熟的小程序就敢接单。但我的建议是：新手不要什么项目都接，但也不用等自己什么都会了才开始。至少先判断核心功能能不能实现，把第一版范围说清楚，接那些自己有机会完成的项目。

从那以后，我对报价慢慢有了感觉。现在我不会上来就报数字，而是先问清楚客户需求。因为同样叫“小程序”，工作量差别太大了：只做前端展示的，大约1000元；要前端、功能、后台、服务器一起上的，基本在2000～2500元。还得让客户明白，花这笔钱能拿到什么、有哪些页面、要不要后台、要不要服务器、怎么测试怎么交付。这样客户就不是单纯比价格，而是在衡量这钱能不能解决他的问题。

## 新手适合接什么项目？这5类最安全

个人经验，新手可以先从这几类入手：

1. 店铺展示型小程序
2. 资料共享型小程序
3. 简单预约型小程序
4. 简单点单/菜单展示型小程序
5. 有基础后台管理但业务逻辑不复杂的项目

反之，这几类尽量别碰：

1. 多商户入驻
2. 复杂分销返佣
3. 强支付风控
4. 复杂会员储值
5. 需要长期运维的大系统
6. 客户自己也说不清需求、总在临时改方向的项目

新手最怕的不是不会写代码，而是接了一个边界不清的活。客户不停加需求，AI也越改越乱，最后双方都崩溃。

我现在的接单流程固定为7步：

1. 判断客户是不是真需求
2. 让客户说清楚想解决什么问题
3. 用Codex把零散需求整理成文档
4. 发客户确认第一版功能，不确认不动工
5. 收定金，再开始做
6. 做完自己先测一遍，再给客户测
7. 客户确认收尾款，再处理上线和售后

这套流程特别重要。因为我不是程序员，没有流程，很容易客户说一句我改一句，项目越做越乱。

## Codex不会替你思考，但能把活干好

客户说完想法后，我不会立刻动手。而是先让Codex帮我整理出一份需求确认文档，再发回给客户确认有没有遗漏功能。等客户说“完美”，我才正式开始。

第一次做正式项目时，很多东西都不懂。小程序选什么类目、备案怎么填、下一步该点哪里，我都会截图问Codex。因为它知道项目的完整上下文，能告诉我接下来要检查什么。不过类目、备案、支付和审核这些经常会变，最终还是要以微信官方为准，不能全信AI。

客户测试发现Bug时，我会先整理清楚是哪个页面、哪个按钮、现在什么效果、希望改成什么样，再交给Codex修改。刚开始我只会说“这里有问题”，后来才明白，给AI的信息越明确，越不容易改坏别的地方。

6月2日客户来问尾款，我们重新核对了总价1100元、已付500元、尾款600元，转账后我继续帮他上线。这个订单虽然金额不高，但让我第一次完整跑通了整套流程。也是从那一刻起，我确信自己真的能把客户的想法变成一个小程序。

现在我都会提前和客户说清楚：报价一般包含3次需求确认、3次第一版验收、1～2轮小修改。这个边界一定要讲明白，不然后续很麻烦。

售后方面，我主要负责Bug和基础使用问题，比如按钮点不了、页面显示不对、数据没保存这类，都会继续修。但如果是新增页面、新增后台模块、新增支付流程，或者整体换方向，那就不算售后范围，要重新评估时间和费用。这也是我踩坑后才明白的：服务要做好，边界也要讲清楚。

## 我负责沟通和服务，Codex负责写代码

我以前做过私域销售，所以深深明白：个人接单不能只把东西做出来，还得让客户在整个过程中放心。我会发需求文档给客户确认，每到一个阶段就让他测试，有问题就记录下来继续处理，从没收完钱就不管。

有一位客户在小程序交付后，还给我寄了一份辣子鸡。寄出之后又发来几个小Bug要改，我也继续配合处理。对我来说，这份礼物代表客户认可的不只是小程序本身，更是我的服务态度。

Codex能帮我整理需求、写代码、修Bug，但这些事只能我自己做：

- 听懂客户真正想解决什么问题
- 和客户确认第一版要哪些功能
- 检查AI做出来的东西能不能正常用
- 处理反馈，区分Bug、修改和新增需求
- 负责上线和售后

后来我又做了其他项目，比如一个已经上线的桌游酒馆小程序，包含会员、酒水点单、成长值、桌面预约、余额和订单等功能。到了6月，我的实际到账达到了11288元。我并不是突然学会了大量代码，而是慢慢跑通了一个固定流程，并把每一次踩坑都记了下来。

现在我已经建立了自己的小程序知识库和工作台，记录每个项目做到哪一步、客户还要确认什么、有什么Bug、收了多少钱、上线前要检查什么。这样每接一个新项目，就不会从头再乱一遍。

关于开发周期，如果只看写代码本身，我现在一个小程序大概3～4天能做出主要功能。但完整交付我会预留10天左右，因为中间还包括需求确认、页面调整、客户测试、Bug修改、小程序审核、上线发布这些环节。尤其审核不是自己说了算，所以报价和沟通时不能只按“写代码时间”算。

## 给新手的6点最真诚的提醒

1. **先验证需求再做完整小程序。** 先做功能图或简单演示，找几个真实用户问一下。有人愿意问价甚至付定金，才算需求成立。我那个去水印小程序就是反例——我以为3000人的群会有需求，结果上线后点击寥寥，大家更习惯在原平台直接保存。

2. **让AI改之前，把问题说清楚。** 别说“这里有问题”，要说哪个页面、怎么操作、现在什么结果、希望变成什么样子，以及哪些正常功能不能动。

3. **一定要保存能用的版本。** 每完成一个重要功能，就保存一个能正常运行的版本。最好学一下Git，不然AI改坏了很难回退。

4. **报价前先确认功能范围。** 同样叫小程序，只做几个展示页面和带后台支付服务器是两个完全不同的工作量。要问清楚：要哪些功能、需不需要后台和支付、谁提供资料、包含几次修改、售后多久。

5. **不要直接把AI做完的东西发给客户。** 自己先把登录、按钮、数据保存、分享和主要流程都测一遍。客户可以帮你验收，但不能让客户替你发现最基础的问题。

6. **服务要好，但要有边界。** 什么是Bug、什么是小修改、什么是新增功能，提前讲清楚。服务好不等于一直免费改。

## 最后说点真心话

这件事不适合想靠AI自动赚钱的人。AI确实降低了开发门槛，但客户沟通、测试、交付和售后依然要自己扛。

如果你和我一样不会代码，不用一开始就做复杂项目。先找一个自己熟悉的人群，看他们经常遇到什么小问题，选一个做张功能图，找5个真实用户聊一聊。没人需要就换方向，有人愿意聊、愿意讨论价格，再让AI帮你把需求整理清楚。

我从连英文都不会，到完成第一笔1100元订单，再到6月实际到账11288元，不是因为突然变成了程序员，只是先接住了一个真实需求，然后在一次次沟通、修改和交付里，把原来不会的事慢慢做会了。

如果你正处于“什么都不会”的阶段，不妨先找一个很小的需求，做一个能展示的作品，去评论区、私信、朋友圈试试有没有人需要。有人问，再一点点把报价、需求和交付流程补起来。

普通人用AI做交付，是真的有机会跑通的。
