你有没有想过，你手里的 API_KEY，可能已经被黑客当成了“免费提款机”？

最近有位朋友跟我诉苦，说他的网站被人绕过了接口鉴权，上游服务被持续狂刷，损失相当惨重。这种遭遇我太有感触了——因为我的网站也刚刚经历过一波攻击，最猛烈的时候，黑客请求达到每分钟数千次。

当时我第一时间止损，然后对整个站做了一次彻底的“安全体检”，并套上了多层防御：

- 强化认证逻辑，堵住可能被绕过的校验口；
- 接入 Vercel KV 和 Upstash，做全局限流；
- 再按 IP 和单个用户分别限制调用频率。

这样一来，哪怕再有人想暴力刷请求，也会被挡在入口之外，很难伤到上游接口。

评论区也有不少“同款受害者”：有人说先点赞再说；还有人分享了一次惊险经历——他在本地 Cursor 中用 Kimi 驱动 Claude Code，并给 CC 安装了 Figma 的 MCP。只要在对话里要求使用 Figma MCP，页面就会快速闪动，系统不断重复发出相同请求，结果却都返回 no request。他按下 ESC 中断后一查，Kimi 的 token 在短短几分钟内就消耗了几百万，速度接近毫秒级。更诡异的是，他回头问 CC 刚才在做什么，结果又触发了同样的疯狂请求，吓得他再也不敢尝试。

这位朋友因此提醒大家：用 API 时一定要时刻留意 token 消耗。无论是被外部攻击，还是内部 bug 引发，接口用量失控的后果都不堪设想。所以，如果你还在依赖简单校验来保护 API_KEY，真的要尽快把认证、限流和用量监控都安排上了。
