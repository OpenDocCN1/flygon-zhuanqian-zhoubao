最近90天，本机环境里消耗了406.11亿 Token，整体榜单第73，惠州本地第1。[PRE0][PRE1][PRE2]

当下主要做小红书的虚拟产品赛道，从挖掘需求、打包产品到内容获客，整条链路已经被AI串起来了。AI负责重复性的抓取、整理、分析与执行，我只管定方向、定产品形态和最终验收。

到现在累计上线了26个虚拟产品，月均被动收入在1万到2万左右。体量不算大，部分环节仍需人工兜底，但这套体系已经可以稳定运转。

这篇文章算是给自己做个盘点，也把这些年跑过的项目和当前的工作流梳理出来。核心讲三件事：怎样让AI稳定操控小红书，从榜单数据里揪出已被验证的需求；怎样把确认的需求交给AI产出虚拟资料或工具；怎样让AI持续产出能带来流量的图文。

# 一、早期摸索

我第一次尝到商业的滋味，是大一升大二暑假给校企合作班做招生。做完之后才知道赚钱是什么感觉。

后来在图书馆看到一本讲万科王石早期倒卖资源起家的书，突然觉得这事也能试。资源方缺人，手上能找到学生，把两端连上就是生意。

那时手上没资源没背景，能想到的平台都去挖过。Boss直聘、智联、猪八戒，以及Soul。只要有人手里有项目需要大量人力，先把业务聊通，谈成就回学校找人执行。

Soul对我影响最大。平台里有不少行业聊天室，也有年入几十万甚至上百万的人常出没。我当年社会经验浅，性格偏内向，线下谈合作总没底气，就常泡在这些房间里听别人怎么说话、怎么处理事，照做。时间长了也认识了一些人。

最早做的是组织学生进厂。之后淘宝店铺注册、自媒体代发、视频剪辑、刷单等各类拉新和校园业务都做过。说白了就是资源方要人，我能把人找来。

业务越来越多，个人主体就不够用了。有些项目要签合同、开发票，回款要走公司账户，个人根本接不了。于是开了公司，后面遇到需要主体资质的项目也不至于卡壳。

做人力期间，也试过互联网与自媒体。抖音、快手的鸡汤号做过一阵子，发励志语录和情绪文案配背景视频和BGM。账号有曝光，却看不到变现路径。当时不懂商业模式，每天只会发，越发越没盼头，最后停了。

中老年情感公众号矩阵算是少数赚钱的互联网尝试。刚有点收入，平台就开始治理，矩阵基本全挂，项目被迫终止。

公众号之后做过两性社群和吃瓜社群。内容偏敏感，主要靠小红书等平台引流到微信群。引流号易出事，微信群也频频被封，最终没能持续。

后来把之前积累的经验和外界资料整理成一套自媒体培训课，放在微信群做文字直播。获客仍靠小红书，找大学生批量发引流帖。流量和转化一般，项目越来越重，收入跟不上，最后停掉。

那一年还跑了两个To G招商项目。资源来自之前做人力时认识的几位前辈，我这边也认识些有政府部门人脉的朋友，想把两边撮合。

当时心里只有一句话：要么不开单，开单吃十年。两个项目前后跑了近一年，最终都没落地。

# 二、连败后的转变

2023年其实赚了不少。人力及其他零散业务累计赚了几十万。对在校生来说不算差。

但心里并不踏实。之前的项目陆续停掉，两个最看重的To G项目也没结果。我当时真觉得能成，也投入了大量时间。

做人力时赚的是差价。资源商把业务转来，招人、执行、交付都能向下推，事情还在自己手里。

招商项目不一样。我能做的只是把项目方和认识的关系接上，真正决定落地与否的是关系链条。我认识的朋友和政府里能推进的人之间隔着两三层。没背景、没长期政府端积累，光靠牵线很难跨过去。

项目迟迟不落地，心态越来越不稳。公司成立后的税务和杂事也很烦人，过去的冲劲在这一年基本被磨平。开始怀疑自己的判断，也怀疑自己到底会不会赚钱。

跑完两个招商项目后，看项目的视角变了。以前觉得找到资源、把两边连上就能成。后来更关注，决定结果的关键要素在谁手里。继续做资源中介，本质还是找资源、牵线、当二道贩子。做多久，项目和资源仍是别人的，自己能沉淀的东西有限。

2024年初缓了很久，甚至考虑找工作。投了几份线上岗位，面试都失败。说实话，就算进了，我心里也不想真正进体制。最终不甘心，还是回来找项目。人力和资源中介逐步放下，精力转向互联网。

先做了小红书商单号，也搞了个MCN。半年多下来，单号收益有限，看不到明显增长。看到同行陆续退出、MCN注销，我也没继续。

手里还剩一批小红书账号，转去开店卖虚拟产品。这块从2024年一直做到现在，产品和店铺倒了不少，平台规则变多次，经历过被刷差评、被举报。商品下架就换品，店铺封了就换店，规则变了就改内容和运营。

到2026年OpenClaw流行起来。我开始思考：能否让AI自己找需求、做产品、发内容，再完成销售？

# 三、需求到获客的AI闭环

## 找需求：AI跑流程，人做判断

要让AI把产品卖出去，先得回答市场上什么东西有人买。以前我靠手动刷小红书。看到数据好的笔记点进去，翻主页看卖什么、价格多少。一天能记几个方向，效率有限，今天刷到什么是什么，没刷到的就错过了。

人工效率低，但千帆里的数据是现成的。这是小红书官方数据中心，每天10点更新阅读榜、引流榜、热卖榜和成交榜。哪些笔记在拿流量、哪些内容能导流到商品页、哪些商品在起量、哪些账号已产生成交，一目了然。比只看点赞收藏更接近真实需求。

现在AI每天自动巡检榜单。8个入口，阅读、引流、热卖、成交各分内容和账号。一轮覆盖数百条数据，范围远超人工。

数据进库后，AI会先给账号打分。成交金额和支付转化率权重最高，阅读量只占小部分；连续多天上榜、同时进入多个榜单，或粉丝少却已成交，也会加分。这一步只决定优先看哪些账号，具体卖什么要进店后判断。

筛选后，AI操控手机逐个打开目标账号的小红书店铺，把商品分享链接复制出来，再由电脑抓取详情和图片。每家采完要核对数量，手机拿到的唯一链接数和本地商品详情数必须一致，不对就补采，不进入分析。

数据齐全后，AI开始逐号分析：品类、定价、爆款、粉丝量、是否低粉高销。

最后把品类和形态相近的账号归到一起。AI会依据账号数、商品数、价格区间、最高可见销量和商品图证据，给出市场状态、结论和下一步建议。交付难度、版权或平台合规问题也会写进结论。

[PRE3]

AI负责抓取、打分、分析和合并，人只需看结果。看板会标注每个方向的状态、账号数、价格带、最高销量和支撑证据，也能在Obsidian里直接看到账号的商品界面，和网页打开效果一致，无需自己刷榜、翻店、记数据。是否跟进、做成何种产品，最终由人定夺。

## 做产品：人定形态，AI做执行

从看板挑一个方向时，对应的数据已在本地：卖什么、什么价、主图和详情长什么样，不用再搜索。

下一步要决定形态。同样需求可以走两条路。

如果是虚拟资料类，模板、教程、素材包，先用拿到的商品信息和图片判断同行在卖什么、怎么展示。详情页看不到交付内容，还需去闲鱼、淘宝、拼多多自费买几份同类成品。付款必须人工完成。资料到手后，和AI一起拆解内容、确定结构，按模块制作自己的版本。

涉及材料：对标店铺的商品信息和图片、闲鱼购买资料、淘宝购买资料、拼多多购买资料、AI分析资料、人定结构、按模块制作。

这些资料仅用于了解品类通常包含什么、哪些痛点未解决。具体内容需重新整理，不能直接拼凑。

如果是APP、网站、小程序，则把需求资料交给Codex。先出图片原型，人确认功能和视觉后，再按原型还原UI、开发逻辑，并逐步截图校验。

虚拟资料还是工具类，由人判断。AI把市场证据和对标数据摆出来，做成何种形态、如何差异化、如何定价，需要人基于市场理解来决定。

需求和对标证据已厘清，做产品时不用再从零猜测用户想要什么。上线后再根据真实反馈迭代功能与内容。

## 做内容：AI跑日常，人定调性

过去做内容的最大问题是不可复制。今天想个选题写一篇，明天再想一个，质量和风格不稳定。能做起来的有运气成分，做不起来的也找不到原因。

现在产品出来后，内容走标准化流水线。

第一步，AI把产品资料理顺：卖给谁、解决什么问题、在什么场景使用。然后确定核心关键词，所有内容围绕这些词布局。

为何从关键词入手？用户在信息流里被动刷到是一种路径，有明确需求时会主动搜索。考研人会搜“考研数学真题”，找简历模板的人会搜“应届生简历模板”。内容只有布局在这些搜索词下，才能兼顾被动和主动流量。

关键词确定后，AI抓取这些词下排名靠前的对标笔记。图文保存正文和全部图片，视频保存原片、关键帧和语音稿。这些素材足够支撑后续拆解，我目前主要靠图文获客，所以流程中会筛掉视频，只让图文继续往下走。做视频业务时，可另起一条视频拆解与聚类线。

收集到一定量后，AI把结构相似的笔记归类，提炼模板草案。例如发现十几篇高互动笔记都用同一种开头和正文结构，就把规律抽出来。

草案出来后需要人工介入。AI归纳的结构不一定全对，哪些有效、哪些细节需调整，靠人判断。确认后，把草案固化为可执行的Content Skill。后续标题、正文、话题、封面、内页图都按这份Skill生成。

[PRE6][PRE7][PRE8]

Skill定好后，每天定时由AI按规则生成笔记初稿，再由AI自检一轮：是否编造事实、图片是否清晰、是否偏离Skill要求。不通过就返工。

新Skill初期可开启人工复核，AI自检后人再看一眼，确保发布质量。有问题就回炉调整Skill。运行一段时间后，若AI产出基本无需修改，可关闭人工复核，让AI自检通过即发布。

Skill跑顺后，每天定时出稿、AI自检、人扫一眼即可发。前期把规则调准，后期就是收割。

# 四、搭建思路

真正搭起来所需的东西并不多。一台电脑、Obsidian、一台已登录小红书的安卓手机，再加一个能读取本地文件、运行脚本并调用工具的AI，基本够用。找需求还需能正常进入千帆数据中心。

我现在用Mac，浏览器是Ego。Windows没有Ego，可换Playwright或其他可被AI操作的浏览器。AI用Claude Code、Codex、Hermes、OpenClaw皆可，只要能把本地文件、脚本和工具串起来。

最顺手的方式是让Codex指挥Claude Code跑流程，有问题由Codex自行解决，人只需关注结果。

这里只讲核心思路，不展开技术细节。完整脚本、配置、Obsidian面板代码、子Agent提示词我会放在文末附件，下载后把文件夹交给AI，让它按你的电脑和手机环境适配。

## 找需求：从榜单筛出可做的方向

此环节由一个主Agent和两个子Agent协同。

千帆采集子Agent负责抓全当日榜单，账号分析子Agent负责逐个查看账号商品和图片。主Agent负责账号打分、商品采集、完整性核对和跨账号汇总。多个账号反复出现的同类产品，最后会聚合成一个待评估方向。

完整流程：

千帆采集子Agent抓全8个榜单入口 → 主Agent给榜单账号打分 → 主Agent操控手机进入高分账号店铺 → 手机取短链、电脑抓全商品 → 主Agent核对商品和图片完整性 → 账号分析子Agent逐号分析 → 主Agent合并重复产品方向 → 同步Obsidian，由人决定是否推进。

正式开始前先确认四件事：

[PRE9]

- 小红书账号能正常进入千帆数据中心
- 浏览器已登录千帆和小红书
- 安卓手机已登录小红书，主Agent可正常操作
- Obsidian工作台能正常打开和保存数据

浏览器最好单独建一个采集空间，名字自定。首次登录后，后续始终使用同一空间，避免任务中途丢失登录状态。

首次运行时先测一个商品较少的账号，确认主Agent能打开主页、进入店铺、复制商品链接并返回正常，再开始批量采集。

### 第一步，采集千帆的8个榜单入口

千帆每日更新笔记排行。采集四类榜单：阅读榜看流量、引流榜看导流能力、热卖榜看起量、成交榜看真实交易。每类再分优秀内容和优秀账号，共8个入口。

优秀内容提供具体笔记，优秀账号提供后续进店对象。两者结合可同时看到内容表现和成交情况。

主Agent先调用千帆采集子Agent。依次打开8个入口，每个入口最多采20页。每翻一页随机等待60到90秒，并校验排名连续性。第一页应为1到10名，第二页应为11到20名。若出现缺号、重复或与页面不符，该页重采。

8个入口全部完成才进入账号筛选。只完成7个，即使已有几百条数据，也先停在采集阶段。

每条数据保留：来源榜单、当前排名、笔记标题和账号名、阅读量区间、商品点击率区间、支付转化率区间、成交金额区间、笔记和账号唯一标识。

此阶段只负责把榜单事实抓全，不根据标题猜品类，也不提前判断产品价值。

### 第二步，筛选值得深挖的账号

8个入口采集完后，主Agent对账号打分。一天榜单账号众多，全量进店不现实，需先出候选名单。

总分构成：账号总分 = 需求证据分 × 可信度加成 × 低粉加成

#### 需求证据分

需求证据分 = 成交分×50% + 支付转化分×35% + 阅读分×15%

成交金额权重最高，因目标是已有人付费的需求。支付转化用于判断购买意愿，阅读只占15%，避免仅有流量无成交的内容排前。

千帆给的是区间，需先映射到0到1分数。

成交金额映射：0～1000元 0.10；1000～5000元 0.30；5000～1万元 0.60；1万～5万元 1.00

支付转化率映射：0～5% 0.10；5%～15% 0.30；15%～25% 0.55；25%～50% 0.80；50%～70% 0.95；70%～90% 1.00

以上是这套工作流的核心拆解。从手动找项目到AI一条龙，踩过的坑不少，但最终跑出了相对稳定的路径。这套流程仍在迭代优化，希望这次复盘能带来一些启发。
