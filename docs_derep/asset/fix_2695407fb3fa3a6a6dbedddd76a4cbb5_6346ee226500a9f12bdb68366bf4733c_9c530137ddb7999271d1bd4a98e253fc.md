## 我经历的技术演进

### 2019年 代码提示与检索

形态以提示补全加代码检索为主。

提示：时常比 IDEA 自带的体验更顺手。

检索：输入关键词即可在 GitHub、Stack Overflow 等站点抓取片段或讨论。

### 2021 年 6 月 GitHub Copilot 预览版

由 GitHub 联合 OpenAI 推出的编程助手，通过机器学习模型给出代码建议，目标是提升编码效率。

底层模型是 OpenAI 早期发布的编程专用模型 Codex。

### 2022 年 11 月 ChatGPT 爆发

技术主线转向大语言模型。代码补全和对话功能均开始依赖 LLM，各类工具井喷。

### 2024年中 成熟期到来

出现一个在价格、响应与综合表现上取得平衡的模型：Claude 3.5 Sonnet，推动了智能体和流程的实用化。

综合处理复杂问题的能力，目前最强的是 OpenAI 的 o1，只不过节奏偏慢，约为思考一分钟后一次性输出结果，而非逐字流式返回。

举例：直接让模型生成单元测试，质量基本不可用。拆分为两步会好很多：先规划测试思路，再落码实现。

延伸：为何多数 AI 商业化项目难以落地。顶尖模型昂贵却能承接复杂任务；弱模型则需把任务切碎才能完成单点，越切越碎，通用性越差。

## AI 编程辅助的四类形态

### Copilot 副驾/高级补全

* 定义：基于上下文实时给出代码完成的工具
* 代表：GitHub Copilot
* 特点：
* 依上下文实时建议
* 原生集成于 IDE
* 聚焦代码层微操作
* 常用场景：
* 代码补全
* 按注释生成方法
* 按方法生成注释
* 新增属性后同步更新构造器
* 产品差异：
* 是否主动弹出提示
* 提示延迟快慢
* 上下文理解差异。如提到端口，能否映射到 IOPort
* 支持单行修改还是多行修改。多行修改示例：
* 是否有光标预测。预测下一次光标位置以便流畅导航
* 提示位置。有的可在新行末尾补全，有的可在行内任意位置插入

补充：
GPT 系列基于 Transformer，自回归生成，擅长由前文推导后文续写，架构本身不天然支持完形填空。完形效果多依赖工程化实现。

### AI 对话助手

* 定义：以自然语言对话形式提供编程支持的工具
* 代表：ChatGPT、Claude
* 特点：
* 支持自然语言交互
* 可解释代码与概念
* 提供更广的编程建议
* 常用场景：
* 编程相关任意对话
* 代码解读与调试
* 架构设计探讨
* 产品差异：
* 是否支持语音交互
* 自动上下文感知能力。依鼠标位置、当前打开文件、历史浏览、工作区收集上下文
* 是否支持手动指定上下文。指定上下文案例：
* 是否支持图像输入。点击聊天下方的图像按钮或拖入图片，把视觉内容纳入对话。如给网页截图让其实现
* 是否可联网提问。从互联网获取最新信息并据此作答
* 是否可引用文档。引用流行库，或使用 @Docs → 添加新文档添加自有库
* 是否能一键写入代码。如 ChatGPT 网页版生成后需手动复制。部分工具可在 Chat 框内以 Git 对比方式预览修改，还可一键拒绝或应用

### AI 智能体

* 定义：具备一定自主决策能力的助手，是对话的进阶形态
* 代表：Cursor agent
* 特点：
* 可主动执行任务
* 理解项目级上下文
* 具备工具调用能力
* 常用场景：
* 按需求实现小型产品或工具，自行选语言、设计布局、创建文件、编写代码
* 编写文档，建立多文件的小型知识库

### AI 流程

* 定义：将 AI 能力嵌入开发工作流
* 代表：Windsurf、Devin
* 特点：
* 更强的上下文感知
* 多工具协同
* 自动化流程
* 更像是人辅助 AI，执行任务需人工操作或确认时，会主动询问人类

# 大模型能力交流

* 最好的推理模型 o1
* 最好的代码模型 Claude 3.5 Sonnet
* 最好的多模态输入模型 Gemini flash 2.0
* 生产上性价比最高的模型 现在是 gpt-4o-mini
* 最强开源模型可能是 qwen 2.5 72B，至少中英文如此，但仍有差距。而国内一线顶尖模型基本也在 qwen 72B 这个水平，包括阿里自家的 qwen-max
* 国内的基础模型、高性价比模型、推理模型都还需要继续迭代
* 国产之光 DeepSeek 很便宜，能力尚可。AI 界的拼多多 DeepSeek
* VS Code 的 cline 插件 + DeepSeek 据说效果还可以（当然能力和使用体验跟付费的有差距）
* kimi：国产总结能力最强
* 秘塔：智能搜索+知识库。可用作对 AI 幻觉的交叉验证，像中国的 Perplexity AI
