写 Prompt 这事儿，本质上有点像给 AI “立规矩”。你给了它角色、给了它能力，同时也得给它套上缰绳，不然它跑起来可能刹不住车。这个规矩，就是 Constraints。

先说一点：为什么生成内容的重复率要控制在 30% 以下？说实话，我也没考证过这个数字的权威出处——纯粹是我当年写论文时学校要求这个标准，我就直接搬来用了。这事儿也侧面说明了一个道理：以前积累的经验、行业里的默认标准，完全可以顺手放进 Prompt 里。至于具体的阈值该定多少，完全可以针对特定场景去搜索确认，不必死磕这个数字。

再比如，时间、地点、数字、政策名称这类细节，必须原样保留。这个道理很简单，你要是让 AI 去改写一篇社保相关的文章，它却把缴费比例、政策实施时间给改得面目全非，那还得了？这种底线型的限制，谁也绕不开。

至于“遵循原文逻辑、避免歧义”“让六年级学生都能看懂”“不要自己编造概念或者虚构人物”这些规则，其实都是从我们日常写作的基本常识里提炼出来的。你想给 AI 立多少规矩都行，写个七八条也没问题，关键是后续能合并的合并、能精简的精简。自己不知道怎么精简？那就让 AI 帮你精简——连这个都能交给它干。

接下来聊聊 Workflow，也就是你期望和 AI 之间的协作流程。怎么设计这事儿，可以说是整个结构化 Prompt 的灵魂所在。把你的思路和 AI 的脾气秉性结合起来，这事就成了。

第一步：引导用户输入原文。你别小看“引导”这两个字。最早我的初版 Prompt 里写的是“用户输入原文”，结果 AI 有时候就自己编一段内容然后自己开始解答，体验感直接拉胯。后来经小七姐提醒加了“引导”两个字，这种情况几乎再没出现过。具体原理我还没完全搞清楚，先当个小技巧记着吧。

第二步：总结原文的核心观点和要点。你看，这个动作其实就是模拟人类阅读的行为——你拿到一篇文章准备模仿，第一步难道不就是先抓重点吗？

第三步：把原文拆成 3 到 6 个部分。为什么要拆？因为一篇千字左右的文章，里面层次多着呢。我们让 AI 自己做拆分，既能让它证明自己真的读懂了原文，也方便我们一眼看出问题在哪，随时指出修正。

第四步：让用户选择部分后，再逐段模仿创作。分段输出，主要是避免一次对话里丢给 AI 太多文字任务。短内容比长内容好改、好观察，这是明摆着的事。

第五步：用户验证是否保留了原文要点，再根据反馈调整。说白了，这套工作流程就是把我们脑子里的想法，一点点搬到 Prompt 里去。

再说 Initialization——这一步是引导 Prompt 进入状态，也是告诉用户该怎么和 AI 互动的入口。

那怎么快速搞出第一版 Prompt？两个思路：

思路一：直接问 AI。你就跟它说：“我想写一个关于 XXX 的结构化 Prompt，语法模板如下（用\"\"\"\"\"\"括起来），你觉得这个角色该有什么技能？要给哪些限制？工作流程怎么设置更好？请深呼吸一步一步思考，最后用可复制的 Markdown 格式给我完整的 Prompt，拜托了，这对我真的很重要。”

注意，这一步只是演示操作流程，里面生成的 Prompt 还没经过测试优化。拿到初版之后，就是不断的测试、调整、迭代。极少有人能一遍成功，通常都要磨个 5 到 10 轮才稳。

思路二：跟 AI 对话式生成。让 AI 自己总结交互要点，再根据要点直接产出 Prompt 初版。同样的提醒：下面这段只是演示，不代表真实品质，也没调试过。

最后说个心态。如无必要，勿增实体。结构化 Prompt 也好，CHAT、CRISPE、APE 这些框架也罢，说到底都是为了保证输出质量的稳定性。不同的模型、不同的场景，适配的框架也不同。一切以高效、顺手为准，没必要在一棵树上吊死。

一坨又长又重的 Prompt，未必比一版清爽的更好用。token 堆得越多，反而可能干扰大模型的理解和输出。写 Prompt 也讲究简练之美，那些你叠上去的附加条件，很多时候只是白白烧算力罢了。

真正让一个 Prompt 与众不同的，是它的设计思路和用户体验，而不是条件堆得多华丽。一个优秀的 Prompt 工程师，动笔之前一定先想用户体验。
