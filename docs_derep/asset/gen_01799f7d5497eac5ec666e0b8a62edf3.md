最近AI圈有两个prompt特别出圈：一个是国外大神的superprompt，一个是李继刚的汉语新解。尤其是汉语新解，效果惊艳，我刷到后当场收藏，玩得不亦乐乎。[PRE0][PRE1][PRE2][PRE3][PRE4]

可玩着玩着，心里有点不是滋味——我好像只会复制粘贴，然后喊一句“牛”，接着继续按别人设定好的规则跑。想改点细节？对不起，看不懂。

学代码？算了，那得等到猴年马月。但我又不想继续当“只会搬运”的那一个。于是，我花了好几天，一口气拆了50个prompt，终于找到一种普通人也能自己动手写的“伪代码式”prompt写法。

先说门槛。

有编程基础的朋友看到这套方法，可能觉得：就这？太初级了。这很正常，因为你们读起来自带加速buff。而完全不懂编程的朋友，也别被吓到。这篇文章确实有点门槛，但不高。你只需要花5分钟去搜一下markdown怎么写，再回来看，一切都会变得特别清晰。[PRE5]

这个方法为什么叫“伪代码”？因为它的核心就一句话：把XML和Markdown揉在一起用。

XML负责把结构立起来，让机器扫描起来不费劲；Markdown负责把逻辑说人话，让人读起来不头疼。两者一拼，就成了一套可拆可装的prompt积木。[PRE6]

为了验证这个思路，我挑了一个特别经典的“方法论大师”prompt来拆。

先看它的效果图：[PRE7][PRE8] 再看李继刚老师的原始prompt：[PRE9] 是不是满屏括号，差点背过气？

别怕，我们来一层层扒开看。[PRE10]

首先你要明白，一个完整的prompt其实包含两层：一层是系统提示词system prompt，负责告诉AI“你是谁、你擅长什么”；另一层是你自己输入的prompt，负责告诉AI“这一轮你到底要干嘛”。[PRE11]

接下来，进入正题——那些高大上的lisp提示词，拆到底，全是在定义函数。

怎么理解“函数”？拿写作文打比方。一篇文章分很多段落，每段都有自己的中心思想，里面的句子全围着这个中心转。你可以让第一段设悬念，第二段造高潮，第三段加阻碍，第四段来转折……这些段落串起来，就是一篇完整的东西。

“defun”就是“定义一个函数”。你看这个方法论大师，先定义角色，再定义“方法论”这个词——什么叫方法论？就是一套系统的、有组织的方法和原则，用来解决问题、开展研究的思路体系。你把这个定义喂给模型，它就有了发力方向。[PRE12][PRE13]

再往后看，那堆密集到让人头皮发麻的括号和引号，其实还是在定义函数，只是多了变量、多了示例，告诉AI“遇到什么情况就调用哪部分知识”。[PRE14][PRE15][PRE16]

然后呢？继续定义卡片样式，说明渲染效果，再把工作流一步步写清楚。到这一步，前面所有“零件”才真正连接起来。[PRE17][PRE18]

看到这里，你应该明白了：高级prompt的底层逻辑，就是拼自行车。每个零件是一个函数；把所有零件按顺序组装好，再接上“工作流”这条车链子，车就能飞跑。你再回头去看那个superprompt，会发现它也是同一套路。[PRE19]

其实知识都是相通的。你可以用化学里的电子排斥力，去理解物理里的接触力；可以用小时候买酱油的经历，去理解公司里采购项目的流程；可以用热水器冷热不均，去理解渣男为什么会忽冷忽热。理解prompt也一样，借自己熟悉的东西去推陌生的东西，就通了。

好，原理讲完，开始动手转化。先记住一个万能骨架：定义一个函数时，可以写清楚它的说明、输入、输出、工作流程。不需要每次都写全，但不知道从哪儿下笔时，就照着这个骨架填空。

我们一步步来，别嫌字多，其实写起来很快。

第一步，先定义一个角色。

原prompt我们不看了，直接看转化后的结构——别被篇幅吓到，真正要填的字不多。[PRE20]

[PRE21]

```markdown
## 函数说明

熟悉各领域知识，善于把经验抽象成方法论的大师。

### 特长

- 逆向思考

- 逻辑推理

- 结构化思维

### 熟悉领域

- 各行业的核心知识

### 内化习惯

- 从现象中提炼方法论

[PRE22]
```

第二步，给“方法论”下定义。

原prompt是一串lisp，转化后其实就是一句话：[PRE23]

[PRE24]

```markdown
## 函数说明

界定方法论：一套系统的、有组织的方法与原则，用于解决问题或开展探究的思维路线和操作体系。

[PRE25]
```

第三步，把输入、输出和工作流写清楚。

到这里你已经成功了一大半，剩下的只是把场景细化：[PRE26]

[PRE27]

```markdown
## 函数说明

根据用户给定的领域及单词，推导出一套逻辑严密、与该领域知识体系契合的方法论。

### 输入

- `领域`：用户希望提炼方法论的领域方向。

- `单词`：该领域对应的英文字段，用来生成首字母缩写。

### 输出

- 方法论结果：          

    - 目标：

        - 创建以单词首字母为骨架的缩写方法论。

        - 对每个步骤进行解释。

        - 给出工作流程图。

        - 附上一句简短总结。

    - 语气：

        - 专业。

        - 清晰。

        - 理性。

    - 输出解释：
```

接下来的内容，就可以照着这个框架自己填了。与其说这是在写prompt，不如说是在做填空题。等你掌握这套“伪代码”写法，那些让你直呼“神仙”的prompt，都可以拆掉再重组，按你的想法重新长出来。

不需要懂编程，不需要背语法。你只需要一点点结构感，一点点逻辑感，再加一点“我也要自己写一个”的冲动。
