只用Cursor，真的能做出一个功能完整的网站吗？

我的答案是：能，而且没有想象中那么难。这篇文章不是空谈，而是我在《Cursor-零基础做软件应用》航海后整理的一份实战复盘，里面既写了怎么一步步把网站搭起来，也记录了不少我自己踩过的坑。顺便说一句，这次航海里有很多产品案例，完全可以整合到同一个网站里，日常用起来会方便很多。

我其实是在Cursor火了大半个月之后才正式上手的。最开始挺惊艳，用着用着又觉得“就这？”，直到真正涉足复杂项目，才发现这玩意儿简直是个神器。现在我几乎每天都会打开它。以前遇到代码问题，我的第一反应是打开百度搜；现在的第一反应，是打开Cursor问。说白了，就是从“面向百度编程”切换成了“面向Cursor编程”。

## 为什么我最终认定了Cursor

好用的人工智能编程工具其实很多，我选Cursor的一个重要原因是：它有免费额度，而且正常情况下完全够用。再加上下面这几个优点：

- 多文件并行修改：它的Composer模式可以按你的指令，一次性在多个文件里生成或修改代码，特别适合大范围重构。
- 智能补全：它能读懂代码上下文，补全建议比较靠谱，能省下不少敲键盘的时间。
- 质量提升：可以自动发现代码里的隐藏问题，并给出优化建议。
- 个性化：VSCode的扩展、主题、设置和快捷键都能直接导入，几乎零成本切换。

不过，新手用它时也容易翻车。最常见的情况是：本来想修一个bug或加个小功能，点下Accept之后，程序直接不能用了，还退不回去。

## 免费使用Cursor的几种“野路子”

想继续白嫖，可以试试这几个方法。

第一个是“销号重开”：去Cursor设置页（https://www.cursor.com/settings）拉到最底部，找到Delete删除账户，然后用同一个邮箱重新注册一个新账号。 [PRE0]

第二个是换邮箱：直接买一个新邮箱来注册，买好之后重新登录就行。 [PRE1]

第三个是处理次数限制。现在免费额度已经从原来的500次缩水到了250次，而且一台机器也不能无限制地来回切免费账号。我试过靠谱的办法是：去扩展市场搜一个名字带 fake 的插件，装好后重启Cursor，一般就能继续用了。 [PRE2]

第四个是绑定自己的API Key。愿意用自己的API成本来换无限消息量，那就彻底不受免费次数束缚了。 [PRE3][PRE4]

## 完整开发流程：我是怎么从零搭出网站的

先说一下目标：做一个相对完整的网页Demo，包含登录认证、前端后端、SQLite数据库，以及AI聊天界面。做完之后的效果大概长这样。 [PRE10][PRE11][PRE12]

### 第一步：明确需求，和Cursor达成共识

不要上来就让它写代码，先像聊天一样把需求问清楚。如果它给的回答不符合预期，就换一种问法重新问，直到双方对齐为止。

需求确认以后，新建一个README.md，把要点写进去。比如我的项目，技术栈用Next.js，数据库选sqlite，核心功能是登录和学生信息的增删查改，本质上是一个学生信息后台管理系统。提示词可以写成下面这种格式。 [PRE13]
项目作用：学生信息后台管理系统；项目功能：登录、学生信息增删查改；后端数据库：sqlite；技术栈：next.js。 [PRE14][PRE15]

### 第二步：让Cursor帮忙初始化项目

这里有个很重要的经验：不要自己去跑脚手架命令。虽然像Next.js这类框架都有自带的项目初始化工具，但手动执行命令对新手来说又麻烦又容易出错，而且会生成一堆用不到的文件。文件一多，你看着烦，Cursor也容易看花眼。正确做法是让Cursor直接生成项目结构。 [PRE16]

这一步容易遇到两个坑：

第一个坑：它不生成文件，只是把代码给你，让你自己动手建。 [PRE17]

第二个坑：它会新建一个目录，而不是在根目录生成文件。目录一多，Cursor可能就找不到正确位置，然后反复在当前目录生成重复文件。我的解决办法是：新开一个Composer窗口，然后把需求重新强调一遍。 [PRE18][PRE19]

另外，如果你手动调整过文件或目录结构，一定要记得告诉Cursor：“@codebase，我调整了代码结构，请刷新缓存，后续不要生成重复的代码，不要生成多余的目录和文件。” [PRE20] 或者去设置里手动刷新一下缓存。 [PRE21]

### 第三步：让程序先跑起来

项目初始化之后，先别急着做业务功能，第一件事是运行程序。哪怕只是一个最简单的页面，只要它能跑起来，就说明环境没问题。不要攒一大坨代码再运行，那样出了问题很难排查。 [PRE22]

当你看到hello world，其实就已经成功一半了。 [PRE23]

如果执行npm install特别慢，可以把npm源切换成国内镜像，命令是：

npm config set registry https://registry.npmmirror.com [PRE24][PRE25]

### 第四步：开发登录页

登录页的提示词我写得很明确：先开发登录页，账号密码可以先写死在代码里；所有页面都必须登录才能访问，如果没登录，就自动跳转到登录页。 [PRE26]

第一版做出来之后，界面通常比较丑，甚至还会出现乱码。这时候有两种优化思路：一种是反复跟Cursor说“好看一点，好看一点”，让它自己不断调；另一种是去网上找一张自己心仪的界面截图或链接发给它，让它照着做，这样能省不少沟通次数。 [PRE27][PRE28]

页面出来以后，可能会发现没居中、不美观等问题 [PRE29]，没关系，继续提优化要求就行。 [PRE30][PRE31]

每做完一个小功能，都要养成验证的习惯。比如确认登录后能不能正常跳转到首页。如果要做谷歌认证，去看谷歌官方文档。反正只要代码一报错，最省事的方法就是把错误信息直接复制给Cursor。 [PRE32][PRE33]

### 第五步：开发网站布局

细心的话会发现，绝大多数网站的不同页面，其实共用一套统一布局。所以布局最好优先于业务功能开发，先把骨架搭好，后面只需要专注填内容。

如果想复刻一个网站的布局，有三种方法：

1. 直接把目标网站链接发给Cursor，让它解析结构。
2. 截图，让Cursor根据图片生成代码。
3. 如果目标网站需要登录，可以打开F12，把页面代码复制到本地文件，然后通过@文件的方式让Cursor分析。

我演示了第三种方式：比如想复刻这个界面。 [PRE34]
因为页面需要登录，所以先在F12里把代码复制到本地。 [PRE35]
然后给出提示词：帮我复刻一个如文件所示的界面布局。 [PRE36]

第一版往往不完美，但没关系，可以继续微调。比如：把顶部导航栏换成指定背景色、高度设为32px，并加上一个能展开/收缩侧边菜单栏的图标；侧边菜单栏背景保持不变，增加一个logo；底部footer背景改为白色，高度设为32px。其实只要知道顶部叫导航栏、左侧叫菜单栏、底部叫footer，就能按位置精准指挥Cursor了。 [PRE37]

### 第六步：开发学生信息系统

从这里开始，才终于进入真正的业务开发。数据流大致是：

前端登录 → 前端展示页面 → 前端向后端发API请求 → 后端逻辑处理 → 数据库

我习惯把这三层理解成一个比喻：前端是销售，后端是产品线，数据库是仓库。销售给客户看产品图，吸引用户下单；后端再按单把产品生产出来；生产出来的东西和原材料，全都放在仓库里。

后台管理系统最常见的操作就是增删查改，也就是搜索、增加、删除、修改。这时候只需要对着README.md里的需求，让Cursor按部就班地开发就好。 [PRE38]

注意，一次性给的需求太多，特别容易翻车。报错也不用怕，老办法：把错误信息丢回给Cursor。我还会在提示词里加一句：把用到的依赖都写入package.json。这样它就不会只给你一条命令；否则当前环境下能跑，换个环境就容易缺包报错。 [PRE39][PRE40]

把报错修掉之后，界面基本就出来了。我验证了一下功能，除了界面丑了点，功能完全没问题。运气好的时候确实能一次过，但大部分时候还是会有小bug需要慢慢磨。 [PRE41]

接下来，我按自己的审美写了新的优化提示词：

1. 删除文字“添加学生”，也删掉姓名、年龄、班级输入框。
2. 把搜索框移到添加按钮左边。
3. 添加和编辑学生信息时，改成侧边栏表单，让用户填写数据并发送请求。
4. 编辑学生信息时，要把已有学生数据自动填充到表单里。 [PRE42]

如果你看不懂这类需求、不知道怎么表达，也有两个办法。办法一：直接问AI，让它帮你重新描述。 [PRE43] 办法二：去官方组件库找术语，比如Element Plus官网 [https://element-plus.org/zh-CN/component/overview.html](https://element-plus.org/zh-CN/component/overview.html)，官方表达最权威，Cursor也一定听得懂。 [PRE44]

另外，有时候想找好看的特效但没灵感，可以试试几个CSS灵感网站，基本都能直接复制粘贴代码：CodePen [https://codepen.io/](https://codepen.io/)、Animista [https://animista.net/](https://animista.net/)、Phuoc Nguyen [https://phuoc.ng/](https://phuoc.ng/)。 [PRE45][PRE46][PRE47]

### 第七步：开发AI聊天界面

最后一个模块是AI聊天界面。我想复刻的是Kimi的聊天界面，所以很多描述都按Kimi的样子来。由于这是我第一次写这类界面，我先把自己的需求发给Cursor，让它重新表述一遍，确认我的表达是否准确。 [PRE48]

我的需求大致是：

1. 把“班级”改成“Kimi”，链接也改成Kimi。
2. 我要复刻Kimi网站，做一个用来和大模型聊天的网站。
3. 内容区拆成两部分：
   - 底部是输入组件，一个简单的输入框，用来接收用户输入；
   - 输入框之上是信息显示区，用户输入后，大模型返回的数据要以流式文字的方式显示。 [PRE49]

以上就是我使用Cursor搭建一个相对完整网站的完整复盘。Cursor并不是万能的，但只要方法对，普通人也能用它独立做出一个能跑、能用、看起来也不差的网站。希望这份避坑指南，能帮你在AI编程路上少走一些弯路。
