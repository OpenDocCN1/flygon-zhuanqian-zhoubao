# 想从Reddit挖用户需求？这个AI Agent把“找痛点”变成了一条自动流水线

做过海外市场、搞过独立开发、或者正在为跨境电商选品发愁的朋友，一定都有过这种体会：**找到用户真正想要、但还没被解决的需求，有时候比写代码本身还难。**

你可能会去刷各种数据平台，或者盯着竞品分析报告发呆。但有一个地方，藏满了用户最真实的心声，却常常被我们忽略——那就是Reddit。

这可不是我瞎说。大家熟悉的“小猫补光灯”这个爆款App，最开始就是有人在一个Subreddit里刷到了一条看起来“很无厘头”的需求，然后顺着这个点，做出了让很多人喜欢的产品。你看，钻石就散落在那些看似闲聊的帖子里，关键是——你有没有一个趁手的挖掘工具。

最近看到亦仁的龙珠悬赏，我决定把自己一直在用的一个挖掘Reddit需求的小工具分享出来。它其实是个AI Agent，我叫它 **Reddit Agent**，专门干一件事：**把Reddit里那些散落的真实需求，自动筛选、分析、翻译，最后整整齐齐地放进你的表格里。**

**为什么Reddit这么值得挖？**

简单来说，Reddit就像一个由无数个兴趣小组组成的大型社区。每个Subreddit里，都是活生生的人在提问、在求助、在分享自己的真实经历。一个用户遇到了麻烦，发个帖子问问大家怎么办——这里没有伪装，说的全是自己的实际痛点。

而如果你想开发一个App、做一个网站，或者选品，第一步要做的事情，就是找到这些“未被满足的需求”。用这个Agent，就能省去大量手动翻帖子的时间。

**这个Agent具体怎么干活？**

不用着急，它就像一条自动化的流水线，一共分六步走：

**第一步：锁圈找人。**你只需要提前把关键词存在一个文档里（比如我放了3个关键词），告诉它去哪个Subreddit小组里找，它就会把含着这些关键词的帖文统统捞出来。

**第二步：粗筛一遍。**捞出来的帖子有点杂，所以它会按照你设定好的条件，先粗略地过滤掉一批。

**第三步：AI智能判断。**这一步是灵魂所在。大模型会仔细阅读每一条帖子的内容，然后判断：这个帖子描述的是不是“商业相关的问题”？或者是在寻求某种解决方案？它会明确返回“Yes”或者“No”。

> 比如，我给它设定的判断标准是：这篇帖子是否提到了某个业务正在试图解决的具体挑战或需求？结果一跑，10篇帖子里有9篇命中，只有1篇被淘汰。

**第四步：清理无关内容。**直接过滤掉刚才判断为“No”的帖子，只留下那些真正有价值的“Yes”。

**第五步：精读并输出方案。**这才是最精彩的一步。它会把留下来的高质量帖文进行三件事的加工：一是总结帖子核心内容；二是翻译成中文（不用费劲看英文了）；三是根据帖子里提到的业务问题，直接给你生发出一个具体的“解决方案”或者“商业点子”。

**第六步：归档入表。**所有处理完的信息——原帖、总结、中文翻译、解决方案——会统一自动写入到你的Google Sheet里。表格一打开，信息一目了然，什么都有了。

**这工具是怎么搭的？**

可能有人会问，这是用什么搞的？其实我用的是一款叫 **n8n** 的低代码AI Agent和工作流搭建工具，底层是基于Langchain构建的。这个工具有个好处是，它要比纯自动化的工具（比如Make）能处理更复杂的逻辑，而且支持本地部署，安全性也更有保障。如果你用过Dify，应该很容易上手，它俩在定位上有些类似。

**除此之外，还能玩出更多花样：**

这个小工具彻底跑通之后，我最大的感受是：它就像一个拥有无限潜力的“需求挖掘机”。只要你愿意，还能延展出很多新玩法——

- **思路一：**让Agent在总结完帖子之后，顺手生成一篇相关的博客文章，自动发布到你的网站上。
- **思路二：**把帖子和评论区的内容全部抓取下来，沉淀成一个数据库。以后想什么时候查，就什么时候查。
- **思路三：**反向操作，让它自动去相关的帖子里回复留言，甚至替你发帖。

最后有一点特别深的感悟：**大模型的输出多多少少存在不可控性，设置好结构化提示词就是最关键的一件事。**只有给了它清晰的指令，才能保证你拿到的东西是稳定且靠谱的。

希望这个小小的分享，能给你带来一些不一样的启发。
