## (精华帖)(127 赞)实战分享：MCP 模式下，我把公众号发布链路做成了对话式一键调用

作者：陈序员大康
日期：2025-04-28

**扣子空间最近又更新了。两天前我还在吐槽 MCP 扩展太少、没法自己加，现在这个限制直接被解开了。**

现在可以直接把扣子工作流平台里搭建好的流程，以及扣子开发者平台上的各类插件，按需接入到自己的扣子空间里使用。

这一消息出来，我第一反应就是：终于可以做“一句话发公众号”了。

比如直接对话输入：“帮我看下今天的热点，写一篇公众号并丢到草稿箱”。

其实类似的一键发公众号，之前用纯工作流、甚至 RPA 流程我都已经跑通了。

**那为什么还要换成聊天触发的 MCP 形态？**

工作流更像是固定生产线，步骤一旦定下来就很难灵活改动，适合已经验证过的批量任务。

但它的短板也很明显，缺乏弹性。比如我之前做国学文章生成，想换个主题风格，就得重写提示词、调整节点；如果写稿时临时要加个路线规划，还得回工作流里去挂地图插件，操作起来很重。

MCP 则是典型的即插即用。以前配图用的是国学古风生图工具，后面要做穿搭类内容，直接把 MCP 配图工具换成穿搭配图 MCP，马上就能用，不用重建一条工作流。想怎么搭就怎么搭，随时组合出新的能力。

**有人会问，这么一来工作流是不是就没用了？**

短期来看并不。无论是 Manus 还是扣子空间，对复杂任务的理解偶尔会跑偏，输出质量不稳定，这点上传统工作流的确定性和可控性还是更胜一筹。

简单说就是：MCP 适合探索和创新，工作流适合稳定量产，各自有各自的战场。
