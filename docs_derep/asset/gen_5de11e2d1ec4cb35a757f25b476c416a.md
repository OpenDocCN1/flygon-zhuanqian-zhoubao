今天咱们聊个挺有意思的事：AI图片站到底是怎么做出来的？很多人以为这背后技术门槛高，其实说白了，大部分AI绘画网站都是“套壳”——核心是把别人训练好的AI模型接口拿来用，再套个网页方便用户输入提示词。这篇文章就从零带你撸一个AI图片网站，哪怕你编程基础不深，照着一步步来也能跑通。

先认识一个利器：Replicate。它相当于一个“AI模型超市”，市面上很多开源模型（比如画图、写文本、生成视频和音乐）都已经被人部署好了，普通用户直接在网页上就能试玩，有些项目连登录都不用，免费就能体验。更棒的是，这些模型全都开放了API接口，你可以把它们接到自己的应用里。官方地址：https://replicate.com/

## 开工前要准备什么

**第一，GitHub账号。** Replicate的登录是走GitHub授权的，所以你肯定得先有一个GitHub账号。[PRE0] 有了账号后，输入用户名密码登录，或者提前登录好GitHub再授权Replicate也能进。[PRE1]

**第二，绑定支付方式。** 点右上角头像，进入“Account settings”，然后在“Billing”菜单里找到“Manage billing”。[PRE2][PRE3] 添加信用卡时，卡号栏会提示支持的卡种。我用的是国内银行的Visa卡，可以正常添加。[PRE4] 为什么一开始就要绑卡？因为Replicate上的模型调用都是要花钱的，没绑定支付方式，接口就会调用失败。怕花超的话，可以在账单设置页面设定调用限额，以后按需调整就行。[PRE5]

**第三，安装Node.js。** 下载地址：https://nodejs.org/zh-cn/download 下载完就是一路“下一步”的傻瓜安装，不会的话随手问问AI也能搞定。装好后，在命令行敲 `node -v`，能看到版本号就说明安装成功了。[PRE6]

## 先快速见效：纯后端调用API

咱们先不着急做网站，先在本地感受一下怎么通过API生成一张AI图片。

**第一步，一行命令初始化项目。** 有个npm包叫 `create-replicate`，执行它后会自动帮你创建一个项目目录，并写入初始代码。[PRE7] 你先建好一个文件夹，进入该文件夹并打开命令行，执行这条命令。[PRE8] 命令跑起来后，它会要求你粘贴Replicate API token。你直接敲回车，它会自动打开浏览器，带你去获取token的界面。[PRE9] 在页面上随意给token取个名字，点“Create token”。[PRE10] 然后把新生成的token复制回到命令行粘贴上。[PRE11] 看到“初始化完成”提示后，你的目录下就多了一些项目文件。[PRE12][PRE13]

**第二步，用编辑器打开项目。** 用VSCode或Cursor都行，直接把整个项目文件夹拖进Cursor里。[PRE14]

**代码原理其实不难。** 刚才你填的那个token，就是后面调用API时用的凭证，代码里通常不会写死，而是放在 `.env` 环境变量文件中。[PRE15][PRE16] 接着你要指定想调用哪个图像模型，比如Replicate上的Stable Diffusion XL（SDXL），官方调用示例里会写明具体的模型名称。[PRE17] 调用时需要传参，最重要的就是 `prompt`，也就是你想生成的图像提示词。其他参数不用管，保持和官方示例一致就行。[PRE18] Replicate上模型很多，每个模型都有官方示例，照着改即可。

**第三步，把生成的图片下载到本地。** 默认的初始化代码只会把生成图片的URL打印到控制台，看不方便。所以我们借Cursor改一下代码，让程序把图片下载到当前目录下的images文件夹里。[PRE19] 改完按Cursor的提示安装必要依赖。[PRE20] 然后在控制台运行项目。[PRE21] 跑完后，到根目录的images文件夹里就能看到AI生成的作品了。[PRE22][PRE23]

**小结一下：** 这是纯服务端代码调用Replicate图像模型API，直接在你电脑本地生成图片的方式。现在许多文生图网站本质就是这套逻辑，只不过外面套了一层网页：用户在前端输入提示词，后端把提示词传给模型API，生成完再返回页面展示给用户。

## 用Next.js搭建一个最简单的文生图网站

接下来咱们动真格：搭一个可访问的网站，部署到Vercel上，用户输入提示词就能生成图片。

### 前置条件

需要准备四样东西：
- Node.js环境（前面已介绍）
- Replicate账户（用来调用模型）
- GitHub账户（托管源代码）
- Vercel账户（部署网站）

### 搭建过程

**1. 创建项目并初始化。** 在本地新建一个文件夹，名字随意，比如 `demo-web`。在该目录下打开命令行，或者用 `cd` 命令进入这个目录，执行初始化项目的命令。[PRE24][PRE25] 过程中会问你项目名称等选项，嫌麻烦直接一路回车用默认值就行。[PRE26] 初始化完成后，`demo-web` 文件夹里会多出一个 `my-app` 项目。把 `my-app` 文件夹拖进Cursor打开。[PRE27][PRE28]

**2. 本地试运行。** 启动一下项目，确认初始页面能正常打开。[PRE29][PRE30] 启动成功后，访问控制台给的地址 http://localhost:3000 如果看到Next.js的欢迎页，就说明项目没问题。[PRE31]

**3. 配置环境变量。** 因为要调用Replicate的图像模型，必须把API Token放到环境变量文件里，项目启动后就能自动读取。在项目根目录中执行命令创建 `.env.local` 文件，Next.js会自动加载它。[PRE32] 另外，不同后缀的环境变量文件对应不同环境，比如 `.env.production`、`.env.development`。[PRE33] 创建完文件后，把你的Replicate API Token填进去。[PRE34][PRE35]

**4. 编写后端代码。** 在 `src/app` 目录下新建 `api/predictions` 目录，用于存放业务代码。[PRE36] 然后新建 `route.js` 文件，实现的功能是：接收POST请求，提取用户输入的提示词，调用Replicate API生成图片，并返回生成结果。[PRE37]

**5. Webhook回调说明。** 官方案例里有个 `WEBHOOK_HOST`，它的作用是让Replicate在模型运行过程中，通过Webhook把状态更新（开始、完成、错误）发送到你的应用。代码里是个三元表达式：生产环境用Vercel自动提供的 `VERCEL_URL`，开发环境则用 `NGROK_HOST`，也就是需要你用ngrok把本地服务器暴露到公网。[PRE38] 如果你只是为了跑通MVP，可以先不管这个变量，因为部署到Vercel后，它会自动帮你设置。但如果不配置，可能会遇到这些问题：收不到模型运行状态、生成请求可能失败、调试困难、依赖Webhook的功能无法正常工作。

**6. 动态路由获取生成结果。** 还需要新建一个 `[id]` 目录，并在里面新建 `route.js`。这里 `[id]` 是Next.js的动态路由规则。这个文件实现的功能是：通过Replicate API查询指定模型的生成结果。[PRE39]

到这里，一个文生图网站的骨架就算搭完了。把代码推到GitHub，再导入Vercel部署，就能获得一个公网可访问的AI图片生成站。所谓“套壳网站”，说白了就是“API调用 + 前端交互”。Replicate把繁琐的模型部署和算力问题全解决了，你只要专注做好页面和逻辑就行。是不是比想象中简单得多？那就动手试试看吧。
