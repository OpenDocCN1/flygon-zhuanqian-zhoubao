## 一、Skill 到底是什么？

通俗讲，Skill 就是给 AI 的一套操作手册。

把 Claude 想象成一个超强实习生：

没 Skill 的时候，你让他写公众号文章，得一遍遍交代：“标题要抓眼、段落要分明、结尾放二维码......” 不说清楚就只给你一堆干字。每次重复，费口舌也费 Token。

有了 Skill 的时候，你提前写好一本《公众号爆款写作手册》塞进他背包里。

平时不占内存，用到时才拿出来。只要你说一句“帮我写篇文章”，他就按手册里的标准自动执行。

核心优势很明显：

- 按需唤起：AI 自己判断什么时候该用哪个技能，不用你提醒
- 节省上下文：不用时不占 Context，用时才加载
- 高度复用：一次写好，长期复用，还能分享给团队

## 二、Skill 能做什么？

继续用实习生来类比，Skill 能给它补上三块短板：

1. 复刻你的工作 SOP

最基础的用法。把你的标准、格式、禁忌打包给 AI。

以前让你写周报，格式混乱得改到崩溃。

有了 Skill，给他装上《周报专用 Skill》，里面写明：“先结论后细节”、“数据上表格”、“语气正式”。写出来的东西完全是你的风格。

官方例子 internal-comms 就是干这个的，让全公司周报统一口径。

2. 给 AI 装专业工具

会写还不够，Skill 还能集成代码和工具。

以前让他做动图，他只能干瞪眼。

有了《GIF 制作 Skill》，里面带一段 Python 脚本，他就能直接跑代码生成动图。

同样也能装《Word 专家 Skill》，直接改文档格式和修订记录，而不是只吐文字。

官方例子有 slack-gif-creator 和 docx。

3. 一键复制大神经验

Skill 本质是文件，可以复制。

你招了个新媒体新人不会起爆款标题，直接丢给他一个《咪蒙标题 Skill》或《奥格威标题 Skill》，AI 瞬间拥有大师级起标题能力。

## 三、Skill 和 MCP 到底怎么分？

容易混淆，我们用一个比喻厘清：

- Skill = 菜谱 📘 教 AI 怎么做：切、炒、摆盘
- MCP = 冰箱 🧊 给 AI 提供食材：数据、文档、网页
- Skill 定方法，MCP 供数据，配合就是顶级大厨

[PRE3]

再从三个角度拆开看：

1. 定位不同：内功 vs 外挂

Skill 是内功，How 问题。纯文本指令集，教会 AI 思考和执行逻辑。

MCP 是外挂，What 问题。是连接器，提供外部数据和工具。

2. 场景不同：单兵 vs 联网

以写股市分析报告为例：

第一步 MCP：抓取今日股价、K 线、新闻
第二步 Skill：按《巴菲特价值投资框架》做点评
第三步 Skill：排版成漂亮 PDF
第四步 MCP：邮件发送给老板

MCP 负责搬食材，Skill 负责做成成品。

3. 形态不同：轻 vs 重

Skill 很轻，通常是 SKILL.md 这个 Markdown 文件，方便分享。

MCP 很重，是需要部署的服务，要配环境、API Key，门槛高但能力强。

结论不是二选一，是黄金搭档。用 MCP 连数据，用 Skill 固化流程。

### 第四步：进阶技巧

- 上下文本身就是公共资源，别堆废话。直接写要点。
- 自由度要匹配：创意用文字指令，死板格式用脚本。
- 渐进式加载：大文档放 references/ 文件夹，SKILL.md 里写读取路径，用时再加载，不占内存。

安装好后直接说：“帮我 Review 一下这段代码”，AI 会自动匹配到对应 Skill 执行。

**⚠️ 安全提醒：警惕 Skill 投毒**

Skill 本质是代码和指令，有操作权限。第三方 Skill 可能藏恶意脚本，上传 .env、窃取 Cookie 等。

运行非官方 Skill 前，务必人工检查 SKILL.md 和 scripts/ 目录下的每一行代码，看不懂就让 Claude 帮你审计。数据无价，别盲装。
