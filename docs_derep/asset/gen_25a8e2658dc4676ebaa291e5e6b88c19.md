# 一、XML 到底是什么

XML 是一种很像 HTML 的标记语言。它的核心目的就是传输数据。简单说，看高亮部分就够了。

<xml>标签用来标示 XML 文件的起始与结束，标签里的内容就是 XML 文档。任何软件要处理 XML 代码，这个首标签是必不可少的。</xml>

XML 负责定义技术文档的结构，别的程序再根据这个结构去灵活呈现。

我们平时写提示词时，经常会用“---”“===”“###”“((()))”“<<<>>>”之类的符号来做分隔。但换个模型就可能时灵时不灵。

我测试的 XML 标签在 Claude 上非常稳定，在其他模型里效果也相当不错，很值得长期用。

## 如何用 XML

### 最基础的用法
比如你要描述一位作家：
张爱玲：原名张煐，笔名梁京，祖籍河北唐山丰润，生于上海，中国现代女作家。

### 稍微进阶
比如告诉我你有两个朋友，叫 Lilei 和 Hanmeimei：
<name>Lilei</name>
<name>Hanmeimei</name>

### 再进阶一点
要表示书店的数据，可以创建 <book>、<title>、<author> 等标签。</author></title></book>
一本书的 XML 内容长这样：
<title>Learning Amazon Web Services</title>
<author>Mark Wilkins</author>

本质上就是用标签把内容包裹起来，一层套一层，像俄罗斯套娃那样把信息分层呈现。

不过不建议套太深，一般两层就够了，层级多了既容易自己混乱，也可能影响解析效果，得不偿失。

# 二、实战案例：给航海打卡做一个复盘助手

前面说好了要做一个帮助船员打卡的小工具。下面我会把整个思考拆开讲。

## 先拆问题

航海打卡通常包含哪些内容？
航线图、今日行动、心得感悟、好事分享、下一步计划。

这是临时起意的小玩意，我先用自己过往航海踩过的坑来代替正式调研。

打卡时常见的卡点：
* 有时候做的事情很日常，比如注册账号、买粉；
* 有时候是每日重复项，比如更新文章；
* 有时候发现的问题其实用处不大。

我想帮小组伙伴把思考梳理出来，用来做每日复盘。复盘需要回答：
* 我的目标是什么
* 今天具体做了什么
* 今天哪些做得对，哪些做得不对，离目标还差多少
* 按目标倒推，明天该怎么走

需求已经很清楚了：需要一套指令作为复盘辅助，引导船员完成每日打卡的思考，并在最后由一个有温度的角色把结果讲出来。

往下抽象一层，本质上就是一份带角色扮演的对话式复盘指令。

## 提示词第一版

明确了是复盘工具，那框架里应该有什么？我整理出：目标、行动、思考模型、输出结构、工作流。

工作流这个设定，是最近看到星球里大佬的帖子，受产品流程引擎启发觉得挺有意思，于是加进来了，后来才发现有点多余，一会儿再说。

## 提示词第二版

第一版没达到预期。上篇文章也说过，参数流的核心是精准、简洁。但第一版提示词长达681字，比公众号插两条广告的篇幅还长。

而且参数越多，Claude 的解析衰减越明显，就像故事里的小明，记性有限，记不住那么多。

这就违背了我一开始发现这个方法的初衷。得做减法。

### 思考后整理
* 周目标和日目标如果不是刚需，可以合并成一个北极星指标作为方向指引。
* 行动和思考模型不能砍。
* 输出结构太细了，简化即可。
* 工作流可以省，上文已说 Claude 本身就是从上到下执行，场景简单时重复定义工作流是冗余。

### 【提示词】
优化后的版本如下，参数后的中文为注释，实操可删：
* 把目标、行动、模型统一归到输入区
* 把想要的结果归到输出区
