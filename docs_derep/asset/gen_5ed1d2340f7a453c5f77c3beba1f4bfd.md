平时收集资料最怕什么？内容存下来了，但回头找不到来源；辛辛苦苦剪了一堆，最后却不敢分享。Obsidian Web Clipper 能解决“怎么存”，流程和边界感则解决“怎么用、怎么发”。下面这套完整 SOP 已经帮你把细节捋清楚了。

## 一、先装好

不同浏览器各走各的渠道：

- Edge：去 Edge Add-ons 下载
- Firefox：去 Firefox Add-ons 下载
- Safari：去 App Store 下载

另外，Obsidian 官方也有 Web Clipper 帮助文档，看不懂配置项时先翻官方说明。

## 二、全局参数

打开 Clipper 设置后，先把三个基础项定下来：

- Behavior：Create a new note
- Vault：选你日常使用的知识库
- Note name：{{title}}

## 三、三套模板

建议按内容来源做三套模板，让不同网页自动落到不同目录。

### 通用网页

不用填触发规则，作为默认模板兜底。保存到 `Clippings/Web/{{date|date:"YYYY-MM"}}`，正文取 `{{content}}`，标签给 `clippings`。

### 飞书文档

匹配规则用正则：`/^https:\/\/[^/]*feishu\.cn\/docx\//`。保存到 `Clippings/Feishu/{{date|date:"YYYY-MM"}}`，标签给 `feishu`。

### 微信公众号

匹配 `https://mp.weixin.qq.com/`，保存到 `Clippings/WeChat/{{date|date:"YYYY-MM"}}`，标签给 `wechat`。

Properties 中可以直接使用 `title`、`source`、`site`、`author`、`clipped`、`tags` 这些字段。

Note content 可以按下面这种结构写：

**通用网页**

```markdown
**{{title}}**
> [!info] 来源
> {{domain}}
> 剪藏时间：{{date|date:"YYYY-MM-DD HH:mm"}}
---
{{content}}
```

**飞书文档**

```markdown
**{{title}}**
> [!info] 飞书来源
> 打开原始文档
> 剪藏时间：{{date|date:"YYYY-MM-DD HH:mm"}}
---
{{content}}
```

**微信公众号**

```markdown
**{{title}}**
> [!info] 微信来源
> 打开原文
> 作者：{{author}}
> 剪藏时间：{{date|date:"YYYY-MM-DD HH:mm"}}
---
{{content}}
```

配置完别急着批量使用，先剪一篇真实网页，确认标题、正文、来源链接和保存目录都对。如果飞书文档正文不完整，先手动选中要保存的区域，再执行剪藏。

## 四、第三方平台适配

本地 Markdown 始终保留原始版本。需要发到飞书、Notion、公众号等平台时，不要直接改源文件，先生成一个“平台适配副本”。操作时记住这几条：

- 原文件不覆盖。
- 根据平台能力选 Markdown、DOCX、HTML 或可直接粘贴的排版稿，并说明理由。
- 新建的副本文件名要带上平台名。
- 不添加原文没有的事实。
- 暂时没法直接写入平台时，生成可导入或可复制粘贴的本地版本。
- 涉及账号登录、对外发布或覆盖线上内容，必须再次得到明确确认。

需要 AI 辅助时，可以这样提要求：读取指定原文路径，为某个平台生成一份可用版本，再按上面六条执行。

## 五、对外分享与隐私保护

对外分享只分享“系统”，不要把自己整套知识库原封不动端出去。

可以保留：

- 通用目录示例
- 通用版 README.md 和 AGENTS.md
- 通用 Skills 与总控流程模板
- 空白模板、脱敏示例或虚构示例

必须排除：

- 个人画像、历史对话、每日记录
- 私人项目、原始资料、剪藏正文和附件
- 姓名、账号、联系方式、真实路径、访问凭据
- 能识别个人身份或业务的信息

生成分享版时，先输出“保留清单”和“隐私排除清单”，等确认后再继续。生成后检查最终发布文件夹或 ZIP，而不是只盯着源目录。发现疑似敏感信息，只报告文件路径和信息类型，不展示具体值。最后输出隐私检查报告，并提醒用户做人工终审；不要自己宣布“可以直接发布”。

正式发布前，用户自己还要做四件事：

1. 查看最终发布包的完整文件清单。
2. 搜索姓名、联系方式、账号、盘符、用户名、公司名、客户名和私人项目关键词。
3. 随机打开文档、图片和附件，检查正文、路径、链接和元数据。
4. 确认发布包与源知识库已分离，再决定是否发布。

## 六、常见问题速查

- Codex 找不到知识库：打开本地文件夹或项目，再运行只读访问验证。
- 不知道用什么目录：先回答用途问题，或选择通用最小方案。
- 目录越建越多：合并用途相近的分类；没有真实资料来源的目录先不创建。
- 遇到同名文件：停止处理，先比较差异，让用户决定保留两个、改名或人工合并。
- 文档显示两个标题：检查文件名标题和正文一级标题是否重复。
- 网页正文无法保存：用 Web Clipper、保存 PDF，或复制成 Markdown。
- AI 可能改动原文：用精简 AGENTS.md 约束；高风险操作前先备份，明确只读或只做格式规整。
- 文件目录.md 与实际文件不一致：以实际文件为准重新生成索引，不要按旧索引移动文件。
- 本地知识库是否完全离线：不是。文件在本地，但 AI 处理仍受账户和数据控制设置约束。
- AGENTS.md 能否恢复误删：不能。它是协作规则，不是备份或版本控制。
- 怎样确认备份有效：核对文件数量，并随机打开重要文档和附件。
- Skill 没有出现：检查 .agents/skills 路径、YAML 中的 name 和 description，然后刷新或重启 Codex。
- 总控 Agent 会不会后台自动运行：不会。总控文件需要用户触发，并由 AGENTS.md 路由读取。
- 第三方平台不能直接写入：生成平台适配副本，再手动导入或粘贴。
