最近我把这套“对标采集→拆解→做模版→日更”的流程彻底跑通了，过程中踩了不少坑，也迭代了很多版。今天把最完整的版本说清楚，尤其适合想用 AI 批量生产获客内容的人。

采集完成后，所有图文和视频资料包都能直接在 Obsidian 里打开。视频的采集、抽帧、转写都已完成，原视频、语音稿、关键帧都在同一个包里，AI 要继续分析口播结构、开头钩子、镜头顺序和画面节奏都没有问题。

不过到这一步，我会把视频和图文分开处理。因为我自己的获客主要靠图文，后面的模版和日更也都是围绕图文设计的。所以主 Agent 只会把图文笔记往下传给“单篇拆解”和“模板聚类”，视频则完整留在对标页里，不再自动进入后续流程。

如果你主要靠视频获客，也可以接着用这套采集好的原视频、关键帧、语音稿，再单独接一条视频拆解线：先逐条拆出口播结构、镜头顺序、画面节奏，然后把多条拆解结果放在一起聚类，最后提炼出适合自己业务的视频模版。

进入图文的拆解环节后，主 Agent 会一篇一篇调用子 Agent。每个子 Agent 只看一篇笔记，输出标题公式、正文结构、封面和内页的分工、开头钩子、互动数据，然后把结果写回原笔记。

这里有个关键动作：绝不批量拆。一次塞十几篇进去，A 的标题、B 的正文、C 的图片很容易混在一起，得到的结论表面完整，实际没法用。

标题也要拆到“能直接套”的程度。比如“人群＋具体问题＋结果”“场景＋数量＋解决方案”，拆分后只要替换关键词就能用。如果只给一句“痛点型标题”或“数字型标题”，等于没说。

互动数据必须和内容关联起来看。收藏明显偏高，就去看它是不是清单、教程、或者用户以后会回来翻的内容；评论明显偏高，再去辨别是争议、共鸣、求教还是求链接。如果数据没有明显特征，不用强行总结爆款原因。

等这批对标全部拆完，主 Agent 会调用模板聚类子 Agent。它不会重新混着读全部原文，只拿前面的拆解结果做比较。内容角度、标题结构、正文骨架相近的放一组；视觉看着相似但内容目的不同的，仍然分开处理。

每组至少要有 3 篇对标支撑，才生成模板草案。如果只有一两篇，就继续采集，不用急着把偶然一次的内容写法变成长期规则。

到了第四步，要把模板草案变成真正可执行的 Skill。

模板聚类子 Agent 最终会产出一份“模板说明.md”，写清楚这一类内容常用的标题公式、正文结构、话题策略、互动点和配图方式。但它还只是研究结论，不能直接拿去日更。

真正进生产的是同一个目录里的“SKILL.md”。我后面说的成品模板，就是指这份内容 Skill。日更子 Agent 每次拿到的都是独立任务，没有参与前面的采集和聚类，所以它必须靠 Skill 知道自己该读哪些资料、按什么顺序做、最后交付什么。

首先是产品资料要明确。Skill 里必须列出这类内容允许引用的具体文件，AI 只能从这些文件和产品总览中提取产品事实、数字、评价和截图。每一条都要指向实际文件，不能只丢一个大目录，也不能让它自己在多个产品里乱翻。这样换新 Agent 执行时，也不容易用错资料。

文案怎么写，也要落到具体动作。标题用什么公式，正文分几段，每段解决什么问题，话题怎么选，哪些话不能说，都写进 Skill。如果只写“标题要吸引人”“正文要有干货”，日更的时候 AI 照样靠猜，产出自然不稳定。

图片也一样。封面放什么，每张内页承担什么信息，需要产品截图还是重新排版，用哪个图片 Skill 或脚本来做，文件格式和排列顺序是什么，都由 Skill 定。日更子 Agent 最后交付的不是一篇文章，而是一个完整内容包：标题、正文、话题、封面、全部内页图，一个都不少。

这一步需要人和 AI 配合。不同产品的展示逻辑差异很大：课程可能放步骤和学员结果，软件要放真实界面和操作过程，虚拟资料还得判断哪些内容适合直接展示。人负责确认内容方向和视觉效果，AI 再把判断整理成可重复执行的 Skill。

Skill 初版完成后，先让日更子 Agent 生成一个完整内容包。重点看：文案能不能自然落到产品上？封面和内页能不能稳定产出？产品事实有没有错？每张图都要点开看。连续出现的问题就改 Skill，只有当前一篇的问题就改当前内容。

第五步，日更 Agent 按 Skill 生成，审查 Agent 负责把关。

Skill 测试通过后，在工作台设置每天生成几篇。新 Skill 建议每天 1 篇起步，暂时不用的设为 0。

主 Agent 每次运行会先看今天还缺几篇。比如设定每天 3 篇，已经完成 1 篇，它就只补 2 篇。如果上次停在生成、审查或返工，下次会从原位置继续，不会重新生成一批。

真正写内容的是日更生成子 Agent。它一次只处理一个产品和一份 Skill：先读产品总览和资料索引，再读 Skill 指定的产品文件，然后按照步骤生成标题、正文、话题、封面和所有内页图。Skill 里指定了脚本或图片 Skill，它也会在对应步骤调用，最后把文字和图片组装成完整内容包。

生成结束后，主 Agent 会再启动一个新的内容审查子 Agent。它重新读取产品资料和同一份 Skill，再把文案和每张图打开检查。这一轮里处理的问题包括：产品事实有没有写错，标题和正文是否按 Skill 执行，图片上的文字能不能看清，箭头和圈选有没有指错位置。

审查不通过，意见退回日更生成子 Agent 修改，改完再审。生成和审查必须分开，为了防止同一个 Agent 刚写完内容，又顺着自己思路给自己判通过。

刚开始跑新 Skill 时，建议把人工审核打开。AI 审完之后，再用手机看一遍封面、内页、正文和话题。连续几篇都稳定了，再逐步减少人工检查。

先手动跑几次，确认中断后能恢复、数量不会重复、文案和图片都能正常写进 Obsidian。如果用的 AI Agent 支持定时任务，再设置固定时间唤醒主 Agent。每天生成几篇、哪些 Skill 暂停，都可以在工作台随时调整。

这套流程从搭建到现在，前后改了很多轮。以后我还会拿新品类继续跑，哪里出问题就把处理方式补进去。
