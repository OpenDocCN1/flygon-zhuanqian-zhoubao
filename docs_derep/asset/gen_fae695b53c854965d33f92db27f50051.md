# Obsidian + Codex 从 0 到 1 实操手册 7.31 现场版

用三份资料，20 分钟内跑通整理、使用、产出闭环。现场只做第一部分，后续按需扩充目录、项目和 Skills。

你负责目标判断和最终确认；Codex 负责检查、出方案、执行已确认操作并自检。

## Obsidian 是什么
它是本地 Markdown 编辑器兼知识库，笔记以纯文本保存，可编辑、检索、浏览，通过链接关联。数据在本地，可长期访问，不受平台锁定。

## 安装准备
最小组合三件事：Obsidian、Codex、本地文件夹。

Obsidian 用于阅读和管理本地 Markdown。
ChatGPT 桌面版中的 Codex 用于读取和管理本地文件。
WorkBuddy 可作为 Codex 不可用时的备选。
本地文件夹用于存放知识库文档和附件。

以 Windows 为例，界面名称可能有差异，核心是让 Codex 连接到 Obsidian 正在使用的同一个知识库文件夹。

## 设置本地路径
新建一个空文件夹，建议根目录用英文，内部目录用中文。英文路径兼容性好，中文目录更易理解，迁移备份和 AI 读取都更稳定。

打开 Obsidian，选择刚创建的 KnowledgeBase 文件夹。若之前有仓库，可在底部路径管理处新建一个空仓库。

软件界面分左侧目录、中间编辑区、标签页、搜索和左下角设置。

第一次闭环不需要第三方插件，有需求再装。

## 使用路线
最小闭环版由四层构成：
1. 本地资料：Markdown、PDF、附件等真实文件。
2. 结构说明：README.md 说明目录用法。
3. 操作规则：AGENTS.md 约定可直接执行事项和必须确认事项。
4. AI 协作：Codex 检查、提方案、执行已确认操作并自检，用户保留最终判断权。

Skills 和总控 Agent 属于成熟期自动化能力，第一次搭建不必急着上。

## 适合人群
* 懂 Codex 基础用法，但没用过 Obsidian。
* 希望 AI 能读取和管理本地资料。
* 有长期需要沉淀的学习、工作、写作或项目资料。
* 装了大量 AI 工具，却难以形成稳定工作流。
* 愿意保留最终判断权，并在关键操作前审方案。

## 开始前确认
* 不支持完全离线处理。
* 不要上传密码、验证码、API Key 或高度敏感资料。
* 总控流程只在用户触发时运行，不会后台自动修改。
* 若无真实资料，先准备三份可安全测试的副本或使用手册附件。

## 三种执行角色
* 用户操作：安装软件、选文件夹、备份、放入资料、判断方案、最终确认。
* Codex 操作：读取检查文件、生成方案、执行已确认操作、更新文档、自检。
* 协作模式：Codex 先检查或建议，用户确认后 Codex 再执行。

## 第一次实操

### 第一部分：20 分钟新手闭环

> 1. 当前工作目录的完整路径。
> 2. 根目录下已存在的文件和一级目录；若为空请明确说明。

**生成最小方案**

> 请输出一套可直接执行的最小方案，包括：
> 1. 不超过 5 个核心目录及用途。
> 2. 资料从进入、整理、使用、产出到归档的流向。
> 3. 可直接写入的 README.md 完整草案，说明用途、目录结构、每个目录用途、资料流向。
> 4. 可直接写入的精简版 AGENTS.md 完整草案，至少包含：未经明确要求不删除文件；移动、重命名、覆盖、批量修改、目录调整前先出方案并等待确认；原始资料默认保护正文，不确定格式或内容修改时先询问；创建或移动前检查目标路径，同名文件不覆盖不自动合并；操作后检查状态并汇报；基于知识库回答时列出参考文件，区分资料内容、归纳结论和 AI 推断。
> 5. 本次需创建的目录和文件清单。
> 6. 本次暂不创建的内容，如文件目录.md、项目 PROGRESS.md、Skills、总控 Agent、其他插件目录。
> 7. 可直接执行的操作和必须再次确认的操作。
> 若信息不足，可参考通用最小结构：00_收集箱、01_知识笔记、02_原始资料、03_归档、附件。附件目录先少后多，不建无用分类。
> 现在只输出方案和草案，不创建、移动、删除或修改文件，输出后等待确认。

检查目录是否符合习惯，一级目录是否过多，是否包含无用分类。不满意直接让 Codex 修改，不必编号版本。
> 请根据我下面的意见输出一份可独立阅读的完整修订版方案。我的修改意见：（填写合并、删除、增加或改名内容）现在仍只修改方案，不操作文件，输出后等最终确认。

方案确认后发送：
> 我确认使用刚才最终确认的完整方案，请开始创建最小知识库。执行前：
> 1. 再次确认工作目录即知识库根目录。
> 2. 检查现有文件和目录是否与方案冲突。
> 3. 若已存在同名目录、README.md、AGENTS.md 或其他同名文件，立即停止并报告差异，不要覆盖或自动合并。
> 4. 检查方案是否包含可直接写入的 README.md 和 AGENTS.md 草案，若缺少先停止并告知，不要自行补充。
> 确认无冲突后：
> 1. 只创建方案中已确认的目录和文件。
> 2. 按方案草案写入 README.md 和 AGENTS.md。
> 3. 不自行增删改目录、正文和规则。
> 4. 不创建方案中明确列为暂不创建的内容。
> 5. 若需操作已有资料，先停止并确认。
> 6. 完成后检查目录、README、AGENTS 是否一致，是否意外创建额外文件。
