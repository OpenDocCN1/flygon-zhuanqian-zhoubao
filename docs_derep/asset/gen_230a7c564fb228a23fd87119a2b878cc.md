# 从业务思考到产品落地：把注意力放在真正重要的事上

> 原文：[`www.yuque.com/for_lazy/zhoubao/tibximhxk7ikgx68`](https://www.yuque.com/for_lazy/zhoubao/tibximhxk7ikgx68)

最近和团队复盘时聊了不少关于怎么看待业务、怎么做产品的问题，整理出来和大家一起参考。

对我来说，现在更在意的是培养同事的思考方式，而不是替他们把每件事都想好。直接给结论最快，但学会自己判断才能走得更远。

下面是这次交流里反复提到的几个抓重点、做产品的思路：

1/
信赖自己的判断力，相信直觉、本能和常识。别让忙碌把内心的声音压没了，也别让学来的方法论盖住最本质的道理。好就是好，这件事不需要复杂的理论也能感知到。

2/
做产品的前提是自己先被打动。若自己都不觉得有意思，那很难指望用户买账。自己喜欢不代表用户一定喜欢，但没有这份兴奋感，项目基本可以放弃。

3/
别总想着靠一套组合拳来赢。找准那个最关键的杠杆点，把它做到极致就够了。即使失败，也至少能复盘清楚学到了什么。反倒是靠多点开花成功了，往往搞不清到底是哪个环节起了作用。

与其追求一个模模糊糊的成功，不如拥抱一个清晰的失败，前者对成长的价值更大。

4/
思考要广，做事要窄。思考时要尽量全面深入，但执行时必须聚焦。先把问题想透，再把所有火力压在一处击破。深度思考的意义就是为了锁定关键点。而一旦养成了聚焦的习惯，反而能更深入，因为你会主动过滤掉干扰。

5/
定义问题比解决问题的难度更高，也更重要。要把至少一半的时间花在把问题说清楚上。问题一旦被厘清，真正需要做的事会少很多。如果你觉得手头事情一大堆，大概率是关键点没找对。

轻松且有成果并不是矛盾体，关键在于是否找对了问题。

6/
找重点时可以不断自问：
我们现在到底在讨论哪个具体问题？只留下一个最核心的问题，它是什么？
这个问题的本质到底在哪？追问几次直到触到内核。
如果目标现在就达成，然后呢？会带来什么实质变化？
在众多选项里，哪个优先级更高？不可能同时都最重要。
我们最终想要的是什么，眼前讨论的问题和它有什么关联？如果关联不大，现在讨论的必要性有多高？

7/
质量先于数量。在质量没保障的情况下堆数量，纯属浪费。

8/
别只问我怎么做，要先说明白为什么这是最关键的问题。Why 比 How 更重要。

9/
产品本身比流量更根本。定位就是产品的一部分，要明确在什么定位下，用怎样的产品形态去解决用户的什么具体痛点。
