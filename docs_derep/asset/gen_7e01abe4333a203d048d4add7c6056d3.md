## 二、四个工具如何分工：IMA 负责收，Obsidian 负责炼，飞书负责享，Codex 负责调度

| 工具 | 核心职责 | 适用场景 |
|---|---|---|
| IMA | 收集 | 手机端临时保存文章、网页，并对已上传内容进行查询 |
| Obsidian | 加工 | 保存本地 Markdown、拆分观点、建立链接、沉淀主版本 |
| 飞书 | 分发 | 排版、协作、评论、交付和对外阅读 |
| Codex | 调度 | 读取、整理、拆分、写入、同步，并回到目标端完成验收 |

我后来给这四个工具划定了明确边界：

- **IMA：负责“收”**  
  它适合手机和微信场景。临时看到一篇文章，先快速保存下来；后续也可以基于已经上传的内容进行问答。

- **Obsidian：负责“炼”**  
  它本质上是电脑里的 Markdown 文件系统，适合长期保存、拆解观点、改写内容、建立双链，并沉淀属于自己的方法论。

- **飞书：负责“享”**  
  需要协作、评论、排版、交付，或者需要把内容分享给别人阅读时，再把成品放到飞书。

- **Codex：负责“调”**  
  它是连接各个入口和内容仓库的执行中枢，可以帮助完成读取、整理、拆分、写入、同步和最终检查。

如果只保留一张流程图，可以这样理解：

手机文章、微信记录、电脑网页、历史文档  
→ IMA 或 Obsidian Inbox  
→ Codex 读取、清洗、拆分  
→ Obsidian Notes / Archive  
→ IMA、飞书  
→ 公众号、短视频、朋友圈、课程或方案。

当然，这四个工具并不要求一次性全部部署。

刚开始时，你只需要准备：

- 一个内容入口；
- 一个加工空间；
- 一个输出渠道。

这样就已经能够启动。

## 三、第一次不要搭“大而全”，先让一条内容完整走通

这是我最想提醒新手的一点：

**先人工跑通一条，再考虑自动化。**

第一次测试时，我只拿了一篇文章，按照下面的步骤执行：

1. 用手机把文章分享到 IMA；
2. 回到 IMA，确认文章正文可以正常打开；
3. 让 Codex 读取这篇内容，并保存到 Obsidian；
4. 在 Obsidian 中检查标题、正文开头和结尾、来源链接，以及图片或附件说明；
5. 让 Codex 从原文中提炼出一条可以独立使用的观点；
6. 把这条观点改写成朋友圈内容，或者短视频开场；
7. 将成品放入飞书，再从飞书重新打开检查。

这七步全部完成，我才会认为这条链路真正跑通。

以前我经常把“接口返回成功”误认为任务完成。后来才发现：

- 创建成功，可能只是新建了一篇云文档，并不代表它进入了指定知识库；
- 同步成功，可能只是同步了一个需要登录、别人打不开的空链接；
- 文件出现在 Obsidian 中，也可能正文只写进去了一部分。

所以现在我的验收方式非常简单：

**回到目标端重新搜索，打开文件，从头读到尾。**

能写进去，只是第一步；目标端能够搜到、正常打开、内容完整，才算真正完成。

不要一开始就追求全自动。

## 四、不同来源的资料，分别如何接入

| 内容来源 | 首选入口 | 加工位置 | 常见输出 |
|---|---|---|---|
| 手机文章、即时灵感 | IMA | Codex 拉取至 Obsidian Inbox | 朋友圈、短视频、文章 |
| 电脑网页、公众号文章 | Web Clipper、飞书剪存或 IMA | 检查完整后进入 Obsidian | 选题、文章、项目资料 |
| 微信历史聊天 | yichen-wechat-local-vault | Codex 按对象、关键词和时间整理 | 复盘、案例、客户问题、选题 |
| 过去写过的文档 | 直接放入 Obsidian | 统一格式、拆解和归类 | 飞书交付、IMA 检索 |

### 1. 手机看到的内容：先收进 IMA

【视频演示】手机浏览器内容保存到 IMA（25 秒）

手机端最重要的关键词就是：**快。**

如果看到一篇文章后告诉自己“等回到电脑再整理”，大概率就不会再处理了。

我的习惯是：

点击分享，选择 IMA，放进固定知识库，例如“待整理”。保存后再打开一次，确认全文可以正常查看，这才算真正收藏完成。

IMA 是第一站。之后，我会手动处理，或者在手机与电脑协同的情况下，让 Codex 批量把内容拉入 Obsidian，并且把原始资料和加工后的结果分开保存。

### 2. 电脑网页与公众号文章：先看保存是否完整

以前处理普通网页时，我通常会使用 Obsidian Web Clipper。它是 Obsidian 官方浏览器扩展，可以直接把网页保存成本地 Vault 中的 Markdown 文件。

但需要注意：

**生成 Markdown 文件，并不代表网页内容已经完整保存。**

懒加载图片、复杂表格、轮播模块等内容，都可能在抓取时丢失。

我的检查流程是：

- 先把网页缓慢滚动到底部；
- 再执行剪藏；
- 检查正文开头和结尾；
- 查看图片是否存在；
- 确认原始链接是否保留。

即便如此，有些页面仍然会抓取不完整。

遇到公众号长文或结构复杂的图文内容，如果 Web Clipper 保存效果不好，我通常会删除这份结果，再使用飞书剪存重新处理一次。

飞书在保留原始排版和后续协作方面更有优势。

工具选择的关键，不是哪个名字更高级，而是哪一个能够把当前文章完整保存下来。

长期大量使用后，我发现 IMA 在某些场景下保存效果更稳定，因为它保存的是链接，而不是对网页进行一次性剪藏，因此不容易出现正文缺失。

如果需要长期追踪固定公众号的更新，再考虑自动化方案：

- WeRSS 提供相对稳定的来源；
- 本地脚本负责检查和去重；
- 飞书用于提醒和记录；
- Obsidian 保存正文；
- 同时保留运行日志，以及授权失效提醒。

刚开始不要一次监控几十个公众号，先挑一到三个账号测试。

详细操作见：

《【取公众号】公众号文章监控工作流教程：可复刻执行版》

### 3. 微信历史记录：查询本地 Vault

这可能是许多人最想要、也最刚需的一部分。

【视频演示】在手机微信中发送指令，Hermes 调用电脑本地 Vault，再由 Codex 整理结果。

在电脑端读取微信 Mac 4.x 历史数据时，我使用的是 **yichen-wechat-local-vault**。

它负责维护电脑中已经解密的本地 Vault，Codex 再根据明确的群聊、联系人、时间范围和关键词进行查询。

与旧版 wechat-cli 相比，它还支持读取语音和朋友圈，不需要把微信降级，也不需要安装重签名版微信。

电脑端的基本链路是：

微信本地数据  
→ yichen-wechat-local-vault  
→ Codex  
→ Obsidian 或飞书。

只有在我希望通过手机微信远程发指令时，才会在前面增加 Hermes：

手机微信指令  
→ Hermes  
→ 同一个本地 Vault  
→ Codex  
→ 返回查询结果。

这里要分清三个角色：

- **Hermes**：消息入口和任务调度层；
- **本地 Vault**：微信历史数据所在的位置；
- **Codex**：负责理解需求、执行查询和整理结果的大脑。

Hermes 不是微信数据库，Codex 也不会天然拥有你的聊天记录。把三层关系分开，后续排错会简单很多。

### 4. 自己写过的内容：直接放进 Obsidian

Word、Markdown、飞书旧文档，以及过去发布过的文章，不必重新绕回收藏流程。

我会先确认哪一份是原始版本，再把它放进 Obsidian 对应目录，保留来源和日期，之后让 Codex 协助完成：

- 格式统一；
- 内容拆分；
- 标签整理；
- 分类归档。

Codex 能够理解 Obsidian 的 Markdown、双链、标签和 frontmatter，因此适合承担这类整理工作。

# 实操手册｜如何在电脑上搭建这套内容工作流

这一部分不是要求你一次安装全部组件。

建议先选择一条路线，把一篇真实内容从来源端送到目标端。确认电脑端微信可以正常查询后，再继续加入 Hermes。每完成一个步骤，都要重新回到目标端搜索并读取。

## 1. 先保存官方入口

工具更新速度很快，第三方教程中的安装包、命令和参数可能已经失效。下面尽量只保留官网、官方仓库，或我实际使用过的 Skill 页面。

| Codex CLI（选装） | OpenAI Codex 官方仓库 | 适合习惯终端操作或需要脚本化的人；只使用桌面端可以暂时不装 |

## 2. 推荐安装顺序：先打通基础，再逐步增加入口

### 第一步：安装 Codex 和 Obsidian

先让 Codex 能访问一个明确的 Vault 路径，然后写入并读回一篇测试笔记。

### 第二步：选择一个内容入口

手机内容优先选择 IMA。

电脑网页则可以同时试用：

- Obsidian Web Clipper；
- IMA；
- 飞书剪存。

通过实际保存效果进行比较。

### 第三步：接入微信历史数据

如果需要查询电脑中的微信记录，再安装一尘 Skill。

先确认本地 Vault 正常，再进行限定范围的查询测试。

### 第四步：最后加入 Hermes

只有当你确实需要通过手机微信远程指挥电脑时，才安装 Hermes。

建议先测试普通对话和 PONG，再调用一尘 Skill。

## 3. 第一步：让 Codex 访问 Obsidian

Codex 并不一定要依赖 Obsidian MCP 才能读取 Obsidian。

因为 Vault 本质上就是电脑中的一个文件夹。你只需要先把这个文件夹添加为 Codex 的工作目录，然后发送下面的提示词：

> 这是我的 Obsidian Vault 路径：【粘贴绝对路径】。请先只读检查路径是否正确，不要扫描其他目录。确认无误后：
>
> 1. 保留现有目录结构，不覆盖旧文件；
> 2. 如果不存在，请创建 Inbox、Notes、Archive、Outputs 四个文件夹；
> 3. 在 Inbox 中新建一篇名为“工作流验收测试”的 Markdown 笔记；
> 4. 写入标题、创建时间、来源和一句测试正文；
> 5. 重新读取这篇文件，并告诉我标题、路径、正文开头和结尾；
> 6. 不安装 Obsidian MCP，不删除、移动或批量修改任何旧笔记。
>
> 只有完成写入并重新读回完整内容，才算测试通过。

验收时需要确认：

- 文件确实出现在正确的 Vault 中；
- Obsidian 能正常打开；
- Codex 读回的标题和正文与写入内容一致。

详细说明可参考：

《如何创建 Obsidian：从安装到第一个知识库》

## 4. 手机内容进入 IMA，再由 Codex 读取

先进入 IMA Agent Interface，手动申请 Client ID 和 API Key。

然后把下面的提示词交给 Codex：

> 请安装并检查最新版 ima-skill，先确认 Node.js 版本满足要求。我会按照你的提示在本机输入 IMA Client ID 和 API Key。请将凭证安全保存到本机私有配置目录：
>
> - 目录权限设置为 700；
> - 凭证文件权限设置为 600；
> - 不得在输出、日志、截图或 Git 中显示密钥。
>
> 配置完成后，调用 IMA OpenAPI 的 list_note，执行一次 limit=1 的只读鉴权测试。随后列出我有权限访问的 IMA 知识库名称，不进行任何写入。最后告诉我：
>
> 1. Skill 是否安装成功；
> 2. 鉴权是否通过；
> 3. 是否能够列出知识库；
> 4. 如果失败，具体失败在哪一步。

确认能够列出知识库后，再用一篇真实内容测试：

> 请在 IMA 中根据完整标题搜索【笔记标题】，只处理这一篇。读取正文后：
>
> 1. 将原文保存至 Obsidian 的 Inbox；
> 2. 保留原标题、来源链接、IMA 笔记 ID 和同步时间；
> 3. 检查正文开头、结尾、链接和图片说明；
> 4. 写入后重新读取 Obsidian 文件；
> 5. 告诉我 IMA 命中数量、Obsidian 文件路径和读回结果。
>
> 不要批量同步，也不要覆盖同名文件。如果发现同名文件，请先停止并告诉我。

完整流程可参考：

《IMA 知识库与 Codex 打通教程》

## 5. 将飞书接入 Codex

首先在飞书开放平台创建企业自建应用，开启所需的云文档和知识库权限并完成发布。

拿到 App ID 和 App Secret 后，不要把 Secret 写进公共提示词。

可以让 Codex 按照当前版本的官方 Skill 和帮助信息完成接入：

> 请根据 lark-cli 当前版本的内置 Skill 和 --help 完成飞书接入，不要直接照抄旧版命令。要求：
>
> 1. 从官方仓库安装或更新 lark-cli；
> 2. 引导我在本机完成应用配置，不在输出中显示 App Secret 或 token；
> 3. 发起 docs、drive、wiki 范围的用户授权；
> 4. 注意 auth login 本身不加 --as user，后续读取和写入 API 时才使用 --as user；
> 5. 验证用户授权状态；
> 6. 只读列出我有权限访问的飞书知识库；
