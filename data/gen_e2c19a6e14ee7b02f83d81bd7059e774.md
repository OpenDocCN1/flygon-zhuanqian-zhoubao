# 怎么才能做出用户真正需要的产品？

先聊需求挖掘。不同产品的需求不同，对应的运营和营销策略也不一样，所以一定要具体情况具体分析。但思考久了，也沉淀出一些通用方法。

**第一，发现身边的需求，包括自己的和周围人的。**

从个人痛点切入是最直接的路径。比如世纪佳缘的创始人龚海燕，当初自己找对象不顺利，就想用互联网解决这个问题，先做了个“爱情日记”网站记录自己找对象的过程，结果发现很多人都有同样的需求，后来干脆转型做了婚恋交友平台。典型的先解决自己的问题，再发现市场机会。因为你是产品的深度用户，你会很清楚供给和需求之间的缺口在哪，跟用户共情起来也更容易，做出来的产品自然更贴合市场。

身边人的需求同样值得留意。我们经常听到朋友吐槽某些产品，这其实就是未被满足的需求。所以我平时很喜欢翻竞品评论区，就是为了找这些缺口。当然还有一类隐性需求，用户自己都说不出来，甚至没意识到。iPhone出现之前，没人知道自己需要触屏手机。想挖掘这种隐性需求，可以看看华哥（老爸带你飞）写过的相关文章。

**第二，榜单选品。**

这个方法很像电商选品。以前做电商带货，我们会去数据分析平台看商品榜单，找出爆款。AI产品也是一样的逻辑。我们经常用Toolify看产品榜单，新产品能上榜，说明有流量也有需求。然后按自己的实力筛选出能跟进的竞品去模仿，有可能蹭到一波热度。

有个小技巧：优先看月榜100名之后的产品。排名靠前的基本都是GPT这种巨头，而100名之后往往藏着近期冲上来的新产品。找到功能自己能复制的，再看看付费流量和自然流量的占比，如果自然流量超过50%，说明搜索需求很强，这就是快速跟爆品的思路。

[PRE4]

**第三，竞品分析挖掘需求。**

如果已经有了大致方向，但不确定是不是伪需求，可以去找有没有对标产品。如果有，就看它的商业模式怎么赚钱，是广告还是付费订阅；再看它的流量来源，是付费投放还是渠道流量。如果对标产品既跑得动流量又跑得通变现，那需求基本就是真的。

**第四，目标用户需求挖掘。**

方向定了之后，得确认目标用户的真实需求。可以先假设一些需求，再想办法验证。注意，不一定非要开发完整产品，Dropbox早期只靠一个视频就验证了需求。我们也可以低成本验证，拿原型图跟用户聊，如果设计的功能跟实际需求有出入，快速改就行。

# 构建-测量-学习，先把MVP跑起来

《精益创业》里有个核心观点：从假设开始，不是从产品开始。需求挖掘本质上是提出假设，然后验证假设。做产品的大部分过程，都是不断提出假设、验证假设、积累经验的过程。功能也好，运营也好，先假设某个方法成立，再跑数据验证。

有了需求假设之后，重点是搭一套能把假设测出来的闭环系统——快速做一个最小可行产品（MVP），让真实用户来验证，根据数据和反馈快速迭代。说白了就是先上线，再收集用户数据，持续打磨。

**AIMIX的MVP怎么做的？**

开发之前，我们结合自己对业务场景的理解和竞品调研，明确了产品方向，围绕用户真实业务场景设计功能。我们真正想做的其实是内容营销的完整闭环——从创意、制作到分发。但MVP阶段不可能一口气做完，所以选了“内容制作”这个切口。第一版非常简陋，各种问题不少，但推到市场后很快有了第一批种子用户，验证了方向，也拿到了珍贵的反馈。

**数据观测怎么做？**

数据收集是产品优化的指南针。一般要找到北极星指标，但北极星会随着阶段变化。初期可能更关注日活和留存；稳定阶段就要看用户时长。B端和C端的关注点也不一样。C端社交产品重点看日活和停留时长。比如抖音早期把创作者的视频完播率当作核心权重，所以当时7秒左右的短视频特别容易爆。到了存量时代，用户增长乏力，平台开始收割用户时长去做广告变现，重点指标就变成了停留时长，于是我们开始刷到越来也多的中长视频，甚至几个小时的长视频。

# 增长的核心：找到PMF

**增长和留存指标（产品使用行为）：**

- DAU/MAU：用户活跃增长
- 用户留存率，比如次日、7日、30日留存
- NPS 净推荐值够高，用户愿意自发推荐
- 自然流量持续增长，比如搜索、口碑

[PRE28]

**商业转化指标（付费行为）：**

- 免费用户主动转付费
- 续费率、复购率高
- CAC < LTV，获客成本小于生命周期价值

统计转化率要结合数据埋点，比如用GA画转化漏斗，从访问到付费每一步的转化都能看到，再结合用户行为分析优化产品。我们产品目前还没做到那么细致的统计，所以转化率还是预估为主。

**找到PMF的四步路径**

**第一步：锁定“目标用户 + 痛点”**

回答两个问题：我的产品为谁解决问题？用户的核心痛点是不是强需求？

常用方法：用户访谈、调研、五问法深挖问题、竞品评论分析。
常用工具：用户旅程图、Persona模型、JTBD（Jobs To Be Done）。

需求程度可以用“高频/刚需”两个维度来分：

- 刚需高频：像微信、支付宝，每天离不开。
- 非刚需高频：抖音、微博这类娱乐产品，虽不是刚需但容易上头，打发时间首选。
- 刚需非高频：工具类产品，日常会用到但频率没那么高。尤其行业工具，很值得创业者考虑。
- 非刚需非高频：用户付费意愿就很弱了。

**第二步：构建MVP验证**

不要上来就开发全功能版本，应该聚焦最核心的需求，快速出原型。

工具：Figma做低保真原型、快速做Landing Page加表单收集意向、MVP快速开发框架比如no-code/low-code/SaaS。

前面说过，MVP不一定是产品，关键是能验证假设。

**第三步：观察行为，快速迭代**

跟踪几个关键信号：
- 用户会不会主动留存？
- 有没有使用深度，即某个功能被频繁使用？
- 愿不愿意付费？愿不愿意推荐？

方法：Mixpanel做行为分析、留存漏斗、A/B测试、用户访谈。

数据不会骗人，让数据指导决策，方向就不容易跑偏。而且快速迭代是接近PMF的最短路径。我们的产品上线一年多迭代了30多个版本：

**第四步：打磨价值主张，放大传播和转化**

当你在某批用户里看到了强烈黏性和自然增长，就可以进一步做这些事：
- 明确你的独特价值主张（UVP）
- 搭建高转化增长通道，比如推荐机制、内容营销、广告投放
- 复制用户群体，扩大规模

到这一步，产品基本就有了稳定的增长模型——不管你是靠投放、口碑还是SEO，现在要做的就是放大这个模型，不断复制，开始跑马圈地。

# 竞争的本质，是价值网络的竞争

产品竞争从来不是单一维度的。只模仿竞品功能还不够，营销渠道可能也打不过人家，所以要把自己的价值网络一点一点补全。

我们很早就意识到，AIMIX这个产品的复杂度和专业性决定了自然增长会比较慢。原因有两个：一是客户端产品，用户要下载安装，链路变长，加上使用环境的差异性和兼容性，问题也会多；二是它属于比较专业的工具，用户需要有一点剪辑基础，有学习成本。产品性质决定了增长复杂度。

所以我们对产品的定义不是一个工具，而是对用户交付一整套完整服务。从购买前的咨询，到使用中的文档教程，再到售后服务，整个流程都是服务体验。为此我们积累了大量文档，录制了视频教程，还专门做了一套矩阵运营的知识体系课——这些都是价值网络的一部分。这套模式现在看，已经验证了可行性。
