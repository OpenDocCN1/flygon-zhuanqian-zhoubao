# 把 YouTube Shorts 做成一条可复制的自动化流水线

> 来源：[https://ia0969wpr2.feishu.cn/docx/ELcgdUKJToK95YxuoCUc33XVnzh](https://ia0969wpr2.feishu.cn/docx/ELcgdUKJToK95YxuoCUc33XVnzh)

大家好，我是钱塘江鲤。受亦仁的超级标启发，最近一段时间我一直在琢磨 YouTube Shorts 的 AI 驱动运营。摸索下来，整个作业链路已经被我一点点跑通并固化成了自动化系统。起初觉得这块没有太多技术壁垒，也还没跑出明显成绩，一直没好意思拿出来讲。直到前两天和@土豆君 闲聊时聊到这件事，被他一鼓励，这才决定把现在用的做法整理出来，和同样在试这条路的朋友做个参考。

下面这篇文章讲的是我如何借助 Cursor + AI 把 Shorts 的运营效率拉满。现阶段除了图片和成片的挑选需要我人工过一遍，从素材采集、对标复刻、创意生成，到画面合成、视频合成、剪辑打包，再到多账号矩阵发布，基本都已跑在自动化里。早期我也试过完全无人值守，但成品质量拉胯，后来在画面生成和视频生成这两个环节加了反向筛选的人工节点，采用先大量生成再精挑细选的策略，效果明显回升。

单条视频的成本根据选用的图生模型不同，大体在几分钱到几毛钱之间。进一步压成本当然可以，但质量也会跟着掉。所以在现有的质量水位下，这个花费我是能接受的。

我这套组合现在在用：

提示词反推：midjourney describe 和 gpt4o-mini
画面生成：flux+comfy / midjourney
动态生成：即梦 / 可灵 / 海螺

先说下前提。这篇笔记是我在自建账号期间，顺手搭的一个内容管理与发布中台。全部代码都是在 Cursor 的辅助下产出。受限于篇幅，历史上的完整 Prompt 我不可能全列出来，而且当下的模型能力已经很强了，不需要那些花哨的“封神级”提示技巧，说清楚需求就能把产品搭起来，上手其实门槛不高。

文章里我会把一些需要多轮调试才能跑通的功能核心代码贴出来，比如场景切分、视频批量生成、Discord 或即梦无水印下载的油猴脚本等。其他部分更多还是需要你自己上手试、调。

另外由于涉及的细节碎片很多，篇幅有限讲不全，读起来可能会觉得脉络跳跃、抽象。但如果你已经把基础流程跑通，现在卡在放大规模上，这份梳理应该能帮上忙。不足之处也很多，欢迎在星球里一起讨论，互相打磨出更好的答案。

接下来讲整体实现路径。

## 对标视频的拆解与复刻自动化

先从对标视频的像素级拆解和自动复刻说起。

一套完整的复刻流程大致是：视频下载 → 场景切分 → 提示词反推 → 新图生成 → 动态生成 → 剪辑拼接 → 配 BGM → 导出发布

这条链路理论上都能自动化，但为了保质，在画面生成和视频生成这两个关键点我保留了人工筛选，其余环节全交机器。我投入在 YouTube 的时间有限，所以最初的设计目标就是：丢一个对标链接进去，机器自动生成复刻分镜的视频片段，我只需要动鼠标点选，其他的切分、重绘、剪辑、上传、数据统计全部自动跑。

要达成这个目标，第一步是先有个自己的素材中枢，用来创建草稿项目、管视频、管代理信息和矩阵账号等。
