## 一、2026年的AI编程，早不是你想的那样

很多人对AI编程的印象还停留在“让ChatGPT写段代码，自己复制粘贴”的阶段。

但2026年的AI编程工具，已经进化到另一个维度了。

**Claude Code** 绝非一个简单的对话框。它就像一个住在你电脑里的同事。

你告诉它“帮我做个待办清单网页”，它会：

- 自动创建项目文件
- 自动完成代码编写
- 自动装好依赖包
- 自动跑测试
- 遇到Bug自己修
- 完事告诉你“做好了，打开这个地址看效果”

全程你碰都不用碰代码。

你只需要做三件事：

- 第一步：用中文说清楚你要什么
- 第二步：打开浏览器看效果，检查它做出的东西
- 第三步：哪里不满意，用中文告诉它改

这就是AI编程的“黄金三步”。听着简单，但90%的人卡在第一步——不知道说什么、怎么说、说到什么程度。

## 二、从零到能用：完整安装配置指南

我把这节写得格外详细，因为太多人就卡在安装这一步走不下去。

### 2.1 准备工作

- 一台电脑（Mac或Windows均可）
- 网络连接
- 不需要任何编程基础

### 2.2 安装VS Code（大约5分钟）

如果电脑上已有VS Code，直接跳到下一步。

**Windows用户**：

1. 浏览器搜“VS Code下载”或直接访问https://code.visualstudio.com
2. 点下载按钮，获取Windows安装包
3. 双击安装包，一路点“下一步”即可
4. 装好后打开VS Code

**Mac用户**：

1. 同样访问https://code.visualstudio.com
2. 点击下载Mac版本
3. 下载完把VS Code拖入“应用程序”文件夹
4. 打开VS Code

### 2.3 安装Claude Code插件（约5分钟）

这一步相当于把AI程序员请进你的编辑器。

1. 启动VS Code
2. 看左侧竖排图标栏，找到“扩展”图标（长得像四个方块），或直接按快捷键：
   - **Mac**：Cmd + Shift + X
   - **Windows**：Ctrl + Shift + X
3. 搜索框输入**“Claude Code”**
4. 找到**“Claude Code” by Anthropic**（认准Anthropic官方出品）
5. 点击**Install**
6. 安装完毕后，VS Code侧边栏或底部会出现Claude Code面板

### 2.4 模型配置（约10分钟）

Claude Code插件装好后，默认使用Anthropic自家的Claude模型。但你也可以换到国内模型，价格更划算、国内网络环境用起来更顺。

目前我推荐的两个模型选择：

| 模型 | 提供方 | 特点 | 费用 |
|------|--------|------|------|
| **GLM-5.1** | 智谱AI | 编码能力较前代提升28%，兼容OpenAI接口 | 按量付费，比Claude便宜很多 |
| **Kimi K2.6** | 月之暗面 | 2026年4月发布，1万亿参数MoE模型，支持300个子Agent并行，原生多模态 | $0.60输入/$2.50输出 每百万token |

我自己现在用的是**GLM-5.1**。日常开发完全够用，成本比Claude低不少。

配置**GLM-5.1**操作：

1. 打开VS Code设置文件。按Cmd + Shift + P（Mac）或Ctrl + Shift + P（Windows），输入“settings json”，选**“Preferences: Open User Settings (JSON)”**
2. 在打开的settings.json文件里，找到或添加Claude Code相关配置，把模型改为glm-5.1

也有更省事的方式——直接在Claude Code设置界面改：

1. 点击VS Code底部状态栏的Claude Code图标
2. 找到模型设置选项
3. 选择或输入模型名称

详细的配置指引看智谱官方文档：https://bigmodel.cn/claude-code

## 三、最关键的一环：让AI帮你搞定CLAUDE.md

这一步我觉得是整个AI编程流程里最核心的。

CLAUDE.md是什么？一个特殊文件，Claude Code每次启动都会读取它。相当于你给AI员工写的“工作手册”——告诉它用什么技术栈、遵守哪些规矩、哪些事不能碰。

这个文件决定AI编程质量的上限。没有它，AI就像个能力很强但没人管的新人，随心所欲乱来；有了它，AI就像个训练有素的工程师。

**千万别自己套模板——让AI帮你生成**

网上不少教程会丢一个CLAUDE.md模板让你自己改。但说实话，普通人不具备改它的能力——那些技术术语你根本不认识，改个啥？

我的做法是：直接跟AI讨论，让它帮你产出。

具体操作：打开Claude Code，输入：

AI会跟你聊几个问题（比如“你想做哪种类型的网站”“有没有偏好的技术栈”），然后生成一份完整CLAUDE.md，直接写入项目文件夹。

你不需要看懂里面的每一条技术细节。你只需要在后续使用中发现问题时，告诉AI：“上次你用XX方案出问题了，以后别用了，换YY方案”，AI会自动更新CLAUDE.md。

CLAUDE.md的核心玩法就是“持续迭代”：

1. 先让AI生成基础版
2. 用一段时间，AI犯错，你纠正
3. 把纠正加进CLAUDE.md（或让AI自己写进去）
4. AI后面就不会再犯同样的错

这就跟带新人一样——先给一份工作手册，他犯错就把手册补全，时间越久他越靠谱。

### 4.6 理解AI的“记忆”——上下文管理

Claude Code有“短期记忆”，叫上下文。就像你的办公桌——桌面就那么大，堆太多东西就会开始“找不到”早先放的文件。

核心规则：**60%法则**。上下文占用超过60%后，AI的表现会明显下滑——忘掉早期对话里的约束、重复做过的操作、生成跟前面对不上的代码。

**什么时候该开新对话**：

- 从功能A切到功能B
- 感觉AI开始“断片”
- 单次对话超过30轮

两个关键命令：

- `/compact`——压缩对话，保留关键信息，释放空间（同一任务继续时用）
- `/clear`——直接清空对话，从头再来（切新任务时用）

优先用`/compact`，实在不行再`/clear`。

## 五、三件套怎么配合：一个人顶一个技术团队

三件套已装好，CLAUDE.md已配好。现在讲它们怎么协同作战。

### 5.1 三件套各管什么

#### GSD（项目管家）——管“做什么”“什么时候做”“做了多少”

GSD把大项目拆成小阶段，每阶段有目标、有验收标准。你完成一步，它自动推进下一步。最关键的是——它把所有状态都存在.planning/目录里。也就是说，你今天做到一半关机走人，明天打开还能继续，进度不丢。

GSD的5步流水线：

纯文本

spec（需求）→ discuss（讨论）→ plan（计划）→ execute（执行）→ verify（验证）

#### gstack（专家团队）——管“做得好不好”“有没有漏掉什么”

gstack像一个外部顾问团，里面有不同的角色：

| 角色 | 命令 | 干什么 |
|------|------|--------|
| CEO顾问 | /office-hours | 帮你想清方向，追问你没想到的问题 |
| 代码审查员 | /review | 检查代码质量、安全隐患、合规性 |
| QA测试员 | /qa | 用真实浏览器跑测试，截图给你看 |
| 安全官 | /cso | OWASP + STRIDE模型全面安全审计 |
| 发布经理 | /ship | 部署前最后检查，一键发布 |
