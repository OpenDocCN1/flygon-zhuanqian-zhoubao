# 从小白到上手：AI 产品怎么一步步做出来？

最近整理了不少 AI 产品相关的实战干货，发现孙志岗（AI 师傅创始人）分享的这套从零起步做 AI 产品的方法，特别适合想自己动手试试的朋友。这里把它重新梳理一遍，结合我自己的理解，希望对你有所启发。

---

## 一、产品设计：不是一上来就写代码

很多人一拍脑袋就说“我要做个 AI 产品”，然后直接开写——这个顺序其实是反的。正经的做法是先把三件事想清楚：

- **功能**：这个产品到底干什么？
- **信息架构**：这些功能怎么摆？
- **交互**：用户用起来顺不顺手？

如果你对视觉效果有执念，还得单独做视觉设计；不讲究的话，套个模板也能凑合。

对独立开发者来说，这三件事不是先后顺序，而是交织在一起反复调整的。但最开始怎么动手呢？答案是：**抄**。

不过“抄”也有优雅的姿势：

1. **先自己设计一遍，再去看别人怎么做的**——这样你至少有自己的判断力，不会盲目跟风；
2. **学结构和交互，别抄视觉**——像素级复刻别人的界面，是会被人笑话的；
3. **取各家之长，做整合和抽象**——这意味着你有机会跳出别人的思路，重新开始。

还有一个避坑提醒：看到别人的设计，用“5 个为什么”推演一下对方为什么这么做。如果找不到合理的解释，那最好别轻易抄，不然容易踩坑。

---

## 二、写 PRD：不是为了给别人看

不管你多不喜欢写文档，PRD（产品需求文档）一定要写。原因很简单：

- 写的过程本身就是帮你理清思路，哪怕写完了没人看，也比不写强；
- 飞书有一套特别趁手的 PRD 模板，直接填就行，省心省力；
- 也可以让 ChatGPT 帮你找灵感和框架，常规功能它写得还挺像样的。

## 三、AI 产品设计原则：先把这些记在心里

### GitHub Copilot 的四个支柱

GitHub Copilot 可以说是目前最成功的 AI 垂类产品之一。它的团队总结过四个关键点，值得每个做 AI 产品的人认真看：

1. **可预测**：工具要引导用户达成目标，但不能让人困惑或措手不及。
2. **可容错**：AI 犯错是常态，用户要能轻松发现建议有误，并且低成本纠正，才能保持生产力。
3. **可操控**：当 AI 的回答不对路时，用户能引导它往正确的方向走，而不是干等一个完美答案。
4. **可验证**：输出必须容易被评估。模型不完美，但只要用户能验证结果，它就有大用。

### 七个实战经验

综合孙老师的教研经验、有赞 CEO 白鸦的分享，以及微软的 Collabrative UX 实践，有这么几条特别实在：

1. **永远别让 AI 直接生效**——人工确认这个步骤不能省；
2. **AI 幻觉永远都在**——所以要靠人来兜底；
3. **AI 可以代替操作和探索，别代替思考**——用户得知道自己想要什么；
4. **把 AI 当人看，把用户当老板**——只是老板不动脑子的话，也别怪 AI 不给力；
5. **尽量减少聊天框**——能做表单就用表单，准确又快捷，对话只当兜底方案；
6. **直接给结果**——用户没耐心，别让他等你展示思考链；
7. **明确标注这是 AI 生成的**——给用户“可能出错”的预期，也是一种免责和保护。

### 其他几个关键提醒

- **收集反馈**：有反馈才能迭代。像 ChatGPT 那样放 👍 👎 按钮，或者像 Copilot 那样采集用户有没有按 tab，都叫作“收集”。
- **尊重传统**：AI 不是来颠覆的，是来增强的。以前那套产品设计经验，全都可以继续用。

### UE/UX 方面的设计经验

这方面可以参考 shapeof.ai 上总结的几大类：识别、命名、向导、反馈、调节、控制、信任……说得直白一点：用户要能认得出哪些是 AI 功能，知道怎么用，也知道 AI 会犯错，还能随时调整和反馈，才敢放心用。

## 四、原型设计：别急着写代码

程序员最致命的习惯是：直接上代码。但实际上，代码写出来就会产生感情，后面的改起来心理负担大；画原型图反而能让你在整体和具象之间自由切换，不容易陷进去。

独立开发的流程建议是：

- 画个线框图就够了，不用太精细；
- 细节直接在代码里调，更快更准；
- 除非你直接用 AI 生成原型图，那就另说了。

### AI 原型工具推荐

1. **Motiff（妙多）**：国产全能型设计工具，AI 生成 UI、布局、组件识别都行，魔法框很懂你想要什么。
2. **Galileo AI**：支持文字转 UI、图片转 UI，设计精美，还可以继续用 prompt 调整，能直接导出到 Figma。
3. **v0**：Vercel 出的，支持文生 UI 和图生 UI，直接生成 React 代码，细节控制比 Galileo 更强。

建议流程：要么只用 Motiff，要么用 Galileo 出图后再丢给 v0 做细节打磨。

### 传统工具也别丢掉

- **draw.io**：免费开源，对程序员极度友好，改 style 超级顺手，画架构图有一绝。
- **Figma**：专业玩家必备，协作强、插件多、还能生成样式代码，唯一缺点是学习门槛高一点。

顺带推荐一本书：《写给大家看的设计书（第 4 版）》，做 UI 设计的人值得翻一翻。

## 五、快速搭 demo：用 Gradio 就够了

现在的 AI 工具发展很快，未来也许 PRD 直接变成产品也不是梦（MetaGPT、Devin 都在路上）。但对现在的独立开发者来说，**Gradio** 是搭 demo 的最快路径：

- 纯 Python 就能写出功能完整的 Web 界面，不用碰 JS 和 CSS；
- 响应式设计，手机电脑都能用；
- 文档全、样例多、上手快。

Chatbot Arena、Stable Diffusion WebUI 这些知名项目，都是拿 Gradio 做的界面。它内部组件非常丰富：图片编辑、语音、表格、3D 模型、进度条……基本你要的都全。布局就是 tab、row、column 三件套，简单直接。

---

## 六、迭代：克制是美德

最后一条最关键：**别老加功能，守住小而美**。

- 用高频迭代证明自己勤奋，不如把运营做扎实；
- 第一版只做主路径功能，但细节体验不能丢；
- 用 KANO 模型找提升核心用户满意度的功能；
- 非核心用户骂你，别在意；
- 核心用户画像别轻易变，真想变，不如做个新产品。

---

**以上就是老余整理的 AI 产品从 0 到 1 的实操路径。** 从产品设计、PRD 写作，到原型工具选择和迭代策略，其实核心就一句话：**思路比技术更重要，克制比堆功能更像高手。**

如果你想动手做一个自己的 AI 产品，希望这份总结能帮你少走一些弯路。
