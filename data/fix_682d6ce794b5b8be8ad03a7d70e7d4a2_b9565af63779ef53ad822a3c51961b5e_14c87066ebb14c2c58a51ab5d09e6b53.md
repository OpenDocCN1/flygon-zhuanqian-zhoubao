## 先教会它读你的飞书资料库

最爽的是这一步。你不用翻命令行文档，不用拼参数，也不用研究底层数据结构。直接把飞书链接丢给 Codex，例如：请读取这篇飞书 wiki，链接是 https://你的飞书链接。帮我做四件事：
1. 总结这篇文档现在在讲什么
2. 找出结构混乱、重复表达和空标题
3. 提出一个更适合继续扩写的结构
4. 先不要改，等我确认

本质上，Codex 在背后替你完成了本来要手动做的 CLI 调用，而你感受到的只是自然语言。我建议一开始别把权限放得太猛。先让它读，再让它提方案，最后再让它动手。比如方案确认后，可以继续说：按照你刚才的整理方案，直接帮我更新这篇飞书 wiki。要求：
1. 不要编造新信息
2. 保留原意
3. 涉及大段改写就分块处理
4. 改完后告诉我改了哪些地方

这一步一旦跑通，你对个人笔记库的体验会完全不同。以前你是编辑、排版工、整理员，现在你只负责判断，AI 负责执行。这个角色切换太关键了。

这套体系里，三个角色分工很明确。
- **底层**：飞书。负责承载你的笔记、消息流、表格、文档和日常信息输入。
- **中间层**：飞书开源 CLI。负责把飞书能力封装成 AI 能稳定调用的接口，说白了就是 Codex 的手。
- **顶层**：Codex 桌面端。负责理解你的意图、拆解任务、调用工具、执行流程、汇总结果。

#### 在飞书对话框里直接指挥 Codex

上面这些操作，你都不需要坐在电脑前手动发指令，在飞书对话框里就能直接指挥。具体来说：你在手机上发一句话，本地进程收到飞书事件，调用 `codex exec` 执行，再把结果自动回复到飞书线程。这个味道完全不同。它已经不是一个孤立工具，而是一套在后台持续运转的小型工作流。

对新手可以这样理解，整套系统分 4 层：
1. 飞书里有一个 bot
2. 本机的 lark-cli 负责收飞书事件、回飞书消息
3. 本机的 Codex 负责真正执行任务
4. 一个常驻 Python 守护进程把 2 和 3 串起来

**第一次使用时，把这段提示词发给 Codex：**请帮我在这台 Mac 上搭一个“飞书对话框里直接指挥 Codex”的本地工作流。我是小白，请你不要只讲思路，直接帮我检查环境、创建文件、配置后台服务，并在每一步告诉我需要我点击或确认什么。目标是：我在飞书里给一个 bot 发消息 -> 本机后台进程收到飞书消息事件 -> 本机自动调用 codex exec 执行任务 -> 执行结果自动回复到原飞书线程 -> 整套流程配置成后台常驻，电脑开着就能用。**请按这个顺序完成：**检查这台电脑有没有安装 Python、Codex CLI、lark-cli；如果缺东西，告诉我最简单的安装方式；引导我在飞书开放平台创建一个 bot 应用；告诉我这个应用要开哪些权限、订阅哪个事件；帮我完成 lark-cli 配置和授权；帮我生成本地桥接脚本，要求只允许我本人触发；帮我生成 launchd 配置，让它在 macOS 后台常驻；帮我做最小测试，比如 /codex ping；如果测试失败，继续排查，不要停在分析；最后把我在飞书里能用的指令写成一份简短说明给我。

注意：我是新手，不要默认我会命令行。需要我手动点网页、登录、授权的时候再叫我，其他能自动做的你都直接做，不要只给教程，直接在本机帮我搭好，然后等着 AI 干活就行。

##### 把 Codex 机器人接入群聊

下面按飞书当前常见中文界面整理，个别按钮名若有细微差异，通常都在同一位置。

官方入口：

- [飞书管理后台](https://open.feishu.cn/)

参考官方说明：
- [认识与配置飞书集成（飞书官方）](https://open.feishu.cn/)

###### 一、创建飞书机器人应用

1. 打开 [开发者后台](https://open.feishu.cn/)，用飞书账号登录。
2. 点 **创建企业自建应用**。
3. 填应用名称，建议写“Codex助手”或“我的Codex机器人”，方便在群里识别。

###### 二、给应用开通机器人能力

4. 上传头像，填一句应用描述，例如：在飞书里一句话触发本地 Codex 执行任务并自动回复结果。
5. 点 **创建**。
6. 进入刚创建的应用后台，在左侧找类似 **添加应用能力**、**能力**、**机器人** 的区域。
7. 打开 **机器人** 能力。如果看到欢迎语、消息卡片、可见范围等配置，先保持默认，跑通后再调。

###### 三、开通权限

这步是关键。没权限的话，机器人即使进了群也收不到消息、回不了消息。

8. 打开左侧 **权限管理** 或 **权限配置**，搜索并开通和 IM 消息相关的权限。对“飞书里一句话触发 Codex”场景，优先开：
- `im:message:send_as_bot`
- `im:message:readonly`
- `im:message.group_at_msg:readonly`
- `im:message.p2p_msg:readonly`
- `im:chat:read`

以后想收图片、文件、语音，再补：
- `im:resource`
- `im:message.reactions:read`

开完点页面上的 **申请权限**、**批量开通** 或同类按钮。

###### 四、订阅事件

这一步是让飞书把新消息推给本地进程。

9. 打开左侧“事件订阅”，搜索并添加：`im.message.receive_v1`。如果界面要求填“请求网址”或“回调地址”，分两种情况：
- 走 lark-cli 的本地事件消费方式，通常本地工具会接管，不需要你手填公网回调。
- 走传统 webhook 回调，就需要填一个外网可访问的回调地址。
你现在这套“本地收到事件 -> 调 Codex”方案，本质就是让消息事件能被订阅成功。

###### 五、发布应用

很多小白会漏掉这一步。不发布，前面的权限和能力经常不生效。

10. 打开左侧“版本管理与发布”，点“创建版本”，填版本号（如 1.0.0），填发布说明（如：开通机器人消息接收与回复能力），按提示继续。如果提示有权限待申请，先补齐。提交发布。企业内应用通常还要把可用范围设给自己或测试成员。

###### 六、把机器人加进群聊

这一步在飞书聊天界面操作。

打开飞书，新建一个测试群，建议只拉自己或 1 到 2 个测试成员，别一上来进正式群。进入群聊右上角 ... 或 **群设置**，找 **群机器人**、**机器人**、**应用**、**添加机器人** 入口。在机器人列表里搜刚创建的应用名，点 **添加**。如果提示确认权限或使用范围，点确认。添加成功后，群里会看到机器人加入提示。

###### 七、测试能不能触发

先在群里 @机器人，发一条最简单的消息，例如：`@Codex 助手 /codex ping`。私聊机器人就直接发：`/codex ping`。正常情况下，本地进程收到事件后会把结果回复到该线程。

###### 八、常见卡点

1. 只创建了应用，但没开机器人能力。
2. 开了权限，但没发布版本。
3. 发布了应用，但没把机器人加进群。
4. 机器人在群里，但没开消息接收相关权限。
5. 私聊能收、群聊收不到，通常是群 @ 权限没开。
6. 群里能触发但回复失败，通常是 send_as_bot 权限没开，或可用范围没放通。

###### 九、一句话总结

先去飞书开放平台创建“企业自建应用”，开启机器人能力，开通消息读取和机器人发消息权限，订阅 `im.message.receive_v1` 事件，创建版本并发布。然后回到飞书聊天界面，新建测试群，在群设置里把机器人添加进来。完成后再让 Codex 接上本地执行链路。
