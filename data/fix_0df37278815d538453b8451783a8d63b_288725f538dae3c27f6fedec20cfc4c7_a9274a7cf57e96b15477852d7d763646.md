## 实际对话与调试路径

模型选用 GPT-4，执行环境是 PyCharm 搭配 Anaconda。明确的需求是：抓取 CoinMarketCap 首页的代币全称、简称、详情页链接，并写入 Mac 桌面新建的 `new.xlsx`，同名文件先删除。

首版对话信息量过大，我重新开了一轮更聚焦的对话，核心提示大致如下：

- 请扮演专业 Python 开发者，协助抓取指定站点
- 我会提供网址与字段清单
- 网址：https://coinmarketcap.com/，字段：代币名称、代币简称、详情链接。以 Bitcoin/BTC、Ethereum/ETH、Tether/USDT 为例
- 已装 requests、beautifulsoup4、openpyxl，出现错误请先诊断再改代码
- 只抓到后 90 条，前 10 条缺失，且简称为空，请分析并修复
- 页面明明有 100 条，为何只出 10 条
- 后续改走详情页提取策略，提供新的 class 结构请求更新代码
- 需要加入防频繁请求与更真实的请求头模拟
- 只需 1-91 页的数据

整个过程大量试错，简化版对话记录放在 2.2 末尾。

## 过程中踩到的坑

### 环境与依赖
起初在系统终端安装依赖失败，后经提示在 PyCharm 自带终端中安装才成功。目录问题耗掉不少时间。

### Class 定位是最大耗时项
脚本能跑，但字段总是对不上。要么只有二级链接和全名，要么简称抓不到。最终发现是 Class 的“标签名 + 属性值”两者必须同时精确。

普通页面里 class 前面常是 div，但目标元素标签并不固定；属性值也必须逐字符核对。这个认知盲区占了我近四分之三的调试时间。最后做法很笨：把浏览器 Elements 面板里整行代码复制给模型，让它自行解析，再据此改写选择器，才拿到正确名称与简称。

### 列表页无法全量
一度以为快结束了，结果首页 100 条只拿到后 90 条，前 10 条始终缺失。反复排查无果后，改用逐个详情页提取的方案，重新获取详情页的 class 信息后，整页数据才完整。

### 反爬与保存策略
抓多页后频繁触发请求限制。加入 1-3 秒随机休眠、动态请求头后有所缓解，但并未根治。另一次在第 6 页时报错，已抓数据全部丢失。随后改为“逐页写入单独 sheet”的方式，确保中途中断也能保留成果。

## 需求归纳

V1 版的最终总结更清晰：

需爬取 CoinMarketCap 前 90 页的加密资产数据：全名、简称、详情页 URL。关键 class 特征：

- 详情页全名标签 class 为 "sc-1d5226ca-1"
- 详情页简称标签 class 为 "nameSymbol"
- 列表页名称链接 class 为 "cmc-link"，href 拼接主域名即为完整 URL

执行要求：逐页写入桌面 `new.xlsx` 的不同 sheet；每页成功打印提示；请求前刷新 User-Agent；详情页请求间隔 1-3 秒；出错时保存已有数据并输出信息；禁用已废弃的 .append 方法。

---

## 复盘要点

1. 采用最小单元验证思路：先单元素、后多元素，再到整页、多页
2. 报错时让模型先做原因分析，后续提示会更精准
3. 很多失败点不在模型，而在环境、网络与定位细节
4. 仍未解决的问题：列表页直接全量提取、彻底规避请求频率限制
