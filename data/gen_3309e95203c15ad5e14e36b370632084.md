如果你手上刚好有本次文档里提到的那3份测试材料，直接复制上文的任务指令就能用来跑测试。

先把前面整理好的3份资料通读一遍，再来完成下面这个真实任务：【填写你想解决的问题或希望得到的具体输出】注意点如下：

1. 回答只能基于当前资料和能明确核实的事实。
2. 必须列出参考的文件名或相对路径。
3. 要把资料本身的信息、你的归纳总结、以及AI的推断三者区分开来。
4. 资料不足就直接说明缺什么，不要自己编造事实。
5. 先在对话里给出结果，不要直接写进知识库。

如果结果符合预期，可以继续说：

【要输入具体的目录，没有目标目录可以输入“帮我创建用于XX的目录，目录结构按你的建议来”。】

请把刚才确认好的结果保存成一份新的 Markdown 文档，放进【目标目录】。保留参考文件清单，保存完后检查文件是否真的创建成功。

第一次闭环的完整链路是：

资料进入→ Codex 提出整理方案→ 用户确认→ 文件整理完成→ 基于资料完成真实任务→ 结果沉淀回知识库

# 成果展示

展示时只聚焦三点：

1. 我到底要解决什么问题。
2. 我的最小知识库结构长什么样。
3. Codex 依据资料完成了什么真实产出。

现场做到这一步，闭环就算完成，后续就不用每次都重复搭建流程。日常维护知识库时，直接告诉 Codex 需要做什么就行。

# 从首次操作到日常使用

完成现场这轮操作后，知识库才算真正开始日常运转。我后面用得最多的四类任务，都是下面这几句口语化指令。

## 第二部分：日常管理｜四句口令管知识库

日常只要说清楚任务目标、资料范围和边界条件；AGENTS.md 和已验证的流程会负责其余约束。

**1. 帮我整理知识库／帮我整理新增资料**

帮我整理新增资料。先自检并给出执行方案；涉及新增分类、迁移、改名、覆盖或修改原文时，全部等我确认后再动手。

**2. 帮我创建项目**

帮【项目名称】建个项目。先核查是否已有同名或功能重叠的项目，再给出项目目录、目标、交付物和 PROGRESS.md 的草案。确认后再创建。

**3. 帮我检查哪些文档需要更新**

只读扫描知识库，找出需要更新的文档。重点看 README.md、AGENTS.md、已有文件目录.md、各项目 PROGRESS.md，以及内容与现状不符的文件。先列出原因和修改建议，不要直接改。

**4. 帮我基于 XX 资料输出 XX 内容**

请阅读【资料范围】，基于这些资料产出【目标内容】。列出参考文件名或相对路径，区分资料原文、归纳结论和 AI 推断。资料不够就说明缺口，不要虚构。先在对话里输出，确认后再保存。

### 高频口语化表达

| 场景 | 可以这样说 |
|------|-----------|
| 格式规范 | 帮我把这些文档的格式统一一下，原文内容不要动 |
| 剪藏整理 | 把网页剪藏入口里的文章整理一下，分类不确定先问我 |
| 继续项目 | 先读项目 PROGRESS.md，再继续推进，完成后更新进度 |
| 学习复盘 | 读相关资料，总结现在掌握的程度和下一步行动建议 |
| 知识问答 | 按指定资料回答问题，列出参考文件，资料不足要明确说明 |
| 执行方案 | 可以，按刚才确认的方案执行，完成后自检 |

# 第三部分：进阶可选

等真实需求出来再扩展

日常任务稳定使用一段时间后，再考虑备份、项目和 Skills。以下内容可按需选择，第一次搭建不必全部完成。

## 完善个人知识库

### 隐私与数据边界

“本地知识库”指原始文件存放在自己的电脑上，不等于 AI 处理过程完全离线。Codex 读取资料并作答时，其内容仍受当前账号、套餐、数据控制策略和组织规则约束。

开始前要留意：

- 核查 ChatGPT 的数据控制设置和组织管理要求。
- 知识库中不要存放密码、API Key、验证码、恢复码等访问凭证。
- 身份证、财务、医疗、合同、客户资料只提供完成任务所需的最小范围。
- 对外分享或生成平台副本前再次审视隐私。

### 输出更完整的个性化方案

现场最小闭环跑通的人，可以继续补充真实需求：

请只读检查当前知识库，不要修改文件。请先了解：

1. 我搭建知识库的长期目标，以及希望得到的输出类型。
2. 我常保存哪些资料，资料来源有哪些。
3. 我已有的文件、目录和正在推进的项目。
4. 我对命名、分类数量、操作确认、隐私保护和协作方式的偏好。

随后结合实际文件，输出完整修订方案，包含：

- 推荐目录及每个目录的必要性
- 资料进入、整理、使用、产出、归档的流向
- README.md 和 AGENTS.md 的调整建议
- 是否需要文件目录.md
- 只有长期项目才考虑 PROGRESS.md
- 现有资料的迁移方式
- 日常管理方式
- 执行顺序、确认节点和验收标准

先少后多，不要为完整而创建暂时无用分类。现在只输出方案，不操作文件。

Codex 给出方案后，需要用户确认：

- 目录名称是否易懂
- 分类是否存在重叠
- 每个目录是否有真实资料来源或用途
- 文件移动、原文保护、备份和隐私边界是否可接受
- 执行顺序和完成标准是否清晰

### 何时需要文件目录.md

文件目录.md 不是首次搭建的必选项。

满足以下任一情况再生成：

- 文件量明显增多
- 资料分散多级目录，经常找不到
- 需要一个可快速检索文件名、类型、路径的索引
- 需要核查资料是否已归档或有重复

请只读扫描实际文件，按真实文件生成文件目录.md，至少包含：

- 文件名
- 资料类型
- 当前目录
- 相对路径
- 更新时间

要求：

1. 实际文件系统是唯一事实来源
2. 文件目录.md 可重新生成
3. 不依据旧索引移动文件
4. 不记录对外分享时不应公开的完整本地路径
5. 现在只创建或重建索引，不移动、删除或修改正文

若索引与实际文件不一致，应重新扫描实际文件，而不是按旧索引调整文件。

### 备份与高风险操作

首次低风险测试请用资料副本。

以下操作前必须先在知识库外建立可恢复副本：

- 批量移动或重命名
- 删除或覆盖文件
- 目录重构
- 大规模正文修改
- 导入大量唯一原件

备份后至少核对文件数量，并随机打开重要文档或附件。同步盘主要解决同步，不可作为唯一备份。

### 格式整理与原文保护

Codex 默认可直接处理：

- 多余空行和空格行
- 行尾空格和不可见字符
- 导入产生的重复首标题
- 空标题
- 明显断裂的序号和项目符号
- 列表项间不必要的空行

Codex 默认不可直接处理：

- 改写或润色正文
- 删除看似重复但可能有意义的段落
- 调整观点顺序
- 改变标题层级所表达的含义
- 用摘要替代原文

若无法区分格式修复还是内容修改，一律先询问用户。

### 完整基础验收

现场4项清单完成后，可课后做更全面检查：

- Obsidian 能正常打开知识库
- Codex 已只读验证知识库路径与实际文件
- 目录源于真实目标或最小化方案
- README.md 与实际目录和资料流向一致
- AGENTS.md 精简，并包含确认、原文保护、同名检查和自检规则
- 若创建了文件目录.md，与实际文件一致且可重建
- 高风险操作前有库外可恢复备份
- 敏感信息检查不复述具体值
- 首批资料完成先方案、确认后执行
- 同名文件未被自动覆盖或合并
- 格式整理未改写原文
- 已完成一次带来源的真实问答或内容输出
- 长期项目有 PROGRESS.md

请只读检查当前知识库是否完成从0到1的基础搭建。用表格输出：

- 检查项
- 状态
- 实际证据
- 需要修正的内容

只检查当前实际存在的基础功能，不要把网页剪藏、项目管理、第三方平台、Skills 和总控流程作为通过条件。现在只检查，不修改文件。

### 建立项目管理

满足任一条件就适合建项目：

- 有明确目标和交付物
- 需要跨多次对话推进
- 有重要决策和下一步需记录
- 相关资料会持续累积

请在知识库中为【项目名称】建立项目目录和 PROGRESS.md。PROGRESS.md 包含：

- 项目目标
- 当前状态
- 已完成
- 最近决策
- 下一步
- 待确认问题

要求：

1. 先检查是否已有同名或用途重叠项目
2. 若存在重叠，先汇报现状、差异和建议，确认后再创建
3. 不编造已完成事项
4. 创建后检查 README.md 是否需更新
5. 若已使用文件目录.md，按实际文件更新索引
6. 最后检查项目目录、PROGRESS.md 和相关说明是否一致

后续继续项目时可说：

请先读取【项目路径】中的 PROGRESS.md，再继续推进【本次任务】。完成后更新进度并自检。

## Skills 与总控流程

### Skills 源于重复任务

我的4个 Skills 也是知识库投入使用后才做的。先让真实任务重复出现，再把稳定步骤沉淀为 Skill，更容易判断职责，也更容易验收。

先理解三个概念：

| 名称 | 常见理解 | 举例 |
|------|---------|------|
| AGENTS.md | 知识库长期遵守的精简规则 | 不擅自删除文件、保护原文 |
| Skill | 一项重复工作的固定步骤 | 资料分类、格式整理、项目进度更新 |
| 总控流程 | 根据任务选择并组合合适的 Skills | 收到整理任务后依次分类、整理和自检 |

Skill 是 Codex 可识别的可复用工作流。

项目级 Skill 存放于：

.agents/skills/【Skill 名称】/SKILL.md

每个 SKILL.md 至少包含 name 和 description，且只负责一类明确任务。

本手册中的：

.agents/knowledgebase-manager-agent.md

是作者使用的本地总控流程文件，并非平台自动注册的 Agent。它需用户发起任务，并由 AGENTS.md 指示 Codex 读取后才会工作。

### 何时创建

先正常使用知识库。当一项操作重复3次以上，且步骤和判断已稳定，再考虑做成 Skill。

请读取当前知识库的 AGENTS.md、README.md、已有项目 PROGRESS.md，以及可查阅的知识库管理记录。找出有证据表明重复3次以上、步骤和判断已稳定的操作。输出完整 Skills 和总控流程方案，包含：

1. 适合做成 Skill 的操作及重复证据
2. 证据不足暂不适合的事项
3. 每个候选 Skill：负责什么、不负责什么、触发条件、建议名称、保存路径、SKILL.md 中的 name 和 description、核心步骤和安全边界
4. 可由总控流程组合调用的 Skills
5. 是否需要总控流程文件及建议路径
6. 根目录 AGENTS.md 需要增加或调整的路由规则
7. 计划创建和修改的完整文件清单
8. 创建后的低风险测试方法和验收标准

项目级 Skill 默认规划到：

.agents/skills/【Skill 名称】/SKILL.md

总控流程如需，默认规划到：

.agents/knowledgebase-manager-agent.md

以上路径和结构须作为方案的一部分供确认。证据不足时明确标注“证据不足”，不自行假设。现在只输出完整方案，不创建或修改文件，待确认。

### 确认后创建

我确认使用刚才最终确认的 Skills 和总控流程方案，请按确认内容执行。执行前：

1. 检查计划中的目标目录和文件是否存在
2. 如存在同名 Skill、总控流程或 AGENTS.md 路由冲突，立即停止并报告差异，不覆盖或自动合并
3. 再次核对准备创建和修改的文件是否都在确认方案中展示

确认无冲突后：

1. 只创建确认方案中选定的 Skills
2. 按确认方案的名称、路径、name、description、职责、触发条件和安全边界写入 SKILL.md
3. 按需创建总控流程文件
4. 只按确认方案修改根目录 AGENTS.md 的启动和路由规则，不复制全部 Skill 细节
5. 不自行增删合并未经确认的 Skills
6. 未经授权且无固定规则覆盖时，删除、移动、重命名、目录调整和正文修改仍需先确认
7. 创建后只检查：文件路径和名称、YAML 元数据、Skill 职责与触发条件、总控流程引用、AGENTS.md 路由
8. 本次不自动运行真实知识库整理任务

完成后告知实际创建和修改的文件、自检结果，以及建议使用的低风险测试任务。

第一次测试使用少量资料，并明确说：

请使用 knowledgebase-manager-agent 帮我整理新增资料。先检查并给方案，不要直接执行高风险操作。

若 Skill 未出现在 Codex 中，先检查路径和 SKILL.md 元数据，再刷新或重启 Codex。

# 六、结尾

## 这套方法的工作顺序

该方法通过以下管理链路持续运转：

按真实用途设计→ 从3份资料起步→ Codex 先给方案→ 用户确认后执行→ 基于资料完成真实任务→ 结果沉淀→ 流程稳定后再做成 Skill 和总控。先完成可用最小闭环，再按真实需求逐步升级。

## 手册本身的协作过程

本实操手册由 Codex 基于搭建过程对话总结 + Obsidian 沉淀的过程记录，输出方案和初稿，我负责核查事实、步骤和表达并给出修改意见，Codex 按意见迭代，每次调整后还需检查手册、PPT 和相关文件版本是否一致。

现在可准备3份非敏感资料，先完成首次整理和使用，再选一个真实需要解决的问题，确认当前版本已能帮到你，再决定下一步新增哪些目录和功能。
