那一刻我才意识到，这些看似普通的方法，其实对别人有真实价值。也谢谢这些反馈，让我下决心写出更完整的版本。

很多人缺的并不是更多智能工具，而是一条能长期走通的路：今天保存的内容，明天还找得到；找到之后，能变成自己的观点；写公众号、做短视频、发朋友圈、提方案时，还能再次拿出来用。我过去的状态也很典型：客户沟通留在微信，收藏文章堆在手机，网页停在浏览器，长文躺在飞书，零碎笔记散在文件夹。每个角落都有资料，可真正要动笔时，还是只能从头想。

所以我才动手搭这套机制，不是为了把工具全装一遍，而是想解决三个实际的问题：

1. 遇到有价值的内容，能不能用最短的路径先收下来？
2. 收下之后，能不能继续被加工，而不是进了收藏夹就结束？
3. 加工完成的成果，能不能顺利流到真正发布和交付的地方？

## 二、一句话分工：IMA 收集，Obsidian 提炼，飞书共享，Codex 调度

我后来给四个工具划了很清楚的边界。

- IMA 负责“收集”。它适合手机和微信场景，看到内容随手一存，之后也能基于已存内容提问。
- Obsidian 负责“提炼”。它本质上是一个本地 Markdown 文件夹，适合长期保存、拆分观点、建立双链、沉淀自己的方法。
- 飞书负责“共享”。需要排版、评论、协作、交付，或者要发给别人阅读时，我会把成品放到飞书。
- Codex 负责“调度”。它连接这些入口和仓库，帮我完成读取、整理、拆分、写入、同步，以及最后的目标端验收。

如果只记一张流程，可以这样看：手机上存下的内容、聊天中的记录、浏览器里的网页、旧文稿 → 先进 IMA 或 Obsidian 的 Inbox → Codex 读取并拆解 → 进入 Obsidian 的 Notes 或 Archive → 再到 IMA、飞书 → 最后流向公众号、短视频、朋友圈、课程或方案。

这四个工具并不是非齐不可。第一次搭建时，甚至不需要全部部署。你只要有三样东西：采集端、加工点、输出口，就能先运转起来。

## 三、别急着做自动化，先让一条内容完整走通

我特别想提醒新手：先手动跑通一篇，再谈自动化。我第一次测试时只选了一篇文章，完整步骤如下：

1. 用手机把文章分享到 IMA；
2. 回到 IMA，确认全文能正常打开；
3. 请 Codex 取出这篇内容，放进 Obsidian；
4. 在 Obsidian 里检查标题、正文开头和结尾、来源链接、图片或附件说明；
5. 让 Codex 从原文中抽出一条可以独立使用的观点；
6. 用这个观点写一条朋友圈，或写一段短视频开场白；
7. 把成品放到飞书，再重新打开检查。

走完这七步，我才认为这条链路真的通了。以前我很容易被“接口返回成功”骗过去。后来发现，创建成功可能只是多了一篇云文档，文档不一定进了目标库；同步成功可能只是一个需要登录的空链接；文件虽然出现在 Obsidian 里，正文也可能少了一截。所以现在的验收标准很笨，但很好用：回到目标端重新搜索、打开、从头读到尾。能写进去是一回事，目标端能搜到、能打开、内容完整，是另一回事。不要一开始就追求全自动。

## 四、不同来源的内容，分别怎么接入

### 1. 手机上的内容：先进 IMA

【视频演示】手机浏览器里的内容如何保存到 IMA（25 秒）

手机场景最重要的就是快。看到一篇文章，如果总想着“等回到电脑再整理”，大概率就再也想不起来了。我的做法是：点分享，选 IMA，放进固定的“待整理”目录。保存以后，再在 IMA 里打开一下，能正常阅读才算真正收下。IMA 只是第一站。之后我会手动，或者在手机和电脑同时可用时，让 Codex 批量把内容取回 Obsidian。原始资料和加工结果分开存放。

### 2. 电脑网页和公众号文章：先看能不能完整保存

普通网页我习惯先用 Obsidian Web Clipper，这是 Obsidian 官方浏览器扩展，能把网页抓成本地 Markdown。但“生成了 Markdown 文件”并不等于“保存完整”。懒加载图片、复杂表格、轮播内容都可能丢。我的流程是：先把页面慢慢滚到底，再执行剪藏，随后检查正文开头、结尾、图片和原链接。即使这样，有些页面还是抓不全。

遇到公众号长文或复杂图文，如果 Web Clipper 效果不理想，我会删掉，改用飞书剪存再试一次。飞书在保留排版和后续协作上更有优势。选择标准不是哪个工具听起来更高级，而是哪个能把这篇文章完整留下。长期用下来我发现，IMA 在某些场景里更稳，因为它保存的是链接而不是剪藏，所以正文不容易丢。

如果要做固定公众号的监控，我才会加自动化：WeRSS 提供内容源，本地脚本负责检查和去重，飞书负责提醒和表格记录，Obsidian 保存正文，同时保留日志和授权失效提醒。一开始不要监控几十个号，先拿 1 到 3 个号测试。

详细操作见：【取公众号】公众号文章监控工作流教程：可复刻执行版

### 3. 历史微信聊天记录：直接读本地 Vault

这一部分可能是很多人的刚需。

【视频演示】在手机微信发出指令，Hermes 调用本机 Vault，再由 Codex 整理结果。

电脑端读取微信 Mac 4.x 历史数据，我使用的是 yichen-wechat-local-vault。它负责维护本机已经解密的 Vault，Codex 再按明确的群聊、联系人、关键词和时间范围查询。和旧版 wechat-cli 相比，它还能读取语音和朋友圈，不需要降低微信版本，也不用安装重签名版微信。

电脑端的链路很直接：微信本地数据 → yichen-wechat-local-vault → Codex → Obsidian 或飞书。只有想从手机微信里远程下指令时，我会在前面加 Hermes：手机微信指令 → Hermes → 同一个本地 Vault → Codex → 返回结果。

这里要分清三个角色：Hermes 是消息入口和调度层，不是历史数据库；Codex 是理解和执行的大脑，也不会凭空拥有微信记录。分清楚以后，排错会简单很多。

基于本机微信聊天记录，还能生成「社群活跃统计罗盘」。

### 4. 自己写过的文档：直接放进 Obsidian

Word、Markdown、飞书旧文档，以及以前写过的长文，不需要再绕一圈收藏。我会先确定哪一份是原稿，放进 Obsidian 对应目录，保留来源和日期，再让 Codex 做格式统一、拆分、归类。Codex 本身能理解 Obsidian 的 Markdown、双链、标签和 frontmatter，做这类整理很合适。

## 实操手册｜在自己的电脑上跑通这套流程

下面不是要求你一次装完所有组件。先选一条路线，把一篇真实内容从源头送到出口。电脑端微信能查通以后，再加 Hermes。每完成一步，都要回到目标端重新搜索和读取。

### 2. 正确的安装顺序：先基础，再加入口

1. 先装 Codex 和 Obsidian。让 Codex 能看到一个确定的 Vault 路径，完成一次写入和读回。
2. 再选内容入口。手机端用 IMA；电脑网页可同时试用 Web Clipper、IMA、飞书剪存，实际感受差异。
3. 需要微信历史数据时，再装一尘 Skill。先验证本地 Vault，再做限定范围查询。
4. 需要手机微信远程指挥时，才加 Hermes。先测试普通对话和 PONG，再调用一尘 Skill。

### 3. 第一步：让 Codex 连接 Obsidian

Codex 不是一定要通过 Obsidian MCP 才能读 Obsidian。Vault 本质上就是本地文件夹。把文件夹添加为工作目录，然后把下面的提示词发给 Codex：

这是我的 Obsidian Vault 路径：【粘贴绝对路径】。请先只读检查这个路径是否正确，不要扫描其他目录。确认无误后：

1. 保留现有结构，不覆盖已有文件；
2. 如果缺少，就创建 Inbox、Notes、Archive、Outputs 四个文件夹；
3. 在 Inbox 新建一篇“工作流验收测试”Markdown；
4. 写入标题、创建时间、来源和一句测试正文；
5. 重新读取这个文件，告诉我标题、路径、正文开头和结尾；
6. 不安装 Obsidian MCP，不删除、移动或批量改写任何旧笔记。只有“写入后重新读取完整”才算成功。

验收时要看到：文件出现在正确的 Vault，Obsidian 能打开，Codex 读回的标题和正文一致。详细安装说明可看《如何创建 Obsidian：从安装到第一个知识库》。

### 4. 手机内容进入 IMA，再让 Codex 读取

先去 IMA Agent Interface 手动申请 Client ID 和 API Key。然后把下面的提示词发给 Codex：

请安装并检查最新版 ima-skill，先确认 Node.js 版本满足要求。我会按你的提示在本机输入 IMA Client ID 和 API Key。请把凭证安全保存在本机私有配置目录：

- 目录权限 700；
- 凭证文件权限 600；
- 不在输出、日志、截图或 Git 中显示密钥。

配置后调用 IMA OpenAPI 的 list_note，做一次 limit=1 的只读鉴权验证。然后列出我能访问的 IMA 知识库名称，不做任何写入。最后告诉我：Skill 是否安装成功；鉴权是否成功；能否列出知识库；如果失败，失败发生在哪一步。

能列出知识库以后，再测试一篇真实内容：

请在 IMA 中按完整标题搜索【笔记标题】，只处理这一篇。读取正文后：

1. 保存原文到 Obsidian 的 Inbox；
2. 保留原标题、来源链接、IMA 笔记 ID 和同步时间；
3. 检查正文开头、结尾、链接和图片说明；
4. 写入后重新读取 Obsidian 文件；
5. 告诉我 IMA 端命中数量、Obsidian 文件路径和读回结果。

不要批量同步，不覆盖同名文件；发现同名时先停下来告诉我。

完整版参考《IMA 知识库与 Codex 打通教程》。

### 5. 把飞书接到 Codex

先在飞书开放平台创建企业自建应用，开通云文档和知识库权限并发布。拿到 App ID 和 App Secret 后，不要把 Secret 写进公共提示词。

请按 lark-cli 当前版本的内置 Skill 和 --help 完成飞书接入，不要照抄旧版命令。要求：

1. 从官方仓库安装或更新 lark-cli；
2. 引导我在本机完成应用配置，不在输出中显示 App Secret 或 token；
3. 发起 docs、drive、wiki 范围的用户授权；
4. 注意 auth login 本身不加 --as user，后续读取和写入 API 时才使用 --as user；
5. 验证用户授权状态；
6. 只读列出我能访问的飞书知识库。

到这里，这条内容流水线就算接起来了。接下来不是继续堆工具，而是拿一篇真实内容，从入口走到出口，反复核验。先跑通一次，再慢慢扩大边界。
