### 我想解决的到底是什么问题

我真正想解决的不是“怎么把抖音视频转成文字”。这太小了。

我真正关心的是：

每天冲浪捕捉到的信息，如何进入我的知识系统？进入之后，如何判断价值？有价值的信息该怎么变成内容素材、支持卡、SOP 备选或方法论备选？这些处理结果又如何反过来让知识库持续生长？

简而言之，就是把“刷到信息 → 保存原文 → 判断价值 → 分流复用 → 沉淀为长期资产”这一条线跑通。

你也会看到真实的踩坑：

这篇的价值不在于展示一个完美系统，而在于记录一个普通冲浪灵感，如何一步步长成可复用的个人知识库工作流。

## 开篇：我为什么要写这篇记录

最近两天，我做了一件很小却很有启发的实验：

先刷到一个能把抖音视频转成文字的 Skill，让 Codex 帮我装上。

第二天又刷到一条关于“Codex + Obsidian 搭建自生长知识库”的视频，恰好回答了前一天的疑问：转出来的文字该怎么用？

两条视频连起来，就成了一次真实的知识库工作流搭建实验。

起初我以为自己在装工具，后来才明白，核心是信息入口问题。

每天的信息流太多：抖音、公众号、小红书、网页文章、行业动态、投资观察、AI 案例……刷到的瞬间都觉得有用，可一旦只是收藏，最后基本都会沉睡。

我想要的不是存更多资料，而是让信息真正进入系统，并形成流程：

刷到 → 保存原文 → 判断价值 → 分流复用 → 生成内容、方法、SOP、项目动作或长期判断

这篇记录就是这个流程从想法到可跑通闭环的全过程。

## 背景：我的信息输入为何失控

我每天接触的信息来源很多。

抖音里有工具分享、流程拆解、AI 工作流案例。

公众号里有行业文章、成长心得、商业判断、运营复盘。

小红书里有热点选题、用户原话、场景反馈、对标案例。

网页文章里有教程、案例、报告、政策。

还有自己线下的灵感，会议中的突发观点、刷手机时的顿悟、做项目时的沉淀点。

过去的问题是：信息很容易停在“我觉得有用”的阶段。觉得重要就收藏，结果进入黑箱。过几天就忘了收藏了什么。

到要写文章、做项目、做复盘时，才会问自己：我是不是看过类似案例？视频在哪？文章怎么说的？我当时觉得有用，到底有哪点有用？

收藏只是缓解了怕丢的焦虑，并没有解决复用问题。

对我来说，知识库要解决的不是存储，而是复用。

一条内容进入知识库后，至少要回答：

它是什么？从哪来？对我有什么用？归哪套系统？能变成素材吗？能变成方法吗？有没有 SOP 潜力？会不会推动项目下一步？

没回答这些问题，资料只是从一个平台搬到另一个文件夹，并没有变成资产。

## 第一天：刷到 douyin-video-to-text Skill

第一天的起点很简单。刷到一个叫 douyin-video-to-text 的 Skill，能把抖音链接转成文字。

第一反应是：如果以后每天的优质视频都能一键转文字，抖音就能成为知识库输入源。

于是让 Codex 安装。很快完成安装和依赖配置，用一条链接做测试。

当时的要求很克制：只测转写，不落库。

很多系统搭建会急着自动化和沉淀，第一步其实是确认工具能不能用。

测试结论：可以，确实能提取出视频文字。

工具算是装成功了，但新问题立刻出现。

## 第一次卡住：原文有了，却不知往哪放

转成文字后，真正难题开始了：放哪？

放 Downloads 只是临时文件，容易被清理，也不属于知识库主空间，Claude、Codex、Obsidian 插件未必会读。

放 Obsidian 又放哪？每日总控？素材库？内容输出？方法论库？具体项目？

更关键的是，原文放好后怎么办？

它有价值吗？值得深加工吗？适合做素材吗？能成支持卡吗？有 SOP 价值吗？该进方法论库吗？会影响项目动作吗？

我意识到，安装工具只是开始，难的是把输出接入自己的工作流。

缺的不是转文字能力，而是外部信息进入知识库后的处理规则。

所以第一天结束时，我只有原文，没有闭环。停下来想清楚规则，比盲目往下做更重要。

## 第二天：刷到“Codex + Obsidian 自生长知识库”视频

第二天刷到一条抖音：用 Codex + Obsidian 搭建自生长知识库。

正好击中前一天的卡点：转出来后怎么进入系统？视频讲的就是信息如何进入 Obsidian，经 Codex 整理、总结、回写，让知识库持续生长。

我的判断是，这不是工具介绍，而是一个流程：

信息来源 → 进入 Obsidian → Codex 整理 → 生成结构化总结 → 回写知识库 → 反哺下一轮输出

启发是：信息不该只被保存，要进入循环。原文只是起点，后面还有整理、判断、分流、复盘、输出、回写。

所以我没有立刻设计自己的方案，先让 AI 回到视频原文，把博主的流程梳理清楚。

## 我没照搬，先让 AI 还原博主流程

刷到好教程最容易犯的错误是直接照搬。别人用什么我也用，别人怎么目录我就怎么建。

但每个人的结构、工作方式、输入源、输出目标都不同。

我先让 Codex 把视频内容整理成博主的流程逻辑，而不是直接设计我的方案。

提示词大致是：先回到这条抖音原文，不要设计我的方案，先帮我梳理博主的自生长知识库流程。

梳理后的核心流程是：

1. 打通 Codex 与 Obsidian
2. Obsidian 作容器
3. Codex 作整理与执行助手
4. 信息来源分线上自动、线上手动、线下灵感
5. 信息进入素材库后由 Codex 整理成结构化日报或总结
6. 总结回写 Obsidian
7. 知识库反哺选题、报告、思维导图、内容创作
8. 以日周月节奏让库持续生长

一句话总结：自生长知识库不是自动收藏，而是让信息持续进入、整理、回写、复用。

这句话把我从“装工具”拉回“设计流程”。

## 我把博主流程映射到自己的 Founder OS

没有直接复制，而是把逻辑翻译成自己的系统：

关键不是复制工具组合，而是把流程逻辑接入自己的目录、规则、Agent 分工和复用节奏。

博主是 Codex + Obsidian，我的是 Founder OS + Obsidian + Codex + Claude。

我已有目录：01_每日总控、02_输入箱、05_内容输出、07_方法论库、08_素材库

因此不能生搬硬套，要按自己的结构重新定义信息流。

最终映射为：

外部信息来源 → Founder OS 原文池 → 快速判断 → 分流复用 → 周期复盘 → 反哺下一轮采集与判断

**第一层：外部信息来源**

V1.0 优先：

- 抖音转写原文
- 个人公众号文章原文

暂不全部启用，先跑通一条线再扩展。

**第二层：Founder OS 原文池**

原文进入：

- 08_素材库/每日冲浪原始采集/抖音转写原文
- 08_素材库/每日冲浪原始采集/公众号文章原文

定位是“证据层”，不是发布稿，不是正式 SOP，只是可复用保存。

**第三层：快速判断**

原文进库后先判断，不急着深加工：

- 一句话主题是什么？
- 核心观点是什么？
- 对我有什么用？
- 值得深加工吗？
- 建议分到哪？

**第四层：分流复用**

值得处理后分流到：

内容素材、资料卡、支持卡、SOP 候选、方法论候选、项目动作、仅归档、不确定进输入箱

**第五层：周期复盘**

默认节奏：

- 每日：采集原文 + 快速判断
- 每周：挑选 3-5 条深加工
- 每月：判断是否升维为内容系列、SOP、方法论或项目资产

这才是我理解的自生长：在有边界的系统里持续生长。

## 第一层建设：先把原文落点定下来

设计清楚后，第一件事是原文落点。落点不清，后续复用全乱。

工具默认输出到 Downloads，不适合长期保留，会被清理，也不归工作区。

决定所有长期原文必须进入 Founder OS 内部：

- 08_素材库/每日冲浪原始采集/抖音转写原文
- 08_素材库/每日冲浪原始采集/公众号文章原文

还有一个区分：个人日常阅读的公众号原文进“每日冲浪原始采集”，而公众号项目对标账号、爆款分析、赛道资料等进公众号项目自己的原始采集体系。

同样是公众号文章，用途不同，落点就不同。否则后期会混乱。

## 第二层建设：建立“原文沉淀规则”

原文落点确定后，让 Codex 建立第一份规则：

每日冲浪与外部信息原文沉淀规则_V1.0.md

解决的问题：原文怎么保存、抖音转写如何变 Markdown、个人公众号原文与项目原文如何区分、每日总控的角色。

关键决定：**原文长期保存用 Markdown**

工具可先出 txt，但进 Founder OS 时转为 Markdown 原文卡。Markdown 更适合 Obsidian、Claude、Codex 读取，可带 frontmatter，能记录处理状态和分流。

流程：抖音链接 → douyin-video-to-text 转写 → txt 中间产物 → Markdown 原文卡 → 进入原文池

原文卡最小元数据：source_type、platform、source_url、aweme_id、capture_date、status、processing_state、related_project、created_by

这样看到卡片就能知道来源、状态、阶段，不靠记忆。

**每日总控只记录不存长原文**

总控是时间线和摘要入口，记录今天采集了什么、原文路径、快速判断、是否值得深加工、后续动作。长原文放素材库。

**第三层建设：建立“复用与分流规则”**

原文沉淀只解决进来问题，核心是进来后怎么用。

建立第二份规则：每日冲浪信息复用与分流规则_V1.0.md

解决：如何判断价值、是否继续处理、如何分流、如何通过日周月节奏持续生长。

默认三层：原文层 → 判断层 → 复用层

**原文层**：保存原始材料和元数据，不判断不写作不升级

**判断层**：只回答有没有用

判断模板：

- 一句话主题
- 核心观点
