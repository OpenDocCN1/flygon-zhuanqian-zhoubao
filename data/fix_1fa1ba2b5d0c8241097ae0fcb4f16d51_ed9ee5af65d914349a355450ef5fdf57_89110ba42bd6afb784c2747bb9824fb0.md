### 时序图：看清组件间的协作顺序

时序图（Sequence Diagram）属于交互图的一种，重点刻画多个进程之间的调用顺序与配合方式。

[PRE4]`mermaid

sequenceDiagram

    actor U as 用户

    participant A as API

    participant D as 数据库

    U->>+A: 发送请求

    A->>+D: 查询数据

    D-->>-A: 返回数据

    A-->>-U: 响应结果

[PRE5]

[PRE6]

它能够：

*   还原交互的先后次序

*   界定各方职责边界

*   发现异步环节

*   定位响应时间瓶颈

常见使用场合：

*   组件间协作

*   API 调用链

*   消息通信

### 类图：描述系统静态结构

类图是 UML 中的静态结构图，通过类、属性、方法以及对象之间的关系来展示系统结构。它既是面向对象建模的基础，也常用于概念建模、代码生成前的详细设计，甚至可用于数据建模。

        <>

        +generate_sql()

        +train()

    }

    class VectorStore {

        <<interface>>

        +add_data()

        +query()

    }

    VannaBase <|-- VectorStore

[PRE9]

它的核心价值：

*   呈现类之间的关联

*   约定接口行为

*   标明继承结构

*   为系统扩展留出空间

适合用在：

*   系统架构设计

*   类关系梳理

*   接口定义

### 甘特图：管理项目时间线

甘特图以条形方式显示项目进度，清晰标出各项任务从开始到结束的周期。该图最早由 Karol Adamiecki 于 1896 年提出，后来 Henry Gantt 在 1910 年代又独立开发出来。

    任务2    :after a1, 20d

# 四、 Mermaid 使用建议（持续补充中）

图表设计应遵循几条基本准则：内容简洁、重点清晰、颜色适度、布局美观。

（1）让图表信息更精炼

Mermaid 的初衷是“用最简单的语法表达信息”，所以在创建图表时要做到：

*   节点文案不要太长

*   连线尽量避免交叉

*   整体布局保持整齐

*   色彩醒目但不过度

（2）让图表融入工作流

仅仅画出来还不够，更重要的是在团队协作中实际使用：

*   在设计阶段，用图讲清架构和流程

*   做代码评审时，把关键逻辑画成图来解释

*   带新人时，借助图来读代码

*   做技术分享时，用图提升表达效果

（3）持续迭代图表

图表本身也需要不断打磨：

*   及时更新内容

*   根据反馈持续优化

*   定期调整图表结构

*   尝试引入新的图表类型
