#### 直接在飞书对话框里指挥 Codex

以上操作，你完全不用坐在电脑前发指令，直接在飞书对话框里指挥就行。也就是说，你在手机上发一句，本地进程收到飞书事件，再调用 `codex exec`，结果自动回飞书线程里。这个体验就完全不一样了。它已经不是工具，而是一套在后台持续运转的小型工作流。

对新手来说，整套就 4 层:

1. 飞书里有一个 bot

2. 本机有 lark-cli，负责收飞书事件、回飞书消息

3. 本机有 codex，负责真正执行任务

4. 本机有一个常驻 Python 守护进程，把 2 和 3 串起来

**你只需第一次在 codex 里输入这个提示词：**请帮我这台 Mac 上搭一个“飞书对话框里直接指挥 Codex"的本地工作流，我是小白，请你不要只讲思路，直接帮我检查环境、创建文件、配置后台服务，并在每一步告诉我需要我点击或确认什么。目标是：我在飞书里给一个 bot 发消息 -> 本机后台进程收到飞书消息事件 -> 本机自动调用 codex exec 执行任务 -> 执行结果自动回复到原飞书线程 -> 整套流程配置成后台常驻，电脑开着就能用。**要求你按这个顺序帮我完成：**检查这台电脑有没有安装 Python、Codex CLI、lark-cli；如果缺东西，告诉我最简单的安装方式；引导我在飞书开放平台创建一个 bot 应用；告诉我这个应用要开哪些权限、订阅哪个事件；帮我完成 lark-cli 配置和授权；帮我生成本地桥接脚本，要求只允许我本人触发；帮我生成 launchd 配置，让它在 macOS 后台常驻；帮我做最小测试，比如 /codex ping；如果测试失败，继续排查，不要停在分析；最后把我在飞书里能用的指令写成一份简短说明给我。

##### 把 Codex 机器人接入群聊

我按飞书当前常见中文界面整理的，按钮名字若有细微差别，通常在同一位置。

官方入口:

- [飞书开放平台](https://open.feishu.cn/) - 开发者后台 / 我的应用

- [飞书管理后台](https://open.feishu.cn/)

参考官方说明:

- [认识与配置飞书集成（飞书官方）](https://open.feishu.cn/)

- [飞书接入 OpenClaw 的安全防护与治理指南（飞书官方）](https://open.feishu.cn/)

###### 一、先创建飞书机器人应用

1. 打开 [开发者后台](https://open.feishu.cn/), 用飞书账号登录。

2. 点击 **创建企业自建应用**。

3. 填应用名称。建议写成 Codex 助手、我的 Codex 机器人，后续在群里更好识别。

###### 二、给应用开通机器人能力

4. 上传头像，填一句应用描述。例如：在飞书里一句话触发本地 Codex 执行任务并自动回复结果。

5. 点 **创建**。

6. 进入应用后台。找到左侧类似 **添加应用能力**、**能力**、**机器人**的区域。

7. 把 **机器人**能力打开。如有欢迎语、消息卡片、可见范围，先保持默认，后面跑通再调。

###### 三、开通权限

这一步很关键。没权限，机器人就算在群里也收不到消息、回不了消息。

8. 打开左侧 **权限管理**或**权限配置**。搜索并开通与 IM 消息相关的权限。对“飞书里一句话触发 Codex"场景，优先开：

- `im:message:send_as_bot`

- `im:message:readonly`

- `im:message.group_at_msg:readonly`

- `im:message.p2p_msg:readonly`

- `im:chat:read`

后续想收图片、文件、语音再补：

- `im:resource`

- `im:message.reactions:read`

开完后点页面里的 **申请权限**、**批量开通**或同类按钮。

###### 四、订阅事件

这一步是让飞书把新消息“推”给本地进程。

9. 打开左侧事件订阅。找到添加事件或订阅事件。搜索并添加：`im.message.receive_v1`。如果界面要求填“请求网址”或“回调地址”，你有两种情况:

- 如果走 lark-cli event consume 这种本地事件消费方式，通常由本地工具接管，不必自己填公网回调。

- 如果是传统 webhook 回调，就需要填一个外网可访问的回调地址。你现在这套“本地收到事件 -> 调Codex"方案，核心就是让这条消息事件能被订阅成功。

###### 五、发布应用

很多新手会漏这一步。不发布，前面的权限和能力往往不生效。

10. 打开左侧版本管理与发布。点击创建版本。填版本号，例如：1.0.0。填发布说明，例如：开通机器人消息接收与回复能力。按提示继续下一步。如果系统提示有权限待申请，先补齐。提交发布。企业内应用通常还要把可用范围设给自己或测试成员。

###### 六、把机器人加进群聊

这一步在飞书聊天界面完成。

1. 打开飞书，新建一个测试群。建议只拉自己或 1-2 个测试成员，别一上来进正式群。进入群聊右上角 ... 或 **群设置**。找 **群机器人**、**机器人**、**应用**、**添加机器人**入口。在机器人列表里搜索刚创建的应用名字，例如：Codex 助手。点 **添加**。如有权限或使用范围确认提示，点确认。添加成功后群里会看到机器人加入提示。

###### 七、测试群里能否触发

2. 在群里 @机器人。发一条最简单的测试消息。例如: `@Codex 助手 /codex ping`私聊机器人就直接发：`/codex ping`正常情况下，本地进程收到事件后会把结果回复回该线程。

###### 八、常见卡点

1. 只创建了应用，没开机器人能力。

2. 开了权限，没发布版本。

3. 发布了应用，没把机器人加进群。

4. 机器人在群里，没开消息接收相关权限。

5. 机器人能收私聊收不到群消息，通常是群 @ 消息权限没开。

6. 群里能触发但回复失败，通常是 send_as_bot 权限没开，或可用范围没放通。

###### 九、简单总结

先去飞书开放平台创建“企业自建应用”，开启机器人能力，开通消息读取和机器人发消息权限，订阅 im.message.receive_v1事件，创建版本并发布。然后回到飞书聊天界面新建测试群，在群设置里把机器人添加进来。完成后再让 Codex 接本地执行链路。
