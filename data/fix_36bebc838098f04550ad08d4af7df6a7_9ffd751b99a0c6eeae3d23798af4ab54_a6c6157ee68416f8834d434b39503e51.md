拿到任何一条外部内容，我都会先过四道问题：它对生意、写作、工作方法、个人判断、投资视角分别可能带来什么；是否值得继续打磨；应该送去哪个归类；接下来如何推进。

**再利用层**

只有确认值得继续投入，内容才进入再利用层。可选的去向包括：单纯存档、创作素材、参考卡、论据卡、流程规范备选、方法备选、项目执行项，暂时拿不准就放进待定箱。

这一层最重要的边界是：备选不等于定案。哪怕一条信息再诱人，也不能因为它看起来正确就直接升级成正式流程或正式方法。它必须先以备选的身份存在，经过多次真实使用验证后，再考虑转正。

**核心规则必须写进 AGENTS 入口文件，原因如下**

搭建过程中，我给自己加了一条硬性要求：核心规则不能只躺在文档里，必须直接写进 AGENTS 入口文件。

原因在于，Agent 进入我的体系时，最先读到的就是这份入口文件。如果里面只写“请参考某某规则文档”，实际操作中很容易出现：Agent 忘记去读；Agent 读了但理解偏差；Agent 只读了入口，没读正文；Agent 因为上下文过长，执行时丢掉了关键约束。

所以我要求把最核心的执行约定直接压进入口文件，包括：三层处理逻辑、初步权衡标准、归类去向清单、每日/每周/每月复盘节奏、备选与正式的分界。详细文档负责展开，入口文件负责让 Agent 在最短路径里知道如何行动。

这件事让我意识到：规范不是写给人看的装饰，而是写给 Agent 执行时少走弯路的操作约束。如果规范只存在于某个深层文件里，又没有稳定触发机制，那它等于没有真正进入体系。

**踩坑一：同一句话，不同 Agent 执行出不同结果**

很典型的例子，是 Claude 和 Codex 对 douyin-video-to-text 的理解不一致。

我让 Claude 也安装同名技能，结果它装出来的不是同一套工具，而是更宽泛的社交平台转写器。这件事提醒我：自然语言指令不等于确定性执行。

同样一句话，对人来说非常明确；对 Agent 来说，它可能理解成：安装同名工具；找功能相似的工具；安装更通用的转写器；按已有环境挑别的安装包。

最终我决定让 Codex 接管这件事，处理方法是：

1. 先确认 Codex 这边已经装好并测通了正确的 douyin-video-to-text；
2. 检查 Claude 那边安装的是不是同一套；
3. 不一致的话，清掉 Claude 侧不匹配的工具；
4. 把 Codex 已验证的版本对齐给 Claude；
5. 让两边读取同一组规范，使用同一组落点。

这次经历给我的启发是：多个 Agent 协作时，不能默认它们对同一句话的理解一致。工具、规范和落点，必须显式对齐。

**踩坑二：工具输出成功，不代表内容进入资料库**

还有一处容易翻车，是默认输出目录。

douyin-video-to-text 确实能把视频转成文字，但一开始输出到了系统下载目录。站在工具的角度，任务已经完成；站在资料库的角度，这还不算完成。

下载目录只是临时落脚点，过几天一清理，原文就没了。更重要的是，我后续还要在 Obsidian、Claude 插件或 Codex 工作区里继续加工这些内容。原始内容如果不在体系内部，就很难成为体系的一部分。

所以我重新定义了“成功”：不是文件生成了，而是文件进入正确位置，并且能被后续流程调用。

这件事让我想明白：资料库体系里最关键的，不是生成文件，而是文件进入正确语境。

**踩坑三：txt 能保存文字，但不适合做长期档案**

第三个问题出在格式上。

工具默认生成 txt，优点是简单，确实能保存文字，但不适合做长期资料卡。

因为我后续需要的不仅是正文，还包括：原始链接、平台来源、视频编号、采集时间、处理状态、是否完成提炼、是否完成归类、生成了哪些后续产物。这些信息用 txt 也能写，但结构不够清晰，不方便阅读和维护。

Markdown 更合适。所以我决定：txt 只作为中间产物，长期保留在体系里的原文，一律做成 Markdown 原始档案。

**踩坑四：AI 交付文件，也必须验收**

另有一类很小但很典型的坑，是流程图。

我让 AI 把“每日浏览信息自生长回路草图”导出成微信能打开的图片。第一次，它生成了 SVG，微信打不开。于是我要求改成 PNG 或 JPG。第二次，它确实生成了 PNG 和 JPG，但图片内容被裁切了，右边不完整，底部也不完整。

这个问题本身不大，但它非常典型：AI 生成了文件，不代表交付合格。如果只检查文件是否存在、大小是否正常，很容易误判。

真正该验收的是：用户能不能打开？内容是否完整？有没有裁切？是否符合实际使用场景？

后来我重新生成了竖版微信长图。处理方式是：不再用系统缩略图转换；重新生成竖版 HTML 图稿；用浏览器完整渲染页面；截取完整长图；再实际打开 PNG 和 JPG 检查；确认从标题到最后“回路含义”都完整。

这件事可以总结成一句话：AI 执行完不等于任务完成。真正的完成，是交付物被验证过，且用户能直接使用。

这个原则适用于所有 AI 交付物：脚本要跑过；文件要读回；索引要能搜到；图片要打开看；规范要确认能触发；状态要确认没有误标。

**最终测试：用一条真实视频跑完整回路**

当原始归档规范、再利用与归类规范、AGENTS 入口规范都写好以后，还差最后一步：用真实内容跑一次完整回路。

规范写好了，不代表体系跑通了。所以我用“Codex + Obsidian 自生长资料库”这条抖音内容，跑了一次完整的每日浏览信息再利用测试。

测试链路是：抖音原始档案 → 初步权衡 → 归类决策 → 创作素材 → 论据卡 → 流程规范备选 → 档案回写 → 方法库索引更新 → 执行日志。

先调出原始档案。档案位于 08_素材库/每日浏览原始采集/抖音转写原文，里面包含原始链接、视频编号、采集日期、标题、标签、转写正文、处理状态。

接着做初步权衡。结论是：这条内容值得深加工，但只能进入备选级。原因有三：它与当前体系建设的需求高度相关；它提供了“多来源输入 → 机器整理 → 回写资料库 → 周期复盘”的参考路径；它已经帮助我产出了原始归档规范、再利用与归类规范和个人 IP 内容素材。但目前只有一条样本，不能直接升级为正式规范。

随后定归类去向。这条内容被归为三类：创作素材、论据卡、流程规范备选。创作素材进入 05_内容输出/02_资料库版本/AI 成长记录；论据卡和流程规范备选进入 07_方法库/04_机器协作方法。

然后制作论据卡。主题是：真正有用的信息冲浪，不是收藏，而是把信息变成自己的体系。它的作用是：以后写文章、做分享、讲资料库建设时，可以快速调用这个判断和案例。它不是正式方法，只是备选支撑材料。

再建立流程规范备选。主题是：每日浏览信息进入资料库再利用回路。它记录了输入是什么、适用场景是什么、不适用场景是什么、操作步骤是什么、输出标准是什么、升级条件是什么、风险边界是什么。它也不是正式流程，因为目前只用一条内容跑通过。按约定，至少需要再用 3-5 条不同来源的内容复验，才考虑升级。

之后回写原始档案。档案补充了初步权衡摘要、归类结果、产物路径、后续处理记录。以后再打开档案时，就能看到它不再只是“已采集”，而是“已完成再利用测试”。

最后更新索引和执行日志。方法库索引新增了 MT-C01 论据卡备选、MT-C02 流程规范备选；执行日志明确记录：未升级正式流程，未升级正式方法，未创建正式技能，未启用定时任务，未写入个人档案，未标记任何内容为已发布，未修改 .obsidian。

这一步让我很安心，因为体系不只是产出了东西，也留下了边界。

**最终资产清单**

这次实验总共沉淀出以下成果：

1. 抖音内容 Markdown 原始档案：保存原始转写、来源链接、状态和后续利用记录。
2. 每日浏览原始归档规范：规定外部信息如何进入体系，解决抖音原文放哪、公众号原文放哪、Markdown 档案怎么生成、下载目录不能当长期库、每日总控只记摘要和路径。
3. 每日浏览信息再利用与归类规范：规定原文进入后怎么判断、怎么归类、怎么再利用。出口包括仅归档、创作素材、参考卡、论据卡、流程规范备选、方法备选、项目执行项、待定箱。
4. AGENTS 入口文件核心规则：让 Agent 进入体系后直接看到关键规则，而不是只看到一个路径。
5. 个人 IP 资料库草稿：主题是“真正有用的信息冲浪，不是收藏，而是把信息变成自己的体系”，后续可改写成公众号、小红书、社群分享或飞书公开文档。
6. 论据卡：同样的主题，作为未来文章、演讲、分享中的论据和案例支撑。
7. 流程规范备选：主题是“每日浏览信息进入资料库再利用回路”，记录候选操作步骤，等待更多内容复验。
8. 方法资产索引记录：让备选论据卡和流程规范备选能被方法库检索到。
9. 执行日志：记录本次测试做了什么、没做什么、边界在哪里。
10. 微信版流程图：把整套流程图形化，既方便自己理解，也方便后续分享。

测试抖音链接、只看转写结果：

原文入库：

理解外部教程：
> 请回到这条抖音原文，先不要设计我的方案，先梳理博主讲的自生长资料库流程，让我看懂它的处理逻辑。

映射到自己的体系：

生成流程图：

建立规范草案：

把核心规则写进 AGENTS 入口文件：
> 请把规范文档中最核心的执行内容提炼出来，直接写进 AGENTS 入口文件，不要只放路径，避免 Agent 读不到正文时无法执行。

跑测试回路：
> 请基于今天这条“Codex + Obsidian 自生长资料库”抖音内容，跑一次每日浏览信息再利用测试。

限定备选边界：
> 本次只做备选级测试。不要升级正式流程、正式方法、正式技能；不要标记任何内容为已发布；不要写入个人档案；不要启用定时任务。

读回校验：

每周回顾：
> 请回顾本周每日浏览原始库，挑出最值得深加工的 3 条，按创作素材、论据卡、流程规范备选、方法备选、项目执行项分别给出建议。

**这套方法适合谁，不适合谁**

先说适合谁。

这套方法适合这些情况：每天信息输入很多的人；想做个人 IP 内容输出的人；已经在用 Obsidian、飞书、Notion 或本地笔记的人；希望用 AI 辅助整理外部信息的人；不想只收藏资料、而是想把资料变成长期资产的人；愿意维护一套轻量规范、而不是追求一键全自动的人。

如果你经常觉得：好像刷到过某个很有用的内容，但事后找不到了；收藏了很多内容，但真正动笔时用不上；想用 AI 整理资料，却不知道资料该放哪里；想做个人 IP，但日常输入没有变成稳定素材。那这套方法可能适合你。

再说不适合谁。

这套方法不适合这几类人：只想要一键全自动的人；不愿意维护规范的人；希望 AI 替自己做所有判断的人；不区分原始内容、草稿、备选和正式资产的人；还没想清楚资料库入口，就急着做复杂自动流程的人。

最后一点尤其重要。如果连原文放哪里、状态怎么标、归类出口是什么都没确定，就直接上自动流程，很可能只是在自动制造混乱。

**下一步：暂时不碰大自动流程**

博主视频里提到了自动抓取、定时日报、自动整理。但我不会马上照搬。

原因很简单：没有被验证过的自动流程，只会自动制造混乱。现在我只用一条内容跑通测试，样本不足以支撑全自动。

接下来我更想做的，是用 3-5 条不同来源的内容继续验证，包括抖音、公众号文章、网页文章、小红书。每一条都要回答：能不能顺利进入原始库？初步权衡是否有效？归类去向是否合理？论据卡或流程备选是否真的能再利用？索引能否稳定更新？有没有误升级、误发布、误写个人档案？

只有这些问题被多次验证后，我才会考虑下一步自动流程，比如：每周自动生成浏览回顾；自动挑出最值得深加工的内容；自动生成待确认的归类建议；自动提醒哪些备选可以进行复验。

但这些都应该建立在稳定规范之上。否则，自动流程不是加速器，而是放大器，它会把混乱一起放大。

**结尾：我真正搭建的不是工具，而是外部大脑的入口**

回头看这两天，我做的好像都是一些小事：安装一个抖音转文字技能；测试一个抖音链接；把 txt 转成 Markdown；建几个目录；写两份规范；生成一张流程图；做一次测试回路。

但真正让我觉得有价值的，不是这些动作本身，而是我第一次把“信息冲浪”接进了自己的资料库体系。

以前，冲浪就是冲浪。刷到一个视频，觉得有用就收藏；刷到一篇文章，觉得不错就转存。

现在，我开始有了一条新的处理路径：这条信息能不能进原始库？它对我有什么价值？它适合归到哪一类？能不能变成创作素材？能不能变成论据卡？有没有流程备选的价值？会不会影响某个项目？需不需要留到每周复盘？

这才是我想要的资料库：不是堆资料的仓库，而是能持续吸收、判断、再利用、进化的外部大脑。

所以这两条抖音视频对我来说，并不是两个简单教程。第一条让我获得了一个信息入口，第二条让我理解了信息进入体系之后应该如何生长。

而我做的事情，是把这两者接起来：从抖音转文字，到 Markdown 原始档案，到资料库原始库，到初步权衡，到归类再利用，到论据卡和流程备选，再到后续周期复盘。

这就是我这次搭建的最小回路。它还不完美，也还不是正式流程，但它已经跑通了一次。

下一步，我会继续用更多真实内容来验证它。如果它能稳定跑通，我再把它升级成正式流程，甚至未来变成一个更稳定的技能。

最后用一句话总结：真正有用的信息冲浪，不是收藏信息，而是把信息变成自己的体系。
