# 一、XML 究竟是什么

XML 是一种与 HTML 相似的标记语言，设计初衷是用于数据传输。简单理解，看加亮的部分即可。

<xml>标签用于标识 XML 文件的开始与结束，标签内部的内容即为 XML 文档。任何程序要解析 XML 代码，这个起始标签是必须的。</xml>

XML 定义了技术文档的结构信息，后续程序再基于该结构进行灵活呈现。

我们平常写提示词时，习惯用“---”“===”“###”“((()))”“<<<>>>”等符号来分割结构。可换一个模型就可能失效。

我验证过的 XML 标签在 Claude 上很稳定，在其他模型上表现也不错，值得长期用。

## XML 的用法

### 最基础用法
例如描述一位作家：
张爱玲：原名张煐，笔名梁京，祖籍河北唐山丰润，生于上海，中国现代女作家。

### 进阶用法
例如告知你有两个朋友，Lilei 和 Hanmeimei：
<name>Lilei</name>
<name>Hanmeimei</name>

### 再进阶用法
要表达书店数据，可创建 <book>、<title>、<author> 等标签。</author></title></book>
一本书的 XML 内容如下：
<title>Learning Amazon Web Services</title>
<author>Mark Wilkins</author>

核心就是用标签把内容包裹起来，形成层层嵌套，像俄罗斯套娃一样呈现信息层次。

不建议套得太深，通常两层足够，层级过多容易自己混乱，也可能影响解析效果，得不偿失。

# 二、实战案例：为航海打卡做复盘助手

前面说好要做一个帮助船员打卡的小工具。下面我把思考拆开讲。

## 问题拆解

航海打卡一般包含哪些？
航线图、今日行动、心得感悟、好事分享、下一步计划。

这是临时起意的小玩意，调研暂时用我过往航海踩的坑代替。

打卡时的常见卡点：
* 有时做的事情很日常，比如注册账号、买粉；
* 有时是每日重复项，比如更新文章；
* 有时发现的问题其实价值不大。

我想帮小组伙伴梳理思考，用于每日复盘。复盘需要回答：
* 我的目标是什么
* 今天具体做了什么
* 今天哪些做得对，哪些做得不对，距离目标还有多远
* 结合目标倒推，明天该怎么走

需求已明确：需要一套指令作为复盘辅助，引导船员完成每日打卡思考，并在最后由一个有温度的角色把结果讲出来。

再往下抽象，本质上是一份带角色扮演的对话式复盘指令。

## 提示词第一版

明确了是复盘工具，框架里应该有哪些？我整理出：目标、行动、思考模型、输出结构、工作流。

### 【逻辑解释】
先讲个《小明的快乐童年》小故事：

妈妈本来想发火，想到是亲生的，就用抖音学来的方式“成熟地”教育孩子。
先夸小明“买回来这么多东西，能帮妈妈干活了”；再严肃指出没买香菇；最后给出计划去旁边菜店补齐30个香菇。

## 提示词第二版

第一版没达到预期。上篇文章也说过，参数流的核心是精准、简洁。但第一版提示词长达681字，比公众号插两条广告的篇幅还长。

而且参数越多，Claude 的解析衰减越明显，就像故事里的小明，记性有限，记不住那么多。

这就违背了我一开始发现这个方法的初衷。得做减法。

### 思考后整理
* 周目标和日目标如果不是刚需，可以合并成一个北极星指标作为方向指引。
* 行动和思考模型不能砍。
* 输出结构太细了，简化即可。
* 工作流可以省，上文已说 Claude 本身就是从上到下执行，场景简单时重复定义工作流是冗余。

### 【提示词】
优化后的版本如下，参数后的中文为注释，实操可删：
* 把目标、行动、模型统一归到输入区
* 把想要的结果归到输出区
