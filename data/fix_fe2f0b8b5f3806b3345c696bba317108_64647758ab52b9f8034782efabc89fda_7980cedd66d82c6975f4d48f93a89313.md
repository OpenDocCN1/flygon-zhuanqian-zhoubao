# 二、这条产线是怎么磨出来的

先说我的来路，你才知道后面每个设计为什么会这样长。

最早我做的是流量号。娱乐八卦、情感、婆媳、银发赛道，哪个有风口追哪个。跑起来的时候，单篇能到十万多阅读，评论区热热闹闹；但平均下来，爆文也就一两万，还有一堆号根本没起来。

那种打法很野，常在红线边上试探。违规、违禁、律师函都经历过，号死的死，残的残。

那些十万+里面，有的擦边，有的被投诉，有的踩了红线。一旦被判违禁，收益清零，号也救不回来。所以我现在拿一个老号试着洗，看能不能洗出来，后面有结果再跟你说。

从那以后，我悟出一个流量主保命技巧，大部分人不知道：做风口类、短平快的流量文，爆了、收益到了手，就主动删。

这类内容，平台不会持续推流，本质上就是一次性生意。留着没用，风险还一直挂着。主动删，收益落袋；等被投诉或者被判了再删，收益就没了。我的爆文，大部分是自己删掉的。

这也是为什么这篇帖子里看不到10万+截图——我现在还能翻到的，最高七万多。钱进了口袋才是自己的，闷声发财最重要。

那批号教会我两件事。第一，流量号是概率游戏，爆不爆看平台，死不死看自己手痒不痒。第二，平台红线不是摆设，它真能让你几个月的号一夜清零。

流量号起起落落的那几年，朋友圈IP日更一直没断。

日更真的挺苦。我很早就想让模型来帮忙。第一次把原料丢过去，说“写口语一点、真实一点、别太机器腔”。结果出来的东西，排比句一串接一串，每段结尾立一个金句，整齐得像广播体操。

但那时候我没想那么多，既然生成了就直接发。发是发了，别人只知道我在更新，内容本身没有任何意义。等于告诉所有人：这是机器写的，朝暮本人早就下班了。

后来想明白，想把号真正做起来，这一关躲不掉。于是我开始了漫长的提示词打磨。

最早的版本我叫它2.0，一页纸：5个标题公式，3个内容池，正文三步走，完了。

一路迭代到5月，3.2.3版，17章一万六千字。标题公式扩到8个；情绪节奏单独成了系统，4种骨架配10种风味；发布前检查清单20条；连脱敏对照表都有。

再往后是7.2，朝暮日更全量上下文系统。

但做到这一步，问题出来了：提示词越长越难管。改一个地方，别的地方就串了；换一个模型，指令认不全；上下文一长，前面的规则直接被吞掉。

提示词的极限，就是它只能活在一次对话里。对话一结束，它什么都不记得。

这就是我后来做Skill的原因。

Skill的本质还是提示词，内容是一样的。区别在存放方式和执行方式。

提示词：每次开新对话，你都要手动重新粘贴，让模型重新了解你。太长了贴不完，贴完了它也不一定全记住。

Skill：存在一个.md文件里，AI Agent（能帮你操作软件的智能体）每次自己去读，按里面写好的流程自己走。你不需要记住提示词在哪、先贴哪段后贴哪段，启动Skill，它自己跑。

更关键的区别：提示词活在一次对话里，Skill活在文件系统里。

提示词每次都要重贴。Skill保存在本地文件里，改了之后，下次运行自动读取最新版。你的配置、案例、禁用词表、人格内核和任务产物，都可以存在指定目录里，由总控按阶段读取，不需要每次手动整包投喂。

打个比方：提示词像菜谱，每次做菜你都要从头翻一遍、自己买菜自己切。Skill像一条装好的产线，原料丢进去，按设定好的工序自动走完，成品出来。

从提示词到Skill，不只是换名字，而是从手工作坊升级成了工厂。

最开始我教大家的都是提示词，不是Skill——因为很多人连Skill是什么都不懂，先用最简单的方式跑起来更重要。但提示词的天花板很快就能碰到，Skill才是能长期跑的东西。

到今天，这条产线的主体是一条主产线、5个专业工位。总控负责启动、自检和调度，七罪标题系统管标题，5个引擎各管一段明确的工作：

| 角色 | 它负责什么 | 主要产物 |
|---|---|---|
| 总控 | 检查配置、环境和任务状态，按阶段调度Skill，记录路径、确认点和风险 | 启动自检、任务状态 |
| 淘金引擎 | 归档原始材料，拆出事实、判断、金句、案例和证据位置 | 原始材料、素材包 |
| 布局引擎 | 拆篇、查重、追问缺口，安排栏目、顺序与对标任务 | 拆篇计划、对标拆解 |
| 铸文引擎 | 读取已确认的计划、原料、人格内核和对标，生成初稿；不自我质检 | 初稿 |
| 七罪标题系统 | 生成标题候选，检查正文能否兑现，再由用户确认最终标题 | 标题候选、标题确认 |
| 鉴文引擎 | 由未参与写稿的独立上下文做8层鉴文，给出证据和局部修改建议 | 鉴文报告、修正稿 |
| 淬文引擎 | 完成32项发布终审，核对事实、隐私、平台边界、格式与未通过风险 | 淬文报告、发布稿 |

中文阅读包里是5个中文引擎，方便逐个读懂；机器安装包里一共有7个可调用Skill，因为总控和持续进化系统也要单独被识别。它们只是同一套逻辑的两种包装，不是两套各跑各的东西，也不要求放进Obsidian。

为什么要拆这么细？因为同一个模型不能又当运动员，又当裁判。

我反复测过：让生成正文的同一个上下文立刻检查自己，特别容易漏问题。它记得自己为什么这样写，会不自觉地替刚才的表达找理由。必须换一个没参与写作的独立上下文来做鉴文，生产和质检才能真正分开。

这就是工厂逻辑：每个工位只干自己的活，质检和生产必须分开。

这一套前后改了400多次。有了全套东西之后，我依然觉得文章生成得不够好。不是说不对，而是不像我。后来我一直在找答案。真正让我开窍的，不是某条具体规则，而是中间某次改稿时突然反应过来：

我在提示词里堆了几十条“不要这样、不要那样”，模型照样写不像我。问题从来不在指令，而在于它根本不够认识我。

从那天起，我的重心从“怎么命令模型”，换成了“怎么让模型深度认识我”。

后面所有东西——人格档案、鉴文引擎、七罪引擎——都是从这个顺序长出来的。它们不是孤立工具，而是工厂里的工位，每个工位解决一个问题。

今年5月，我把这套东西搬到线下，一场课14个人，一下午跑完流程，当场就有人出了第一篇初稿。流程可行，验证过了。

这就是这篇帖子的全部来历。

# 三、为什么你写出来的东西，一看就不像你

先说几个扎心的。

大多数人让模型写文章，就一句话：“帮我写一篇副业干货，干货一点，不要有机器味。”出来什么效果，你自己清楚。开头“在这个快节奏的时代”，中间排比三连，结尾“愿你我都能成为更好的自己”。

发出去没人看，平台还标你低原创，限流。

这时候，市面会给你三个答案。第一个，说你提示词不行，卖你提示词包。第二个，说你模型不行，让你充会员上更贵的。第三个，卖你一个一键降机器味的工具。

三个我全试过，全是止痛药。提示词包收了不少，写出来还是那个味。更贵的模型，废话只是更流畅了。降机器味工具最坑，检测是过了，人读不下去了。

核心问题根本不在提示词。

模型让写东西越来越便宜，一个选题丢进去，几分钟一篇稿子就出来。但你有没有发现，写得越多，能用的越少？生产成本降到接近零，但判断什么值得写、什么像你，这个成本反而越来越高。

问题出在四重错配。

第一重，方向错配。你让模型“写一篇爆款”，却没说写给谁、解决什么问题。没有靶心的内容生产，子弹越多越乱。

第二重，原料错配。你只丢给模型一个选题和一句提示词。但真正决定内容质量的，是你的真实经历、你踩过的坑、你对标的爆文。一篇稿子的质量，对标素材占60%，任务描述占30%，提示词技巧只占10%。你把全部力气砸在那10%上，能好才怪。

第三重，角色错配。你把判断、立场、故事全交给模型，自己只负责复制粘贴。正确的分工是：你出判断、出经历、出立场，模型出结构、出连接、出执行力。

第四重，回路错配。大部分人的流程是：脑里冒个选题→丢给模型→复制粘贴发出去→完事。发布后的数据、评论、用户问题，没进入下一轮创作。每次都从零开始，模型永远不会越来越懂你。

一篇文章发完就死了，它只是内容。里面的经历、判断、用户反馈能喂进下一篇，它才算资产。

大多数人用模型写作，生产了一堆内容，没攒下一点资产。

这四重错配，再往下挖一层，其实是同一个问题：

## 模型对你一无所知

它不知道你是谁，不知道你踩过什么坑，不知道你说话什么腔调。你让一个认识你三秒的陌生人替你说话，它只能给你全人类的平均值。

全人类的平均值，就是机器味。

有个最简单的检验方法：把文章作者的名字盖掉，看同行能不能直接拿去发。如果答案是他能——那这篇就不是你的IP内容，是公共内容。模型给你的，就是这种东西。

模型对你一无所知，一半是你没喂它。另一半更扎心——你自己也未必讲得清自己。你跟它说“写得真实一点”，你的“真实”长什么样，你说得出来吗？你的口头禅是哪几个？你的判断跟别人差在哪里？

说不出来，就别怪模型。它放大你的清楚，也放大你的模糊。

还有件事很多人没想过。底层模型是公共的，你用的Claude、豆包，别人也在用，明天还会更好用，这一头拉不开任何差距。真正私有的，是你喂进去的东西：你的经历，你的判断。这两样，别人抄不走。

所以正确的顺序是倒过来的：先让模型认识你，再让它认识市场，最后才轮到写。

这就是这条产线的根本原则。下面按这个顺序，一站一站教你搭。

但动手之前，先把下面这件事定了。

# 四、第零步：先选入口——你喂它什么

整条产线是通用的。唯一不同的，是你从哪个入口把原料喂进去。

两个入口，对应两条路。

## 入口A：你自己的原料 → IP号打法

你每天遇到什么事、冒出什么想法、跟谁聊了一个有意思的观点，对着手机讲一遍，转成文字，这就是你的原料。

系统拿到这些原料，会自动匹配你的人格档案，按你的节奏、你的语气、你的判断，生成一篇像你说出来的文章。

IP号的逻辑：垂直到最小的目标人群，先服务好一个小圈层，再往外长。

选了IP这条路，动笔之前还有一个问题，比写什么更要紧：你的交付产品是什么？

很多人IP文写不好，不是文笔问题，是没想清楚自己到底交付什么。你是要做信任，还是要带货？这个不定下来，写出来的东西就是散的，东一篇西一篇，读者看半天不知道你是干嘛的。

产品是根，你所有内容都要从这根上长出来。

那还没有产品怎么办？先做你这个人。这个阶段，你这个人就是产品。

IP号这条路，我拿自己当样本。我朋友圈写了三年。前面很长一段时间，没效果、没变化，什么都没有。阅读就那么点，也没人找我，看起来就是无用功。

但写着写着，有一样东西在慢慢长出来——信任。现在谈合作、对接资源，只要对方加了我微信，翻到朋友圈看到我日更了这么多天，基础信任感立刻就有了：这人靠谱，不会跑路。

“朝暮日更”这个标签已经跟我绑死了，别人一想到坚持、想到靠谱，就会想到我。朋友圈这个阵地管的就是信任。人从别处来，信任从日更来。

这里有个很反直觉的点：刚开始，你的内容不需要多好。

它只需要让所有人知道三件事：这个人在坚持，这个人靠谱，这个人一直在做这件事。

信任不是靠某一篇惊艳的文章建起来的，是靠一千多天“朝暮今天又发了”堆出来的。

垂直类的号，逻辑都一样：一厘米宽，一万米深。

你只要垂下去，一直写，写个一两百篇，用户在微信搜一搜里搜你这个领域的问题，弹出来的全是你。这个细分赛道的位置，就是你的了。

IP变现的公式就一条：信任+需求=购买。

## 入口B：爆款对标 → 流量号

流量号的入口不是你的原料，而是别人已经验证过的爆款。

找好对标之后，把人家爆文里的状态、情绪、反差拉进你的文章。流量文全是有公式的。

做泛流量，吃流量主收益，不要过度垂直，垂直了流量池就小了。

核心动作链是点击、完读、点广告——用户点开广告的收益，是没点开的10倍以上。

追热点，拼速度，需要多账号测试。要吃流量，就纯吃流量，别想着顺便做积累。又想吃流量、又想当IP、又想攒粉丝，三头都想抓，最后会很乱，哪头都抓不住。

多账号还有一层意义，是我用真金白银换来的：保命。我那批号要是只有一个，出事那天我就直接归零了。

做流量主，要做个渣男，脚踏多条船，号挂一个，其他还能继续用，心态不会崩。

两个入口怎么选？

看你的目的：想沉淀长期信任，走IP号；想快速拿流量收益，走流量号。
