最近折腾 Node 服务的转发规则时，被一个细节绊住。先说宝塔里的设置方法：目标地址写成 http://127.0.0.1:3000，即本地 Node 进程的监听地址；发出方域名沿用系统默认的 $host；转发路径填写 /api，意指所有以 /api 开头的请求都导向 Node 进程，其余参数维持原样，点下保存即可。[PRE0]

设置完成后，形如 http://你的域名/api/xxx 的请求会进入 http://127.0.0.1:3000/api/xxx 的处理流程，也就是落到 Node 服务上。需要留意的是，这里生效的是域名触发的转发；如果直接用 IP 拼凑 http://ip/api/xxx 并不会走这条规则，也无需刻意处理。用浏览器打开 http://域名/api/test 能正常返回，就代表转发生效。之所以会出现这种现象，是因为宝塔默认的转发策略仅作用于域名，IP 形式的访问不会被送到对应端口。当时我自检很久都没找到症结，后来在航海群求助，两位同行一眼就点出了关键。[PRE1]
