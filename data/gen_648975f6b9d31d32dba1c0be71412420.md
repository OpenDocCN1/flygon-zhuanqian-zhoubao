#### 6.6 用 Navicat 连接本地 MySQL，由 Codex 协助配置

下载地址：https://www.navicat.com.cn/products/navicat-premium-lite，基础版免费够用。很多新手习惯用 Navicat / DBeaver / TablePlus 在本地查看数据库。但第六步已说明 3306 不能对外开放，所以不能直接用 公网IP:3306 连接。

推荐做法只有一种。

**方式一（首选）：SSH 隧道连接，最安全**

让 Navicat 先通过 SSH 连上服务器，再连服务器本地的 127.0.0.1:3306。MySQL 只监听本机，SSH 隧道相当于从内部连自己，无需改监听地址也不用开放 3306。

简单说：SSH 隧道就是用服务器的 SSH 账号做跳板，Navicat 连到的是服务器内部的 127.0.0.1。

### 方式二（不推荐）：公网直连 3306，有风险

仅在工具不支持 SSH 隧道且你能承受风险时使用，会把 MySQL 暴露到公网。

让 Codex 额外执行的步骤：

继续配置“直连”模式，已确认需要且知晓风险：

1. 修改 MySQL 配置 bind-address = 0.0.0.0 并重启
2. 创建用户 navicat_user@'%'，强密码，仅授权 miniapp_todo 库
3. 云安全组 + 宝塔安全放行 3306，但来源 IP 限本机公网 IP，禁止 0.0.0.0/0
4. 建议把 MySQL 端口改为非默认如 33060，减少扫描
5. 确保 root 用户仅限 localhost

⚠️ 直连会暴露在公网，可能被扫描爆破。必须做到强密码 + 限制 IP + 改端口，否则不要开放。

### Navicat 连接失败排查顺序

| 现象 | 可能原因 | 处理方法 |

|---|---|---|

| SSH 阶段报错连不上 | IP/端口/账号密码错误或安全组未放行 22 | 核对 IP、开放 22、确认密码 |

| SSH 成功但 MySQL Access denied | 用户名密码错或用户 host 非 localhost | 让 Codex 重新确认用户和密码 |

| 报 Can't connect to MySQL on 127.0.0.1 | 隧道正常但 MySQL 未启动或未监听本机 | 让 Codex 在服务器本地执行 mysql -h 127.0.0.1 测试 |

| 直连报 2003/10060 | 3306 被防火墙阻挡或 bind 仍是 127.0.0.1 | 检查安全组放行、bind-address 配置 |
