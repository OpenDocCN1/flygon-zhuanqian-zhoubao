做个人付费类项目时，大多数人会先想着写功能代码，其实更早一步要把收款主体准备好。最省事的方式是用线上流程注册一家个体工商户，费用低、手续快。拿到主体后就能以这个主体去申请小程序并开通微信支付商户号。

注意点是，商户号 mchid 和小程序 AppID 必须属于同一主体，并在小程序后台的微信支付模块里完成关联。

#### 10.1 微信支付商户号人工开通

下面这几步必须本人操作，AI 无法代劳。

| 序号 | 操作入口 | 具体事项 |
|---|---|---|
| 1 | 微信支付商户平台 pay.weixin.qq.com | 用个体工商户资料提交申请，获取商户号 |
| 2 | 商户平台 → 产品中心 | 开通 JSAPI 支付，小程序场景仅支持 JSAPI，不用 Native 或 APP 支付 |
| 3 | 小程序后台 → 微信支付 | 把新申请的商户号与当前小程序 AppID 绑定 |
| 4 | 商户平台 → API 安全 | 生成 32 位 APIv3 密钥，自行妥善保存 |
| 5 | 商户平台 → API 安全 | 下载 API 证书 `apiclient_cert.pem` / `apiclient_key.pem`，私钥只能放在服务器，严禁放到前端或小程序 |
| 6 | 记录信息 | mchid、AppID、APIv3 密钥、证书在服务器的保存路径全部记下 |

mchid、APIv3 密钥、证书可视作支付的“钱袋钥匙”。和 AI 交流时，只提供 mchid 与接口说明；密钥和证书由 AI 从服务器安全文件读取，不要粘贴到聊天窗口。

#### 10.2 给 AI 的后端 Prompt 示例

要在现有 Laravel 后端接入微信支付 JSAPI 供小程序使用，请用中文说明实现：

1. 创建支付订单接口
   - 路径：`POST /api/pay/create`
   - 需登录校验，用现有 token 识别用户
   - 入参：`product_id`、`openid`
   - 流程：按 `product_id` 查出应付金额 → 调用微信统一下单 JSAPI → 得到 `prepay_id` → 按微信规范生成小程序所需 5 个参数 `appId`、`timeStamp`、`nonceStr`、`package`、`paySign`
   - 返回：HTTP 200 及上述 5 个参数
   - APIv3 密钥与证书从服务器安全路径读取，禁止写死

2. 支付结果通知接口
   - 路径：`POST /api/pay/notify`
   - 微信会异步推送支付结果到此地址
   - 流程：校验签名 → 用 APIv3 密钥解密报文 → 核对金额 → 将订单状态更新为已支付 → 为用户开通会员权益
   - 必须按微信要求返回成功报文，否则会重复推送

[PRE2]

3. 订单查询接口
   - 路径：`GET /api/pay/order?out_trade_no=xxx`
   - 返回订单状态及是否已支付

说明：金额单位为分；回调必须验签；订单状态变更建议使用数据库事务，防止重复发放。

#### 10.3 给 AI 的前端 Prompt 示例

在微信小程序“我的 / 会员中心”页面增加功能，采用原生小程序写法：

1. 套餐列表：调用 `GET /api/membership/plans` 获取套餐名称、价格、权益说明，用卡片展示
2. 立即开通
   - 先请求 `POST /api/pay/create` 获取 5 个支付参数
   - 再调用 `wx.requestPayment`，把参数原样传入
   - 支付成功提示开通成功并刷新会员状态；失败或取消给出对应提示
3. 会员状态展示：页面加载时调用 `GET /api/me` 获取 `is_vip`、`vip_expire_at`，已开通显示“会员有效期至 X”，未开通显示开通按钮
4. 前端不得写入任何密钥、mchid、证书，均由后端保管

注意 `wx.requestPayment` 的 `paySign` 必须由后端按规则计算返回，前端仅负责调用。

#### 10.4 iOS 的关键限制

虚拟商品如会员、金币、课程，在 iOS 端不可使用微信支付，苹果强制要求 IAP，否则审核会被拒。

因此会员类业务需区分：
- Android / 微信端：可继续使用微信支付
- iOS 端：要么接入 Apple IAP，要么暂不开放购买，仅提示“请在安卓 / 微信内购买”

实物商品不受此限制，微信支付可在全平台使用。

#### 10.5 小程序后台配置要点

- 微信支付接口由后端服务器调用，前端仅需 `wx.requestPayment`，无需在小程序后台的服务器域名中额外添加微信支付域名
- 后端服务器需能公网访问 `api.mch.weixin.qq.com`，使用宝塔时注意检查出站是否被拦截
- 类目要选对，例如“文娱-付费内容”、“工具-会员服务”，隐私指引中需说明会收集支付订单信息
- 相关权限需提前申请

### 第十一部分：代码托管到 Gitee

项目上线后，若代码只留在本地电脑或服务器，设备损坏或误删就会丢失。Gitee 是国内的 GitHub 替代品，免费、访问快、界面中文，适合个人开发者做云备份并记录每次改动，方便回滚。

通俗理解：**Gitee 等于代码网盘 + 时光机。**后续部署章节提到的 Git clone 能力即来源于此。

#### 11.1 新建 Gitee 仓库

1. 访问 gitee.com，用手机号注册登录
2. 右上角 + → 新建仓库
3. 仓库名填项目英文名，如 `miniapp-todo`，路径自动生成
4. 选择私有，避免泄露 `.env`
5. 初始化时勾选添加 README，不要勾选 `.gitignore` 和许可证，后续自行添加
6. 创建后记录地址：`https://gitee.com/你的用户名/miniapp-todo.git`

建议新手先用 HTTPS 推送，后期可切 SSH 免密。

### 11.2 给 Codex 的宝塔部署指令

服务器使用宝塔面板，Nginx/PHP/MySQL 已装，网站根目录 `/www/wwwroot/api.你的域名.com/backend/public`，SSL 已申请，数据库 `miniapp_todo` 已创建，用户名 `miniapp_user` 密码已保存。

请负责：
1. `git clone` 到 `/www/wwwroot/api.你的域名.com/backend`
2. `composer install --no-dev --optimize-autoloader`
3. 创建生产 `.env`，`APP_DEBUG=false`，数据库信息按宝塔填写
4. `php artisan key:generate`
5. `php artisan migrate --force`
6. `php artisan config:cache && php artisan route:cache`
7. 权限：`storage` 与 `bootstrap/cache` 设 775，其余 755/644，禁止 777
8. `chown -R www:www storage bootstrap/cache`

不要自行安装环境、修改 Nginx、申请 SSL。需用户操作的事项请列为“用户待办”。
