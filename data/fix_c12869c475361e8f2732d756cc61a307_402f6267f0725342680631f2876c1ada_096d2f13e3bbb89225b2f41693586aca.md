把个人海量资料整理成 Codex 能直接调用的工作资料柜，关键在于信息既要保持流动性，又要确保最终拍板权永远在人手里。Markdown 的优势就在这里：纯文本格式不受工具限制，任何编辑器都能打开，内容所有权不被平台锁死，双链机制让笔记彼此牵连，形成可回溯的知识网，而不是一堆孤立文件。

Codex 的定位是执行层，人始终是决策层。它可以直接访问 Obsidian 的文件夹，不必来回复制。先读取本地文档、梳理思路、调用外部工具，最后把成果写回本地目录。通过 AGENTS.md 和 Skills 为它设定工作规则，使用频率越高，配合越顺手。整个协作的底线是保留人的思考与判断，模型只负责把想法落地，而非替代判断。

### 知识库里到底放什么

一上来就追求完美目录是常见误区。结构不是提前设计出来的，而是反复使用中自然长出来的副产物。先用碎片化记录堆积素材，随用随整理，框架会自行演化。先有内容积累，后有结构自洽，才是可落地的做法。

一个能快速上手的最小版可以划为六个仓位：

**1. 个人底座库**
关于“我是谁”的核心信息：信念、价值观、人生经历与故事线。所有对外输出的底色都从这里来。

**2. 产品现况库**
在售项目清单、定价与权益、核心差异、为什么是你的供给、能解决的具体问题。确保模型能用你的原话复述产品。

**3. 客户洞察库**
客户画像、分层痛点、原话摘录、对受众的理解、他们常用的搜索词。尤其是客户曾经的抱怨，要原样保留。写作时从读者视角出发，靠这部分支撑。

**4. 素材沉淀库**
案例、故事、常见问题、基础概念、购入的电子书、课程笔记、复盘记录、曾产生流量的内容。另开行业动态与关键词更新区，写作时可有意识布词。段子、金句、生活化表达也收进来。

**5. 方法沉淀库**
你的判断依据、学到的技能、课程提炼、爆款写法、标题技巧、方法论、文章框架等可复用创作手段。

**6. 内容生产库**
已发布与待发布池、选题沉淀区。再加一个缓冲区，放暂时用不上但舍不得丢的内容。

整体覆盖收集、创作、储备、规划、沉淀、成果、复盘、缓冲的完整闭环。Codex 调用时就像去专属资料柜取件。它不是资料堆砌，而是可调用资产。先把真实内容填进去，再在实操中不断归类、补充、调整。你提供得越真实，它写得越像你。甚至录音里的口头禅、停顿、没说完的半句话都可以保留，这些不规范的痕迹恰恰是个人风格的来源。

两天搭出最小可用库是现实的。

### 内容如何进入库

让“干活本身”等于“喂库”。

**方式一：语音流转**
把日常沟通、客户对话、个人复盘录音转成文本，让 Codex 依库结构归档。信息越全，归档越准。

**方式二：存量迁移**
已学课程、业务经验、课件，直接让 Codex 写入 Obsidian。

**方式三：外部优质内容汇总**
平时刷到的优质内容分散各处，可用 Obsidian 插件或 Get 笔记集中保存。浏览网页时一键入库：点插件图标→确认路径→添加，内容自动进入知识库。

### 与 Codex 协作的边界设定

协作要让模型搞清四件事：你是谁、它该怎么帮你、哪些可自主完成、完成后结果放哪、如何持续改进。

可以按此框架写成协作制度：

**AI 协作工作制度**
一、你在和谁协作
二、我的业务和客户
三、协作原则
四、行为边界和确认权限
五、项目文件夹索引
六、素材归档规则
七、打标签规则
八、不同任务的处理流程
九、统一输出格式
十、结果如何反哺知识库
十一、定期体检和维护规则

### 别把所有事塞进一个提示词，拆成 Skill

过去总想一个万能提示词，输入选题就全自动产出。实操中很容易失控。把每日重复的动作拆开，每个动作对应一个独立 Skill：

- 从选题库筛选选题
- 写一篇公众号长文
- 从长文提取知识卡片正文
- 从长文提取朋友圈文案
- 用知识卡片提示词生成器生成内容
- 生成每张图片的提示词
- 发布前检查

拆开后可精准迭代。比如知识卡片原本要求 1000 字总是超限，就单独把该 Skill 调成 600 字；模型写得焦虑，就加一条“不制造焦虑，改成陪伴型表达”。

可以下载开源 Skill 让 Codex 阅读后调整，也可自行生成。告知它：帮我把 XX 流程生成一个 Skill，知识库地址是 XXX，按什么要求做什么，输出是什么格式。

# 公众号文章写作

###### 输入

- 接收一个已确定的选题及相关知识库素材。

- 只使用已提供或已读取的素材；缺少技术事实、案例、数据或来源时标记为“待确认”，不得补造。

- 原始素材含代码示例时，除非明确要求改写，否则保留原样。

###### 写作要求

- 围绕一个能站得住脚的观点展开，优先交付可执行的方法、清单或认知收获。

- 面向 26 至 45 岁的计算机视觉与嵌入式软件从业者，以平等、同行陪伴式口吻解释技术概念。

- 从具体项目痛点、好奇点或风险切入，依次推进为有用解释和示例、可记住的洞见、后续讨论邀请。

- 长短句交替；每段不超过五行；每三到四段切换一个自然子话题。

- 仅在帮助说明观点时使用克制的生活例子、轻度幽默或工程观察。

- 不使用夸张比喻、虚假权威、空洞口号、无依据的效果承诺、泛化的 AI 套话或标题党表达。

###### 输出

- 只输出长文正文，不生成标题、贴图正文、朋友圈文案、前言或写作说明。

- 使用清晰的 Markdown 小标题组织正文。

- 不沿用来源材料的数字编号。

# 公众号标题生成

###### 输入

- 接收公众号长文正文，以及需要时使用的原始选题和素材摘要。

- 标题必须与正文可以兑现的内容一致；信息不足时标记“待确认”，不虚构事实。

###### 生成要求

- 输出一个标题，落在工程师具体的工作处境、压力或发现上。

- 语气平等、有陪伴感，让有经验的工程师感到被理解。

- 优先表达真实矛盾、工程判断或可复用的发现，而不是泛泛承诺。

- 禁止制造恐慌、许诺结果、夸张好奇、诱导点击和居高临下的说教语气。

###### 输出

只输出最终标题，不附解释、候选标题、编号、引号或 Markdown 标记。

后续可再拆出贴图正文 Skill、朋友圈 Skill，以及把知识卡片提示词封装成 Skill，先运行生成器再基于长文产出绘画指令。

这套体系的核心是：Obsidian 承载可迁移的个人知识，双链形成网络，Codex 担纲执行层，Skill 把重复动作标准化。人的判断始终在前，模型越用越像你的副手。
