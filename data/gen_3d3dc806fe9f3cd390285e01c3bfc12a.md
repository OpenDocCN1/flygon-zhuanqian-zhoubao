# 如何让公众号文章自动写完、自动配图、自动上传？

做公众号的朋友都懂：找选题、写正文、配图、排版、上传，每一步都是时间黑洞。尤其当你需要批量产出高质量内容时，重复性操作简直让人崩溃。

今天我想和你分享一个“偷懒”方法——用 n8n 把整个内容生产流程串成一条全自动流水线。从提取资料、让 AI 写文章，到自动生成配图、上传公众号素材，全程无需手动干预。

这条流水线是怎么跑的？我拆给你看。

**第一步：把分散的资料“打包”成一个标准数据包**

在开始写作之前，总得先收集各种信息。工作流的第一节点会从你的表格里，把“AI爆款理由”、“文章目标”、“参考文章”、“用户画像”、“素材”这五类内容提取出来，再用一条竖线拼接成一个长字符串。这样，后续所有节点都能拿到统一格式的输入，不会出现字段缺失之类的怪问题。

**[PRE0] 交给大模型：生成文章和图片提示词**

资料打包好了，系统会把数据包发送给 qwen-plus 模型，同时附上一套精心设计的提示词。要求它扮演资深新媒体主编，分析同行爆款的结构和亮点，再结合用户画像、文章目标等内容，生成一篇 2000 字左右的公众号原创文章，并输出为严格的 JSON 格式——里面既有 HTML 正文，也有纯文本正文，还有至少三张配图的图片提示词，以及一个按“数字+人群+痛点+方案”格式起的爆款标题。

**[PRE1] 处理模型的返回结果**

模型返回的是一串 JSON 文本，n8n 里这个节点会先把它解析成 JavaScript 对象，再把 Prompt 数组里的每个图片提示词提取出来，用竖线拼接成字符串，方便后边逐条生成图片。解析成功后，还会额外增加一个 PromptString 字段，让整个数据流更顺畅。

**[PRE2] 把生成结果写回表格**

拿到文章和提示词后，下一步是把它们存回多维表格。节点会把 HTML 正文、纯文本正文、图片提示词字符串以及标题，分别写入对应的字段，方便你随时查看和校对。

**[PRE3] 拆解图片提示词**

写回的图片提示词是一整串文本，这里会按照竖线分隔符拆开，变成一个个单独的提示词对象。每个对象都包含一个 prom 字段，相当于给后面的图片生成环节准备了“订单清单”。

**[PRE4] 调用图片生成模型**

接下来，每个提示词都会被送到 qwen-image-plus 模型。节点会设置负向提示词、关闭水印、指定 1664×928 的尺寸，然后等待模型返回一张和场景高度匹配的插画。所有请求都是独立循环发送的，所以即便有十几张配图，也能在几分钟内全部跑完。

**[PRE5] 收集生成图片的 URL**

图片生成完成后，接口会返回一个 JSON 数据，这里会把图片下载链接提取出来，并且和对应的提示词文本捆绑在一起，方便你后面对照检查。每一张图都配上“原图+提示词”，就算以后想复现风格，也有据可查。

**[PRE6] 合并所有链接和参数**

现在，所有图片的 URL 已经躺在列表里了。这个节点会一次性把它们全部收集起来，用竖线合并成一个长字符串，同时还会带上多维表格的 token、表格 ID、选中的行记录，以及微信的 access_token。这些信息是后续上传素材和更新表格所必需的。

**[PRE7] 选出封面图**

文章通常需要一张封面。这个节点非常简单：从合并后的 URL 列表里，取出第一个链接作为封面图。当然，你也可以根据自己的需求修改逻辑，换成指定某一张。

**[PRE8] 给封面文件改名**

微信公众平台要求上传的图片有文件名，这里会把封面对应的二进制文件重命名为“cover.png”，这样既统一规范，也能避免一些奇怪的字符导致上传失败。

**[PRE9] 上传封面并提取 media_id**

接着，系统会把这张封面图通过接口上传到微信公众号的素材库。上传成功后，接口会返回一个 media_id，这个 ID 是公众号识别素材的唯一凭证，后续排版发布时可以直接引用。

**[PRE10] 把封面 ID 写回表格**

拿到 media_id 后，节点会更新表格里的“封面ID”字段，让整个流程记录完整可追溯。这样下次再跑同一篇内容时，就能直接复用封面，不用重复上传。

**[PRE11] 更新剩余字段，闭环完成**

最后，工作流还会再执行一次字段更新操作，把最终确认的正文、标题等数据同步到表格，确保所有信息保持一致。到这一步，一篇带配图、带封面、带标题的文章就已经整整齐齐地躺在你的表格里了，只需要手动点一下发布，或者再接一个自动发布节点，就能完成最后一步。

你发现没有？整个流程真正需要人工介入的，只有最开始录入素材，和最末尾点击发布。中间的写稿、配图、命名、上传，全部交给了机器。如果你也想把内容团队从重复劳动里解放出来，不妨照着这个思路，在 n8n 里搭一条属于你自己的“爆款生产线”。
