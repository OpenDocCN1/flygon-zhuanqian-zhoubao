不少刚接触 n8n 的人都会好奇：为什么这个自动化工具用起来这么顺手？答案可能出乎意料——它的创始人其实是设计师出身，而非程序员。正是这种背景，让 n8n 的界面交互处处透露着精心打磨的痕迹。大量“拖拽”式操作虽然对新手来说需要一点适应时间，但只要多点点、多拉拉，你会发现很多隐藏的小惊喜。等你真正熟悉之后，就会忍不住感叹：这产品用起来是真舒服。

### 左侧栏：工作流、凭证与执行记录

点开左侧的“Overview（概览）”，你会进入“Workflow（工作流）”页面。顶部分别排列着：

*   **Credentials（凭据）**：所有凭证统一存放在这里，方便随时查看与管理。
*   **Executions（执行）**：相当于所有工作流的“运行档案”，每一次自动化流程的启动过程、输出结果以及潜在异常都会被记录下来。如果某次运行出现错误，页面会显示 Error，你可以顺着提示定位到出问题的具体节点。

### 中央工作区：像白板一样自由创作

这是你搭建工作流的主战场。你可以把不同节点拖到这里进行连接，还能借助“便利贴（Sticky Notes）”写下备注说明。

#### 怎么写一份工作流“操作说明书”？

在构建和调试自动化流程时，你通常需要反复点击 “Execute step”，确认每一个环节都按预期运行。不过，一旦工作流稳定上线，你基本不会天天回来看它——除非出了岔子。

这时候，把工作流的思考逻辑和操作步骤记录下来，就变得非常有价值。它就像给未来的自己或同伴留下的一本操作手册，同时也是对当下设计的一种深度复盘。复盘不只是简单回看，而是为了在未来实现真正的有效提升。

养成记录习惯，不仅能让你快速重温工作流的设计思路，更能在故障排查时提供可靠线索，让自动化流程的维护变得轻松许多。

具体做法很简单：

1.  进入 n8n，打开你需要做记录的工作流；
2.  点击工作区右侧的便签按钮，添加一张便利贴；
3.  在便利贴里记录你的思考逻辑和步骤说明。Sticky Note 支持 Markdown，所以可以灵活使用标题、粗体、链接等格式。

[PRE3]

#### 关于 Executions 的那些事

在画布顶部切换到 “Executions” 标签，就能看到该工作流历次运行的完整记录。

这个功能特别实用——因为 n8n 的画布不会自动保存，如果你想找回以前设计过的逻辑片段，就可以来这里翻找历史记录，甚至把它们重新复制回画布。

Executions 页面中的每个节点都可以点击查看，里面包含详细的配置信息和 Log 日志。

#### 自动化两大核心概念：触发器与动作

一个自动化工作流通常由两种节点构成：**触发（Trigger）** 和 **动作（Action）**。

举个日常例子：「早上 8 点的闹钟响了，你就起床刷牙。」这里的“闹钟响”就是触发点；“起床刷牙”则是要执行的动作。

*   **触发节点：什么时候开始执行流程？**
    这个节点相当于告诉 n8n：“嘿，该干活了！”比如：当有人填写了 Notion 表单、当某篇 Facebook 帖子发布，或者当时钟走到某个固定时间点。
    添加节点时，只要看到节点名称后面带有“闪电符号”，就说明它可以作为触发节点使用。

[PRE7]

*   **动作节点：具体要做什么？**
    当触发节点被激活后，动作节点就开始执行相应的操作。例如：每天早上 9 点发送邮件摘要，或者当有新订单时自动更新 Notion 数据库。

    提示：一个工作流里通常会有多个动作节点。动作节点越多，需要测试的内容就越多，一旦出了问题，需要排查的位置也会相应增加。建议新手刚开始从简单的工作流练手，再逐步增加复杂度。

*   **数据该存到哪里？**
    想清楚触发点和动作之后，还有一件重要的事：决定数据“输入/输出”的存放位置。比如常用的 Notion、Discord、Telegram（配置简单、速度快、功能齐全），或者 Google Sheets，这些都是很好的数据记录工具。

#### 节点详情页界面介绍

n8n 的每个节点都分为三大区域：**入参区域**、**处理逻辑与设置区域**、**出参区域**，分别对应节点详情页的左、中、右三个位置。

[PRE8]

*   **入参**：显示当前节点从上一个节点接收到的数据。
*   **处理逻辑与设置**：用来配置当前节点的处理逻辑。
*   **出参**：展示入参数据经过处理后的结果，以及对应的处理日志。

入参和出参区域都提供三个查看选项：Schema、Table 和 Json。

[PRE9]

*   **Schema** 视图：展示上一个节点输出结果的元数据（可以理解为字段名或表头）以及样例数据。
*   **Table** 视图：以表格形式展示上一个节点输出的全部数据。
*   **Json** 视图：以 JSON 格式展示上一个节点输出的全部数据。

无论你处于哪种视图模式下，都可以把入参区域中的变量名，直接拖拽到中间的“处理逻辑与设置”文本框里，从而引用上一个节点产出的数据来进行处理。

更妙的是，你不仅能选择上一个节点的变量，还能选择上上个、上上上个……所有前序节点的变量。这些数据经过多个程序处理和传递后，n8n 会在内部自动建立唯一关联，根本不用担心数据“串错”的问题。这就是 n8n 中非常重要的“隐式传递”设计思路。

设置好逻辑后，点击 “Execute step” 按钮，只要上一个节点有缓存的处理结果，系统就会开始单步调试——也就是只执行当前节点的任务。

## 实践学前班：n8n AI 节点完整指南（选修）

### 前言

n8n 内置了可视化的 Langchain 节点，可以让你快速接入各种大语言模型。不过，在正式上手之前，有几个基本概念需要先搞清楚。

### 基础概念扫盲

#### 什么是大语言模型？

大语言模型本质上是一种深度学习模型，核心任务是理解和生成人类语言。它通过海量文本数据（网页、书籍、论文等）进行训练，从中学习语言的规律和结构。

你可以向它提问，它会尽量给出相关回答；你输入半句话，它能帮你续写下去。更进一步，你甚至可以让它根据自然语言描述生成代码，或者分析一段文本中蕴含的情绪倾向。

#### 有了 ChatGPT Plus 就够了吗？

很多人以为订阅了 ChatGPT Plus 就万事大吉，这其实是个误区。

ChatGPT Plus 确实说明你能访问海外网络，这一点很重要。但这只是第一步——想要使用 GPT-4、Gemini Pro 或 Claude 3 的 API，你还得注册开发者账号。

简单来理解：

*   **ChatGPT** 是给人使用的聊天界面；
*   **GPT-4 API** 是给程序调用的接口；
*   **n8n 需要的是后者**。

所谓 API，就是应用程序接口，它定义了软件组件之间交互的规则。n8n 作为自动化程序，必须通过 API 才能调用 AI 能力。

至于各家 AI 厂商的开发者账号注册方式，涉及一些比较敏感的话题，这里就不展开讲了。

#### LangChain 到底是什么？

LangChain 是一个专门为大语言模型接入而设计的框架。它最大的价值在于把不同模型的 API 接口做了统一——无论是 GPT-4、Gemini Pro，还是 Claude 3，在 LangChain 眼里都以同样的方式调用。

这意味着什么？你在调试工作流时，可以随意切换不同的 AI 模型，而无需重新配置所有参数。LangChain 就像是 AI 与程序员之间的“翻译官”。

在 n8n 中，LangChain 以节点形式存在，并且包含多个子节点。这种设计大大提升了调试效率。

### 节点总览

n8n 的 Advanced AI 是一个专门的节点分类，里面包含多种 AI 节点类型。每个节点的介绍中都会写明用途，你还可以通过 AI Templates 下载社区贡献的现成方案。

这里重点介绍两个最常用的节点：**Basic LLM Chain** 和 **AI Agent**。

### Basic LLM Chain 详解

Basic LLM Chain 是最简单的 AI 节点，非常适合一次性文本处理任务，比如文本总结、语法纠错、内容分类等。

它的逻辑很直白：接收上游数据 → 将 Prompt 和数据提交给 AI → 返回结果。

**Model（必填）**

这是一个子节点，需要单独添加到工作流画布上。n8n 目前支持这些模型：

*   Google PaLM/Gemini Chat Model
*   Groq Chat Model
*   Mistral Cloud Chat Model
*   Ollama Chat/Model
*   OpenAI Chat Model/Model
*   Cohere Model
*   Hugging Face Inference Model
*   Azure OpenAI Model
*   AWS Bedrock Chat Model
*   Anthropic Chat Model

不同模型的参数设置会略有差异，具体可以查看官方文档。

### Chat Trigger 说明

Chat Trigger 是一个特殊的触发器，可以通过聊天窗口启动工作流。

几个要点：

*   无需配置参数，创建即生效；
*   每发送一条消息，就会完整触发一次工作流；
*   默认不记录对话历史，每次都是“全新开始”；
*   虽然系统建议把它与 AI 节点连接，但你完全可以把它当成一个普通的输入触发器来用。

## AI Agent 深度解析

AI Agent 是 Basic LLM Chain 的升级版，它把 LangChain 的潜力真正释放了出来。从外观上就能看出差别——它拥有更多插槽，可以连接更多子节点。

[PRE15]

### Agent 类型详解

**Conversational Agent**
*   专为对话场景设计；
*   支持 Memory（记忆）和 Tool（工具）；
*   既可以添加上下文记忆，也能接入搜索、天气等外部工具。

**Tools Agent**
*   用自然语言来操作工具；
*   典型应用：让 AI 做精确计算（因为对 AI 来说，计算器就是一个工具）；
*   不支持上下文记忆。

**OpenAI Functions Agent**
*   专用于 Function Call；
*   适合需要调用特定函数的场景。

**Plan and Execute Agent**
*   通过自然语言调用多个工具；
*   AI 会自主决定使用哪些工具，以及如何组合它们。

**ReAct Agent**
*   Plan and Execute 的进阶版；
*   工作模式类似 ChatGPT Plus；
*   AI 会根据任务选择工具、检查结果，如果不满意会尝试其他方法；
*   可能发起多次 AI 请求。

**SQL Agent**
*   直接与 SQL 数据库对话；
*   支持 Memory 功能。

### Memory 子节点选择

AI Agent 支持多种记忆服务：

**Window Buffer Memory**
*   基于浏览器窗口的缓存记忆；
*   优点：无需额外部署；
*   缺点：页面一刷新就没了。

**Redis Chat Memory**
*   存储在 Redis 缓存服务器中；
*   刷新后记忆仍然可以找回；
*   属于短时记忆，会按时间策略被清理。

**Motorhead**
*   专为 AI 设计的开源记忆服务；
*   支持记忆的存储、向量化和检索。

**Xata**
*   面向 AI 的无服务器数据检索系统；
*   付费服务，无需自己部署；
*   相当于在云端购买了一个即插即用的数据库。

**Zep**
*   另一家 AI 长期记忆服务商；
*   付费使用，免部署。

### Tool 子节点功能

Tool 子节点让 AI 能够执行特定的非 AI 任务：

**Calculator**
*   传统数字计算；
*   避免 AI 出现“1+1=8”这种尴尬错误。

**Custom Code Tool**
*   自定义 JavaScript 或 Python 代码；
*   让 AI 调用你亲手写的工具。

**SerpAPI**
*   Google 搜索 API；
*   让 AI 具备联网查资料的能力。

**Wikipedia**
*   从维基百科获取信息；
*   能有效减少 AI 的“幻觉”问题。

**Wolfram Alpha**
*   学术型问答搜索引擎；
*   信息质量更高，支持高级数学问题。

**Custom n8n Workflow Tool**
*   把其他 n8n 工作流当作工具来调用；
*   这可是一把“大杀器”。

对中文用户来说，Custom n8n Workflow Tool 尤其有用。原版 n8n 缺少连接国内平台的能力，但通过这个工具，你可以先做一个“向飞书发消息”的工作流，再把它当作工具接入 AI 节点。这样一来，AI 完成任务后就能自动推送通知到飞书。

### 扩展应用

掌握了 Basic LLM Chain 和 AI Agent 后，其他 AI 节点基本都能举一反三。比如 OpenAI 节点支持绘画和文件上传，Question and Answer Chain 专门优化了知识库问答——但核心逻辑始终是：输入数据 → 规定 AI 行为 → 接入合适工具 → 获取结果。

n8n 官方社区还有一个模板市场，通过 Advanced AI > AI Templates 就能进入。里面有很多现成的 AI 功能模板，一键复制即可使用。

如果所有预制节点都无法满足你的需求，还有 **LangChain Code 节点**。顾名思义，你可以直接编写 LangChain 代码，定制 AI 的任意行为。

n8n 的 AI 节点体系设计得非常巧妙，从简单的 Basic LLM Chain，到复杂的 AI Agent，再到完全自定义的 Code 节点，基本覆盖了所有应用场景。

关键在于理解每种节点的适用场景：

*   一次性文本处理 → 用 Basic LLM Chain；
*   需要工具调用和记忆功能 → 用 AI Agent；
*   有特殊需求 → 直接写自定义代码。
