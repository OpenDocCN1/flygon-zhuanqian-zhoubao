# 我现在能做到什么程度

目前主攻的是 AI 达人秀赛道的 Shorts。抛开爆款复刻，常规的制作链路是：构思分镜 -> 分镜出关键帧图 -> 关键帧图转视频 -> 视频拼接。

这条链路里绝大部分环节都能被自动化，只是目前我的技术还做不到全链路一键串通。现阶段的落地效果是：分镜图的 PS 修图和图生视频的审核这两种需要人眼判断的操作保留人工干预之外，其余环节都已实现无人化处理。

其实不止达人秀，凡是动作能标准化的赛道，都可以考虑上自动化，把人的精力留给更核心的创意和把关。希望这套思路能给你启发。

# 我用的工具组合

这套方案核心是 coze、影刀 RPA、豆包、Monica、Runway、飞书这几块拼起来的。

*   **coze**：负责达人秀场景的策划，并自动产出多组备选分镜图；
*   **影刀**：去自动操控那些只有网页界面的客户端，比如 Monica、Runway。不是不想调 API，主要是 API 成本太高；
*   **豆包**：字节系，和 coze 集成很顺。个别图不满意时可以单独召回补图。有人吐槽豆包出图不行，我的实测是提示词写到位了，效果完全可用；
*   **Monica**：一个大模型集合器，能随时切 GPT、Claude、Gemini。我主要让 Claude 帮我写首尾帧之间图生视频的过渡关键词；
*   **Runway**：图生视频环节，性价比高，除了大动作戏份，日常质量已经能用；
*   **飞书**：用来沉淀 coze 产出的场景和分镜图，方便统一管理。

## 达人秀场景设计 + 自动生成分镜

这是整个系统里最复杂的一环，需要一点技术基础和工作流搭建经验。做出来后想直接分享现成模板，但工具是用谁的额度算谁的，所以还是教大家自己搭。

大体思路是：我指定一个动物，coze 自动调用豆包生成几个分镜的文生图提示词，并把每个分镜的提示词拆开，每组生成 4 张备选图，最后写入飞书表格。

#### 开始节点

开始节点接收被拆分后的提示词数组，并为每个场景自动出 4 张图。配置要点如下，点击节点后右侧会出现配置面板：

[PRE6]

BOT_USER_INPUT：自带的参数不用改，设为非必填；
prompt_array：分镜提示词数组，变量类型选 Array<string>，必填，无默认值；
concurrent_count：并发线程数，变量类型 Integer，必填，默认 4，这个并发量比较稳，太高容易报错；
batch_count：每个场景出图数量，变量类型 Integer，必填，默认 4，4 张基本够用了，极少才需要补。
