# 从“工具奴”到“AI指挥官”：一场关于内容生产新范式的实战复盘

这两天，朋友圈被一场特殊的“AI大考”刷屏了。据说，参与者们像备战高考一样，前一晚熬夜调试网络、赶制课前作业，只为迎接接下来两天高密度的实战洗礼。

这并非传统意义上的考试，而是一场关于“AI Native”的深度研修。我最大的感触是，AI的发展速度，已经从“万事不决问AI”，进化到了“让AI独当一面，而我们成为管理者”的新阶段。这种变化之快，确实让人有“稍不留神就掉队”的紧迫感。为此，这次大课特别邀请了三位在AI业务一线实战的专家——包子老师、叁斤老师和楚川老师，系统拆解AI Native时代的内容生产新法则。

以下是我从这场信息爆炸的大课中，提炼出的核心思考与笔记。

## 第一部分：包子老师——做好AI的“伯乐”，而非“马夫”

开场分享的包子老师，是超级个体（OPC）的典范，他一个人产出的效率，甚至超过了许多百人团队。这堂分享击中我的，并非某个炫酷的技巧，而是一个认知上的根本校正：

**很多人并非不会用AI，而是仍在用旧工作模式去指挥AI。** 结果就是，AI速度越快，产生的“半成品”就越多，反而让自己更加疲惫。要实现真正的AI Native，核心是用AI彻底重构工作流，而不是把自己变成流程中最慢的一环。

### 1. 什么是真正的AI Native？

试想，你听到“apple”这个词，先要翻译成“苹果”，再在脑海中形成画面——这不是母语思维。只有当你听到“apple”时，大脑能直接理解其含义，无需翻译，这才算“Native”。

AI的应用同理。

*   **使用AI**：让AI帮你写文案、做客服、查资料，这仅仅是给旧流程添了个新工具。
*   **AI Native**：重新设计你的工作流程，让AI成为生产链路中不可或缺的“原生”部分。

**AI Native的精髓，不是让AI帮你完成旧工作，而是让你有能力重新设计工作。**

实现这一转变的抓手有很多，比如知识库、上下文管理、工作流设计、人机分工等。最高级的玩法是将其叠加，例如包子老师结合知识库、AI音乐、数字人，制作趣味横生的专业介绍视频，甚至构建了一套完整的升学SaaS系统，用AI优化直播、实现客服自动化。他已经用AI重塑了全部工作流。

### 2. 世有伯乐，而后有千里马

AI的能力之强，堪比一个全科博士或高级工程师。但为什么在很多人手中它却“跑不起来”？问题不在于AI，而在于我们一开始就给它套上了太多“缰绳”。

以下四根缰绳，看看你中了几根？

*   **旧流程惯性**：习惯把事情拆解成A、B、C、D、E，只让AI做其中一小步。
*   **工具视角**：把AI当作写文案、做客服的软件，而非能判断方向的协作伙伴。
*   **信任缺失**：只给AI极窄的上下文，只允许它回答当前这一个问题。
*   **想做总调度**：目标、资料、判断、拆解、推进、验收全部攥在自己手里，AI只能被动接活。

松开缰绳，不是让AI信马由缰，而是为它铺设一条能真正奔跑的赛道：**完整的现场、清晰的目标、明确的边界、可检验的成果**。

今天包子老师分享的核心，就是如何从“用AI制造更多半成品”，走向“让AI深度参与完整生产”。这具体化为两个生产方式的升级：

*   **升级一：用AI重塑旧流程。** 将原本卡在人身上的生产链路，改造为AI能参与、能推进、能验收、能沉淀的流程。
*   **升级二：用AI创造新产品。** 当AI大幅降低生产和组织成本，过去无法实现的个性化交付，就可能成为新的产品机会。

### 3. 为什么用了AI，反而更累？

包子老师分享了一个真实的“踩坑”经历，引人共鸣。他曾在高考前赶制一批视频，传统流程“写稿→录制→剪辑→字幕→特效”完全来不及。

他本能地求助于AI：写稿、起标题、整理素材，每一步都加快了，但最终视频依然难产。为什么？

**因为AI产出的只是“半成品”。** 稿件有了，却不一定适合口播；口播顺了，上屏文字又一团糟；文字OK了，视频风格又接不住。零件越来越多，而组装这些零件的人，依然是他自己。

最扎心的一句话是：**“我以前最强的能力（剪辑判断），反而变成了整条生产线最大的瓶颈。”**

### 4. 真正的转变：把自己从流程中“拿掉”

这是整场分享的转折点，也是方法论的精髓所在：

*   **空杯心态，承认“无知”**。
*   **把自己从流程里拿掉**。
*   **让AI来主导流程**。
*   **与AI充分讨论，给予足够上下文**。
*   **让AI来决定人机如何分工**。

包子老师做了一个关键实验：不追求完美，让AI完整地做一版——稿件、上屏、数字人口播、画面节奏、特效剪辑，全权交付，他只审阅最终结果、把控大方向。

结果虽不完美，但“能用”了。**不完美没关系，关键在于它从“材料”变成了“成果”。有了成果，人才能判断方向。**

从这一刻起，分工彻底改变：

*   **AI负责**：大量执行、初版生产、整理组织、跑通第一版。
*   **人负责**：方向、标准、审美、业务判断、最终验收。

最终的产出物，不只是一条视频，而是一条**视频生产线**：资料输入 → AI生成草稿 → 系统预览 → 人工审核 → 修改沉淀 → 下一条复用。

现场有两个可以直接拿走的认知：
*   **工作流无需从零设计，可以直接向AI提问。** 不要自己硬想分工，先问AI：“针对这个项目，你对我们的分工有什么建议？”
*   **先跑通“最小闭环”，再升级“生产闭环”。** 第一张图跑通，证明“这条路能走通”；能每天稳定批量产出、失败可重跑、结果可追踪，才叫“生产闭环”，才能让别人放心使用。最好是像包子老师那样，用工具将流程搬到云端并挂载到协同平台上，实现“@一下就出活”——从“在家试做一道菜”到“餐厅后厨稳定出餐”。

## 第二部分：叁斤老师——搭建7x24小时全天候的“AI内容获客系统”

紧接着包子老师的“AI Native工作流”，叁斤老师聚焦于最关键的环节之一：**如何将你的个人经验，沉淀为一个AI随时可调用、并能自我进化的知识库。**

他称其为“AI内容获客系统”，但其本质与“获客”关系不大——它并非教你写爆款，而是搭建一套让你个人经验自动产生复利的系统。

### 1. 为什么创始人必须自建AI知识库？

叁斤老师直指几个几乎所有老板都会踩的痛点：

1.  **经验记不住，留不下**：与客户交流后，对方提了10个需求点，现场只记住1-2个；学习后笔记零散，不久就忘了具体步骤。
2.  **经验都在老板脑子里，团队无法复制**：小团队最怕招人、带人难。产品卖点、客户案例、方法论全在老板脑袋里，员工无从下手。让员工写宣传文案，写不出老板的深度；老板亲自写，又缺乏专业运营能力。
3.  **工具用了一堆，却落不到业务上**：知道AI厉害，但没人教如何将其接入具体业务。工具用了不少，但只停留在ChatGPT、Claude官网对话框里的闲聊，聊完即忘，毫无沉淀。

有了这套知识库系统，链路彻底改变：客户沟通内容自动入库；课程学习内容由AI提炼成方法论，随时复用。**一份输入（哪怕是录音），能产生无限次价值。**

这里他强调了一个关键认知：**真正的差距不在模型本身。** Claude、GPT、Gemini等模型谁强谁弱无关紧要，因为模型始终在升级迭代。真正属于你、能沉淀下来的资产，是这套系统，而非某个模型。

他举例了一家旗袍定制老板的案例：以往款式卖点、客户案例全在老板脑中，员工写的文案只能平铺直叙。搭建知识库后，AI自动调取产品卖点、客户画像、定制过程，生成结构化文案——**同样的人、同样的产品，差别就在于背后是否有一个“懂卖点”的知识库。**

### 2. 这个AI知识库该如何搭建？

搭建流程可拆解为“选工具 → 搭骨架 → 喂内容 → 三个进化设计 → 跑通闭环”。

**第0步：核心工具**
*   一个能操控本地文件的AI（如Codex或Claude Code，任选其一）。
*   一个知识库软件：Obsidian（本地化、结构化、移动端同步）。
*   为何非Obsidian不可？因为知识库的核心是让AI可读取。Notion/飞书文档数据在云端，AI读不了；Notebook只能查不能补充；Cursor/Trae无法可视化同步。一句话总结：**Git是给AI看的，Obsidian是给人看的，两者配合使用。**

**第1步：搭骨架——六大核心知识库 + 采访机器人**
先建立六大知识库（这是地基）：① 个人说明书 ② 产品库 ③ 客户需求库 ④ 素材案例库 ⑤ 方法论库 ⑥ 内容生产库。
建好后是空的，需要跑一遍“采访机器人”，让它采访你，自动将信息归类填入，让AI从此“知道你是做什么的”。后续一切自动分类、筛选都依赖这一步。

**第2步：喂内容——收录外部优质信息**
*   **图文**：用Web Clipper插件一键采集进Obsidian。
*   **视频**：用工具抓取逐字稿，同步至Obsidian。
*   收集后，用“录音处理skill”自动归档成方法论。

**第3步：三个进化设计（系统精华）**
知识库存久了会有三个问题，用三个机制解决：

1.  **让AI调得更准：主题分类 + 双标签**。不要按“来源”分类（如“某书的笔记”），因为AI写销售文案时，不知道哪本书讲销售。要按主题分（销售/营销放一起），并打两个标签：来源标签（可追溯）+ 应用标签（未来用于何处）。
2.  **让素材不重复：三次封顶机制**。为防止AI偷懒，设置规则：一个素材最多用3次，用满自动移入“已过时素材”区（不删除，特殊情况可调回）。这样素材库像河流一样，有进有出，越跑越厚，而非一潭死水。
3.  **让知识库自我进化：跑“体检”**。六大库是通用版，不贴合你的业务。让AI参照你的业务做一次全面体检，它会指出你缺什么，由你拍板新增。

**第4步：跑通——录音处理skill**
将一段录音丢进“待处理”文件夹，告诉AI“帮我处理”——它会自动识别音频类型（长/短录音、对话），分配资源处理，产出选题、方法论、需求素材，并分流入库。这一步是链路真正跑通的关键。

### 3. 最终成型：自动滚大的五步复利闭环

将所有环节串起来，就是一套自我强化的循环：

**输入（聊天/录音/课程）→ AI自动沉淀入库（六大库分类）→ 调用skill生产多平台内容 → 分发 → 数据回流复盘（读取数据，让AI提炼“哪些标题/开头数据好”，沉淀为新方法论）**

每跑一圈，知识库就加厚一点，产出的内容就越来越像你本人所写。

### 4. skill的三种“聪明玩法”

如果说知识库是“资产”，skill就是“将重复劳动固化的流程”。

1.  **让skill织成网**：每个skill运行后，自动推荐“下一步该做什么”。无需记忆安装了多个skill，跟随AI的推荐链路即可。
2.  **Big10对标取标题**：起标题最耗时耗力。将10个风格差异巨大的对标账号标题风格喂给AI，写作后让它一次生成10-20个备选标题，让起标题变得可控。
3.  **让AI反向学习你的修改**：AI初稿修改后不要直接发布——让它对比“初稿 vs 终稿”，分析你的改动遵循了哪些方法论，沉淀进风格库。**你每改一次，AI就更懂你一分，未来你要修改的地方就会越来越少。**

还有两个值得借鉴的方法：
*   **制作skill无需懂原理**：手动跑一遍流程，告诉AI“帮我固化成skill即可”。若无现成流程，可让AI去GitHub等平台搜索成熟方案，它会根据你的定位推荐最合适的，并提醒潜在风险。
*   **保留“半自动”而非“全自动”**：重复性工作交给AI，但“写哪个选题、发不发、好不好”等关键节点，永远需要人来做最终决策。

## 第三部分：楚川老师——AI内容工程化，把内容做成生产线

下午压轴的楚川老师，将前两位老师反复提及、但未深入展开的词，讲透了——**判断力**。

如果说包子老师讲“让AI接管流程”，叁斤老师讲“搭一个会复利的知识库”，那么楚川老师回答的正是更底层、更关键的问题：**知识库里究竟该装什么，AI产出的内容才能真正代表你、甚至替你做出判断？**

### 1. 三位老师的两个共识

听完一整天，你会发现三位老师的路径虽不同，但有两个判断高度一致：

*   **共识一：让AI主导并承担整条生产流程。** 不再是人在一线干活、AI打下手，而是把大量执行——写文案、做素材、出图、剪视频、整理沉淀——尽量交给AI去跑，人从“亲自做”后退到“设计与指挥”。
*   **共识二：人退到判断位，负责审美、品味与判断力。** 叁斤老师讲“半自动而非全自动，关键判断权永远在人”；楚川老师则更直接——**AI解决不了审美问题，也解决不了质检问题。** 因此，他们反对一键生成、反对完全自动化。人审100条素材、100张图、100条视频，用半小时沉浸进去的，是审美、质感、品味和判断力，这是AI无法替代的环节。

两个共识合起来就是一句话：**AI负责大规模生产，人负责判断与决策。** 而楚川老师接下来重点分享的，正是“人的判断力，如何沉淀进系统、让AI也能具备”。

### 2. 最核心的新知：知识库的灵魂是“判断力”

楚川老师将知识库分为三层，并指出大多数人只做了前两层，恰恰缺失了最关键的第三层：

*   **① 信息层**：让AI知道你卖什么（产品参数、定价、使用场景、通用知识）。
*   **② 故事层**：让AI知道你是谁（深度访谈、创始人经历、用户案例、研发故事）。
*   **③ 判断力层**：让AI替你决策。**这才是知识库的灵魂。**

为什么你的知识库不管用、AI总出现幻觉？因为你只塞了第一层——产品参数、大盘数据、基础知识。AI识别不出你的特色，自然做不出你想要的内容。比如“益生菌对肠道有没有帮助？对，但没用”——这就是最无效的知识。

**那什么是判断力？** 是当客户嫌你贵时，你如何说服他；是写内容时，AI该从哪个角度切入。它由四块构成：**用户洞察、竞品认知、自身竞争力、失败的经历。**

楚川老师特别强调“**失败的经历**”在知识库中极为重要。现在AI帮他写口播稿、聊公司战略时，会主动提示他“你过去遇到类似情况是怎么想、怎么解决的”，判断力就在这样的对话中慢慢生长出来。

#### 判断力如何构建？两种知识库+具体来源
这是一套比“六大库”更聚焦的分类法：

*   **IP知识库（用于获客、做内容）**
    *   判断力来源：人生转折点、高光时刻、失败教训、被质疑的经历、客户嫌贵怎么聊、三观分析、做人红线。
*   **项目知识库（用于卖货、做运营）**
    *   判断力来源有两部分，操作性很强：
        1.  **竞品分析**：竞品发多少条内容、主打什么卖点、用哪些关键词、走什么链路。
        2.  **至少收集500个差评**——每个差评都代表“用户需求未被满足”。差评+竞品链路→就能倒推出适合自己的1~3条内容链路。
        *   从差评切入用户视角，补足竞品未关注的方向，天然就有一批种子用户在等你打动。这也是ROI越做越高的根本原因。

### 3. 判断力如何让文案有“人味”？一个具体案例

楚川老师举了一个例子。同样写“跑步”，豆包直接生成的是“跑步教会我的道理”——教科书般的鸡汤，毫无新意。而融入判断力（个人真实经历）后，挖出了受访者的原话：“逼自己跑5公里”“缠了多年的鼻炎慢慢变好”“感受到身心自由生长”——瞬间有了人味。

**结果**：后者文章篇幅是前者的2.5倍，拿下了她第一篇10万+爆文（现在阅读量已16万）；4个月产出了4篇10万+爆文。而构建过程只用了最朴素的动作：收集她朋友圈的高频词、句式、比喻 → 做一次2小时深度访谈 → 录音转文字 → 交给Claude整理成3万字 → 沉淀出金句库和内容模板。没有使用任何高级Agent，没有复杂操作。

### 4. 判断力会自我进化：反馈闭环 + “吸星大法”

判断力并非一次成形，它会越用越强：

*   **反馈闭环**：AI帮你设想10个切入角度，你做了其中6个且效果很好，将结果反馈给AI，它就能新增认知“这个方向有效”——知识库自身就完成了更新迭代。
*   **吸星大法**：看到别人产出爆款，立即拆解、融入自己的框架，测试有反馈后再迭代。新工具、新流量打法都这样被吸收进来。

因此，这套体系是越升级越强的——大模型迭代、新工具出现、他人的爆款方法论，都能被吸纳进同一套知识库中持续进化。

#### 一个被低估的认知：知识库“无边界”
最后，楚川老师提出一个格局更大的观点：**别把知识库局限于“做内容”。** 它应是你整个业务和认知体系的“操作系统”，驱动你做出更精准的决策，跑通更稳健的商业模式。
