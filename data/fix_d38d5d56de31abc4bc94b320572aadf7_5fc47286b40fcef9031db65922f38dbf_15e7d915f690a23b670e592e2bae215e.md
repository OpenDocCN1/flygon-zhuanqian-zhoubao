Claude 3.7 在审美把握、SVG 绘制以及在线配图能力上的跃升，让近期涌现的 HTML 创作案例异常活跃。可问题也随之而来：每个示例的指令都繁复冗长，仿佛要反复打磨，且不同品类的 HTML 指令各不相同，学习成本很高。

这张海报也是本次模板的产出。

于是我花了大半天把即刻、公众号等平台上走红的 HTML 案例收集下来拆解，消耗了不少额度，最终归纳出下面这套通用指令框架。用它便能产出精致的演示文稿、求职简历、个人名片、高保真原型、知识点卡片、动态交互模块等各类网页应用。

为何偏爱 HTML？

归根到底 AI 的运转底层就是代码：

*   文字对话 ➡️ 自然语言会被转成可识别的编码
*   图片/视频对话 ➡️ 多媒体会被切分为像素块，同样以编码形态被模型理解

相较于自然语言描述，代码是与模型沟通更直接的媒介。而 HTML 是搭建网页内容门槛最低的编码形式。

尚未接触过 HTML 也无关紧要，接下来我会示范如何借助 AI 批量生成各式 HTML 页面，请准备好接收干货。

## 通用指令框架

该框架覆盖了 HTML 生成的全流程要素，从视觉到技术，从素材到交付标准。覆盖面完整后，缺漏风险降低，输出可控性自然提升✅

[PRE1]

使用方式很直接：把你的业务需求与功能清单连同框架一起交给模型，让它先输出一份定制化的指令，再用这份指令生成 HTML 页面。

注意⚠️ 通常不是一次成型，有了框架支撑，一般 2-3 次对话迭代就能逼近预期效果。

## 框架拆解与填写要点

### 1. 身份定位

[PRE2]

说明：

*   职业角色：例如“界面设计师”“前端开发”“数据可视化专家”。
*   专业方向：例如“交互”“响应式”“分析”。
*   产出形态：例如“高保真原型”“产品落地页”“数据仪表”。

技巧：
✅ 可叠加：如“兼具数据分析与视觉呈现能力的全栈开发者”。

### 2. 任务概览

[PRE3]

说明：

*   内容类别与主题：如“销售数据看板”或“个人职业履历”。
*   使用目的：如“帮助团队快速捕捉趋势”或“在招聘场景突出专业背景”。

技巧：
✅ 尽量量化，例如“8页演示文稿”或“含6张图表的报告”。

### 3. 内容规划

[PRE4]

说明：

*   分析：引导模型拆解需求与背景，如“梳理目标用户的使用习惯”。
*   方案：要求规划设计，如“制定契合品牌调性的视觉与交互方案”。
*   实施：规定实现手段，如“基于 Flexbox 构建响应式栅格，保证多端一致”。

技巧：
✅ 步骤数随复杂度调整，3-5 步较为合适。

### 4. 视觉规范

[PRE5]

说明：

*   整体基调：如“极简现代”“科技感”“商务正式”。
*   色彩：指定主色与点缀，可用具体色号或 Material Design 等体系。
*   字体：如“无衬线为主，标题加粗”。
*   视觉元素：如“线形图标，以几何图形做背景点缀”。
*   交互动效：如“悬停微放大，卡片切换淡入淡出”。

技巧：
✅ 直接放一张参考图最省事。

### 5. 技术规范

[PRE6]

说明：

*   框架：Tailwind CSS、Bootstrap 或纯 CSS，通常推荐 Tailwind。
*   脚本：原生 JS、jQuery、React 等。
*   响应：适配手机/平板/桌面，断点如 576/768/992。
*   性能：首载 <2s，图片懒加载等。

技巧：
✅ 不熟技术可留空，让模型补全。

### 6. 素材配置

[PRE7]

说明：

*   图片来源：如“Unsplash 关键词 business”或“通过 CDN 引入项目素材”。
*   图标系统：Font Awesome、Material Icons 或自定义 SVG。
*   外部库：Google Fonts、Chart.js、GSAP 等。

技巧：
✅ 此环节影响观感，数据类页面务必明确可视化库，如 ECharts。

### 7. 交付要求

[PRE8]

说明：

*   代码规范：结构清晰、关键处注释、CSS 采用 BEM。
*   兼容范围：最新版 Chrome、Firefox、Safari、Edge。
*   文件形式：单文件 HTML 或分离式 HTML/CSS/JS。

技巧：
✅ 重点明确输出形态。

### 8. 补充说明与示例

[PRE9]

说明：
收纳不属于上述模块的特殊需求，如特定功能、无障碍、品牌限定等。

技巧：
*   能给示例就给；
*   若迭代效果不佳，不必反复修补旧结果，可回到此处重述需求再生成。

## 正确打开方式：让模型为你写指令

这套框架并非直接套用，而是用来让 AI 生成专属指令的“指令”。

例如近期为朋友做站，我把框架交给模型并输入朋友的需求描述，模型立刻输出了一份新指令。

[PRE10]

随后用这份新指令在 Claude 中生成 HTML，效率提升明显。

想把 HTML 做得好看，仍需实践：

1. 由简入繁：从小型项目入手，理解各模块作用
2. 灵活增删：按项目裁剪框架内容
3. 反复优化：依据产出反馈调整指令
4. 参考优秀案例：学习他人参数写法
5. 划定边界：避免需求过于宽泛导致页面臃肿
