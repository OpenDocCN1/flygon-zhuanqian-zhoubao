# Building effective agents 构建有效的智能体

2024-12-20

过去一年里，我们与数十支来自不同行业的团队一同搭建 LLM 智能体。经验归纳下来，最靠谱的落地往往不是堆砌复杂平台或专用组件，而是回归朴素、可复用的组合思路。

本文汇总了我们服务客户和自研过程中的观察，并为从业者提供一套落地的实践建议。

# What are agents? 什么是智能体？

“智能体”目前没有统一口径。部分团队把它理解为能够长期独立运行、调用多种工具来完成复杂事务的全自动系统；另一些团队则更偏向把它视作一套依循固化流程的规范化方案。在 Anthropic 的划分里，这些形态都可归为智能体范式，但我们在工作流与智能体之间做了关键的结构区分：

*   Workflows 是借助预置代码路径来调度 LLM 与工具的体系。工作流是通过预定义代码路径协调 LLMs 和工具的系统

*   Agents 则不同，LLM 会在其中动态主导自身流程和工具调用，对任务的完成方式拥有主导权。另一方面，在智能体系统中，大语言模型（LLMs）可以动态地指导自己的进程和工具使用，并保持对完成任务方式的控制

后续内容会分别深入这两种范式。附录 1《Agents in Practice》中，我们会呈现两个客户从中获得明显价值的应用情境。

# When (and when not) to use agents 何时（以及何时不）使用智能体

做 LLM 应用时，我们一直建议先求最小可行解，需要时再提升复杂度。有时甚至不必上智能体。智能体通常会以更高的时延与成本换取任务表现的提升，是否划算需要审慎评估。

当确实需要更复杂方案时，工作流能为边界清晰的任务提供稳定可预期结果；而智能体更适合大规模场景下需要高度灵活与模型自主判断的情形。对多数业务来说，仅对单次 LLM 调用做检索与上下文示例的优化，往往已足够。

# When and how to use frameworks 何时以及如何使用框架

市场上已有不少帮助搭建智能体的框架，例如：

*   LangGraph from LangChain; 来自 LangChain 的 LangGraph ;

*   Amazon Bedrock's AI Agent framework; 亚马逊 Bedrock 的人工智能代理框架；

*   Rivet, a drag and drop GUI LLM workflow builder; and Rivet 是一种拖放 GUI LLM 工作流构建器；以及

*   Vellum, another GUI tool for building and testing complex workflows. Vellum 是另一款用于构建和测试复杂工作流程的图形用户界面工具。

这些产品通过封装 LLM 调用、工具定义解析、调用串联等底层工作，降低了上手门槛。但同时也叠加了额外抽象，容易遮蔽底层提示与返回，提升排错难度，也容易诱导过度复杂化。

我们的实践建议是先直接调用 LLM API：大量模式可用极简代码实现。若选用框架，务必透彻理解其内部实现。对底层机制的误判是客户踩坑的高频原因。

可参考我们的 cookbook 查看参考实现。

# Building blocks, workflows, and agents 构件、工作流程和智能体

本节梳理我们在生产环境中看到的典型智能体模式。由基础构件——增强型 LLM 起步，逐步提升复杂度，延伸到组合工作流与自主智能体。

## Building block: The augmented LLM 构件：增强型 LLM

智能体系统的最小单元，是被检索、工具、记忆等能力增强的 LLM。当前模型已能主动运用这些能力——自行产出检索式查询、挑选适配工具、决定信息保留策略。

[PRE0]

The augmented LLM 增强型 LLM

落地时建议聚焦两点：一是按具体场景定制能力，二是为 LLM 提供简洁、文档完善的调用接口。实现路径多样，其中一种选择是借助近期发布的 Model Context Protocol，让开发者以极简客户端接入不断扩大的第三方工具生态。

本文后续内容默认每个 LLM 调用均已具备上述增强能力。

## Workflow: Prompt chaining 工作流程：链式提示词

Prompt chaining 将任务拆解为步骤链，后一步的 LLM 以前一步的输出为输入。可在任意中间节点加入程序化校验，即图中所示的 “gate”，以确保流程不偏离。

[PRE1]

The prompt chaining workflow 链式提示词工作流程

When to use this workflow: This workflow is ideal for situations where the task can be easily and cleanly decomposed into fixed subtasks. The main goal is to trade off latency for higher accuracy, by making each LLM call an easier task.

何时使用此工作流：此工作流程适用于可以轻松、简洁地将任务分解为固定子任务的情况。其主要目的是通过使每次 LLM 调用更容易完成，从而以延迟换取更高的准确性。

### Examples where prompt chaining is useful:

链式提示词有用的例子

*   Generating Marketing copy, then translating it into a different language. 制作市场营销文案，然后将其翻译成不同的语言。

*   Writing an outline of a document, checking that the outline meets certain criteria, then writing the document based on the outline. 编写文件大纲，检查大纲是否符合某些标准，然后根据大纲编写文件。

## Workflow: Routing 工作流程：路由

Routing 先对输入做分类，再分发至对应的专业后续任务。该模式实现了关注点的分离，让提示更聚焦。若不采用路由，单一优化往往会牺牲其他输入类型的表现。

[PRE2]

The routing workflow 路由工作流程

When to use this workflow: Routing works well for complex tasks where there are distinct categories that are better handled separately, and where classification can be handled accurately, either by an LLM or a more traditional classification model/algorithm.

何时使用此工作流程：路由功能适用于复杂的任务，在这些任务中，最好分别处理不同的类别，并通过 LLM 或更传统的分类模型/算法准确处理分类。
