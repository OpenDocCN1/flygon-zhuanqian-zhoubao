过去十年教育行业增长经验，我如何用 Codex 与 Obsidian 做成第二副脑

我叫娃哥，平时做教育机构获客，忙完爱喝两杯。这篇不是工具推荐文章，也不是“十个提示词做出爆款”那种快餐笔记。我想认真梳理一下，自己最近是怎么用 Codex 与 Obsidian，把过去在内容创作、流量获取、矩阵搭建、私域运营、投放、数据复盘和交付环节攒下的经验，逐步搭建成一套属于我自己的业务资产系统。

这套系统现在还远没到最终形态，但它已经解决了一个困扰我很长时间的问题：我做过不少项目，写过不少文章，改过不少稿子，踩过不少坑，也形成过不少判断。但这些东西过去散落在各处。有的在公众号后台，有的在飞书文档，有的在微信聊天记录里，有的在数据表里，有的干脆只在脑子里。每次要写新内容、做复盘、做方案、做交付，我都要重新翻找、重新回忆、重新组织。

更让我在意的是另一件事：很多教育机构的老板，缺的其实不是让模型帮忙写作的能力。你抛一个话题给 GPT、豆包、DeepSeek 或 Claude，很快就能得到一篇初稿。但写完就结束了，下一篇照样归零重来。你明明把多余的话删掉了，把业务判断补齐了，把一线细节加了进去，可模型不知道你到底改了什么。你嫌它写得不像人，却没有把“哪里不像、怎么改才像”这件事告诉它。

所以我现在愈发认定：最重要的不是学会让模型写一篇文章，而是让模型长期学习你的业务、你的内容、你的判断，最终成为你的第二副脑。下面我把细节尽量讲透。先解释这两款工具是什么，再讲我为什么拿它们来搭系统，接着拆我的实际操作：目录怎么排、主控文件怎么写、Agent 行为规范怎么定、初稿到人工修订再到反馈入库的流程怎么跑。最后用几个具体案例说明这套东西如何服务内容生产、数据追踪和项目增长。

文中涉及的业务数据、项目名、账号名和客户信息都会脱敏。所以你会看到“某项目”“某渠道”“某账号”“xx 万”“xx 条线索”这类说法，不是故弄玄虚，是为了保护真实信息。但方法、流程和踩过的坑，我会尽量说透。

一、先给结论：它不是写作工具，而是业务资产化系统

最关键的判断放在前面：Codex 与 Obsidian 组合真正值钱的点，不在于能把文章写得多快，而在于你做过的每一件事，都有可能留存为下一次随时可调用的资产。过去我写内容是一次性生产。写完、发掉、结束，最多把文章存档。现在整个流程变了。

每写完一篇文章，我会留下至少四样东西：模型初稿、人工修订稿、模型对比两版后总结出的修改偏好、最后进入资产库的精选语料或方法。如果文章背后有实际项目数据，我还会继续拆出案例复盘、选题素材、交付材料、运营 SOP。

这已经不是“写一篇文章”了，而是把一次内容生产变成一次模型训练。再往大一点说，我正在做的不是写作工具，而是一套教育行业增长经验资产化系统。底层逻辑是：真实业务产生素材与数据，Obsidian 承担长期存储与结构管理，Codex 的职责是读取、生成、修改、对比、归纳与执行，人工负责判断、取舍和补充真实细节。最后，所有这些修改、复盘和判断都会重新写回资产库，成为下一次工作的输入。

这个循环跑得越多，模型就越懂我。它知道我反感哪种表达，知道数据类内容不能写成报告，知道规则类内容要写清楚时间、账号和发布形式，知道给机构老板看的内容不能停在概念上，必须落到线索、成本、ROI、转化和组织动作。

它还会慢慢知道，写矩阵运营不能只讲账号数量，要讲风险、周期和承接；谈技术赋能教育行业不能只喊趋势，要讲普通机构眼下就能做的事。这是我最兴奋的地方：模型不是一次性变聪明的，它是被持续训练出来的。训练它的不是玄学提示词，而是你每一次真实修订、真实复盘和真实业务判断。

二、Codex 与 Obsidian 到底在做什么

很多同行听过这两个名字，但没有真正用过。我用外行能懂的方式解释它们在系统里的分工：Obsidian 管存储，Codex 管执行。

Obsidian 是一个本地笔记工具。它与飞书、Notion 或石墨这类在线协作文档不同，它的笔记本质上是一堆 Markdown 文件，放在你自己的本地文件夹里。一个目录就是一个库，一个 Markdown 文件就是一篇笔记，文件之间可以互相链接，也可以用标签、双链、图谱把内容连起来。

它天生适合做长期积累，比如历史文章、选题、标题、风格样本、方法、案例、产品资料、项目资料、个人思考、会议纪要、话术、用户问题。对教育机构来说，Obsidian 的核心价值在于“可控”：资料在本地，结构自己定，Codex 也能直接读取这个目录。

这个能力很关键。因为资料如果散在微信、飞书、公众号后台、Excel 和截图里，模型很难系统调用。一旦整理成本地资产库，模型才能持续围绕内容、数据、项目和方法工作，而不是每次临时翻一篇。

Codex 则可以理解为一个能读本地目录、能修改文件、能执行任务的模型助手。它本来是给程序员写代码、改代码、跑项目用的。我现在把它当本地资产库的执行助理。它能读取项目目录里的大量文件，能按规则检索资料，能新建、修改、移动、整理文件，能比较两个版本的差异，能把总结结果写回资产库，还能按 Agent 工作规范长期遵守一套流程。

这和通用聊天模型很不一样。通用聊天模型更像临时外援：你今天问一次，它答一次；下一次换个窗口，它可能又忘了你是谁。Codex 加本地资产库，更像办公室里的常驻助理。你给它规定“这个文件夹是我娃哥的教育行业增长资产库，开工前需要先读取主控文件、风格规范、人工修订记录和历史文章参考”，它就能按这套流程反复执行。你还可以指定初稿存哪里、修订稿存哪里、对比后怎么入库。它按规范工作，而不是每次都要从头摸索。

为什么不用 ChatGPT、豆包或 DeepSeek 就好？这些工具并不差，我自己也常用。但如果只写单篇内容，任何模型都可以；要做长期资产库，我更看重三点：能不能稳定读取本地文件，能不能按固定目录结构保存结果，能不能把人工反馈写回系统并让下一次变得更好。通用聊天工具适合临时问答，Codex 加 Obsidian 适合持续生产和积累。两者不冲突，只是分工不同。通用对话模型更像是外部大脑，Obsidian 是长期仓库，Codex 是在仓库里干活的人。

三、教育机构为什么格外需要这套系统

做电商、做短剧、做本地生活的人也需要资产积累，但我认为教育机构尤其需要。因为这个行业有一个很现实的问题：大量经验都长在人身上，而不是长在系统里。

某位老师很会讲课，但讲课心得只存在脑子里；顾问很会成交，但成交话术只留在微信对话里；运营很懂平台规则，但人一离职，账号就没人接得住；老板每月都在做渠道、预算、人员判断，但忙完之后，这些判断大多停留在记忆里。家长在私信里问了很多真实问题，却没人整理成选题、异议、内容素材；学生提分案例不少，却没人拆成可复用的内容弹药和销售弹药。

于是很多机构看起来做了很多事，真正能留下的却很少。结果就是每个月都像重新开始。换个运营，要重新讲一遍；换个销售，要重新培训一遍；换个平台，要重新摸索一遍；老板自己一忙，项目就停在那里。

我一直觉得，机构未来的竞争不只是课程和老师，也不只是流量和投放，而是经验能不能被留存、调用和放大。你的机构有没有一套机制，把老师遇到的高频问题、家长表达的真实焦虑、销售解决的关键异议、运营验证过的有效素材、矩阵里跑出来的爆款规律、内容生产背后的风格标准、项目复盘里的数据结论、老板做过的重要判断，全部留下来？

如果没有，模型再强，也只能给你一份通用答案。如果有，模型才可能成为内容策划助理、数据分析助理、运营复盘助理、产品交付助理，甚至新人培训助理。我现在做这套系统，是因为我越来越相信：不会积累的增长只能靠人力硬堆，能持续积累的增长才有机会变成系统。

四、底层结构：五类资产、两个主控、一条循环

我搭的这套东西结构并不复杂。一开始别搞得太重，先用一个最简版本。这个版本不追求把所有资料一次整理完，而是先让它能完成真实任务：能写内容、能做复盘、能收反馈。

第一类，内容资产区。这里放所有已经产出、以后还能复用的内容，例如公众号文章、小红书笔记、朋友圈文案、直播稿、短视频脚本、选题、标题、老师口述语料、家长问题语料、人工修订稿、模型初稿、精选语料和录音稿。原始内容可以多，但精选语料数量不必多，质量必须高。很多人搭系统容易做乱，就是因为把所有材料不加区分地塞进去。我的做法是：历史文章全部归档，但让模型优先学习的，只有那些能代表我风格、判断和行业经验的精选内容。普通存档不进入优先样本。

第二类，方法库。这里放可以反复使用的业务判断，比如内容线索成交一体化模型、增长预算分层模型、公众号贴图号运营方法、小红书 KOS 矩阵方法、老师 IP 孵化 SOP、模型内容系统搭建方法、数据复盘指标体系、私域承接话术框架。方法库不是简单存文章。文章是给读者看的表达，方法是给团队用的认知。比如我写过很多教育内容文章，但进入方法库的从来不是整篇文章，而是背后的结论：什么内容能带来线索，什么内容只能带来阅读，什么内容容易吸引同行，什么内容吸引家长，什么内容适合投放，什么内容适合搜索留存，什么内容适合私域转化。把这些判断抽出来形成独立条目，下一次写方案、做培训、搭系统时，模型才能直接调用。

第三类，案例回顾区。这是我最看重的一类。很多机构的问题是只会做数据报表，不会做案例复盘。某个渠道跑了一段时间，有线索、有完课、有成交、有投放成本、有 ROI，如果只汇报一下就结束，那它就是一次项目结果；如果能写成复盘，它就会变成资产。我会把实际项目拆成九块：背景、目标、核心动作、过程数据、关键结果、问题判断、踩坑记录、下一步动作、可留存资产。举个例子，某个公众号贴图号项目，脱敏后的信息大致是：某阶段累计做了 xx 个内容账号，获得 xxxx+ 条线索，推动 xxx+ 次体验，最终成交 xx 单，整体 GMV 达到某个体量级，总成本约某个量级，单条线索成本和成交成本都低于主要付费渠道。

如果这组数据只躺在汇报 PPT 里，它很快就会过时。放进资产系统后，它能延展出一篇公众号文章、一份项目复盘、一套账号矩阵 SOP、一份预算申请材料、一份兼职老师培训方案、某客户陪跑案例、一套数据看板字段模板。同一个项目，从一次汇报变成多类可复用资产，这才是系统最值钱的地方。

第四类，交付资产区。这里放未来可以卖、可以交付、可以反复使用的东西，比如低客单资料包、课程大纲、陪跑交付 SOP、咨询问题库、训练营内容、社群运营动作、客户诊断表、复盘报告模板。这部分对我特别重要，因为我不想只做内容。我真正想做的是把经验变成产品、服务和系统。每一次项目复盘、每一次内容创作、每一次咨询回答，如果能进入交付资产区，长期就会变成我的交付底盘。比如我做某个早教项目陪跑时形成的账号定位表、内容选题表、转化链路表、周报模板，都可以拿去服务其他本地教育机构。前提是做完就要留存，否则每个客户来了，你都得重新做一遍。

第五类，在办项目区。这里放正在进行中的实际项目，包括主增长项目、常规推进项目、IP 类项目、自由项目和已归档项目。这里有个关键：在办项目区要和资产库区分开。项目区是“现在正在操盘的事”，资产区是“操盘完之后沉淀下来的打法”。项目里会有很多临时资料、过程文档、会议纪要、数据表，但不是所有东西都值得长期保留。要定期筛选，把有复用价值的迁移到方法库、案例回顾区和交付资产区。我给自己定的规则是：过程资料留在项目区，关键结论进入资产区，可交付内容进入交付资产区，可写成文章的进入内容资产区，可反复调用的进入方法库。

再就是两个主控文件。第一个是业务与人设主控，我的叫《000_娃哥大脑主控》。里面写明我是谁、定位是什么、服务谁、核心标签是什么、做过什么项目、相信什么、反对什么、内容写给谁、风格是什么、业务最终导向哪里、哪些数据不能公开、哪些内容必须落到教育增长。机构版也可以照这个思路写：做什么赛道、目标用户是谁、核心产品是什么、课程优势是什么、老师优势是什么、家长为什么买、家长为什么不买、历史成功案例有哪些、哪些数据必须脱敏、内容最终引导到资料、诊断、试听还是咨询，以及团队过去写内容最常犯什么错。

第二个是 Agent 工作规范，也就是给 Codex 看的执行文件。它不是一个给人读的宣言，而是告诉 Codex：每次开工前要读哪些文件、哪些文件优先级最高、生成内容保存到哪里、初稿放哪里、修订稿放哪里、修订记录怎么更新、哪些目录不能碰、哪些数据必须脱敏、哪些项目不能混用、不能自行删改或迁移文件、遇到不确定的情况怎么处理。

这一步很关键。因为 Codex 能操作文件，能干活，也可能干坏活。必须给它边界。规范不要写“你要成为优秀助手”这类空话，要写具体的规则，比如：本项目只围绕娃哥教育行业增长资产库展开；涉及实际项目、实际客户、实际账号、实际人员、实际数据，默认全部脱敏；除非明确授权，否则不能对项目之外的文件进行删除、移动或改名。写作规则也可以放进去：写作前需要读取《000_娃哥大脑主控》、风格规范、人工修订记录库和精选语料目录；生成文章时同时保存初稿和修订稿；收到“改好了，学习并入库”后，必须对比两版、总结修改偏好并追加到人工修订记录库。这才是让 Codex 长期稳定工作的核心。

五、最核心的工作流：初稿—人工修订—反馈入库

整套系统最核心的不是目录，而是这条循环：模型初稿、人工修订、差异对比、偏好提炼、记录入库、终版归档、下次优先调用。这也是大多数人用模型写内容时最容易漏掉的一环。

很多人把模型当外包。扔一个话题过去，让它写一篇，写完觉得不满意，自己改一改，然后发布，到这里就结束了。这恰恰浪费了最值钱的部分。因为你的真正能力就体现在“怎么改”上：你删掉了哪些空话，保留了哪些表达，补了哪些数据，加了哪些业务判断，调整了哪些结构，把哪句话从通用感改成了人味，为什么觉得某个案例不够真实，为什么觉得某个标题不够狠，为什么觉得某个结论没有落到成交。这些东西才是你的风格和经验。如果它们没有被留存，模型永远学不会。

我现在每次写内容，都会让 Codex 生成两个文件：一份叫模型初稿，一份叫人工修订稿。两份内容刚开始完全一样，我只改人工修订稿，不去碰模型初稿。改完之后我会告诉 Codex：“我改好了，请对比两版，总结这次的修改偏好，并把最终版入库。”

这时 Codex 会做几件事：对比两版差异，归纳我删掉了哪些通用表达、强化了哪些判断、补充了哪些一线细节、调整了哪些结构；把这些偏好追加到人工修订记录库；把最终版复制进正式内容区；如果内容足够好，就进入精选语料。这就形成了训练循环。

举几个实际例子。

写数据类文章时，模型很容易写成报告。比如开头就是：“本文将从数据维度、渠道维度、转化维度进行分析。”这句话没错，但不像我。我会改成：“最近看了不少教育机构的数据表，越来越有一个感受：很多老板不是不看数据，而是看了一堆没用的数据。”改完之后，修订记录库会记下：数据类文章不能用写报告的方式起笔，要从一线观察和老板的真实困惑切入。

写表格类文章时，模型喜欢每张表后面补一句：“这张表主要用于查看账号基础情况。”我会把那句废话删掉，直接写：“这张表不需要复杂，老板只用看三件事：账号是谁在做、发了多少、有没有线索。”修订记录库会记下：表格类内容别解释概念，要直接告诉老板看什么、怎么用、谁负责。

写平台规则类文章时，模型常写：“最近平台发布了新规。”我会改成：“某平台在某个时间节点，通过某个官方账号、后台通知或规则页面，释放了一个很明确的信号。”修订记录库会记下：引用平台规则要尽量写清时间、来源、发布形式和业务影响，别只是一句泛泛的“最近”。

这套循环跑三次，感觉可能不明显；跑十次，模型就会明显开始贴近你的偏好；跑五十次，它会越来越像你；跑一百次，它就不只是帮你写内容了，而是在学习你的表达系统和业务判断系统。到那时，它才真正配得上“第二副脑”这个名字。
