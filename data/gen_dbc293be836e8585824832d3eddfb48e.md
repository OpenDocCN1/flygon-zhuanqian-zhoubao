# 153个AI公众号的7万篇文章，如何用数据还原爆款账号的成长路径？

前段时间，亦仁提到过一个值得关注的AI赛道机会：围绕某个细分方向，持续输出AI资讯、工具测评或行业内容，积累影响力后，再通过商单、服务等方式完成变现。

这个方向到底有没有可复制性？

与其凭感觉判断，不如直接研究已经跑出来的账号。

于是，我做了一次相对系统的数据采集与分析：整理公众号AI领域头部KOL的历史文章，观察他们的内容类型、阅读走势、爆款节点以及账号成长过程，试图从真实数据中总结出AI自媒体的运营规律。

目前，第一阶段已经完成。

## 一、我采集了哪些数据？

这次主要从公众号开始，完成了三项工作：

1. 汇总153个公众号AI垂类账号；
2. 抓取这些账号公开发布过的历史文章，累计超过7万篇；
3. 对文章进行AI辅助分析，包括摘要提取、软文识别、内容分类等。

每篇文章尽可能保留了完整字段，包括：

- 文章标题；
- 原文链接；
- 发布时间；
- 阅读量；
- 点赞数；
- 公众号名称；
- 是否原创等信息。

在账号层面，我还进一步分析了：

- 账号文章数量；
- 历史阅读量变化；
- 爆款文章出现的时间；
- 内容发布节奏；
- 月度阅读和点赞趋势；
- 账号从积累到爆发的关键节点。

为了更直观地观察数据，我还使用Claude辅助制作了可视化图表，并为每个公众号生成独立分析报告。

接下来，我会逐步公开这批AI公众号文章数据、AI分析提示词以及相关处理方法。后续也会继续扩展到小红书、抖音、Twitter等平台，持续采集热门AI创作者的内容。

## 二、案例：卡兹克是如何完成破圈的？

我们先看一个典型案例——卡兹克公众号。

从采集结果来看，卡兹克真正实现流量跃升，并不是突然发生的，而是经历了较长时间的内容积累。

按照文章阅读量排序后可以看到：

- 2024年1月10日，一篇介绍Magnific AI的文章首次突破10万阅读；
- 2024年2月，Sora相关内容再次达到10万+；
- 在此之后的半年多时间里，账号持续产出爆款，共有11篇文章突破10万阅读。

换句话说，Sora并不是账号第一次被看见，而是前期积累之后的一次集中爆发。

这组数据说明，AI公众号的增长往往不是单篇爆文决定的，而是由长期积累、热点捕捉和连续输出共同推动。

## 四、拿到7万篇文章后，如何进行分析？

原始数据规模较大，如果只打开Excel逐行查看，很难发现账号的长期变化。

因此，下一步是把文章数据转化为可视化结果。

我向Claude提出的目标大致包括以下几个方面：

### 1. 搭建可视化看板

希望能够展示：

- 阅读量随时间的变化；
- 账号发文数量；
- 阅读量和点赞数趋势；
- 爆款文章分布；
- 不同账号之间的对比。

图表形式可以包括：

- 折线图；
- 柱状图；
- 散点图；
- 热力图；
- 分布图。

同时，最好支持从账号整体数据逐层下钻到具体文章。

### 2. 分析用户反馈与发布时间

重点关注：

- 日、周、月阅读量走势；
- 点赞数与阅读量的比例；
- 评论数、点赞数和阅读量之间的关系；
- 不同发布时间对文章表现的影响；
- 高阅读量文章集中出现在哪些时期。

### 3. 自动生成分析报告

最终希望系统能够自动输出：

- 账号整体概况；
- 关键增长节点；
- 代表性爆款文章；
- 阅读和互动趋势；
- 账号运营特点；
- 后续可参考的内容策略。

数据库表结构如下：

```sql
CREATE TABLE `wechat_articles` (
  `id` int NOT NULL AUTO_INCREMENT,
  `user_name` varchar(255) DEFAULT NULL,
  `nick_name` varchar(255) DEFAULT NULL,
  `original_article_count` varchar(255) DEFAULT NULL,
  `original_content_str` text,
  `title` text,
  `digest` text,
  `show_desc` text,
  `item_index` varchar(255) DEFAULT NULL,
  `url` varchar(255) DEFAULT NULL,
  `is_original` tinyint(1) DEFAULT NULL,
  `read_view` int DEFAULT NULL,
  `like_count` int DEFAULT NULL,
  `send_time` datetime DEFAULT NULL,
  `collect_time` datetime DEFAULT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `url` (`url`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

这张表已经能够支撑大部分分析需求，包括账号识别、文章统计、阅读量计算、原创文章判断、发布时间分析等。

## 五、从单个公众号报告，升级到批量生成

Cursor第一次生成的代码已经能够完成数据处理和图表绘制，但在实际运行中发现了一个问题：

它误把数据库里的全部文章当成了同一个公众号。

因此，需要明确告诉它：数据库中包含100多个不同账号，必须按照公众号名称分组，分别生成每个账号的分析结果。

每个公众号至少需要输出以下内容：

- 公众号名称；
- 最早发文时间；
- 最近发文时间；
- 文章总数；
- 平均阅读数；
- 平均点赞数；
- 原创文章数量；
- 阅读量最高的20篇文章；
- 阅读量随时间变化的曲线；
- 文章阅读量分布图；
- 按月统计的阅读量趋势；
- 按月统计的点赞数趋势。

再次执行后，系统已经能够针对每个公众号生成独立报告。

不过，如果每个账号都单独输出一个文件，阅读和分享都不够方便。因此，下一步是把所有账号的结果合并成一个PDF。

## 六、最终的报告结构

合并后的PDF不只是简单拼接页面，还需要增加一个总目录。

目录中列出所有公众号名称，并支持点击后直接跳转到对应账号的分析部分。

这样，整份报告的阅读方式就变成：

1. 先通过总览了解全部账号情况；
2. 在目录中选择目标公众号；
3. 点击账号名称跳转；
4. 查看该账号的完整数据分析；
5. 对比不同账号的增长阶段和爆款表现。

最终生成的PDF将包含：

- 公众号目录；
- 每个账号的基础信息；
- 历史发文时间范围；
- 文章规模；
- 阅读量与点赞量概况；
- 爆款文章排行榜；
- 阅读趋势图；
- 阅读量分布图；
- 月度阅读与点赞趋势；
- 账号阶段性增长总结。

整个过程最后被压缩成一个自动化脚本：读取数据库或Excel文件后，自动完成数据清洗、账号分组、指标计算、图表生成、报告排版、目录创建，并导出一份完整PDF。

也就是说，不需要手动逐个处理账号，也不用反复复制图表。

只要准备好原始数据，运行一次脚本，就可以得到一份包含153个AI公众号分析结果的总报告。

这套方法的价值，不只是做出一份漂亮的图表，更重要的是能够从大量公开文章中观察：

- 哪些AI主题更容易获得传播；
- 一个账号从何时开始出现增长拐点；
- 爆款之前是否存在明显的铺垫；
- 不同账号的内容结构有什么差异；
- AI工具、行业解读和热点追踪分别带来了怎样的流量；
- 公众号的增长究竟来自偶然爆文，还是稳定的内容系统。

对于想研究AI内容赛道、寻找账号增长规律，或者准备进入垂直AI自媒体的人来说，这些数据比单纯阅读几篇爆款文章更有参考价值。
